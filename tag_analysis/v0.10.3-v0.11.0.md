# Changes from v0.10.3 to v0.11.0

## Overview

**Date Range:** October 2, 2013 - November 2, 2013
**Total Commits:** 246
**Release Date:** November 2, 2013

This release represents a significant milestone in Elixir's development, introducing major architectural improvements to the protocol system, substantial Unicode support enhancements, and significant performance optimizations across the board.

---

## Summary

The v0.11.0 release focused on three primary areas: **protocol system optimization**, **comprehensive Unicode support**, and **performance improvements**. The protocol consolidation feature represents a major architectural change that improves runtime performance by pre-computing protocol implementations at compile time. Parallel to this, Elixir made Unicode the default for all regex operations and updated the Unicode database to the latest standard (6.3.0). Additionally, native implementations of number parsing (Integer and Float) replaced generic solutions, and the Mix build system received critical improvements for handling umbrella projects and dependency convergence.

The release also introduced the long-awaited `IEx.pry/1` feature for interactive debugging, refactored the IEx architecture to be more robust, and deprecated several language features in preparation for future simplification.

---

## Major Features and Improvements

### 1. Protocol System Consolidation

**Commits:** Multiple including `a2c1f362c`, `bae4c1c4c8`, `fad38e1bab`, `2297f3417`

Protocol consolidation is a major architectural improvement that pre-computes protocol implementations at compile time rather than determining them at runtime. This provides significant performance benefits for systems that use protocols extensively.

- **Implementation of protocol consolidation:** Protocols are now consolidated during compilation, eliminating the overhead of dynamic dispatch lookups
- **Removal of `@prioritize` directive:** Simplified protocol declaration by removing the need to manually specify implementation priorities
- **Explicit fallback to any:** Protocols that fall back to the `Any` implementation must now explicitly declare this behavior, making code more explicit and preventing surprising behavior
- **Protocol attributes stored:** `@protocol` and `@impl` metadata are now stored with key-value information for better introspection

This change makes protocols much more performant without requiring any changes to protocol usage patterns.

### 2. Unicode Support Enhancements

**Commits:** `5f6fa9be1`, `81c6ac254`, `6fbc92b08`

Elixir significantly expanded its Unicode support to align with the latest Unicode standard and made Unicode the default for regex operations:

- **Updated Unicode database to 6.3.0:** The latest Unicode character properties, categories, and grapheme breaking rules are now supported
- **GraphemeBreakProperty implementation:** Now uses the proper Unicode Annex #29 specifications for determining grapheme cluster boundaries, providing correct handling of complex scripts like Devanagari and combining marks
- **Unicode as default for regexes:** Regular expressions now use Unicode by default, making `.` match Unicode graphemes properly and enabling correct case-insensitive matching for international text

This aligns Elixir with modern internationalization standards and removes the need to explicitly specify `u` flag for regex.

### 3. Native Number Parsing

**Commits:** `64754ab7b`, `60d11ed7c`, `95e3fec72`, `046af30c1`

Replaced generic number parsing with native Erlang implementations for dramatically improved performance:

- **Native Integer.parse/1:** Uses native Erlang parsing, significantly faster than previous implementation
- **Native Float.parse/1:** Native float parsing with proper handling of edge cases
- **Additional validation:** Both functions now properly reject double signs (`++`, `--`) and multiple decimal points (`.` appearing more than once)
- **Extra test coverage:** Comprehensive test coverage ensures edge cases are handled correctly

These implementations improved parsing performance substantially, which is particularly important for parsing large amounts of numeric data.

### 4. IEx Interactive Debugger Integration (Pry)

**Commits:** Multiple including `0df9285db1`, `9fbe5cc57c`, `3eb89fb31c`, `cbec46355`, `78b5debd35`, `79d2ddc46a`

A major feature addition that enables developers to pause execution and drop into an IEx session for debugging:

- **IEx.pry/1 implementation:** Allows developers to insert breakpoints in their code that drop into a live IEx session at that point
- **Server-based architecture:** IEx now uses a dedicated server process for managing the interactive environment
- **Process takeover:** The interactive process can take over from its parent, allowing pry to work even in deeply nested evaluations
- **IEx.Helpers.respawn:** Helper function to respawn the IEx process
- **Proper scope capture:** Pry captures the correct scope and binding, allowing inspection of local variables

This feature proved to be one of the most important additions for Elixir developers, making interactive debugging much more accessible.

### 5. Enhanced IEx User Experience

**Commits:** Multiple including `af2ce9cfc4`, `0b51a53fe9`, `bc10b6d848`, `76b3a2af69`, `06126261de`

Significant improvements to IEx usability and documentation:

- **ANSIDocs integration:** Better formatted documentation in IEx with proper handling of markdown, code blocks, lists, and links
- **History management:** IEx.History.reset/0 allows clearing command history
- **Configuration unification:** All IEx configuration now handled centrally by IEx.Server
- **Markdown escaping:** Proper handling of escape sequences in documentation
- **Color management:** Better color support detection and categorical color configuration

These improvements made IEx more pleasant to use and more informative when reading documentation.

### 6. Mix Build System Improvements

**Commits:** Multiple including `737b398, `67ac77fd, `7d2669634`, `8be9ceac82`, `ca8a877d69`, `caa2eb170`

Significant enhancements to the Mix build system, particularly for umbrella projects:

- **Manifest-based compilation:** Mix now uses cached manifest information to determine what needs recompilation, dramatically speeding up incremental builds
- **Dependent file tracking:** Mix tracks which files depend on which, allowing for more precise recompilation decisions
- **Umbrella project refactoring:** Apps in umbrella projects are now treated as dependencies, simplifying the model and improving correctness
- **Automatic umbrella refs:** When creating new apps in an umbrella, dependencies are automatically generated
- **Dependency convergence:** Ensures dependencies at the same level are converged, removing duplicates
- **Escript support:** Mix works correctly even when installed as an escript

These changes made incremental compilation much faster and umbrella projects much more manageable.

### 7. String and Collection API Enhancements

**Commits:** `9a9fc731`, `4c2301b3a`, `e93bd1e21`, `a4deb46d9`, `429548ea7`, `ea9b0e07d`, `15d2d9f24`, `a31f180dd`, `821b7c6f7`

Consistent improvements to collection manipulation:

- **String.slice with Range:** String.slice now accepts Range arguments, enabling idiomatic slicing like `String.slice(str, 0..5)`
- **Enum.slice with Range:** Similar to String.slice, Enum.slice now supports Range arguments
- **Set and Dict === consistency:** Both Set and Dict APIs now consistently use `===` (strict match) instead of `==`, ensuring proper semantics for comparing keys
- **Number protocol split:** The generic Number protocol was split into Integer and Float for better type safety
- **Tuple module:** Tuple-related functionality was consolidated into its own Tuple module
- **Access improvements:** Eliminated unnecessary flattening in access operations

## Breaking Changes

The following changes break backward compatibility and require developer action:

### 1. Protocol Deprecations

- **`@only` and `@except` directives:** These protocol-level directives are deprecated. Protocols that need to limit implementations should use consolidation or explicit guards
- **`@prioritize` removed:** Code using this directive must be refactored to use other approaches

### 2. Pattern Matching Changes

- **`x in y` syntax deprecated:** The `x in y` pattern matching syntax is deprecated in favor of `x <- y` in comprehensions and other explicit patterns. This removes ambiguity between the operator and pattern matching context

### 3. Set and Dict API Changes

- **Operator changed from `==` to `===`:** This is a semantic change - both Set and Dict now use strict match comparison for keys instead of equality comparison. This prevents bugs where floats and integers with the same value would be considered the same key:
  ```
  # Before: Set.put(set, 1) and Set.put(set, 1.0) would conflict
  # After: They are distinct keys
  ```

### 4. Encoding-based Conversions Deprecated

- **Atom ↔ Binary conversions with encoding:** Functions that converted atoms to binaries with specific encodings are deprecated. These should be replaced with more explicit operations

### 5. Kernel Module Cleanup

- **Pid conversions removed:** Functions for converting PIDs to strings were removed from Kernel. These operations should use the String.Chars protocol instead

### 6. Configuration File Removed

- **`.elixirrc` file support dropped:** The per-project `.elixirrc` file is no longer supported. Use `mix` configuration instead

### 7. Macro.expand_all Deprecated

- **`Macro.expand_all/1` is deprecated:** This function's behavior is redundant with other macro expansion mechanisms

## Bug Fixes and Corrections

### Compiler and Language

- **Fixed nil.func() error messages:** Error messages for calling methods on nil are now clearer
- **Fixed nested defmodule alias shadowing:** Nested module definitions no longer incorrectly shadow aliases from outer scopes
- **Fixed module redefinition race condition:** Concurrent module redefinitions in tests no longer cause subtle failures
- **Improved interpolation handling:** String interpolation no longer performs unnecessary char list conversions
- **Fixed redefining modules in mix tests:** Mix test framework now handles module redefinition correctly

### IEx and REPL

- **Fixed autocomplete on single dot:** IEx no longer terminates when attempting autocomplete on a bare dot (`.`)
- **Fixed Process.group_leader for pry:** The Process.group_leader function now works correctly with IEx.pry, allowing proper output redirection

### Collections and Enumerables

- **Fixed Enum.member? semantics:** Enum.member? now correctly uses match semantics (`===`) to check membership
- **Fixed Stream.flat_map wrapping:** Stream.flat_map no longer incorrectly intercepts wrapped lazy enumerations

### Build System

- **Do not write manifest on compilation errors:** If compilation fails, the manifest is not updated, preventing stale cache issues
- **Fixed build bootstrap issues:** Various bootstrap issues with the build system were resolved
- **Improved error messages throughout Mix:** Mix now provides more helpful error messages in various failure scenarios

### Documentation and Type Specs

- **Numerous type spec corrections:** Fixed invalid raise specifications and other type spec issues
- **Documentation improvements:** Extensive cleanup and improvement of docstrings across the standard library
- **Markdown escaping in docs:** Underscores and other special characters in documentation links are now properly escaped

## Themes and Architecture Direction

This release demonstrates Elixir's commitment to:

1. **Performance without sacrificing simplicity:** Protocol consolidation shows that Elixir can achieve significant performance improvements through compile-time optimizations rather than requiring developers to change their code

2. **International first-class support:** Making Unicode the default and updating to the latest standards shows commitment to applications that need to work globally

3. **Developer experience:** The introduction of IEx.pry and significant IEx improvements prioritize making Elixir a pleasant language to work with and debug

4. **Simplification and clarity:** Deprecating multiple features (@only, @except, x in y) shows an intention to reduce API surface and remove sources of confusion

5. **Robustness:** Build system improvements for umbrella projects and dependency handling make large projects more reliable
