# Changes from v0.12.0 to v0.12.1

## Overview
- **Released**: January 4, 2014
- **Previous Release**: December 15, 2013
- **Time Span**: 20 days
- **Total Commits**: 155 commits

This release focused on significant internal refactoring of the compilation system, new testing capabilities, and important bug fixes. The changes represent substantial architectural improvements to how Elixir handles expression expansion and compilation.

---

## Summary of Key Themes

The v0.12.1 release represents a major maintenance and improvement release with three primary focus areas:

1. **Compilation Architecture Refactoring**: A large-scale refactoring to move from an older form-based system to a newer expression-based expansion system. This involved systematic rewriting of core compilation components for better performance and maintainability.

2. **Test Framework Enhancement**: Introduction of a comprehensive filtering system for ExUnit tests, allowing fine-grained control over which tests run based on tags and filters. This feature was built through careful iteration and refinement.

3. **Documentation and Output Improvements**: Significant refactoring of ANSI documentation display system, moving code from IEx into a more general `IO.ANSI.Docs` module, with improvements to color handling and presentation.

---

## Major Features & Improvements

### 1. ExUnit Test Filtering System

One of the most significant feature additions in this release is the comprehensive test filtering framework:

- **Tag-Based Filtering**: Tests can now be filtered by tags, allowing selective test execution
- **Include/Exclude Filters**: Support for both positive inclusion and negative exclusion of test tags
- **Multiple Tag Matching**: Filters can match on multiple tag conditions with AND/OR logic
- **CLI Integration**: New command-line options for specifying filters when running tests
- **Documentation**: In-depth documentation on using filters as flags

**Key commits**: Multiple foundational commits establish the filter infrastructure, parsing logic, and test application. The system evolved from basic tag support to more sophisticated include/exclude filter mechanisms.

### 2. Expression-Based Compilation System

A major refactoring effort that moves the core compilation from an older form-based approach to a modern expression-based system:

- **Expansion Framework**: Complete rewriting of how expressions are expanded during compilation
  - Moved from relying on forms to directly working with Elixir expressions
  - Systematic expansion of all major language constructs

- **Covered Constructs**: The expansion system now handles:
  - Aliases (with separate expansion phase)
  - Variables (new expansion phase)
  - Tuples and other special forms
  - Quote expressions
  - Remote calls
  - `^var` (pin operator)
  - Super calls
  - Comprehensions
  - Requires and imports
  - Case, receive, try statements
  - Function definitions (fn)
  - Captures

- **Performance Improvements**: Local variable tracking and caching improves compilation speed and reduces memory consumption

**Key commits**: This refactoring spans a large portion of the release, with commits showing systematic progression through each language construct. The work includes renaming of core components (e.g., `DispatchTracker` to `LocalsTracker`) and optimization of variable handling.

### 3. IO.ANSI.Docs Module

Refactoring and expansion of ANSI documentation display functionality:

- **Module Reorganization**: Moved `IEx.ANSIDocs` functionality to a more general `IO.ANSI.Docs` module
- **Parameterized Colors**: Complete refactoring to use parameterized color options throughout
- **Improved Documentation**: Enhanced documentation for printing functions with color support
- **Flexible Defaults**: Removed IEx-specific options from default arguments, making the module more general-purpose
- **Inline Handling**: Improved color handling for inline code and formatting

**Key commits**: Series of methodical refactors moving color parameters through the codebase, improving structure and maintainability.

### 4. Documentation Improvements

- Fixed typos in Kernel and String module documentation
- Fixed typos in URI module documentation
- Fixed code sample bugs in Stream.resource documentation
- Improved documentation for core language features (case, try, receive, ^)

## Bug Fixes

### Critical Fixes

1. **ExUnit Setup/Teardown**: Fixed issue where teardown would not run if setup failed
   - Important for test cleanup to avoid leaving resources in inconsistent state
   - Ensures proper resource cleanup even in failure scenarios

2. **GenServer/GenFSM Unknown Messages**: Fixed handling of unknown messages
   - GenServer now stops on unknown call/cast requests
   - GenFSM now shuts down on unknown messages
   - Prevents unexpected behavior when receiving unexpected message types

3. **Float Parsing**: Fixed `Float.parse` to correctly handle negative zero format ("-0.x")
   - Important for numeric accuracy and edge case handling

4. **Lexical Scope in Try Blocks**: Fixed bugs and simplified lexical scope handling in try expressions
   - Critical for variable scoping correctness

5. **Variable Leaking**:
   - Ensured variables in remote calls do not leak to arguments
   - Do not leak clause heads (fixes #1948)
   - Fixed environment macro counter handling

### Important Fixes

6. **Module Reload**: Ensures modules are loaded before attempting to reload
   - Prevents errors when using IEx's `r` helper

7. **IEx Helpers**:
   - Improved error message when `r` helper is used on non-existent modules
   - Made sure IEx `r` helper does not return a record

8. **Filter Bugs**: Fixed various bugs in test filter application and evaluation
   - Fixed bug in applying multiple filters
   - Proper handling of filter edge cases

9. **IO.ANSI.Docs**: Fixed multiple issues in documentation rendering
   - Fixed references and test cases

10. **Mix Symlinks**: Using relative symlinks properly (fixes issue #1953)
    - Important for portable builds and development

11. **Lock Status Check**: Fixed origin URL handling during dependency updates
    - Ensures dependency lock files remain consistent

12. **Warning Recording**: Ensured warnings are recorded only if there are no compilation errors
    - Prevents false warnings in presence of critical errors

## Breaking Changes

### Deprecations

1. **`__FILE__` Deprecation**:
   - `__FILE__` is now deprecated in favor of `__DIR__` or `__ENV__.file`
   - Provides better semantics: `__DIR__` gives directory, `__FILE__` gives full path
   - Allows more explicit control over what information you need

### Notable Internal Changes

These are not necessarily user-facing breaking changes but represent significant API reorganization:

1. **Compiler API Refactoring**:
   - Renamed internal components (e.g., `DispatchTracker` to `LocalsTracker`)
   - Removed `is_` prefix from internal APIs (naming consistency)
   - Renamed `translate_each` to `translate`, `temp_vars` to `match_vars`
   - Changed AST representation of `->` operator

2. **Module Compilation Flow**:
   - Module compilation now relies on new `elixir_exp` expansion system
   - Function bodies now use expansion instead of older form-based approach

3. **Removal of Deprecated Functions**:
   - Old deprecated functions have been removed

## Notable Implementation Details

### Compilation System Architecture

The compilation refactoring represents a shift from form-based to expression-based processing:

- **Before**: Used Erlang forms as intermediate representation
- **After**: Works directly with Elixir expressions for better control and clarity
- **Benefit**: More maintainable code, better performance, clearer semantics

### Variable Hygiene Improvements

- Implemented main counter for hygienic variable generation
- Optimization of variable merging by keeping a counter (significant performance improvement)
- More conservative counter passing to reduce variable copying

### Test Filter System Architecture

The filter system evolved through careful incremental refinement:

1. Started with basic filtering infrastructure
2. Added support for multiple tag matching
3. Implemented include/exclude filter logic
4. Integrated with command-line interface
5. Added comprehensive documentation

## Conclusion

Version 0.12.1 represents significant internal improvements and architectural refinements to Elixir. While the user-facing changes (test filtering, deprecations) are important, the compilation system refactoring represents the most substantial technical achievement of this release.
