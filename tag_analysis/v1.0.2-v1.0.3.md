# Changes from v1.0.2 to v1.0.3

## Overview

**Date Range:** October 21, 2014 - February 12, 2015
**Total Commits:** 60
**Release Date:** February 12, 2015

This release spans nearly 4 months of development and represents the first significant patch release after v1.0.2, focusing on stability improvements, Windows compatibility fixes, and various tooling enhancements.

## Summary

v1.0.3 is primarily a maintenance and bug fix release that addresses stability issues, improves developer experience, and significantly enhances Windows compatibility. The release includes important internal refactoring to improve state management, substantial improvements to the interactive shell (IEx), and fixes to several core libraries. No major breaking changes were introduced, making this a solid incremental improvement.

## Major Features & Improvements

### Internal State Management Architecture

The most significant architectural change involves introducing dedicated state management modules:

- **Mix.State**: Stores internal mix state (replaces ad-hoc state storage)
- **IEx.Config**: Stores internal IEx state for consistency and reliability
- **elixir_config**: Provides a centralized location for internal Elixir state
- **Logger state management**: Improved configuration handling through `config_change/3` to maintain logger state across configuration changes

This refactoring enhances code reliability by preventing state races and ensuring clean state management across different components.

### IEx Interactive Shell Enhancements

Significant improvements to the interactive experience:

- **Enhanced autocomplete implementation**: Complete rewrite of autocomplete logic with better performance and reliability
- **Erlang module completion**: Added support for completing Erlang modules, not just Elixir modules, expanding the utility of autocomplete
- **Loaded application modules**: IEx now properly uses loaded application modules for completion, providing more accurate suggestions

These changes make the interactive shell more responsive and helpful for developers working with both Elixir and Erlang code.

### Mix Compiler & Build Improvements

- **Nested directory handling**: Mix compiler can now properly handle nested directories during compilation
- **Clean failure states**: Compilation failures no longer leave spurious data in the build directory, improving build reliability
- **Windows build consistency**: "Always rebuild structures on Windows" ensures consistent builds across Windows machines

### Documentation System

- **Documentation compilation**: Docs are now compiled to `doc/` directory instead of being generated ad-hoc
- **URI documentation improvements**: Enhanced docs for URI parsing with clearer examples and better edge case documentation

## Bug Fixes

### Critical Fixes

1. **Enum.take/2 boundary fix**: Fixed an off-by-one error in `Enum.take/2` that could cause incorrect results (closes #3042)
2. **Logger configuration persistence**: Fixed logger to maintain configuration state across configuration changes, preventing logger from shutting down unexpectedly
3. **Bootstrap issues**: Fixed critical bootstrap failures that prevented Elixir from starting in certain environments

### Important Stability Fixes

1. **Inspect error stacktraces**: The original stacktrace is now preserved when inspect encounters errors, improving debugging
2. **Compilation warnings**: Stopped showing aliases and import warnings when code cannot compile, reducing noise in error output
3. **Logger shutdown**: Only shut down Logger if the application is being actually started, preventing premature shutdown in certain scenarios
4. **Application info queries**: Switched from undocumented `application.info` to `which_applications`, improving compatibility with different Erlang/OTP versions

### Windows-Specific Fixes

1. **File copying on Windows**: Ensured `priv/include` are copied on Windows even if source modification time unchanged
2. **Escripts on Windows**: Rebar is now properly quoted when running escript on Windows, fixing path issues with spaces
3. **Archive error handling**: Improved error messages for archive operations on Windows

### IO/ANSI Improvements

1. **Regex escape character handling**: Initially added proper handling for escape characters in regex patterns, then reverted due to unexpected impacts
2. **ANSI format consistency**: Mixed shell messages now properly use `IO.ANSI.format/1` for consistent escape sequence handling
3. **Documentation backticks**: Fixed IO.ANSI.Docs handling of backtick characters in documentation

## Code Quality & Maintenance

- **Map reduce optimization**: Optimized `Enum.reduce` for maps, improving performance on map operations
- **Compiler warnings**: Added handling to ignore exported vars warnings during compilation
- **Error messages**: Improved error message clarity for invalid structures in maps, helping developers debug more quickly
- **URI parsing**: More strict URI scheme matching to prevent accepting invalid URIs
- **Copyright years**: Simplified copyright requirement to just show the starting year

## Testing & Hex Integration

- **Hex archive support**: No longer goes through hex.pm API server to install Hex, improving reliability and offline usage
- **Mix archive tests**: Properly set `MIX_ARCHIVES` environment variable in mix archive tests
- **Logger flush in tests**: Proper flushing of logger after tests to ensure clean state
- **ANSI escape handling**: Fixed mix shell tests when ANSI escapes are disabled

## Breaking Changes

**None identified.** This is a pure maintenance release with backward compatibility maintained throughout.
