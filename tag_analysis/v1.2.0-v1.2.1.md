# Changes from v1.2.0 to v1.2.1

## Release Timeline
- **Start Date**: January 1, 2016 (v1.2.0 branch creation)
- **Release Date**: January 14, 2016
- **Duration**: 13 days
- **Total Commits**: 12

## Summary

Elixir v1.2.1 is a patch release focused on bug fixes and stability improvements rather than new features. All 11 substantive commits (excluding the release commit) address specific issues discovered after v1.2.0's initial release. The changes span across core language modules (Macro, Access, Protocol), testing infrastructure (ExUnit), and development tools (IEx, Mix). This was a fast turnaround patch release aimed at addressing critical issues with AST handling, type definitions, and dependency resolution.

## Key Themes and Changes

### 1. **AST and Macro Handling Improvements**
Two commits focused on fixing issues in the `Macro.to_string/1` function, which is responsible for converting Elixir code trees back into strings. This is critical for code introspection and debugging tools.

- **Fix crash in Macro.to_string for sigil-like trees** (Jan 12): Addressed a crash that occurred when the AST tree resembled a sigil syntax but the function was not an atom. This prevents runtime crashes during AST manipulation and string generation.
- **Correct Macro.to_string/1 formatting for capture operator** (Jan 6): Fixed formatting issues with the capture operator (`&`) in macro string output, ensuring consistent and correct representation of captured function references.

### 2. **Access Module Enhancements**
The Access module received significant improvements with 103 insertions focused on documentation and error handling.

- **Improve docs and error handling for Access** (Jan 4): Enhanced documentation and added better error handling for the Access module. This is Elixir's primary module for key-based access to data structures (maps, keyword lists, etc.). Better error messages improve developer experience when things go wrong.

### 3. **Protocol and Type Definition Corrections**
Protocol handling received refinements to catch misuse and type definitions were corrected.

- **Warn when defimp is called for consolidated protocol** (Jan 11): Added a compile-time warning when developers attempt to use `defimp` to implement a protocol that has already been consolidated. This catches a common mistake where protocol implementations are added after consolidation has occurred.
- **Correct the type definition of ExUnit.state for the failed state** (Jan 12): Fixed type definition accuracy in ExUnit's state type spec, ensuring type checkers and documentation tools have correct information about the "failed" state.

### 4. **ExUnit Assertion Improvements**
Several commits improved the robustness of ExUnit's assertion infrastructure.

- **Preserve variable metadata during collection from assertion pattern** (Jan 9): Enhanced metadata preservation when ExUnit extracts variables from assertion patterns. This ensures that variable context is properly maintained for more detailed error reporting.
- **Do not warn in match assertion if variable is reused in pattern** (Jan 6): Fixed an issue where ExUnit would generate false positive warnings when variables were legitimately reused in match assertions. This reduces noise in test warnings.

### 5. **IEx (Interactive Elixir) Improvements**
Two commits improved the REPL experience.

- **Support remote pids/ports with IEx helper i/1** (Jan 2): Extended the `i/1` helper function in IEx to handle remote process identifiers and ports, providing better introspection capabilities for distributed Elixir systems.
- **Fixes bug in IEx.Config.configuration** (Jan 4): Corrected a bug in IEx's configuration system that affected how configuration was loaded and applied in the interactive shell.

### 6. **Mix Dependency Management**
The Mix tool received significant attention for proper dependency handling across different build environments.

- **Ensure dependencies are properly skipped when running in another environment** (Jan 6): This was a substantial refactor of Mix's dependency resolution logic. It ensures that dependencies are correctly skipped when running in alternative environments (e.g., test environment vs. production). This involved changes to both the dependency converger and loader modules, affecting how Mix calculates the dependency graph.

## Major Features/Improvements

1. **Enhanced Access Module** - Better documentation and more informative error messages when working with key-based data access
2. **Improved IEx Capabilities** - Remote PID/port introspection support for better distributed system debugging
3. **Better AST Manipulation** - More robust Macro.to_string handling prevents crashes on edge cases
4. **More Informative Warnings** - New warning when defimp is misused with consolidated protocols helps catch implementation bugs
5. **Dependency Resolution Robustness** - More reliable cross-environment dependency handling in Mix

## Bug Fixes

1. **Macro.to_string crash** - Fixed runtime crash when processing sigil-like AST without atom functions
2. **Macro.to_string capture operator** - Fixed formatting of capture operator in string output
3. **IEx.Config.configuration** - Corrected configuration loading bug in the interactive shell
4. **ExUnit assertion warnings** - Fixed false positive warnings for legitimately reused variables in match assertions
5. **Protocol implementation warnings** - Now properly warns when defimp is called on consolidated protocols
6. **Type definition accuracy** - Corrected ExUnit.state type definition for the "failed" state
7. **Dependency environment handling** - Fixed improper dependency skipping across build environments
8. **IEx introspection** - Extended i/1 helper to support remote PIDs and ports

## Breaking Changes

**None identified.** This is purely a patch release with no breaking changes to the public API. All changes are backward compatible and focus on bug fixes and improvements.

## Notable Commits Worth Highlighting

### 1. **Ensure dependencies are properly skipped when running in another environment** (8da4936ac3)
**Impact**: Medium to High
This commit reorganized how Mix's `dep/converger.ex` and `dep/loader.ex` handle dependency resolution when running in different environments. With 55 insertions and 45 deletions across multiple files, it's the most substantial change in this patch release. This affects the reliability of build reproducibility and environment-specific dependency handling.

### 2. **Improve docs and error handling for Access** (e05bfc78cb)
**Impact**: Medium
With 103 insertions, this commit significantly expanded the Access module with better documentation and error handling. Access is a fundamental module for working with data structures in Elixir, so improvements here benefit many developers' daily experience.

### 3. **Fix a crash in Macro.to_string if a tree looks like a sigil but the function is not an atom** (58a6291f17)
**Impact**: Medium
This fixes a runtime crash that could occur during AST manipulation, which is used in many metaprogramming scenarios and developer tools. Preventing crashes in fundamental operations like this is critical for stability.

### 4. **Warn when defimp is called for consolidated protocol** (81884247d7)
**Impact**: Low to Medium
This adds a helpful compile-time warning for a specific anti-pattern in protocol implementation, making it easier for developers to spot mistakes during development rather than at runtime.
