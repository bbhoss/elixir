# Changes from v1.6.1 to v1.6.2

## Release Overview

- **Release Date**: February 28, 2018
- **Date Range**: January 29 - February 28, 2018 (30 days)
- **Total Commits**: 39 commits (including release commits)
- **Commit Count (substantive)**: 37 commits excluding merge commits and release tags

## Summary

v1.6.2 is a patch release that focuses on bug fixes and refinements to the major features introduced in v1.6.0 (code formatter and DynamicSupervisor). This is not a major feature release, but rather a maintenance release that stabilizes the v1.6 line. The primary themes are:

1. **DynamicSupervisor Stabilization** - Multiple bug fixes addressing error reporting and child restart behavior
2. **Code Formatter Improvements** - Enhanced configuration support and edge case handling
3. **API Restorations** - Bringing back accidentally removed APIs from v1.6.x development
4. **Documentation Refinements** - Clarifications and improvements to existing documentation
5. **Core Compiler/Runtime Fixes** - Several correctness issues in module loading and code generation

This release demonstrates a typical maintenance cycle: stabilizing new features and fixing issues discovered by the community after the major release.

## Major Features & Improvements

### Mix Format Enhancements

#### Subdirectory Support in `.formatter.exs` (#7398)
The most significant enhancement in this release is support for `:subdirectories` configuration in `.formatter.exs`. This feature allows umbrella applications and monorepos to specify multiple directories with their own formatter configuration files:

```elixir
[
  subdirectories: ["apps/app1", "apps/app2", "libs/shared"]
]
```

**Impact**: This makes formatter configuration significantly more flexible for complex project structures. The `mix new --umbrella` command was also updated to use this configuration by default, making it the recommended pattern.

**Changes**: ~329 lines of new/modified code in the format task and its tests, showing this was a substantial feature addition.

#### Erlang Compiler `-behavior` Declaration Support (#7290)
The Mix Erlang compiler now accepts an alternative spelling of the behavior declaration. Erlang code can now use both `-behavior(Mod)` (new) and `-behaviour(Mod)` (original Elixir style):

**Impact**: Improves compatibility with Erlang projects and codebases that use the American spelling variant.

### Documentation Improvements

#### ExUnit.Callbacks Documentation (#7338)
Comprehensive refinement of `ExUnit.Callbacks` documentation covering:
- Setup and setup_all callbacks
- Context introduction and usage patterns
- Multiple ways to define setup code (atoms, lists of atoms, blocks)
- Clarification that multiple setup callbacks can be combined
- Clearer explanation of return values

#### DynamicSupervisor Documentation Updates
Multiple commits improved documentation for `DynamicSupervisor`:
- `child_spec/1` is now publicly documented
- Documentation for `DynamicSupervisor.start_child/2` was clarified
- Guidance on when to use `Supervisor.init/2` vs `supervise/2`
- New child specification format documentation

#### Other Documentation
- Clarification of guard failure behavior (#7334)
- Documentation of `defoverridable` behavior regarding compilation callbacks
- Public documentation of `child_spec/1` callback

### Code Generator Optimizations

#### Attribute Reading Code Injection (5e1e2e6a83)
Reduced code generation when reading attributes through `@attribute` expressions. This optimization decreases the size of generated code and may improve module load times.

## Bug Fixes

### DynamicSupervisor Fixes (Critical)

#### Error Report Tagging (fc1c303481, 8a1c5c38d0)
**Issue**: DynamicSupervisor error reports were not being properly tagged, preventing the Logger from correctly translating and formatting error messages.

**Fix**: Ensured error reports include proper tags so Logger middleware can process them correctly.

**Significance**: This is a behavioral fix that improves error reporting visibility in production environments.

#### Child Restart with Extra Arguments (#7371, 815420ce0f)
**Issue**: When DynamicSupervisor restarted a child with extra arguments provided during `start_child/3`, those extra arguments were not being preserved during restart.

**Fix**: Modified restart logic to properly track and reapply extra arguments when child processes are restarted.

**Significance**: This is a correctness fix for a common dynamic supervisor use case.

### Code Formatter Fixes

#### Arrow Operator Line Length (cba11d6941)
**Issue**: The `->` operator in code could cause line length limits to be exceeded even when explicitly configured.

**Fix**: Ensured that `->` does not pass line length constraints to the formatter.

**Example Impact**: Prevents awkward formatting of multi-clause functions and case statements that could exceed configured line widths.

### Module and Function Handling Fixes

#### Module Loading Before Export Check (717c72e71b)
**Issue**: IEx autocomplete and module inspection could fail if a module wasn't yet loaded into memory.

**Fix**: Added `Code.ensure_loaded?(mod)` check before attempting to call `function_exported?/3`, with proper fallback to `module_info(:exports)`.

**Significance**: Improves robustness of IEx autocomplete and prevents potential runtime errors.

#### Documentation Preservation with @impl (0ded67dd60)
**Issue**: When using `@impl true` on a subsequent function declaration in a protocol, the previous function's documentation was being removed.

**Fix**: Modified compiler logic to preserve documentation from previous declarations when `@impl true` is used.

**Significance**: Prevents accidental loss of documentation in protocol implementations.

### Mix API Restoration

#### Mix.Shell.cmd/2 Restoration (bd0a2e8a12)
**Issue**: The `Mix.Shell.cmd/2` function was accidentally removed during the v1.6.0-v1.6.1 development cycle. This arity was provided via a default argument in `cmd/3` that was lost.

**Fix**: Restored the two-arity version by properly defining the default argument.

**Significance**: A breaking change fix that restores API compatibility for existing code using the two-arity function.

### Supervisor Behaviour Annotation Fix (#7288)

**Issue**: Using `use Supervisor` was not properly adding the `@behaviour Supervisor` annotation to the module.

**Fix**: Ensured the macro injection adds the required behavior annotation.

**Significance**: Allows compiler checks and tools to verify that modules using supervisors actually declare the behavior.

### Guard Expression Fixes

#### Guard Expression Evaluation Order (4b43c7ae20)
**Issue**: Code invocation semantics were being incorrectly changed when guards were involved, potentially affecting argument evaluation order.

**Fix**: Ensured guards do not alter the normal evaluation order of code invocations.

**Significance**: Prevents subtle bugs related to side effects in guard expressions.

#### Missing `do` Option Consistency (0c81857622)
**Issue**: Inconsistent error messages when the `do` option was missing from various definitions.

**Fix**: Standardized error handling to consistently raise errors when `do` is missing.

**Significance**: Better error messages and consistent behavior across different definition contexts.

### Stream API Fix

#### eprof Tool Multiple Process Support (#7317)
**Issue**: The `eprof` profiling tool didn't work correctly when profiling multiple processes simultaneously.

**Fix**: Updated eprof integration to support multi-process profiling scenarios.

**Significance**: Makes the profiling tool more useful for concurrent applications.

### Minor Fixes & Improvements

- **Parenthesis Preservation** (ca49a53ab2): The formatter now more consistently preserves user choices regarding parentheses in code
- **Guard Behavior Clarification** (55241d92e2): Improved documentation explaining guard behavior
- **Missing Dependency Errors** (11086ac450): Error messages now include the current environment context
- **add_doc/6 Restoration** (966f8f74ae): Brought back the six-arity `add_doc` function that was removed

## Breaking Changes

No breaking changes are intentionally introduced in v1.6.2. However, the restoration of `Mix.Shell.cmd/2` and other APIs prevents breaking changes that would have been introduced if they remained removed. This release maintains backwards compatibility with v1.6.1 code.

## Release Patterns & Context

This release reflects Elixir's maintenance practices:

1. **Quick Turnaround**: Released exactly one month after v1.6.1, showing active development cycles
2. **Community-Driven**: Issues are addressed based on user feedback (multiple issue numbers referenced)
3. **Comprehensive Testing**: Each fix includes test updates, visible in the commit logs
4. **Documentation First**: Multiple commits focus on clarifying existing features
5. **Backwards Compatibility**: API restorations show commitment to stability

The focus on DynamicSupervisor and code formatter fixes indicates these were the most impactful features in v1.6.0 that needed refinement. The mix of bug fixes, documentation, and feature enhancements is typical of a healthy maintenance release.
