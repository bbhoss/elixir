# Changes from v1.11.2 to v1.11.3

## Release Overview

**Date Range:** November 3, 2020 - January 4, 2021
**Total Commits:** 30

This patch release focused primarily on bug fixes, compatibility improvements, and documentation enhancements. The release addressed multiple compatibility issues across different Erlang/OTP versions and improved error messaging throughout the compiler and toolchain.

## Summary of Key Themes

v1.11.3 is a maintenance release that consolidates fixes and improvements across three major areas:

1. **Compiler & Language Improvements** - Adding new guard literal support and enhancing tokenizer capabilities with better error location tracking
2. **Compatibility & Maintenance** - Extensive work to maintain compatibility with both older (OTP 23) and newer (OTP 24, Erlang master) runtime versions
3. **Error Handling & Developer Experience** - Improved error messages, warnings, and documentation to help developers understand issues more clearly

## Major Features & Improvements

### Support for All Literals in Guards (#10613)
**Commit:** 3fc334ebc3
**Impact:** Significant language feature enhancement

This is the headline feature of v1.11.3. The change extends guard clause support to handle all literal values more consistently. Previously, only certain types of literals were allowed in guards. This enhancement refactored how the compiler handles pattern matching in guards, making the language more expressive and consistent. The implementation involved substantial changes to `lib/elixir/lib/module/types/pattern.ex` (274 lines changed).

**Why this matters:** Developers can now write more flexible guard clauses without workarounds, improving code clarity and reducing the need for helper functions in guards.

### Enhanced EEx Tokenizer with Line and Column Information (#10638)
**Commit:** 9d03032cfd
**Impact:** Improved error diagnostics

Added precise line and column information to EEx template tokenizer errors. This enhancement directly improves the developer experience when debugging template syntax errors, providing exact locations rather than vague error ranges.

## Bug Fixes

### Compatibility Fixes

**OTP 24 Compatibility** (c42f7af02b)
- Do not match on `error_info` field on OTP 24
- OTP 24 introduces new error information structures; this ensures Elixir works correctly with them

**OTP 23 Documentation Tests** (35e4263934 - #10510)
- Fixed documentation test failures specific to OTP 23

**Erlang Master Compatibility** (23934b48ba and 32692f14ff)

- Ensures forward compatibility as new Erlang versions are developed

**Private/Removed API Migration** (43327512da - #10439)

**File Module Wrapping** (6d918f5fb42)

## Reverted Changes

### Rebar3 Output Environment Option
**Commit:** 72ec90255431ae
**Status:** Reverted

The support for new rebar3 output environment option (from #10018) was reverted. According to the commit message, this feature was deferred to v1.12 instead. This ensures v1.11.3 remains focused and doesn't introduce experimental features.

## Upgrade Path

Recommended for all v1.11.x users, particularly those on:
- OTP 24 (if using v1.11.2)
- OTP 23 running documentation tests
- Projects using `with` expressions with embedded `case` or similar constructs
- Projects using advanced guard patterns

No breaking changes means this is a safe upgrade.
