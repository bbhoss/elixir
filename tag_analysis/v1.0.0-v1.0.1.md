# Changes from v1.0.0 to v1.0.1

## Overview

**Release Date Range:** September 10, 2014 - October 7, 2014 (27 days)
**Total Commits:** 37
**Version Type:** Patch Release (Bug fixes and minor improvements)

This patch release focused on stabilizing Elixir after the v1.0.0 launch, with significant improvements to the build system, error handling, and system integration.

---

## Summary Analysis

v1.0.1 represents a focused patch release addressing critical issues discovered shortly after the 1.0 launch. The release contains three major categories of changes:

1. **Compiler and Build Infrastructure Improvements** - The most significant changes involve the compiler's module lifecycle management and build artifact tracking. These fixes ensure that recompilation scenarios work correctly, particularly when files are removed or when using custom compiler paths.

2. **Error Message and Stack Trace Improvements** - Multiple commits addressed stack trace noise by filtering out internal Elixir modules, making error messages more user-friendly and less cluttered with framework internals.

3. **System Integration Fixes** - Improvements to System.cmd/3, dependency loading order, and Windows-specific enhancements (PowerShell prioritization) to improve the out-of-the-box experience across different operating systems.

The release maintains backward compatibility while fixing several edge cases and improving the overall robustness of the build and test infrastructure.

---

## Major Features and Improvements

### 1. Compiler and Build System Enhancements

The most substantial changes in this release involve the module compilation pipeline:

- **Module Lifecycle Management** (`d37a10bbd0`, `61b116c1a5`, `df70729b14`, `597381b2e0`)
  - Implemented proper purging and deletion of compiled modules before recompilation
  - Extended this behavior to test compilation scenarios
  - Added manifest writing when files are removed, ensuring the build system tracks deleted source files
  - This ensures that incremental compilation and clean builds handle removed files correctly

- **Path Handling in Compiler** (`b026e8877a`)
  - Enforced that `--elixirc-paths` must be a subset of project paths
  - Since the manifest is shared, this constraint ensures the compiler knows what to change and what to preserve
  - Prevents subtle bugs when using custom compilation paths

**Impact:** These changes make the build system more reliable, especially in complex scenarios with multiple compiler paths or when refactoring code and deleting files.

### 2. Stack Trace and Error Output Improvements

Three related commits improved debugging experience by filtering internal Elixir modules from stack traces:

- **Stack Trace Filtering** (`ad88ac642f`, `1f744f4dac`, `f7015166dc`)
  - Removed `:elixir` module from stack traces
  - Removed `:elixir_exp` module from stack traces
  - Filtered out `:elixir_lexical` from stack traces
  - These modules are part of the compiler's internal machinery and add noise to error diagnostics

**Impact:** Developers see cleaner, more focused stack traces that point to actual application code rather than framework internals.

### 3. ExUnit and Testing Improvements

- **Timeout Handling** (`a4cb74a83f`)
  - Added stack trace inclusion in ExUnit timeouts
  - Previously, timeout errors didn't show where the test was blocked

- **Test Process Handlers** (`bbf955218`)
  - Added comprehensive tests for `ExUnit.Server.add_process_handler/2`
  - Ensures critical test infrastructure is well-tested

**Impact:** Better diagnostics when tests timeout, making it easier to identify problematic test code.

### 4. Configuration Management

- **Deep Config Merging** (`a1668a6b28`)
  - Fixed `Mix.Config` to properly deep merge nested configuration maps
  - Previously, nested maps would not be merged correctly, requiring developers to be careful about configuration structure
  - Simplified configuration handling for applications with complex nested structures

**Impact:** More intuitive configuration merging behavior that follows developer expectations.

### 5. System Module and Port Handling

- **Path Resolution** (`ae07124550`)
  - Fixed `System.cmd/3` path resolution behavior
  - Ensures relative paths are properly rejected as documented
  - Includes new tests to prevent regression

- **Option Handling** (`a4be8fb260`)
  - Fixed the `:stderr_to_stdout` option in `System.cmd/3`
  - This option is commonly used to capture error output alongside standard output

- **Port Command Robustness** (`2d01aa1c6a`)
  - Fixed issue with passing `false` to port commands
  - Prevents crash conditions with certain command configurations

**Impact:** More reliable system command execution with better option handling.

### 6. Dependency and Hex Management

- **Version Requirement Changes** (`c6f346a355`)
  - Updated version requirement format in new apps from `~> MAJOR.MINOR.PATCH` to `~> MAJOR.MINOR`
  - Provides more flexibility for dependency updates while still maintaining stability
  - Better aligns with semantic versioning practices

- **Hex Integration** (`de1d5ff793`, `f7956e9d80`)
  - Pass Elixir version as parameter when installing Hex
  - Bump Hex requirement to version compatible with this Elixir release
  - Ensures compatibility between Elixir and Hex

- **Dependency Loading** (`e621b5828e`)
  - Fixed dependency loading order to occur before `deps.check` compilation
  - Prevents missing dependency errors during the check phase

**Impact:** Smoother dependency management and better integration with the Hex package manager.

### 7. Build Tool Improvements

- **Archive Building** (`da6892aa96`)
  - Added MIX_ENV output to `archive.build` command
  - Provides transparency about which environment is being used for archive creation

- **File Operations** (`2e48d81c20`)
  - Moved printing logic out of copy operations
  - Always ensure directories are created during file operations
  - Prevents issues with missing directories during asset deployment

**Impact:** More reliable asset handling and better visibility into build processes.

### 8. Platform-Specific Enhancements

- **Windows PowerShell Support** (`58946ce87`)
  - Give higher priority to PowerShell on Windows platforms when installing tools
  - Previously may have defaulted to other shell options that are less reliable
  - Improves out-of-the-box experience for Windows developers

**Impact:** Better tooling support for Windows users.

### 9. Other Improvements

- **Proxy Environment Handling** (`db4089cc71`)
  - Don't crash when encountering malformed proxy environment variables
  - Gracefully handle misconfigured proxy settings

- **Stream Halt Behavior** (`403a50fbcd`)
  - Ensure `Stream.chunk/4` correctly handles halt signals
  - Prevents stream processing issues when operations need to stop early

- **Function Spec Fix** (`031a27f5fa`)
  - Fixed specification for `surround_many` function

**Impact:** More robust handling of edge cases and environment configurations.

## Breaking Changes

**None.** This is a patch release that maintains full backward compatibility with v1.0.0. All changes are either bug fixes or internal improvements that don't alter the public API.

However, note the following behavior changes:

- **Mix.Config deep merging** now works correctly - if applications were working around this issue with manual deep merging, they may now be double-merged. This is unlikely but worth testing.
- **Version requirement format** for new projects changed from `~> MAJOR.MINOR.PATCH` to `~> MAJOR.MINOR` - this only affects new projects created after this version, not existing projects.
- **Relative paths in System.cmd/3** are now properly rejected - code that was passing relative paths and failing will continue to fail, but with correct behavior as documented.

## Technical Analysis

### Compiler Architecture Refinement

The series of commits related to module purging and manifest management (commits `d37a10bbd0`, `61b116c1a5`, `df70729b14`, `597381b2e0`) represents a significant refinement to how the Elixir compiler handles module lifecycles. The compiler now properly tracks deleted files and ensures modules are purged before recompilation, which is critical for:

- **Incremental compilation** - Only changed files are recompiled
- **Clean builds** - Module state doesn't leak between compilation cycles
- **Test isolation** - Tests have clean module state
- **Custom paths** - Multiple compilation paths work correctly

### Error Message Quality

The stack trace filtering commits demonstrate a philosophy of user-centric error messages. By removing internal framework modules, developers see stack traces that are relevant to their code, reducing cognitive load when debugging.

### Configuration System Maturity

The deep merge fix in Mix.Config shows the system maturing beyond the initial 1.0 release. Nested configuration is now handled intuitively, which is essential for complex applications with multiple components.

## Conclusion

v1.0.1 is a high-quality patch release that stabilizes Elixir after the initial 1.0 launch. Rather than adding new features, it focuses on:

1. **Fixing edge cases** in the build system
2. **Improving diagnostics** through better error messages
3. **Enhancing cross-platform support**
4. **Strengthening the dependency system**

The release demonstrates the Elixir team's commitment to stability and developer experience. With 37 commits over 27 days, it represents a measured, focused effort to address issues discovered in real-world usage following the 1.0 release.

All changes maintain backward compatibility, making this an excellent update for all Elixir 1.0.0 users.
