## Summary

v1.14.3 is a focused patch release that addresses a series of bug fixes and optimizations across multiple subsystems. The release centers on three main themes:

1. **Correctness Issues** - Fixing bugs in Range operations, Calendar subsecond precision, and Macro string conversion
2. **Compiler Performance** - Optimizing module path precompilation and reducing unnecessary Erlang system calls
3. **Developer Experience** - Improving error messages, warning handling, and test infrastructure

The release spans approximately two months of bug reports and fixes, with the core Elixir team addressing issues identified by the community. No breaking changes are present, making this a safe upgrade for users on v1.14.2.

## Major Features & Improvements

### Compiler & Runtime Optimizations

**Precompile runtime module paths (#12294)**
- Optimized module path precompilation for faster compilation
- Reduces runtime overhead by precomputing path information during compilation
- Improves build times, especially for large projects
- Minimal code changes (net -3 lines) with significant performance implications

**Remove unnecessary :beam_lib.info/1 call (#12317)**
- Eliminated redundant Erlang system call during module inspection
- Improves compilation speed by reducing system-level operations
- Shows attention to reducing overhead in frequently-called code paths

### Macro & AST Handling

**Properly handle Macro inputs and output types in expansion (#12299, #12324)**
- Fixed type handling when expanding macros with specific input/output type constraints
- Ensures correct behavior in advanced metaprogramming scenarios
- Critical for libraries relying on precise macro type specifications

**Escape maps when expanding __ENV__**
- Fixes quote/unquote behavior with environment variables containing maps
- Ensures correct code generation when using `__ENV__` in quoted expressions
- Important for metaprogramming and code generation tools

### Testing Infrastructure

**Return values from running doctests**
- DocTest now properly returns values from doctest execution
- Enables doctest results to be captured and analyzed
- Aligns with improved test tooling capabilities
- Reformatted 99+ test cases to accommodate new behavior

## Bug Fixes

### Range Operations (Critical)

**Fix Range.disjoint?/2**
- Corrected logic for determining if two ranges are disjoint
- Updated implementation to handle edge cases properly
- Significant refactoring (27 insertions, 18 deletions) indicates complex fix

**Optimize range membership implementation (#12282)**
- Improved performance of range membership checking
- Reduced code complexity while maintaining correctness
- Part of broader Range module improvements

### Calendar & DateTime

**Consistently merge precisions in Calendar subsecond operations (#12303)**
- Fixed inconsistent precision handling across DateTime, NaiveDateTime, and Time modules
- Ensures consistent behavior when working with subsecond values across all calendar types
- Touched 4 calendar modules (DateTime, ISO, NaiveDateTime, Time)

**Fix Calendar.strftime/2 format negative year incorrectly (#12268)**
- Corrected formatting of negative years in strftime output
- Ensures correct date string representation for historical dates

### String & Formatting

**Fix Macro.to_string/1 for large negative integers (#12326)**
- Corrected handling of very large negative integer values in macro string conversion
- Ensures accurate string representation of edge-case numbers

**Handle false positive on List.to_charlist/1 formatting (#12248)**
- Fixed spurious warnings when using List.to_charlist/1 with proper arguments
- Improves developer experience by reducing false positives in linting

### Warning & Error Handling

**Do not quote doctest excerpt**
- Fixes quoting behavior in doctest error messages
- Improves readability of doctest failures

**Do not crash for missing line info on type warnings**
- Prevents compiler crash when type information is incomplete
- Improves robustness of compiler error reporting
- Important for supporting edge cases in type checking

**Do not warn on captured underscored vars from defmodule**
- Fixes false positive warnings on captured underscored variables
- Reduces noise in compiler output for common patterns

### Edge Cases

**Fix wildcard edge case (#12255)**
- Corrected behavior in wildcard pattern matching for specific scenarios
- Shows commitment to handling corner cases

**Fix unused for optimization (#12252)**
- Fixed variable unused detection in optimization passes
- Ensures compiler optimization doesn't produce false positives

**Keep expression when normalizing is_struct in blame**
- Preserves expression context when normalizing is_struct checks in error messages
- Improves error message clarity and usefulness

**Pass the relevant module when generating unique vars for guards**
- Ensures correct module context when generating unique variables in guard clauses
- Important for guard clause expansion in macros
