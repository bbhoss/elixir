# Changes from v1.10.1 to v1.10.2

## Release Overview

- **Release Date**: February 26, 2020
- **Date Range**: February 10, 2020 - February 26, 2020 (16 days)
- **Commit Count**: 9 commits
- **Release Type**: Patch release (bug fixes and compatibility updates)

## Summary

Elixir v1.10.2 is a focused patch release that prioritizes stability and compatibility with Erlang/OTP 23, which was released around the same time. This release marks a shift from the v1.10.0 feature set toward ensuring compatibility and correctness. The release contains critical bug fixes affecting core components like the compiler, macro processing, logging, and task handling.

The common thread throughout these changes is improving robustness and preventing runtime crashes or unexpected behavior in edge cases. All commits were authored by José Valim, the Elixir lead architect, indicating careful, targeted fixes rather than broad refactoring.

## Key Themes and Analysis

### 1. **Erlang/OTP 23 Compatibility (Primary Focus)**

The most significant theme in this release is ensuring Elixir works seamlessly with Erlang/OTP 23. This manifests in two critical commits:

- **Erlang/OTP 23 compatibility fixes**: Changes to the compiler infrastructure and utilities to handle new behavior in OTP 23. The changes touch `elixir_erl.erl`, `elixir_erl_compiler.erl`, and `elixir_utils.erl`, indicating that the Erlang compilation layer required significant adjustments.

- **Stacktrace rewriting for compatibility with upcoming OTP version**: A preventative commit that reorders and refactors stacktrace handling in `elixir_dispatch.erl` to prepare for future OTP versions. This shows forward-thinking about compatibility.

These changes suggest that OTP 23 introduced breaking changes in how certain Erlang operations work, requiring Elixir's low-level compiler infrastructure to adapt.

### 2. **Compiler Robustness**

- **Do not write files to disk if warnings as errors was triggered (#9808)**: A substantial refactoring of the parallel compiler that prevents corrupting the output when the `--warnings-as-errors` flag causes compilation to fail. This was a critical bug where partial or corrupted files could be written to disk, potentially breaking downstream builds.

### 3. **String Processing Correctness**

- **Only escape contents outside of interpolation (#9812)**: Fixes a bug in Macro module where string escape sequences were being applied incorrectly inside interpolations. This could cause broken or mangled string output when using string interpolation with special characters.

### 4. **Logging System Improvements**

- **Only print metadata of known types (#9814)**: A defensive fix in the Logger formatter that prevents crashes or unexpected output when encountering unknown metadata types. The formatter now filters to only known types, improving stability.

### 5. **Task/Stream Stability**

- **Do not crash on fake down messages on stream monitor (#9803)**: Prevents a crash when the task supervisory system receives erroneous down messages from monitors. This protects against race conditions or unexpected monitor behavior.

### 6. **Bootstrap and Cleanup**

- **Fix bootstrap** and **Fix unused variable warning**: Minor correctness fixes in the macro system and logger that don't affect functionality but clean up the codebase and prevent potential warnings.

## Major Features/Improvements

This patch release contains **no new features**. It is purely a maintenance release focused on:

1. **Compatibility enhancement**: Full support for Erlang/OTP 23
2. **Stability improvements**: Preventing crashes in task handling and stream monitoring
3. **Data integrity**: Ensuring compiled files are not corrupted when warnings-as-errors is enabled
4. **Output correctness**: Fixing issues in string interpolation and logger formatting

## Notable Commits Worth Highlighting

### 1. **Fixes for Erlang/OTP 23** (286d310ac)
**Why it matters**: This is the cornerstone of the release. It adapts Elixir's compiler infrastructure to work with OTP 23's changes. The changes span multiple Erlang source files in the compiler, indicating deep integration work required.

**Files affected**: 6 files
- Core compiler modules: `elixir_erl.erl`, `elixir_erl_compiler.erl`, `elixir_utils.erl`
- Test suite adjustments to accommodate OTP 23 behavior changes

### 2. **Do not write files to disk if warnings as errors was triggered** (e2dc9ae7)
**Why it matters**: This was a critical bug in the parallel compiler. When using the `--warnings-as-errors` flag, the compiler could write incomplete or partial files to disk before discovering it needed to fail the compilation. This could corrupt the build output.

**Impact**: Prevents silent data corruption in CI/CD pipelines using strict compilation settings.

**Files affected**: 2 files
- `lib/elixir/lib/kernel/parallel_compiler.ex` (150 lines changed - substantial refactoring)
- Test suite updates

### 3. **Rewrite stacktraces for compatibility with upcoming OTP version** (2fc916088)
**Why it matters**: Preventative maintenance showing the Elixir team's proactive approach to OTP compatibility. By reordering stacktrace handling logic, the code prepares for changes that haven't yet landed in OTP but are coming.

**Impact**: Future-proofs the codebase against OTP stacktrace format changes.

### 4. **Only escape contents outside of interpolation** (090dddcf0)
**Why it matters**: Fixes a subtle but important bug in how string escaping is applied during string interpolation. This could lead to malformed strings when interpolation is combined with escape sequences.

**Example of the bug**: String escaping rules were being applied inside interpolation expressions where they shouldn't be.

## Conclusion

Elixir v1.10.2 represents a maturation effort for the v1.10 release line. Rather than adding new features, the focus is on ensuring stability and compatibility with the rapidly evolving Erlang/OTP ecosystem. The release is driven by the immediate need to support OTP 23, but also includes important bug fixes that prevent data corruption and crashes in production use cases.

For end users, upgrading to v1.10.2 is strongly recommended if using Erlang/OTP 23, or if experiencing issues with parallel compilation (`--warnings-as-errors`), task supervision, or string interpolation with special characters.
