# Changes from v1.10.0 to v1.10.1

## Release Timeline
- **v1.10.0 Release Date**: January 27, 2020
- **v1.10.1 Release Date**: February 10, 2020
- **Time Span**: 14 days
- **Total Commits**: 21

## Summary

v1.10.1 was a patch release focused on critical bug fixes and minor enhancements to v1.10.0. The release addressed several important issues in the compiler, logger, and code generation subsystems. This was primarily a stability release, with most changes targeting edge cases and error handling improvements rather than introducing new features. The relatively short turnaround between v1.10.0 and v1.10.1 suggests that these were bugs discovered early in the v1.10.0 release cycle.

The key theme of this release was addressing compiler correctness issues, particularly around code generation and guard clause handling, while also fixing important logger functionality issues related to multi-byte character handling and message rebroadcasting.

## Major Bug Fixes

### 1. Logger System Improvements

The logger subsystem received three important fixes:

- **Multi-byte Character Handling** (#9767): Fixed an issue where logger truncation was not correctly handling multi-byte UTF-8 characters. This was a critical fix for applications using non-ASCII characters in log messages, as it could cause malformed logs.

- **Message Rebroadcasting** (#9765): Removed unnecessary message rebroadcasting that was being handled by Erlang's logger itself. This change improves performance and reduces redundant message processing, as Erlang's logger now natively handles this functionality.

- **Report Callback Return Value** (#9798): Fixed the logger to correctly handle the return value from `report_cb/2`. Previously, it incorrectly assumed the return type was the same as `report_cb/1`, but `report_cb/2` returns an already-formatted string rather than format string and data. This was a critical fix for custom logger implementations using `report_cb/2`.

### 2. Code Generation and Formatting Fixes

- **Invalid Code in Map Formatting** (#9771): Fixed a code generation bug where invalid code was being emitted when formatting associative structures in maps. This would have caused compilation errors in certain map formatting scenarios.

- **Access Implication Fix**: Corrected the compiler to not incorrectly imply that `nil` is caused by Access operations. This improves error messages and prevents misleading diagnostics.

### 3. Guard Clause and Pattern Matching

- **Missing `:erlang.size/1` Guard** (#9789): Added the missing `:erlang.size/1` guard to the list of valid guards. This was a gap in guard support that could limit pattern matching capabilities.

- **Unpacking Extra Guards from `with` Matches** (#9801): Fixed guard unpacking logic in `with` expressions, ensuring complex guards are properly extracted and validated.

- **Assert Received Exception Validity** (#9799): Fixed `assert_received` to ensure it still produces valid exceptions when assertions fail, maintaining proper error handling in tests.

## Features and Enhancements

### 1. Compiler Environment Enhancement

- **Remote/RPC Support in `compile_env`**: Extended `compile_env` to support `remote` and `rpc` modes, allowing more flexible compile-time environment configuration for distributed Elixir applications.

### 2. Testing Improvements

- **Timer and Interval Tests**: Added test coverage for timer and interval functions with infinity values, improving test suite completeness.

## Experimental Work and Reversions

### Warnings for Unused Match Variables in Assertions

An interesting pattern emerges in the commit history: on February 6, 2020, a commit was added to "Emit warnings for unused match vars in assertions" (closes #9787), but this was **immediately reverted** the same day. This indicates that while the feature was implemented, it either:
- Caused false positives or warnings in common code patterns
- Was deemed not ready for the v1.10 series
- Required more refinement before release

This type of experimental-then-reverted work suggests active community feedback during development.

## Documentation and Minor Changes

- **Quote Validation**: Deferred line validation in quote constructs to v1.11, reducing scope for this patch release
- **Error Message Improvements**: Added better spacing to quote error messages for improved clarity
- **Documentation**: Updated compiler tracing event documentation and fixed several typos in the changelog
- **Installation Documentation**: Fixed variable quoting in CLI bat_text installation section

## Breaking Changes

**None identified**. This was a pure patch release with no breaking changes to the public API.

## Recommendation for Users

Users running v1.10.0 should upgrade to v1.10.1, particularly if they:
- Use custom logger implementations with `report_cb/2`
- Process log messages with multi-byte characters
- Use complex `with` expressions with multiple guards
- Rely on accurate error messages from Access operations
- Have map formatting in their codebase that uses associative structures

This patch addresses real correctness issues rather than cosmetic improvements, making it a worthwhile upgrade for production systems.
