# Changes from v1.5.2 to v1.5.3

## Release Information

- **Release Date**: December 19, 2017
- **Development Period**: September 29, 2017 - December 19, 2017 (11 weeks)
- **Total Commits**: 14 commits

## Summary

Elixir v1.5.3 is primarily a maintenance and bug-fix release that addresses several correctness issues discovered since v1.5.2. This release focuses on fixing edge cases in existing functionality, improving compiler warnings, and enhancing the robustness of core data structures and streaming operations. The release includes no new features, but rather focuses on polish and stability improvements across the standard library.

## Major Bug Fixes

### 1. **Stream.chunk_every/4 Edge Case Fix** (Most Critical)
- **Commit**: eb7e0984bd
- **Issue**: Stream.chunk_every/4 was producing incorrect results when `step > count` and the last element of the enumerable matched the last element of the final chunk
- **Impact**: This was a correctness issue affecting stream partitioning operations with overlapping or non-contiguous chunking patterns
- **Changes**: Fixed the reducer logic in `stream/reducers.ex` with additional test coverage for various step > count scenarios
- **Related commit**: cde12f75fc (Additional fix for accumulator count logic)

### 2. **MapSet Legacy Data Structure Handling**
- **Commit**: 331a70ade9
- **Issue**: The `MapSet.union/2` function was not properly handling legacy MapSet structures, resulting in invalid MapSet results
- **Impact**: Data corruption when working with MapSets from older versions or different sources
- **Changes**: Enhanced the union operation to validate and handle legacy MapSet formats correctly
- **Test Coverage**: Added 34 lines of comprehensive test cases to prevent regression

### 3. **Calendar.ISO Datetime Precision**
- **Commit**: 15222304eb
- **Issue**: Calendar.ISO maximum possible datetime calculations were not properly considering microseconds
- **Impact**: Could lead to incorrect datetime bounds calculations
- **Changes**: Updated the maximum datetime calculation logic to account for microsecond precision
- **Reference**: Issue #7055

### 4. **MapSet Type Handling**
- **Commit**: ccf939e9e7
- **Note**: Fixed a typo in MapSet tests that could have been masking issues

## Compiler and Tooling Improvements

### 1. **Macro Duplicate Definition Warnings**
- **Commit**: 5e5eaca78f
- **Issue**: The compiler was not properly warning about duplicate definitions in macros
- **Impact**: Developers could have accidentally overwritten macro definitions without being alerted
- **Changes**: Enhanced the `elixir_def.erl` module to track and warn about duplicate macro definitions
- **Reference**: Issue #6637

### 2. **Dialyzer Warning Suppression**
- **Commit**: f6aced3072
- **Issue**: Dialyzer (static analysis tool) was generating false positive warnings for `else` clauses in `with` expressions
- **Impact**: Noise in type checking output that made it harder to identify real issues
- **Changes**: Updated `elixir_erl_pass.erl` to suppress these spurious warnings
- **Reference**: Issue #7031

### 3. **ExUnit Assertion Warnings**
- **Commit**: ab61c09b3d
- **Issue**: `ExUnit.assert_receive/3` was generating compiler warnings in generated code
- **Impact**: Tests produced warnings even when code was correct
- **Changes**: Fixed compiler warning generation in `ex_unit/assertions.ex` (65 lines modified)

### 4. **Future-Proofing Attribute Warnings**
- **Commit**: 45f9c9c1ce
- **Issue**: Upcoming Elixir attributes needed to be added to the no-warn list
- **Changes**: Added new attributes to avoid spurious warnings for code using future features
