# Changes from v1.14.3 to v1.14.4

## Release Information

**Date Range:** January 14, 2023 - April 3, 2023
**Total Commits:** 32 (including release and changelog commits)
**Active Development Period:** ~80 days

## Summary

The v1.14.3 to v1.14.4 release represents a maintenance and compatibility update focused primarily on **Erlang/OTP 26 compatibility** and **bug fixes**. This was a critical patch release addressing compatibility issues with newer Erlang/OTP versions while maintaining stability for existing users. The team conducted extensive testing across multiple OTP versions and fixed edge cases in core functionality.

The overarching theme is **forward compatibility without breaking existing code**. The changes ensure Elixir v1.14.4 runs smoothly on both older and newer OTP versions, particularly OTP 26 which introduced some breaking changes in Erlang's internal APIs.

## Major Features and Improvements

### 1. Erlang/OTP 26 Compatibility Overhaul

The release addresses multiple compatibility issues with OTP 26, a significant undertaking:

- **Logger Formatting Fix** (#12434): Fixed logger formatting that broke under OTP 26's new logging infrastructure
- **Deterministic Output** (#12438, #12433, #12405): Made mix test reports and map inspection deterministic across OTP versions to ensure consistent test output
- **Test Suite Updates** (#12490, #12493, #12415, #12486): Updated internal test suites to work with OTP 26's new behaviors and removed deprecated test utilities
- **Dialyzer Compatibility** (#12486): Fixed dialyzer test integration with OTP 26

**Impact:** Users upgrading to OTP 26 can now use Elixir v1.14.4 without encountering unexpected behavior or test failures.

### 2. API Stability and Forward Compatibility

Two important changes ensure long-term compatibility with Erlang/OTP 26+:

- **IEx.Server Enhancement** (#f596cf1): Switched from deprecated `get_chars` to `get_until` API, necessary for forward compatibility with Erlang/OTP 26+. This was done to prepare for future Erlang versions that may remove the old API.

- **Eliminate Private API Usage** (#12927b8): Removed reliance on StringIO private APIs, ensuring Elixir doesn't break if Erlang/OTP changes internal implementations.

**Impact:** These preventive measures reduce the likelihood of Elixir breaking with future OTP releases.

### 3. Enhanced Inspection and Formatting Capabilities

- **Sort Maps Option** (#12404): Added `:sort_maps` to `Inspect.Opts.custom_options`, allowing developers to control whether maps should be sorted during inspection. This is particularly useful for deterministic output in tests and debugging.

- **Metadata Sorting** (#12440): Improved consistency by sorting metadata before printing, making logs more predictable and easier to diff.

**Impact:** Better debugging experience and more deterministic output for applications that rely on consistent formatting.

## Bug Fixes

### Critical Fixes

1. **Stream.zip/1 Hanging on Empty List** (#12461)
   - Fixed a race condition where `Stream.zip/1` would hang indefinitely when passed an empty list
   - This was a critical issue affecting stream processing pipelines
   - Resolved with proper edge case handling

2. **Tokenizer Column Count Issue** (#12504)
   - Fixed incorrect column counting when tokenizing escaped interpolations in strings
   - This could cause confusing error messages pointing to wrong line/column positions
   - Particularly important for developers using string interpolation with escape sequences

3. **Quote Metadata Path Storage** (#12393)
   - Fixed `quote` to store complete paths in metadata instead of partial paths
   - This resolves issues with code generation and metaprogramming that rely on accurate location information

### Code Generation and Normalization

4. **Code.Normalizer Meta Fields** (#12389)
   - Corrected which meta fields are used in `normalize_call/2`
   - Ensures accurate metadata during code normalization operations

5. **Protocol Dispatch Initialization** (#12421, #3eb94a4)
   - Fixed a critical issue where protocols weren't being loaded before dispatch
   - This was causing errors in libraries like hex that rely on protocol-based dispatch
   - Changed timeout to infinity for the parallel checker to ensure protocols load completely

6. **Debug Info Format Bug** (#12376)
   - Fixed `elixir_erl:debug_info/4` incorrectly returning `core_v1` format
   - Ensures proper debug information is available for compiled modules

### Timeout and Performance Fixes

7. **Parallel Checker Timeout** (#12421)
   - Bumped timeout to infinity in the parallel checker to prevent premature termination
   - This prevented race conditions and loading issues during compilation

8. **Application Tracer Optimization** (#c31d1b3)
   - Optimized the application tracer for better performance

### Development and Testing

9. **Formatter Directory Handling** (#12488)
   - Fixed formatter being incorrectly invoked on directories
   - Prevents unnecessary processing and potential errors

10. **HTTP Client Certificate Verification** (#12485)
    - Added explicit `:verify_none` for httpc to clarify security settings
    - Improves clarity around certificate verification in HTTP requests

11. **Struct Expansion Determinism** (#12418)
    - Made struct expansion deterministic to ensure consistent compilation behavior

## Breaking Changes

**None identified** - This is a pure bug-fix and compatibility release. No public APIs were removed or changed in incompatible ways.

## Notable Commits Worth Highlighting

### Top 5 Most Impactful Changes

1. **Fix dialyzer tests in OTP26** (#12486)
   - Commit: `acb5832c69`
   - **Why it matters:** Dialyzer is a critical static analysis tool. Ensuring it works with OTP 26 is essential for Elixir developers using type checking.

2. **Make mix test reports deterministic in OTP26** (#12438)
   - Commit: `f9c053d60c`
   - **Why it matters:** Non-deterministic test output causes spurious test failures and makes CI/CD unreliable. This fix is crucial for teams running tests on OTP 26.
   - **Details:** Fixed both `mix test` and `mix test.cover` to not rely on map key ordering, which changed in OTP 26.

3. **Fix Stream.zip/1 hanging on empty list** (#12461)
   - Commit: `a8824bab09`
   - **Why it matters:** This was a blocking bug that made certain stream processing patterns completely unusable. High-impact for functional programming patterns in Elixir.

4. **Use get_until in IEx.Server** (f596cf16)
   - Commit: `f596cf1629`
   - **Why it matters:** Proactive fix for future OTP compatibility. Without this, Elixir would break when OTP 26+ removes the old `get_chars` API.
   - **Forward-looking:** Shows the team's commitment to maintaining compatibility with upcoming releases.

5. **Fix column count when tokenizing escaped interpolations** (#12504)
   - Commit: `f026cb375`
   - **Why it matters:** Error messages pointing to correct locations are critical for developer experience. This affects all string interpolation in Elixir code.

### Architectural Improvements

- **Protocol Loading Fix** (#3eb94a48): Ensures protocols are loaded before dispatching, preventing hard-to-debug errors in dependent libraries. This was a deep issue in the module loading system.

- **Code Normalizer Meta Fields** (#9fd9bcee): Corrects metadata handling in code generation, ensuring code generated with macros has accurate location information.

## Development Insights

### Testing-Heavy Release

Approximately 40% of the commits in this release are test-related fixes and improvements. This reflects the importance of ensuring compatibility across multiple OTP versions. The team systematically went through the test suite and fixed issues:

- Map inspection tests (multiple commits)
- OTP 26 specific test behavior changes
- Test determinism improvements
- Supervisor documentation updates

### Compatibility-First Approach

Rather than taking a "break compatibility for newer OTP" approach, the team made deliberate choices to:
1. Support both old and new OTP APIs simultaneously
2. Test against multiple OTP versions
3. Make preventive changes (like moving away from private APIs) before they're necessary

### Quality of Life Improvements

Small but meaningful improvements were included:
- Better error message clarity for certificates
- Documentation fixes for supervisor API
- Addition of `:sort_maps` option for inspection
- Metadata sorting for more readable logs

## Conclusion

v1.14.4 represents a mature, focused maintenance release. Rather than introducing new features, the team prioritized **stability and compatibility** with the rapidly evolving Erlang/OTP ecosystem. The release successfully bridges the gap between older OTP versions and OTP 26, ensuring Elixir developers can upgrade their dependencies without compatibility issues.

The release is particularly valuable for teams working with OTP 26 and demonstrates Elixir's commitment to being a forward-compatible language on the Erlang VM.
