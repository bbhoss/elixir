# Changes from v0.11.2 to v0.12.0

## Release Information

- **Release Date**: December 15, 2013
- **Previous Release**: November 14, 2013
- **Duration**: 31 days
- **Total Commits**: 190

## Summary

Version 0.12.0 represents a significant architectural and feature enhancement release, with primary focus on Stream API expansion, core protocol improvements, and major internal refactoring to move more of Elixir's core from Erlang to pure Elixir. This release brings a more mature and feature-rich enumeration API, better metaprogramming capabilities, and improved exception handling patterns.

The dominant theme of this release is the **expansion and maturation of the Stream module**, which received extensive enhancements including new operations and protocol-level changes. Simultaneously, the Elixir team undertook substantial internal refactoring, implementing core macros and special forms in pure Elixir rather than relying entirely on Erlang implementations.

## Key Themes

### 1. Stream API Expansion and Protocol Evolution
The Stream module was fundamentally enhanced with numerous new operations and improved composition semantics. This was accompanied by significant changes to the underlying Enumerable protocol to support more sophisticated stream patterns.

**Notable additions:**
- Implemented iteratee-based enumeration architecture (commit `8e51528dc1`)
- Added reducer sharing between Enum and Stream (commit `575e0b9494`)
- Protocol change: Enumerable.count/1 and Enumerable.member?/2 now return tagged tuples for better error handling (commit `e49998593e`)

### 2. Major Internal Refactoring - Elixir vs Erlang
Significant effort was invested in porting core Elixir functionality from Erlang to pure Elixir. This includes:

- Implementing defmodule in Elixir (commit `a8bdd19a03`)
- Moving case/try/receive to special forms (commit `b28c95d31a`)
- Porting function/macro definitions to Kernel (commit `abec6af3ac`)
- Implementing macro handling in Elixir (commits around `260be7c8ea`, `1096cd00b9`)
- Moving operators to Kernel module (commits `e553b6780b`, `de3c0f639a`, `398e0fd3fb`)

This refactoring improves maintainability and allows more of the language core to be written in the language itself.

### 3. Metaprogramming and Macro Improvements
Multiple enhancements to macro handling and compile-time code execution:

- Module.eval_quoted/2 implemented in Elixir (commit `63fdbfb8cf`)
- Improved quote/unquote fragment handling (commit `fd3d8b3b98`, `01c2a22bff`)
- Better macro expansion control with location: :keep (commit `043edd4990`)
- Improved hygiene with better variable handling in macro expansions (commit `5dfa6ae618`, `1fbb6871a0`)
- Alias tracking in macro contexts (commits `e424f02812`, `bce9116cff`, `f62c26b9b6`)

## Major Features and Improvements

### Stream Module Enhancements (Primary Focus)

**New Stream Functions:**
- `Stream.scan/2` and `Stream.scan/3` - Accumulate values through a stream
- `Stream.uniq/2` - Filter unique elements
- `Stream.chunks/2,3,4` - Group elements into chunks (previously named chunks*)
- `Stream.chunks_by/2` - Group by a given function
- `Stream.take_every/2` - Take every nth element
- `Stream.each/2` - Execute side effects while streaming
- `Stream.zip/2` - Combine multiple streams
- `Stream.resource/3` - Create streams from resource operations
- `Stream.after/2` - Execute code after stream completion
- `Stream.run/2` - Execute streams for side effects

**Stream Improvements:**
- Support for negative counts in `Stream.drop/2` and `Stream.take/2`
- Better composition and suspension handling
- Improved zippability for complex stream combinations
- Fixed stream behavior with flat_map and nested accumulations

**Related Enumerable Changes:**
- Renamed Enum.chunks* functions to Enum.chunk*
- Deprecated old naming in favor of new convention
- Protocol-level changes for better composition semantics

### Numeric Enhancements

**Float Module:**
- `Float.round/1` - Round floating point numbers
- `Float.floor/1` - Floor operation
- `Float.ceil/1` - Ceiling operation

These additions complete the Float module's basic mathematical operations.

### Module and Compilation System

**Module System:**
- `Module.eval_quoted/2` - Evaluate quoted expressions in module context
- Improved module nesting and context handling
- Better enforcement of build paths for dependencies
- Automatic build path enforcement in in_dependency blocks

**Macro and Special Form Refactoring:**
- Macro.extract_args/1 - Deprecated in favor of simpler alternatives
- Location annotation improvements
- Better handling of aliases in quoted code

### Exception Handling

- Promoted `exception/1` as the preferred mechanism for customizing exceptions
- Improved exception module patterns

### List Module Enhancements

- `List.update_at/3` - Update element at specific index
- `List.delete_at/1` - Remove element at specific index (commit `4358386906`)

### Other Notable Improvements

- Enum.reverse/2 - Reverse with accumulator
- Enum.intersperse/2 - Insert elements between list items
- Better String.Graphemes performance (reduced module size)
- Improved Inspect.Algebra performance (20% faster)
- Better URI documentation and examples
- Enhanced ExUnit/IEx documentation
- Improved version matching with -dev versions
- Better error handling in regex operations
- File.stream_to!/3 for side-effect streaming

## Bug Fixes

- **Version matching**: Fixed `Version.match?/2` with ~> operator and -dev versions
- **Stream operations**: Corrected suspension handling in Stream.zip/2 and Stream.flat_map/2
- **Record handling**: Fixed record aliases in quoted code, fixed dynamic record names
- **Regex**: More precise regex exception handling and improved error messages
- **Module attributes**: Fixed regression with in expressions using module attributes
- **IEx/Pry**: Fixed environment handling in IEx helper functions
- **Consolidation**: Create consolidation directory before writing to it
- **Dependencies**: Fixed `.git` suffix removal for GitHub-referenced dependencies
- **Macro expansion**: Prevent macro expansion on variables (hygiene improvement)
- **Typespecs**: Fixed typespec guards to work with keyword list representations

## Breaking Changes

### Enumerable Protocol Change
The most significant breaking change is in the **Enumerable protocol**:

- **Enumerable.count/1** and **Enumerable.member?/2** now return **tagged tuples** instead of bare values
- This affects any custom Enumerable implementations
- Provides better error semantics and composition capabilities

### Stream Function Deprecations

- **Enum.chunks*** and **Enum.chunks** functions are deprecated in favor of **Enum.chunk***
- **Macro.extract_args/1** is deprecated
- These should be migrated to their newer equivalents

### Iteratee-Based Enumeration

The move to iteratee-based enumeration (commit `8e51528dc1`) is an internal architectural change that maintains backward compatibility at the public API level but significantly changes how Stream and Enum interact with each other.

### Escript Configuration

- **:escript_main_module** is now required for generating Escripts (commit `96077905fb`)
- The -S flag cannot be specified more than once

## Conclusion

Version 0.12.0 represents a maturation of Elixir's functional programming capabilities, particularly in the Stream/Enumerable ecosystem. The release simultaneously improves the developer experience with more powerful APIs while strengthening the language foundation by implementing more core functionality in Elixir itself. The breaking changes are primarily internal/architectural, with the notable Enumerable protocol change requiring updates to custom implementations, but the overall trajectory is toward a more feature-rich and self-contained language implementation.

The focus on Streams and functional composition patterns suggests the Elixir team's commitment to providing powerful, expressive tools for data processing pipelines—a key strength of functional programming languages.
