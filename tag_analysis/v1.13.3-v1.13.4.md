# Changes from v1.13.3 to v1.13.4

## Release Information

- **Previous Release**: v1.13.3 (2022-02-09)
- **New Release**: v1.13.4 (2022-04-07)
- **Duration**: ~2 months
- **Total Commits**: 17

## Summary

v1.13.4 is a maintenance release focused on compatibility with Erlang/OTP 25, bug fixes, and incremental improvements to the language and standard library. The release demonstrates Elixir's commitment to supporting the latest Erlang/OTP versions while addressing regressions and edge cases discovered in the v1.13.x series.

The key themes in this release are:

1. **Erlang/OTP 25 Compatibility**: Significant effort to ensure tests pass and code works correctly with the latest Erlang/OTP version
2. **Type System Fixes**: Critical fix for an infinite loop issue in the type unifier
3. **Regression Fixes**: Addressing regressions introduced in earlier v1.13 versions
4. **Deprecations**: Moving away from older tooling (Rebar2)
5. **Standard Library Enhancements**: Improvements to sigils and supporting functionality

## Major Features & Improvements

### Erlang/OTP 25 Support and Testing

The release includes substantial updates to ensure compatibility with Erlang/OTP 25:

- **Updated OTP-24.3 to CI** (f950226e6c): Added OTP-24.3 to the continuous integration pipeline
- **Skipped Rebar2 tests on OTP 25+** (65681b83d7): Recognized that Rebar2 is incompatible with OTP 25 and updated test suite to skip these tests
- **Manual stacktrace handling cleanup** (e0c8b8af87): Removed unnecessary manual stacktrace munging code that's no longer needed on Erlang/OTP 25+, indicating improved native support for stacktrace handling
- **Test updates for OTP 25 compatibility** (f809d03370, ee6ed7558f): Updated Mix.DepTest and Mix.TasksTestTest to handle different but valid behavior from Erlang/OTP 25's :digraph_utils.topsort/1

### Sigil Enhancements

Two improvements to the sigil system expand their flexibility:

- **Opening delimiter in metadata** (67cf14c857): Added support for including the opening delimiter in sigil metadata/options, enabling sigils to be more descriptive about how they were invoked
- **iodata support in sigil formatting** (4b480cb7e0): Extended sigil formatting functions to accept iodata (lists of bytes/strings) in addition to strings, improving performance for string-heavy operations

### Rebar2 Deprecation

- **Deprecate Rebar2** (63d682b3d7): Officially deprecated Rebar2 as a build tool, signaling that future Elixir versions may remove support entirely. This is part of the Erlang ecosystem's transition to Rebar3

## Bug Fixes

### Critical Fixes

- **Type unification infinite loop fix** (89e57882e1): Fixed an infinite loop that occurred in the type unifier when handling recursive type variables. This was a stability issue that could cause the compiler to hang on certain code patterns.

- **Registry.send with value part** (d52f533761): Fixed an issue where `Registry.send/3` would not work correctly when the registry entry included a value part. This resolves #11740, which likely affected applications using Elixir's Registry for process management.

- **Base.decode16! typespec** (39d8675ac1): Corrected the typespec for `Base.decode16!/1`, improving type checking accuracy for users relying on static analysis tools.

### Documentation & API Fixes

- **URI.Error.message/1 documentation** (1e4ed32eda): Marked `URI.Error.message/1` as `@doc false`, indicating it's an internal implementation detail not part of the public API

- **Only check for unwanted functions** (bb17204741): Refined compile-time function checking to avoid false positives

### Compile-time Dependency Fix

- **Add compile-time dependencies on require** (bac5b1d800): **This is a regression fix** from v1.13.0. The `require` statement now properly establishes compile-time dependencies. This affects projects like Plug that use `require` internally to establish compile-time dependencies, ensuring they can be properly tracked by the compiler.

### Infrastructure Updates

- **Local rebar3 update** (fe43e23a25): Updated the bundled rebar3 version
- **Test fixture recreation** (c028c2d915): Recreated the local.sample task fixture in test_helper.exs for better test isolation

## Breaking Changes

**None identified.** This is a maintenance/patch release with no breaking changes. All fixes are backward compatible.

## Notable Commits Worth Highlighting

### 1. **Tweak type unification to fix infinite loop with recursive vars** (89e57882e1)
This is arguably the most important fix in this release. Infinite loops in the compiler are critical issues that can completely block development workflows. While the commit message is brief, this fix likely addresses cases where the type system could analyze code and enter an infinite recursion, potentially causing the Elixir compiler to hang.

### 2. **Add compile-time dependencies on require** (bac5b1d800)
This regression fix is significant for library authors, particularly those building frameworks like Plug. By restoring proper compile-time dependency tracking for `require`, this ensures that the compiler can correctly identify when recompilation is needed, preventing subtle bugs where code changes aren't picked up.

### 3. **Registry.send work when value part is present** (d52f533761)
A practical bug fix for applications using Elixir's Registry system, which is fundamental to Elixir's process management and supervision patterns. This ensures that Registry-based communication works reliably across different use cases.

### 4. **Erlang/OTP 25 Compatibility Across Multiple Commits**
The collection of OTP 25 updates demonstrates Elixir's proactive approach to supporting new Erlang/OTP versions. Rather than waiting for a major version, these updates ensure v1.13.x users can take advantage of OTP 25 improvements without waiting for Elixir 1.14.

## Development Focus

The release shows Elixir's focus on:

1. **Ecosystem compatibility**: Ensuring seamless integration with the latest Erlang/OTP versions
2. **Stability**: Fixing compiler edge cases and type system issues that could impact user experience
3. **Library support**: Addressing regressions that affect popular libraries and frameworks
4. **Modernization**: Deprecating older tools (Rebar2) as the ecosystem evolves
5. **Standard library polish**: Incremental improvements to sigils and other APIs

## Testing Impact

Multiple commits specifically address test failures or updates needed for OTP 25, indicating that Elixir maintains rigorous testing standards and ensures compatibility is verified through CI/CD pipelines before release.

## Recommendation for Users

Users running Elixir v1.13.3 should upgrade to v1.13.4, particularly if they:
- Are using Registry in their applications (bug fix)
- Are planning to use Erlang/OTP 25
- Experienced compiler hangs with complex type recursion
- Are using libraries that rely on `require` for compile-time dependencies (like Plug)
