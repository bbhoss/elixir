# Changes from v1.11.3 to v1.11.4

## Overview

This release represents a focused maintenance update spanning **71 days** (January 4, 2021 to March 16, 2021) with **4 commits** addressing OTP 24 compatibility and a minor Mix enhancement.

### Date Range
- **Release Date**: March 16, 2021
- **Previous Release (v1.11.3)**: January 4, 2021
- **Total Commits**: 4

## Summary

v1.11.4 is primarily a compatibility release that backports OTP 24 support to the v1.11 stable branch. Elixir v1.11 was released before OTP 24 became available, and this patch version ensures that Elixir 1.11.x can run smoothly with the latest Erlang/OTP version. The release also includes a minor enhancement to Mix configuration readers and routine maintenance.

The work was driven by the compatibility challenges introduced by OTP 24's internal changes to error message formats, warning structures, and compiler behavior.

## Major Features & Improvements

### 1. **OTP 24 Compatibility Backport** (Commit: 99ec7522d3)
This was the significant undertaking of this release, backporting multiple OTP 24 compatibility patches:

#### Erlang Warning Translation Updates
- OTP 24 changed the format of evaluation failures from `{eval_failure, Reason}` to `{eval_failure, Call, Reason}`
- Updated Elixir's warning translation layer to handle this new structure, ensuring consistent error reporting across OTP versions

#### Erl Compiler Error Diagnostics
- The Erlang compiler changed its error reporting to include column information in the form `{line, column}` instead of just `line`
- Fixed Elixir's diagnostic translation to properly handle this enhanced position information from OTP 24
- Since Elixir diagnostics support multiple position formats (nil, line, or 4-tuple `{start_line, start_col, end_line, end_col}`), had to map the new format appropriately

#### Yecc Error Message Handling
- OTP 24 changed Yecc (Erlang parser generator) error message format
- Relaxed assertion checks in error translation to accommodate the new format
- Example: `f.yrl:1: syntax error before: '.'` (OTP 23) became `f.yrl:1:5: syntax error before: .` (OTP 24)

#### 16-bit Float Support in Bitstrings
- Added support for 16-bit float literals in bitstring patterns, a new OTP 24 feature
- This allows code like `<<x::float-16>>` to work correctly, enabling better floating-point handling
- Before OTP 24, such patterns would either error or fail to match

#### Compile Module Behavior
- Fixed handling of `:compile.file/2` return values on OTP 24
- OTP 24 changed error handling behavior when given invalid arguments, previously returning `{:error, :badarg}` but now returning `:error` with different exception patterns
- Updated Elixir to handle both old and new behaviors gracefully

### 2. **Mix Configuration Readers Enhancement** (Commit: 0627d7b0d4)
- Enhanced `Mix.Config` readers to receive both `env` and `target` parameters
- This allows configuration files to make decisions based on both the current environment (dev, test, prod) and the build target (host, embedded, etc.)
- Minimal change (2 line modification) but provides better flexibility for mixed configuration scenarios

## Bug Fixes

The OTP 24 compatibility work itself represents significant bug prevention and compatibility fixes:

- **Fixed compiler error translation**: Ensures errors from OTP 24 are properly converted to Elixir diagnostics
- **Fixed warning translation**: Maintains consistent warning reporting across Erlang/OTP versions
- **Fixed parser error handling**: Yecc errors are now correctly processed regardless of OTP version
- **Fixed bitstring compilation**: 16-bit floats now compile and execute correctly in pattern matching scenarios

## Breaking Changes

**None identified.** This is a patch release designed to be fully backward compatible with v1.11.3 while adding support for newer OTP versions.

## Technical Insights

1. **Version Stability Strategy**: Elixir's approach of backporting critical compatibility fixes to stable releases (1.11.x) while development continued on 1.12.x shows a commitment to allowing gradual upgrades rather than forcing users to adopt new major versions.

2. **Erlang/OTP Interdependence**: This release highlights the tight coupling between Elixir and Erlang/OTP. Changes to error reporting, compiler behavior, and language features in OTP 24 necessitated updates across multiple Elixir subsystems.

3. **Scope Management**: The focused nature of this release (4 commits addressing specific compatibility issues) demonstrates good maintenance discipline. Rather than bundling unrelated features, the team concentrated on stability and compatibility.

## Impact Assessment

- **For Users on v1.11.x**: This release enables upgrading to OTP 24 safely, particularly important for users needing the latest Erlang features or security patches
- **For Users on v1.12.x**: Already had OTP 24 support during development; this backport ensures v1.11 users aren't forced to upgrade Elixir versions
- **For the Ecosystem**: Maintains a wider support window for v1.11 by ensuring it works with recent OTP versions
