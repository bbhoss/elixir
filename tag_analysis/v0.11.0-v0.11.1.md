# Changes from v0.11.0 to v0.11.1

## Release Overview

- **Version Range**: v0.11.0 to v0.11.1
- **Date Range**: November 2, 2013 to November 7, 2013
- **Commit Count**: 64 commits
- **Release Type**: Patch/Minor release with significant internal improvements

## Summary

The v0.11.0 to v0.11.1 release represents a maintenance and refinement cycle focusing on stabilizing Mix build tool infrastructure, improving dependency management, and enhancing user-facing error messages. This release addresses several architectural issues discovered in v0.11.0 and introduces the optional dependencies feature. The majority of changes are concentrated in Mix, with improvements to how dependencies are processed, ordered, and compiled.

### Key Themes

1. **Mix Dependency System Refactoring** - Major restructuring of how dependencies are fetched and loaded
2. **Umbrella Project Support** - Enhanced handling of umbrella projects with topological sorting
3. **Optional Dependencies** - New feature allowing dependencies to be marked as optional
4. **Compiler Improvements** - Parallel compilation status handling
5. **Error Message Enhancement** - More informative error messages throughout
6. **Code Quality** - Cleanup of deprecated code and unused variables
7. **Compatibility** - Support for newer Erlang/OTP versions (R17A) and better URI handling

## Major Features & Improvements

### 1. Optional Dependencies Support
**Commits**: `7aa5a89396b679642c48897729d5b4d4dd91eff0` and related

A new feature allowing dependencies to be marked as optional. This enables users to specify dependencies that may not always be available or needed. The implementation includes:
- New `Mix.SCM.Optional` module for handling optional SCM sources
- Updated convergence logic in `Mix.Deps.Converger` to handle optional deps
- Updated retriever logic to properly process optional dependencies
- Comprehensive test coverage with 59+ new test cases

**Impact**: Projects can now have conditional dependencies that don't cause build failures if unavailable.

### 2. Mix.Deps Architectural Refactoring
**Commits**: `d7764939678c4bd90d7762e22c34ec989a4e5919` (primary)

A significant internal restructuring that splits dependency handling into fetched and unfetched states:
- **Problem Solved**: Previously, dependencies were fetched/loaded before calling `deps.update`, which caused issues because the updated version tried to use the load mixfile cache, often failing to compile
- **Solution**: Clear separation between fetched dependencies (those available and loaded) and unfetched dependencies (those pending download/processing)
- **Files Changed**: 26 files modified, touching most Mix task implementations and core dependency logic
- **Benefits**: More predictable dependency resolution, fixes issues with updating mixed dependency versions, better preparation for future _build directory migration

### 3. Topological Sorting for Mix Dependencies
**Commits**: Multiple including `f6e3b424c4fdae30f4de2c333229ece60c074f28`, `8ee87b9eda91afb84812169a0d4261c4c1ed142c`, `69792f36e0d6febdedba1f80550d721886d58293`

Implemented proper topological sorting for:
- Regular Mix dependencies to ensure correct compilation order
- Umbrella project children to handle complex dependency graphs
- Cyclic dependency detection with meaningful error messages

**Impact**: Fixes issues with incorrectly ordered compilation and improves handling of complex dependency graphs, especially in umbrella projects.

### 4. Umbrella Project Enhancements
**Commits**: Multiple including `a3021f49e725ec451c2e4406e653bc6f0197b407`, `3dbf8990006784a62a3cd007aaa7cf0c670f6687`, `8bbc42bfda1edd667517b544cb57f0c1139b942e`

Several improvements to umbrella project support:
- Proper environment setup for umbrella project children
- Handling of overridden dependencies with cycles in umbrellas
- Insertion of overridden dependencies before their own dependencies (proper ordering)
- Topsort umbrella children to handle complex hierarchies

**Impact**: Umbrella projects with complex dependency relationships now compile correctly and reliably.

### 5. Parallel Compilation Status Tracking
**Commits**: `ac91c25e214c7407a1c34101abdcab506d1226fd`, `427e5ed712ce446e1fd005adc7db125a65189889`

Added separate compilation status per parallel compilation task, preventing status pollution across concurrent builds.

**Impact**: Parallel compilation is more reliable and provides cleaner build output.

### 6. Improved Error Messages and Diagnostics
**Commits**: Multiple including `0d3aa7fd665e0f695b8b63227c4577c804504509`, `4eb9cd3f5912ea79220249f512baadab6790b868`, `e999642a8ed8f1e37257479cf3befc4fe9680793`, `1ea2fe28e0d9f70c65ea68be9ce26f7a7c2a8391`, `773d4b0a2e599b3c3b4243a55df4919e9382023c`

Multiple improvements to error messages:
- Better Kernel error messages
- Improved syntax error messages for invalid calls
- Better error messages for overridden dependencies
- More informative exception messages when apps are missing
- Fixed warning message formatting

**Impact**: Developers receive clearer, more actionable error messages when issues occur.

## Breaking Changes

### Minor Breaking Changes

1. **Optional Parameter Removal** (`ca7f1fee5ab3411c746a5f62a234d3f71da72b29`)
   - Removed optional parameter on `__using__` macro
   - Affects any code that was passing optional parameters to `__using__`
   - This is a relatively minor breaking change as usage was likely limited

2. **Dependency Storage Format** (`3ede5ff7f9b70f7d533f6b61fc157cd946b21f82`)
   - Dependencies now store only app names instead of full dependency information
   - Internal change that could affect code introspecting `Mix.Deps.deps/0` return values
   - Likely minimal external impact due to being a Mix internal API

3. **Load Paths Deprecation** (`c67fba27f27f5bcada0053c9e2540b2d8f414c86`)
   - `:load_paths` in mix.exs is now deprecated in preparation for Mix's `_build` directory migration
   - Users should update their mix.exs files to remove load_paths configuration
   - Migration plan is in place for future versions

4. **Test Status Code Revert** (`a79bdd5cddc7c2bb6e1cd777cbe807f27b4a05ee`)
   - Reverted "Fix status code in mix test"
   - Mix umbrella projects are run together (not separately) as all apps are booted together
   - Tests expecting individual status codes per app will need to adjust expectations

## Summary of Impact

This release is primarily a consolidation and refinement of the v0.11 series. While introducing the optional dependencies feature, the bulk of changes are internal improvements to Mix's dependency resolution and compilation systems. The refactoring of Mix.Deps into fetched/unfetched states represents a significant architectural improvement that sets the stage for future enhancements like the _build directory migration.

The release maintains backward compatibility for most use cases, though users should be aware of the deprecation of `:load_paths` and the removal of the optional `__using__` parameter. The improvements to error messages and dependency handling should make working with Elixir projects more reliable and less frustrating.

**Overall Assessment**: A solid patch release focused on stability and internal improvements rather than new features, with the notable addition of optional dependencies support.
