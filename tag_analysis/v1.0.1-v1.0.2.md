# Changes from v1.0.1 to v1.0.2

## Release Overview

**Date Range:** October 7, 2014 - October 21, 2014
**Total Commits:** 15 commits
**Release Date:** October 21, 2014
**Main Contributors:** José Valim, Eric Meadows-Jönsson, k1complete, Eduardo Gurgel

This was a focused maintenance release addressing critical compiler issues, error reporting improvements, and internal performance optimizations.

---

## Summary

v1.0.2 represents a patch release focused on stability and error handling improvements rather than new features. The release addressed several critical compiler validation issues, improved error messages throughout the EEx template engine and tokenizer, and made significant internal optimizations to module compilation using unnamed ETS tables. Infrastructure improvements include adding OTP 17.3 support to continuous integration.

The release demonstrates Elixir's commitment to compiler robustness and user experience through better error reporting, as 60% of the changes relate to fixing compiler validation issues, error messages, and edge cases.

---

## Major Features & Improvements

### 1. Module Compilation Internal Refactoring
**Commit:** `24f46be14` - "Use unnamed tables for module compilation"

Significant internal optimization to how module metadata is stored during compilation:
- Reorganized ETS table structure used for module information
- Created a main named table for core module information
- Reduced the number of auxiliary tables by consolidating internal data, documentation, and attributes
- Optimized table lookups for retrieving relevant information
- Result: Three-table structure (data, functions, clauses) instead of the previous more distributed approach

This change improves compilation performance while maintaining the same external API, representing important infrastructure cleanup at a critical system level.

### 2. EEx Template Engine Improvements
**Multiple commits:** `529d584262`, `03d0ad3f03`

**Unified Error Reporting (closes #2833)**
- Consolidated error reporting mechanisms across the EEx template engine
- Improved consistency in how compilation errors are presented to users
- Changes affected 5 files with 80 insertions and 59 deletions

**Binary Expression Optimization (closes #2815)**
- Removed inline binary expressions from EEx compilation
- String.Chars is now always inlined by the compiler
- Simplifies the EEx code generation pipeline

### 3. Enhanced Error Messages & Validation

**Better Token Error Messages for Aliases (closes #2818)**
- Improved error reporting when users provide malformed alias tokens
- More helpful diagnostic messages for common alias errors

**Proper Try/Catch/After Validation (closes #2797)**
- Added validation to fail compilation if a `try` block has no `else`, `catch`, `after`, or `rescue` clauses
- Prevents invalid/useless code from compiling silently
- Early error detection improves code quality

**eval_failure Warnings Handling (closes #2835)**
- Properly handles warnings during template evaluation
- Better diagnostic information for template compilation failures

### 4. Build System Improvements

**Binary Beam Location Rebuild (mix compile.elixir)**
- Fixed `mix compile.elixir` to rebuild .beam file locations from scratch
- Ensures proper resolution of compiled output paths
- Prevents stale path references

**Standalone Mix Release**
- Added task for pushing standalone mix distributions
- Facilitates easier Mix distribution and deployment

### 5. Infrastructure & CI Updates

**OTP 17.3 Support**
- Added OTP 17.3 to Travis CI test matrix
- Ensures compatibility with latest Erlang releases
- Expands testing coverage

**IEx Terminal Improvements**
- Fixed null prompt function in dumbterm mode
- Improves user experience in restricted terminal environments

## Breaking Changes

**No known breaking changes** in this release. All modifications are internal optimizations or bug fixes that maintain backward compatibility:
- ETS table changes are internal implementation details
- Error message improvements don't change API contracts
- Compiler validation changes prevent invalid code, which is non-breaking
- All external APIs remain stable

The `.beam` location rebuild and prompt function fix are internal adjustments with no API impact.

## Release Context

This patch release came just 2 weeks after v1.0.1 and focused on stabilizing the 1.0 release series. The concentration of error reporting improvements and validation enhancements suggests the team was responding to early user feedback from the v1.0.0 release in September.

The internal module compilation optimization (`Use unnamed tables`) represents significant technical debt cleanup, modernizing the core compilation infrastructure while the codebase was still relatively young.
