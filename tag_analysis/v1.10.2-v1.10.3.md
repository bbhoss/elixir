# Changes from v1.10.2 to v1.10.3

## Release Information

- **Release Date**: April 25, 2020
- **Previous Release Date**: February 26, 2020
- **Time Span**: ~2 months
- **Total Commits**: 21 commits

## Summary

Elixir v1.10.3 is a patch release focused on addressing critical bugs discovered after v1.10.2, particularly in core code compilation functionality, the ExUnit testing framework, and the release system. This was primarily a maintenance release aimed at improving stability and fixing regressions from v1.10.0, rather than introducing new features. The majority of changes fall into four main categories: compiler stability, ExUnit improvements, string handling fixes, and release process enhancements.

## Key Themes

### 1. Critical API Regression Fixes

One of the most significant changes in v1.10.3 was fixing a critical regression in the Code module. In v1.10.0/v1.10.2, `Code.compile_file/2`, `Code.require_file/2`, and `Code.load_file/2` began returning a different format than documented and expected. Instead of returning `[{Module, binary}]`, these functions were returning `[{Module, map_with_attributes}]`. This broke the documented behavior from v1.9, affecting any code that depended on receiving compiled bytecode. The fix restores backward compatibility and ensures users get the actual compiled binary as expected.

### 2. ExUnit Pattern Matching Diff Improvements

Multiple commits focused on improving the pattern matching diff feature introduced in v1.10. This feature helps developers see exactly which parts of data structures match a pattern and which don't when assertions fail. However, several edge cases were broken:
- Pattern matching with pinned variables
- Variable struct names in patterns
- Binary concat operator (`<>`) patterns where the left side isn't a literal string
- Pseudo-variables like `__MODULE__` and `__DIR__`

All these edge cases were identified and fixed by v1.10.3, ensuring the feature works reliably across different pattern matching scenarios.

### 3. Compiler Parallelization Stability

The Elixir compiler's parallel compilation system, which is critical for fast builds, had two significant bugs that were fixed:
- A crash when the parallel compiler encountered long compilation cycles
- A crash when compiled modules referred to modules that were directly loaded into memory

These fixes improve the reliability of incremental compilation and complex dependency scenarios.

### 4. String and Format Handling

String handling received attention with the undeprecation and fix of `String.normalize/2`, which was causing infinite loops on certain invalid strings. Additionally, the code formatter was improved to respect newlines before and after module attributes, leading to cleaner and more consistent formatted output.

## Bug Fixes

### Elixir Core

1. **Code Module** - Fixed `Code.compile_file/2`, `Code.require_file/2`, and `Code.load_file/2` to return proper bytecode format instead of metadata maps (Critical regression fix)

2. **Formatter** - Made formatter respect newlines before and after module attributes for consistent code formatting

3. **Parallel Compiler** - Fixed crash when parallel compiler encountered long compilation cycles

4. **Parallel Compiler** - Fixed crash when compiled modules referred to modules directly loaded into memory (in-memory beam files)

5. **Module Definitions** - Fixed accidental breaking change where bodiless clauses had their body value set to an empty list instead of `nil` on `@on_definition` callbacks (revert of problematic change from v1.10.0)

6. **String.normalize** - Undeprecated and fixed `String.normalize/2` which was causing infinite loops on certain invalid strings

### Compiler Infrastructure

7. **Compilation Cycles** - Do not assume all files have started to compile in dependency analysis

8. **In-Memory Modules** - Do not attempt to load in-memory beam files (modules loaded directly to memory)

### ExUnit Testing Framework

9. **Pattern Matching Diff** - Fixed pattern matching diff when comparing against pinned variables (pins are now compared as values)

10. **Pattern Matching Diff** - Fixed diffing when matching variable struct names

11. **Pattern Matching Diff** - Fixed diffing when matching on binary concat operator (`<>`) where left side is not a literal string

12. **Pattern Matching Diff** - Fixed diffing when matching pseudo-variables like `__MODULE__`, `__DIR__`

### Mix & Releases

13. **Release Tar Creation** - Fixed `:path` option being ignored when creating tar files for releases

14. **Dependency Resolution** - Fixed "divergedreq" error when dependency update changes requirement and version

### Build & Infrastructure

15. **FreeBSD Support** - Updated build to use a supported FreeBSD version

16. **Erlang/OTP 23+ Compatibility** - Skip sys_core_prepare pass on Erlang/OTP 23+ for improved compatibility

### Documentation & Maintenance

17. **CHANGELOG Updates** - Added missing CHANGELOG entries to ensure all changes are properly documented

## Breaking Changes

There are **no intentional breaking changes** in v1.10.3. However, it does fix what was itself a breaking change introduced in v1.10.0:

- **Code.compile_file/2, Code.require_file/2, Code.load_file/2** return format was corrected back to `[{Module, binary}]` in v1.10.3, which technically "breaks" any code that had adapted to the broken v1.10.x behavior. However, this is a critical regression fix that restores the documented and historical behavior.

Note: One revert of a problematic change was made (`e1158a55a3`) which corrected a v1.10.0 decision about empty keyword lists in module definitions, another regression that was caught and fixed.

## Conclusion

Elixir v1.10.3 represents a focused maintenance release that addressed critical regressions and stability issues discovered after v1.10.2. The release demonstrates the importance of comprehensive testing, as several bugs (particularly the Code module regression and ExUnit.Diff edge cases) would have significant impact on users if left unfixed. The fixes ensure that v1.10.x is now stable and production-ready, with no major feature additions but significant quality improvements.
