# Changes from v0.14.0 to v0.14.1

## Overview

This release covers a 10-day period from **June 8, 2014 to June 18, 2014** and includes **83 commits**. v0.14.1 is a maintenance release focused on bug fixes, API refinements, and documentation improvements rather than major new features.

## Key Themes and Changes

This release reflects several strategic improvements to the Elixir ecosystem:

1. **URI Module Enhancements** - Significant improvements to URL encoding/decoding functionality to ensure RFC 3986 compliance and add convenience functions for web form data encoding
2. **GenEvent.stream/2 Refinements** - Critical improvements to stream cleanup and resource management, with new synchronous mode by default
3. **Documentation Standardization** - Comprehensive reformatting of docstrings and lists to establish consistent formatting conventions
4. **Breaking Changes Cleanup** - Removal of deprecated code from v0.14.0 cycle and introduction of new deprecation warnings for upcoming v0.15.0
5. **Bug Fixes** - Targeted fixes for string/enumerable slicing, path normalization, and test infrastructure
6. **Mix Build System Improvements** - Enhanced handling of umbrella projects and escript configuration

## Major Features and Improvements

### URI Module Enhancements

The URI module received comprehensive improvements for better standards compliance and convenience:

- **RFC 3986 Compliance** (`14722ba10`) - `URI.encode/1` now correctly conforms to RFC 3986, properly escaping reserved and unreserved characters
- **New `URI.encode/2` Function** (`ffa2abd8c6`) - Allows specifying which characters should be escaped, providing finer control over encoding behavior
- **Web Form Data Support** (`40835556da` and `b3cc52712` and `6b45855f0e`) - Introduced `URI.encode_www_form/1` and `URI.decode_www_form/1` functions for proper handling of `application/x-www-form-urlencoded` data
- **Function Naming Improvements** (`7f4437ece5`) - Refined function naming conventions in the URI module for consistency and clarity
- **Binary-only Constraint** (`8635fcc869`) - URI encoding/decoding functions now strictly work with binaries only, improving type safety
- **Improved Documentation** (`aa09b1e2d2`) - Enhanced URI module documentation

### GenEvent.stream/2 Improvements

The GenEvent stream implementation was significantly refined for better resource management and ease of use:

- **Synchronous by Default** (`311efb66a9`) - Changed GenEvent.stream/2 to use synchronous mode by default, reducing complexity and avoiding common race conditions
- **New Stream Modes** (`311efb66a9`) - Added configurable modes (`:sync` and `:async`) for fine-grained control over stream behavior
- **Improved Cleanup** (`4d607ace08`) - Optimized handler cleanup to be more efficient by reusing the monitored process and its link, reducing unnecessary message passing
- **Mailbox Management** (`78adb5b200`) - Ensured handlers don't get stuck and properly clean up their mailbox, preventing stale messages from accumulating

### Base Module Enhancements

- **Case Options** (`91faec5f65`) - Added options to Base functions (`encode16`, `encode32`, `encode64`) to control whether output uses uppercase or lowercase hexadecimal characters
- **Comprehensive Test Coverage** - Added 91 new test cases for the new case options functionality

### Node Module Addition

- **New Node API** (`38aa5c57e5`) - Added `Node.start/3` and `Node.stop/0` functions, enabling better programmatic control over node lifecycle management

### Slice Consistency Improvements

Fixed return value consistency for slice operations:

- **String.slice Consistency** (`000a1743531`) - Ensures `String.slice/2` and `String.slice/3` always return strings (even empty strings for out-of-bounds ranges), never `nil`
- **Enum.slice Consistency** (`d35d03a8ee`) - Ensures `Enum.slice/2` and `Enum.slice/3` always return lists (even empty lists for impossible ranges), never `nil`

### Path Module Improvements

- **Windows Volume Letter Handling** (`5a94906f1d`) - Added proper dispatch for Windows volume letters in path normalization
- **Path Normalization Fix** (`dacb30ad05`) - Fixed path normalization of `"/.."` to correctly handle edge cases
- **Hidden File Handling** (`65cf31d32d`) - Changed `Path.wildcard/2` to exclude files starting with `.` by default, providing more sensible behavior for most use cases

### Documentation Formatting

A comprehensive standardization of documentation across the codebase:

- **Unordered List Formatting** (`915ba1bb29`) - Applied consistent formatting rules for unordered lists across all modules, ensuring bullets are properly indented with 2-space indent
- **Ordered List Formatting** (`41c74e9682`) - Applied uniform formatting for ordered lists with consistent capitalization and punctuation rules
- **Capitalization Rules** (`e0f5dd506a`) - Applied uniform capitalization and punctuation conventions to all list elements across the codebase
- **Table Indentation** (`b959049c77`) - Fixed table indentation in documentation
- **Backtick Additions** (`55503239a4`) - Added missing backticks in documentation

### Mix Build System Improvements

- **Escript Configuration** (`1857267872` and `cb2eb7d376`) - Refactored escript options to be nested under `:escript` key in project config with deprecation warnings for old format
- **Umbrella Project Handling** (`f32ede4e3f`) - Ensured umbrella projects are properly recompiled when child dependencies change
- **Print App Names** (`c377483715`) - Improved `mix test` output for umbrella projects to clearly display which app is being tested
- **Dependency Compilation** (`1dc9193e69`) - Improved `mix deps.compile` to properly compile path dependencies
- **Windows epmd Support** (`911acc3173` and `8f272c4cc8`) - Added attempts to start epmd before running tests to support Windows development

### Test Infrastructure Improvements

- **Test Process Cleanup** (`4682511923`) - Made test and test cases exit with reason `:shutdown` to ensure OTP processes are properly shutdown
- **on_exit Callback Timing** (`6e9f9f254f`) - Fixed critical race condition by ensuring test process is killed only after `on_exit` callbacks complete, preventing links from crashing prematurely
- **ExUnit Callbacks** - Improved handling of `teardown` and `teardown_all` definitions to avoid spurious warnings
- **Task Logging** (`d54d0f6a6b` and `9451e69996`) - Enhanced task supervision logging when tasks exit abnormally

## Bug Fixes

- **Option Parser** (`e942c07f34`) - Fixed option parser to not allow underscores in option names (addresses #2391)
- **Path Normalization** (`dacb30ad05`) - Fixed edge case in path normalization for `"/.."` pattern (addresses #2404)
- **Unicode Update** (`182cbfe541`) - Updated to Unicode 7.0.0 specification
- **Map Printing Indentation** (`f90eeaa024`) - Fixed map printing to correctly indent 2 levels (addresses #2165)
- **Windows Path Handling** (`4d7c75f2ca`) - Disambiguated `(w)erl` references to properly point to `(w)erl.exe`
- **ExUnit Case Template** (`dc9a47d259`) - Fixed spurious warnings on `teardown` and `teardown_all` definitions in case templates
- **Access Documentation** (`29addf9e93`) - Updated Access module documentation (addresses #2388)

## Breaking Changes

The following changes may affect existing code:

1. **Removed `get_in/1`** (`ec0e7d8056`) - The single-argument form of `get_in` has been removed (previously deprecated)

2. **Removed deprecated `on_exit` callbacks** (`90951be944`) - Callback-based `on_exit` registration has been fully removed, use the functional form instead

3. **Removed deprecated behaviors and modules** (`7de880495b`):
   - `Access` behavior removed (use protocols instead)
   - `Application.Behaviour`
   - `Dict.Behaviour`
   - `GenEvent.Behaviour`
   - `GenServer.Behaviour`
   - `Supervisor.Behaviour`

4. **Path.wildcard/2 Default Behavior** (`65cf31d32d`) - Now excludes hidden files (starting with `.`) by default. This changes the behavior of existing calls that relied on matching hidden files.

5. **escript Configuration Structure** (`1857267872`, `cb2eb7d376`) - Escript options should now be nested under `:escript` key. Old format still works but generates deprecation warnings.

6. **URI.encode* Binary Requirement** (`8635fcc869`) - `URI.encode/1` and `URI.encode/2` now only work with binaries, not other data types

## Notable Commits

### High-Impact Changes

1. **GenEvent.stream/2 Mode Change** (`311efb66a9`) - Default synchronous mode is a significant behavioral change that simplifies the API and reduces race conditions. This should improve reliability of event stream code.

2. **Path.wildcard/2 Default Change** (`65cf31d32d`) - Excluding hidden files by default is a common-case optimization but could break existing code that relies on matching dotfiles.

3. **URI Module RFC 3986 Compliance** (`14722ba10` + `ffa2abd8c6`) - Ensures web standards compliance and adds powerful URI encoding capabilities for form data.

4. **Test Process Cleanup** (`4682511923` and `6e9f9f254f`) - Critical fixes for OTP process cleanup in tests prevent race conditions and improve test reliability.

### Documentation Quality

The documentation cleanup commits (`915ba1bb29`, `41c74e9682`, `e0f5dd506a`) represent a significant effort to establish consistent formatting conventions across the entire codebase. This affects dozens of modules and improves readability and consistency.

### Deprecation Management

The release properly manages the deprecation cycle:
- **Deprecated new items** for v0.14.0 are removed (e.g., behaviors, old callback styles)
- **New deprecations** are introduced for v0.15.0 changes (e.g., old escript configuration format)

This ensures users have clear migration paths and advance warning of future changes.

## Release Summary

v0.14.1 demonstrates Elixir's commitment to:
- **Standards Compliance** - URI module now correctly implements RFC 3986
- **API Stability** - Completing deprecation cycles and removing old code
- **Code Quality** - Comprehensive documentation formatting and bug fixes
- **Developer Experience** - Improved GenEvent defaults and path handling
- **Test Reliability** - Critical fixes to test infrastructure for proper OTP handling

The release is primarily maintenance-focused, with no major new features but numerous targeted improvements that enhance stability, compliance, and usability. The changes suggest the team was focused on closing deprecated APIs, fixing edge cases, and establishing consistent patterns across the codebase in preparation for larger changes in future releases.
