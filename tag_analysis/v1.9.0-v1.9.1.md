# Changes from v1.9.0 to v1.9.1

## Release Information

- **Release Date Range**: June 24, 2019 - July 18, 2019 (24 days)
- **Commit Count**: 16 commits (including release commit)
- **v1.9.0 Release**: June 24, 2019 at 11:20:18 UTC+2
- **v1.9.1 Release**: July 18, 2019 at 12:17:13 UTC+2

## Summary

The v1.9.1 release is a patch release focused on bug fixes, error handling improvements, and documentation enhancements. This release addresses critical issues in release generation, code formatting, error reporting, and supervisor management. Notable additions include support for included applications in releases and improved UTF-8 encoding handling in release configuration files. The patch consolidates fixes discovered in the field while maintaining stability and improving developer experience through better error messages and documentation.

## Major Features & Improvements

### Support for Included Applications (#9163)
A significant new feature was added to the release system to support included applications. This allows developers to better manage application dependencies within release configurations. This is particularly important for complex application architectures that rely on multiple coordinated applications.

### Improved Release Documentation (#9187)
Comprehensive improvements to release-related documentation were made to clarify concepts and expected behaviors. This includes better explanations of how releases work and how to configure them properly.

### Better Error Messages
Two key improvements to error reporting were implemented:
- **Formatter error paths** are now printed as relative paths, making error messages more readable and easier to navigate in project structures
- **Mismatched sources** now produce readable, actionable error messages (#9218) instead of cryptic failures

### Enhanced Documentation
- **Tuple documentation**: Improved clarity around tuple immutability and the practice of binding results to new variables
- **Time unit documentation**: Added more comprehensive details about the `:native` time unit, drawing from official Erlang documentation (#9157)

## Bug Fixes

### Release Configuration Issues
1. **UTF-8 Encoding Preservation** (#9225): Fixed critical bug where UTF-8 encoding was not properly preserved in release configuration files. This could cause issues with non-ASCII characters in configuration values.

2. **Content Decoding**: Fixed a crash condition where the decoder would attempt to process empty content, causing failures during release generation.

### Code Formatter Fixes
1. **Nested Parentheses Bug** (#9211): The formatter was incorrectly removing necessary nested parentheses in call-on-call expressions, which could change code semantics. This has been fixed to preserve parenthetical grouping.

### Supervision & Process Management
1. **Supervisor Name Handling** (#8126): Added catch-all handling for bad supervisor names. Previously, if a different supervisor implementation (such as `ConsumerSupervisor` from GenStage) passed a different name structure, the logging system would fail. Now includes defensive checks.

2. **Locals Tracker Cleanup**: Fixed an issue where the locals tracker process could not be properly stopped, preventing clean shutdown in certain scenarios.

### Test Infrastructure
- **EPMD Availability Check** (#9167): Tests now properly check whether the EPMD (Erlang Port Mapper Daemon) is available before attempting to run, preventing test failures in environments where EPMD is not running.

### Module System
- **`:start` Cannot Be Customized on `use`**: Fixed a bug where the `:start` callback was incorrectly being customizable through module attributes in `use` statements. This is now properly restricted to maintain module system integrity.

## Testing Recommendations

When upgrading from v1.9.0 to v1.9.1, pay particular attention to:
- Release generation with non-ASCII characters in configuration
- Code formatting results, especially with nested function calls
- Supervisor configurations using non-standard implementations
- Application startup sequences with included applications
- Error reporting in the formatter and compiler
