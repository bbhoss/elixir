# Elixir v1.16.3 to v1.17.0 Analysis

## Version Information
- **Previous Version:** v1.16.3
- **Current Version:** v1.17.0
- **Release Date:** June 12, 2024
- **Date Range:** May 21, 2024 to June 12, 2024
- **Total Commits:** 607

## Summary

Elixir v1.17.0 is a groundbreaking major release that introduces **gradual set-theoretic types** to the language, providing compile-time type warnings without requiring type annotations. This release also adds the new `Duration` data type for calendar operations, full support for Erlang/OTP 27, significantly enhanced testing capabilities, and numerous quality-of-life improvements. This is arguably the most important Elixir release since v1.16.0's diagnostic improvements.

### Key Themes
1. **Type System Revolution** - Gradual set-theoretic types with compile-time warnings
2. **Duration Support** - New data type for temporal operations
3. **OTP 27 Support** - Full compatibility with latest Erlang/OTP
4. **Testing Enhancements** - Breakpoints, repeat-until-failure, and performance profiling
5. **Language Evolution** - Charlist deprecation and other modernizations

## Major Features and Improvements

### Gradual Set-Theoretic Types (Revolutionary)

Based on research by Giuseppe Castagna, Guillaume Duboc, and José Valim ([Design Principles paper](https://arxiv.org/abs/2306.06391)), Elixir now includes a type inference system that provides warnings without requiring type annotations:

**Supported Types:**
- **Indivisible**: `binary()`, `integer()`, `float()`, `pid()`, `port()`, `reference()`
- **Divisible Atoms**: Individual atoms like `:foo`, `:bar` are distinct types
- **Maps & Structs**: Closed maps (fixed keys) and open maps (allow extra keys)
- **Collections**: `tuple()`, `list()`, `function()` (basic support, will be expanded)

**New Warnings Detected:**
- Map/struct field typos: `%{adress: ...} = user` (should be `address`)
- Invalid field access: `user.adress`
- Invalid struct updates: `%{user | adress: ...}`
- Calling functions on non-modules: `user.address()`
- Function capture on non-modules: `&user.address/0`
- Calling non-functions: `user.()`
- Invalid structural comparisons: `my_date < ~D[2010-04-17]`
- Type mismatches: `integer >= string`
- Binary specifier errors: `<<name>>` (missing `::binary`)
- Rescuing undefined exceptions
- Accessing undefined exception fields

This dramatically improves code quality and refactoring confidence, especially for map-heavy codebases.

**Sponsored by**: CNRS, Remote, Fresha, Starfish*, and Dashbit

### Duration and Calendar APIs

New `Duration` data type for temporal operations:

```elixir
Date.shift(~D[2016-01-31], month: 2)  # => ~D[2016-03-31]
```

**Features:**
- Calendar-aware shifting for `Date`, `Time`, `DateTime`, and `NaiveDateTime`
- Handles time zone changes (DST) correctly
- Recognizes non-associative nature of duration operations
- `Kernel.to_timeout/1` for normalizing durations to Process timeouts

### Erlang/OTP 27 Support

- **Full OTP 27 compatibility** with new features
- **Dropped OTP 24 support** - minimum is now OTP 25
- **WERL deprecation** - Windows graphical terminal will be removed in v1.18
- Migration to OTP 26+ strongly recommended

### Testing and Debugging Revolution

**Mix Test Enhancements:**
- `mix test --breakpoints`: Sets breakpoint before each test
- `mix test --repeat-until-failure`: Runs tests until failure occurs
- `mix test --slowest-modules`: Shows slowest modules by test time
- Parallel HTML coverage generation
- Max cases included in ExUnit reports
- Test process propagated as caller in `start_supervised`

**New Profiler:**
- `mix profile.tprof`: New profiler on OTP 27+ measuring count, time, and heap usage
- Deprecates `mix profile.cprof` and `mix profile.eprof`

### Kernel Enhancements

- **`Kernel.get_in/1`**: Safe nil-handling for nested access
- **`Kernel.is_non_struct_map/1`**: New guard for plain maps
- **`Kernel.to_timeout/1`**: Duration to timeout conversion
- **Uppercase sigils with integers**: Better integer support in sigils
- **Undefined function warnings**: Warns for undefined functions in same context
- **Parsing improvements**: Better handling of `..`, `...`, and ambiguous operators

### String and Access

- **`String.byte_slice/3`**: Slice strings by byte count while maintaining UTF-8 validity
- **`Access.find/1`**: Mirrors `Enum.find/2` for Access protocol

### Date and Time

- **Extended year range**: Dates now support years outside `-9999..9999`
- **Shift operations**: All temporal types support `shift/2` with durations

### GenServer and Process

- **`Process.set_label/1`**: Set process labels (OTP 27 feature)

## Breaking Changes

### Hard Deprecations (Warnings Emitted)

1. **Single-quote charlists**: Now deprecated, use `~c` instead (modernization)
2. **Decreasing ranges**: `10..1` deprecated, use `10..1//-1`
3. **Ranges in patterns/guards**: `left..right` deprecated, use `left..right//step`
4. **IO.read/2 `:all`**: Deprecated, use `:eof` instead
5. **Uppercase sigil escaping**: Deprecate escaping closing delimiter
6. **ExUnit.Case.register_test/4**: Deprecated for `register_test/6`

### Soft Deprecations (No Warnings)

1. **`GenServer.format_status/2`**: Use `format_status/1` instead
2. **`mix profile.cprof` and `eprof`**: Use `mix profile.tprof` instead

## Impact Assessment

**This is a transformative release for the Elixir ecosystem.** The gradual set-theoretic type system represents years of research and development, bringing sophisticated compile-time checking without the burden of type annotations. This positions Elixir uniquely among dynamic languages, offering type safety without sacrificing the flexibility that makes dynamic languages productive.

The Duration type fills a critical gap in Elixir's temporal APIs, making it much easier to work with recurring events and time-based calculations.

The testing enhancements, particularly `--breakpoints` and `--repeat-until-failure`, will significantly improve debugging workflows and test reliability verification.

The charlist deprecation continues Elixir's evolution toward clearer, more explicit syntax.

**Upgrade Recommendation:** Essential upgrade for all users. The type system alone makes this worth upgrading, as it will help find bugs in existing codebases without code changes. Teams should plan migration from OTP 24 if still on that version. The hard deprecations are well-communicated and provide clear migration paths.

**Compatibility Note**: Requires OTP 25+. Projects on OTP 24 must upgrade first.
