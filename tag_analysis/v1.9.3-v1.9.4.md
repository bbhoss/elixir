# Changes from v1.9.3 to v1.9.4

## Summary

v1.9.4 is a critical patch release that fixed a regression introduced in v1.9.3. The previous release added deprecation warnings for unsafe URL-based installations in Mix tasks (`mix archive.install`, `mix escript.install`, and `mix local.rebar`). However, v1.9.3 incorrectly showed these deprecation warnings even when users provided a SHA512 checksum, which was supposed to bypass the warning as a valid security mechanism. v1.9.4 quickly corrected this issue.

This is a textbook example of a hotfix release—a real-world scenario where a security-related feature inadvertently caused friction for users who were already following best practices by providing checksums. The quick turnaround demonstrates the Elixir team's responsiveness to addressing usability issues.

## Bug Fixes

### Mix

**[mix local.hex] Remove invalid deprecation warning on `mix local.hex` command**

**Files Modified:**
- `lib/mix/lib/mix/tasks/archive.install.ex`
- `lib/mix/lib/mix/tasks/escript.install.ex`

**The Problem:**
v1.9.3 added deprecation warnings to discourage users from installing archives and escripts directly from URLs without checksums. The implementation checked for URL-based installations and always warned users, regardless of whether they provided a SHA512 checksum.

**The Fix:**
Both `archive.install.ex` and `escript.install.ex` were updated to **skip the deprecation warning if a SHA512 checksum is provided**. The logic changed from:

```elixir
# v1.9.3 (incorrect - always warns)
def check_install_spec({:url, url} = _install_spec, _opts) do
  Mix.Utils.warn_install_over_http_deprecated("archive.install", url)
  check_extname(url)
end
```

To:

```elixir
# v1.9.4 (fixed - warns only without checksum)
def check_install_spec({:url, url} = _install_spec, opts) do
  unless opts[:sha512] do
    Mix.Utils.warn_install_over_http_deprecated("archive.install", url)
  end
  check_extname(url)
end
```

**Impact:**
- Users who properly secured their installations with SHA512 checksums no longer see false-positive warnings
- The security message still reaches users who attempt unsafe installations without checksums
- Minimal code change (added a condition guard), demonstrating surgical fix approach

## Context and Analysis

### Why This Happened

The release cycle shows careful security consideration:

1. **v1.9.3 Security Focus**: The Elixir team identified that allowing direct URL-based installation of Mix archives and escripts without checksums was a security risk. They added deprecation warnings to educate users.

2. **Immediate User Feedback**: Hours after v1.9.3 was released, the team (likely through issue reports or internal testing) discovered that the warning was too aggressive and penalized security-conscious users who were already using SHA512 checksums.

3. **Rapid Response**: Rather than wait for v1.10, the team released v1.9.4 the same day to fix the user experience issue while keeping the security improvements.

### Technical Quality

The fix is exemplary:
- **Minimal Change**: Only added a guard condition, reducing risk of regression
- **Intentional Design**: SHA512 checksums were always meant to be an exception to the warning
- **Backward Compatible**: Users without checksums still get warned as intended

### Release Philosophy

This release demonstrates Elixir's pragmatic approach:
- **Security First**: Don't compromise on security
- **User Experience Second**: Don't frustrate users who are doing the right thing
- **Rapid Iteration**: Hotfix releases are acceptable for improving user experience, not just bugs
