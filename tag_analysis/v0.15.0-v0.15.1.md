# Changes from v0.15.0 to v0.15.1

## Release Overview

**Date Range:** August 2-10, 2014
**Total Commits:** 85 commits
**Release Date:** August 10, 2014

This patch release (v0.15.1) was a focused effort to address critical bugs, improve stability, and add important quality-of-life features discovered shortly after v0.15.0. The release spanned just over a week and included contributions from the core team and community members.

---

## Summary of Key Themes

The v0.15.1 release focused on four primary areas:

1. **Logger Infrastructure Hardening** - Multiple improvements to the Logger module to enhance reliability and functionality
2. **Terminal/Shell Improvements** - Better terminal support detection and cross-platform compatibility
3. **Path Handling Fixes** - Correcting path normalization behavior that was causing issues
4. **API Improvements & Deprecations** - Adding new utilities while deprecating older patterns

This was primarily a maintenance release focused on solidifying v0.15.0's foundation rather than introducing revolutionary new features.

---

## Major Features & Improvements

### Logger Enhancements

Logger received the most attention in this release with multiple improvements:

- **Logger.flush/0** - Added a new function to flush all pending log messages, essential for ensuring all logs are written before shutdown
- **Logger Metadata Support** - Merged comprehensive metadata support to the Logger module, allowing contextual information to be attached to log entries
- **SASL Log Forwarding** - Added SASL (System Architecture Support Libraries) log forwarding option to Logger, enabling better integration with Erlang's logging infrastructure
- **Improved SASL Report Translation** - Enhanced how SASL reports are translated into readable log formats
- **Logger Padding Fixes** - Fixed padding in log message formatting to ensure consistent alignment of log level indicators
- **Backend Configuration Improvements** - Fixed issues with how Logger backends receive IDs when added to the system

### GenEvent Improvements

GenEvent (Generic Event Handling) received important functionality enhancements:

- **:sync Mode Support** - Added support for `:sync` mode in GenEvent, complementing existing asynchronous modes
- **:ack Mode Default** - Made `:ack` mode the new default behavior for GenEvent, changing from previous default modes
- **Stream Manager Reply** - Fixed GenEvent manager to reply to streams immediately rather than deferring responses

### Terminal & IEx Improvements

Several important changes for interactive shell usage:

- **Terminal Support Detection** - Improved detection of terminal capabilities from the Elixir command line
- **Dual Output Detection** - Enhanced terminal detection to check both stdout and stderr, improving compatibility
- **MinGW Compatibility** - Fixed critical issues preventing Elixir and IEx from working on MinGW (Minimal GNU for Windows)
- **IEx Shell Fixes** - Fixed docs and specs introspection in IEx
- **IEx Documentation** - Improved documentation about .iex.exs configuration files

### Macro & Code Quality Improvements

- **Macro.validate/1** - New function to validate AST (Abstract Syntax Tree) expressions, helping catch errors early
- **Bitstring Escaping** - Ensured bitstrings can be properly escaped in quoted expressions
- **Invalid Quote Handling** - Prevented invalid quoted expressions from leaking into compiled code

### Path Handling

- **Path.join Normalization** - Fixed Path.join/2 to not normalize paths (issue #2500), preserving relative path components as intended
- **Pathtype Detection** - Improved pathtype detection logic, making it reusable across the Path module

### Inspect Improvements

- **Integer Base Support** - Added `:base` option to `inspect/2` supporting `:binary`, `:octal`, `:decimal`, and `:hex` formats, enabling flexible integer representation

---

## Deprecations

### API Deprecations

1. **Module.function/3** - Deprecated the `Module.function/3` function (though likely already falling out of use)
2. **Functions as Collectable** - Deprecated using functions as collectable structures, encouraging users to adopt proper Collectable implementations

These deprecations signal API maturation and encourage patterns that are more explicit and maintainable.

---

## Breaking Changes

**No strict breaking changes** were introduced in this release. However, the following items warrant developer attention:

- **GenEvent :ack Default Change** - If code relied on the previous default GenEvent mode, it should be updated to explicitly specify the desired mode
- **Path.join Behavior Change** - The fix for path normalization in `Path.join/2` changes behavior for edge cases with relative paths containing `..` components

---

## Infrastructure & Cross-Platform

Several improvements were made to support different platforms and build environments:

- **Windows Support** - Added Windows wiki link to README, directing users to platform-specific documentation
- **Cygwin Support** - Fixed issues with `-noshell` flag handling in Cygwin
- **MinGW Support** - Critical fixes enabling Elixir to work on MinGW systems
- **IEx Windows** - Suppress "-s elixir start_cli" for IEx, preventing unnecessary startup scripts

## Notable Implementation Details

### Logger Architecture Changes

The Logger improvements suggest significant maturation of the logging infrastructure:
- Addition of metadata support indicates growing support for contextual logging
- SASL integration suggests efforts to better bridge Erlang and Elixir logging ecosystems
- The flush operation addition shows awareness of ordering guarantees needed in production systems

### GenEvent Mode Strategy

The GenEvent changes reflect a strategic decision to make `:ack` the default mode, suggesting it better matches typical use cases. The addition of `:sync` mode support provides flexibility for scenarios requiring synchronous guarantees.

### Macro Improvements

The addition of `Macro.validate/1` and better quote handling indicates growing support for compile-time metaprogramming, allowing developers to catch errors earlier in the pipeline.

## Conclusion

v0.15.1 represents a focused patch release addressing quality and stability concerns identified after v0.15.0. Rather than adding major new features, the release improved the foundation:

- **Logger** became more robust and feature-complete
- **Terminal handling** was improved for better cross-platform compatibility
- **Path operations** were corrected to match documented behavior
- **Code quality** improved through better validation and error handling

The release demonstrates Elixir's commitment to stability and cross-platform support, with particular attention to Windows and MinGW users who had reported compatibility issues. The various deprecations signal the project's intentions for cleaner, more maintainable APIs going forward.

This was a solid patch release that strengthened the v0.15 line before moving on to v0.16 development.
