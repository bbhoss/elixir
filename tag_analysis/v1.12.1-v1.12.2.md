# Changes from v1.12.1 to v1.12.2

## Release Overview

**Release Date:** June 1 - July 1, 2021
**Total Commits:** 18 commits (plus release commit)
**Release Type:** Patch Release (v1.12.1 → v1.12.2)

This patch release focused on performance optimizations, bug fixes, and compilation improvements. The most significant changes relate to concurrent application loading and dependency management.

---

## Summary: Key Themes and Changes

The v1.12.2 release introduces three major improvement areas:

1. **Performance Optimization**: The most substantial focus of this release. Key improvements include concurrent loading of applications (a significant bottleneck in build times) and optimizations to `Enum.into/2` and `Map.new/1` to reduce unnecessary allocations.

2. **Bug Fixes**: Several important correctness fixes, particularly around compile-time dependency tracking and Rebar dependency handling.

3. **Developer Experience**: Minor improvements to documentation, code formatting, and build feedback (profiling output).

The release represents a continuation of Elixir's commitment to making incremental, focused improvements rather than major feature additions. These optimizations are particularly beneficial for developers working on larger projects where build times matter.

## Major Features & Improvements

### 1. Concurrent Application Loading (5 commits, June 1)

**Most Significant Improvement**

A comprehensive refactoring of how Mix loads applications during compilation. This involved multiple related commits that work together:

- **"Load apps concurrently"** - The primary change that parallelizes application loading using `Task.async_stream/3` instead of sequential loading
- **"Remove duplication across branches"** - Code cleanup to improve maintainability
- **"Simplify reading of apps from deps"** - Refactored the app file reading mechanism
- **"Avoid central bottleneck when loading apps if we know their source"** - Optimization that bypasses Erlang's code loader for dependencies, reading app files directly from disk
- **"Also annotate temp var for remote call in map.foo as generated"** - Code generation optimization related to compiler output

**Impact**: These changes significantly reduce compilation time, especially noticeable in projects with multiple dependencies. The parallel loading and optimized file access patterns provide responsive feedback during `mix compile` and `mix run` operations.

## Bug Fixes

### 1. Compile-Time Dependency Tracking Bug Fix

**"Do not add compile time deps on args to Application.compile_env/2, closes #11052"** (June 8)

**Problem**: `Application.compile_env/2` and `Application.compile_env!/2` macros were incorrectly tracking compile-time dependencies on module aliases used as arguments. For example:

```elixir
Application.compile_env(:app, URI)          # URI was incorrectly marked as a compile dep
Application.compile_env(:app, [:foo, URI])  # Same issue in lists
```

**Solution**: Added an `expand_key_or_path/2` function that expands aliases at macro expansion time (in the caller's environment) rather than at runtime. This prevents Elixir from treating the module reference as a compile-time dependency.

**Impact**: Important correctness fix that prevents unnecessary recompilation when configuration values reference module names that aren't actually used at compile time.

**Files Modified:**
- `lib/elixir/lib/application.ex` (13 insertions)
- `lib/elixir/test/elixir/kernel/lexical_tracker_test.exs` (15 insertions for test coverage)

### 2. Rebar Dependencies Specification Fix

**"Ensure unconstrained rebar deps generate valid mix specifications, #11063"** (June 15)

**Problem**: When Rebar projects declare dependencies without version constraints (just the atom), the Mix integration was generating invalid specifications: `{app, nil, override: true}`. The nil in the middle position is not valid Mix specification syntax.

**Solution**: Changed the tuple format to `{app, override: true}`, which properly represents an unconstrained dependency in Mix.

**Impact**: Fixes mix specifications for projects using Rebar without explicit version constraints, preventing potential compilation errors.

**Files Modified:**
- `lib/mix/lib/mix/rebar.ex` (2 lines changed)
- `lib/mix/test/mix/rebar_test.exs` (2 insertions for test case)

### 3. Deprecated Macros Warning Validation

**"Ensure deprecated macros emit warnings"** (June 23)

**Problem**: The system wasn't consistently ensuring that deprecated macros emit warnings when invoked.

**Solution**: Added proper validation and test coverage to ensure deprecated macros correctly emit warnings to developers using them.

**Impact**: Improves the experience of migrating away from deprecated APIs by ensuring developers receive appropriate warnings.

**Files Modified:**

- `lib/elixir/src/elixir_dispatch.erl` (20 lines modified)

## Technical Details & Architecture Insights

### Application Loading Architecture Change

The application loading refactor is worth understanding as it shows Elixir's ongoing focus on build performance:

1. **Before**: Applications were loaded sequentially, with code loaded via Erlang's code loader (`code.where_is_file`/`erl_prim_loader`)
2. **After**: Applications are loaded concurrently using `Task.async_stream/3`, and for dependencies (where we know the exact location), files are read directly from the build directory

This optimization avoids a central bottleneck in Erlang's code loader, which must be queried sequentially. By batching lookups for dependencies and knowing their exact paths upfront, the system parallelizes what was previously serial work.

### Enum.into/Map.new Optimization Strategy

Rather than creating intermediate data structures or relying on protocol dispatch for each element, these optimizations leverage the fact that both functions are working with known collection types. The optimization reduces allocations and simplifies the code path.

## Conclusion

v1.12.2 is a focused, performance-oriented patch release. The majority of value comes from the concurrent application loading improvements, which should provide noticeable benefits to developers working on projects with multiple dependencies. The bug fixes address important correctness issues, particularly around compile-time dependency tracking. This release exemplifies Elixir's pragmatic approach to maintenance: identifying bottlenecks, fixing them efficiently, and delivering incremental value to users.

The changes are transparent to end users writing Elixir code—no API changes are required—but the performance improvements and bug fixes enhance the development experience and correctness of compilation.
