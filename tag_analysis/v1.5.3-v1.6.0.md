# Changes from v1.5.3 to v1.6.0

## Overview

This release spans from **June 25, 2017 to January 17, 2018** and includes **1,071 commits**. Elixir v1.6.0 is a major release that introduces fundamental tooling improvements and significant enhancements to the standard library, focusing on developer experience and code maintainability.

The release was split into two release candidates:
- v1.6.0-rc.0 (September 6, 2017)
- v1.6.0-rc.1 (January 10, 2018)
- v1.6.0 (January 17, 2018)

---

## Key Themes and Analysis

### 1. **Code Formatter Revolution**
The most significant feature of v1.6.0 is the introduction of an automatic code formatter with the `mix format` task. This represents a fundamental shift in how Elixir code is written and maintained across the ecosystem.

**Why this matters:** Automated code formatting eliminates style debates, improves code consistency across teams, and reduces cognitive load for developers who can focus on business logic rather than formatting rules. The entire Elixir codebase was formatted, and all contributions are now expected to be pre-formatted.

**Key formatter improvements:**
- Added `Code.format_string!/2` and `Code.format_file!/2` APIs
- Introduced `.formatter.exs` configuration file for project-specific rules
- Support for flex breaks in `Inspect.Algebra` for better control over document fitting
- Added `Inspect.Algebra.collapse_lines/1`, `force_unfit/1`, and `next_break_fits/2` for granular formatting control
- Support for groups that inherit parent group breaks
- Proper handling of bitstring and tuple formatting with flex_glue
- Over 12 major formatting passes applied to the codebase during development

**Formatter workflow integration:**
- CI integration friendly with flags for Pull Request validation
- Only writes files that actually changed to minimize git diffs
- Support for reading formatter configuration from dependencies
- Automatic detection of file patterns through `.formatter.exs`

### 2. **Dynamic Supervisor as First-Class API**
The introduction of `DynamicSupervisor` addresses a long-standing architectural issue in Elixir's supervision tree design.

**Background:** Previously, supervisors managing dynamically spawned children used the `:simple_one_for_one` strategy, which had different semantics and APIs compared to regular supervisors. This created confusion and API inconsistency.

**Solution:** A dedicated `DynamicSupervisor` module now encapsulates and properly documents the behavior of dynamically supervised children, with:
- Cleaner API focused specifically on dynamic child management
- New `:max_children` option to limit the number of supervised children
- Better documentation and type specifications
- Migration of `Task.Supervisor` to use `DynamicSupervisor` internally
- Consistent initialization and shutdown semantics

### 3. **Deprecation Infrastructure (@deprecated and @since)**
A new annotation system for tracking API lifecycle was introduced, enhancing the library ecosystem's ability to deprecate code safely.

**Features:**
- `@deprecated` attribute marks functions/macros as deprecated with optional message
- `@since` attribute documents when an API was introduced
- `mix xref deprecated` task detects and warns about deprecated function calls during compilation
- No runtime warnings or performance impact - analysis happens at compile time
- Enables library authors to signal API changes to users systematically

**Example:**
```elixir
@doc "Breaks a collection into chunks"
@since "1.0.0"
@deprecated "Use chunk_every/2 instead"
def chunk_every(collection, chunk_size) do
  ...
end
```

### 4. **Guard Clause Macros (defguard/defguardp)**
Guards in Elixir are restricted to a small set of allowed constructs. The new `defguard/1` and `defguardp/1` macros enable developers to safely extract and reuse guard expressions.

**Impact:**
- Reduces code duplication in guard expressions
- Makes guard logic more readable and maintainable
- Properly handles guard-safe operation constraints
- Enables library developers to provide guard helpers

### 5. **IEx Enhancements**
Significant improvements to the interactive Elixir shell for a better developer experience:

**Contextual Autocompletion:**
- `t Enum.` autocompletes only types in Enum (not functions)
- `b GenServer.` autocompletes only behavior callbacks
- More intelligent REPL exploration

**Formatting Integration:**
- Code snippets, types, and specifications are pretty-printed using the new formatter
- Better visual presentation of complex data structures
- Automatic inclusion of function specifications in documentation

**Breakpoint Improvements:**
- Extended `break!` to support pattern matching: `break! SomeFunction.call(:foo, _, _)`
- Support for guard expressions in breakpoints
- More powerful debugging capabilities

### 6. **Stream and Enumerable Protocol Enhancements**

**API Changes:**
- Renamed `Stream.chunk/4` to `Stream.chunk_every/4` for consistency with `Enum.chunk_every/2`
- Renamed `Stream.chunk_by/4` to `Stream.chunk_while/4` with improved semantics
- New `Stream.intersperse/2` for adding separators between elements
- Fixed `Stream.chunk_every/4` when `step > count`
- Fixed issue where `after_fun` was incorrectly invoked in `chunk_while` when elements halted

**Protocol Addition:**
- New `Enumerable.slice/1` protocol for efficient random-access to collections
- Optimization of many Enum operations using the new protocol
- Data structures with index-based access can now provide non-linear implementations

### 7. **String and Unicode Updates**

**Unicode 10 Support:**
- Updated to Unicode 10 standard
- Better Greek character handling in downcasing operations
- Support for case-ignorable characters

**New String Methods:**
- Context and language-sensitive operations in `String.upcase/2` and `String.downcase/2`
- Currently supports `:greek` context for Greek character handling
- `:ascii` conversion mode for both upcase and downcase
- Support for empty string `match` parameter in `String.replace/4`

### 8. **mix xref Task Expansion**
Powerful analysis tools for understanding code dependencies, significantly enhanced:

**New Features:**
- `--include-siblings` option for umbrella project analysis
- `mix xref graph --format stats` for statistical summaries
- `--only-nodes` option to show dependencies without edges
- `--label` option to filter by relationship type (compile, struct, runtime)
- `mix xref deprecated` task for tracking deprecated function usage
- Enhanced reporting capabilities for large codebases

**Example outputs:**
- Top files by outgoing/incoming dependencies
- Compile vs. runtime vs. struct dependencies breakdown
- Useful for identifying coupling and architectural issues

### 9. **Testing and Profiling Improvements**

**ExUnit Enhancements:**
- Random seed generation per test (in addition to suite seed)
- `ExUnit.Callbacks.start_supervised!/2` for test setup
- Better assertions with `ExUnit.Assertions.assert_in_delta` performing inclusive checks
- Separated reporting of doctests and regular tests

**Mix Test Features:**
- `--slowest N` flag to identify performance bottlenecks
- Run all functions in a describe block by specifying the describe line
- Better test organization and performance analysis

**Profiling:**
- New `mix profile.eprof` task for time-based profiling
- Complements existing `mix profile.cprof` (count-based) and `mix profile.fprof` (flame-based)

### 10. **Calendar and DateTime Improvements**

**New Methods:**
- `Time.truncate/2`, `DateTime.truncate/2`, `NaiveDateTime.truncate/2` for microsecond precision pruning
- `Time.add/3` for adding time intervals
- `Date.from_erl!/2`, `Time.from_iso8601!/2`, `NaiveDateTime.from_erl!/3` for eager loading variants

## Major Features and Improvements

### Code Generation and Compilation
- **Prefix variables with V** when emitting Erlang code for better integration with Erlang tooling and GUI debuggers
- Enhanced `Kernel.ParallelCompiler` with `compile/2`, `compile_to_path/3`, and `require/2` for detailed warning/error information
- Struct dependency tracking between files with smart recompilation
- Better error messages for contextual operators like `|` and `::`

### Exception Handling
- `Exception.blame/3` is now extensible with optional `blame/2` callback for custom exception handling
- Improved guard printing in blamed exceptions
- Proper handling of `:erlang.element` in exception blame
- Better error messages for negative integer inspection in non-decimal bases

### Logger Enhancements
- New `:discard_threshold` option to help with message queue overflow scenarios

### Mix Improvements
- `mix deps.update` now fetches new dependencies automatically
- `mix archive.build` can bundle dot files via option
- Mix compiler tasks now defined via behavior with diagnostics support
- `:system_env` option for specifying environment-dependent dependencies
- Better compiler diagnostics for editor integration

### Record and Macro Improvements
- `Record.extract/2` now accepts `:macros` and `:includes` options
- `defdelegate` no longer auto-generates documentation when delegate exists
- Don't add parentheses for `defrecord/3` and `defrecordp/3` calls

## Breaking Changes and Deprecations

### API Removals and Changes
1. **`Keyword.replace/3` and `Map.replace/3` deprecated** - Scheduled for v1.8
2. **`Range.range?/1` deprecated** - Use pattern matching instead
3. **`Stream.chunk/4` renamed to `Stream.chunk_every/4`** - Consistency with Enum API
4. **`Stream.chunk_by/4` renamed to `Stream.chunk_while/4`** - Better semantic name

### Behavioral Changes
1. **Reverted soft module purging** - Was causing badfun/badarg errors on anonymous functions
2. **Task.Supervisor rewritten** - Now uses DynamicSupervisor internally but maintains API compatibility
3. **IEx.break! semantics** - Now properly supports pattern matching and guards

### Warnings and Lint Improvements
- **Warning on `length(x) == 0` in guards** - Use guards that don't require function calls
- **Warning if `catch` comes before `rescue` in try** - Wrong exception handling order
- **Warning if heredoc is outdented** - Code formatting consistency
- **Warning on trailing commas in calls** - Code style consistency
- **Warning if `init/1` not implemented in GenServer** - Common mistake detection
- **Warning on duplicate definitions in macros** - Macro hygiene
- **Warning on multiple clauses with default values** - Unclear semantics

## Impact and Significance

Elixir v1.6.0 represents a maturation of the language's tooling ecosystem:

1. **Formatter eliminates style debates** - Enables teams to focus on logic and design
2. **Better supervision abstractions** - DynamicSupervisor clarifies architecture patterns
3. **Safer deprecations** - Libraries can evolve API without runtime overhead
4. **Enhanced diagnostics** - mix xref and error messages improve codebase understanding
5. **Richer REPL experience** - IEx becomes more powerful for exploration and learning
6. **Unicode improvements** - Better internationalization support for global applications

This release set the stage for Elixir to be adopted more widely in enterprise environments where tooling consistency and clear upgrade paths are critical.
