# Changes from v0.14.1 to v0.14.2

## Release Information

**Date Range:** June 18 - June 29, 2014
**Total Commits:** 76 commits
**Release Date:** June 29, 2014

---

## Summary

Version 0.14.2 represents a significant maintenance and refinement release focused on language semantics improvements, performance optimization, and tooling enhancements. The release addresses several critical compiler issues, introduces new module metadata capabilities, and improves the build system's flexibility. While primarily a bug-fix and refinement release, it includes important language changes that affect core control flow constructs and operator handling.

---

## Major Features & Improvements

### 1. **`cond` Refactored as Special Form** ⭐
The `cond` construct was transformed from a macro into a special form in the compiler, preventing variable leakage from clause heads. This is a significant internal change affecting variable scoping semantics:
- **Commit:** `64f8541ee61a796d7ecd8782f5ef143e79eb728a`
- **Impact:** Improves correctness by preventing unintended variable bindings from guard conditions
- **Files Changed:** 13 files, ~50 insertions/deletions
- **Breaking Change (Semantic):** Code that relied on variable leakage from cond guards will no longer work

### 2. **New `@external_resource` Attribute** ✨
Introduces a new module attribute that allows declaring external dependencies for dependency tracking:
- **Commit:** `c8a0158791913d9d531542d86b178acf29669923`
- **Use Case:** Enables Mix to properly track when EEx templates, text files, or other external resources change, triggering recompilation
- **Files Changed:** 6 files including EEx and Module implementation
- **Benefit:** Improves incremental compilation and dependency tracking in Mix projects

### 3. **Performance: Iolist-Based String Operations**
Both `Enum.join/2` and `Enum.map_join/3` now use iolists instead of string concatenation:
- **Commit:** `5cee19067d6b6bf97d0022cab71b73fcb9313c71`
- **Benefit:** Significant performance improvement for large enumerations, reduces memory allocations
- **Implementation Detail:** Leverages Erlang's efficient iolist-to-binary conversion

### 4. **Archive Path Support in CLI Options**
Enhanced `-pa` and `-pz` command-line options to support paths inside archives:
- **Commit:** `fd9ca435b771c2e1748552e0d91fc4cca834b216`
- **Use Case:** Allows developers to reference code paths within .ez archives
- **Flexibility:** Better support for modular deployments and archive-based distributions

### 5. **MIX_ARCHIVES Environment Variable**
New environment variable for controlling the location of Mix archives:
- **Commit:** `02a415facdfc86373eebaf507b83061b291fd6d2`
- **Purpose:** Gives users more control over where Mix stores and searches for archives
- **Use Case:** Useful in restricted or non-standard filesystem configurations

### 6. **Typespec Compilation Timing Improvement**
Delayed typespec compilation to occur after module expansion:
- **Commit:** `587c83cbffc55dc11c92e2f3c6cd11766839c735`
- **Impact:** 394 lines of tests changed, significant refactoring
- **Benefit:** Allows type specifications to reference expanded/normalized forms of types, improving correctness

## Breaking Changes & Deprecations

### Breaking Language Changes

1. **`&` Operator Precedence Change** ⚠️
   - **Commit:** `b4415f2a14673f9651101b4dc3a1dd9d1611a518`
   - **Change:** & operator no longer special-cases the `/` operator
   - **Impact:** Code using capture syntax with division may be affected
   - **Example:** `&./2` parsing behavior changed

2. **Sigils Token Balancing Removed** ⚠️
   - **Commit:** `e5712189174919eadf7eeff4c0ceb0f334b22796`
   - **Change:** Sigils no longer require balanced start and end tokens
   - **Benefit:** More flexible sigil usage, especially with asymmetric delimiters
   - **Issue Closed:** #2284
   - **Note:** Simplifies interpolation handling significantly

3. **`cond` Variable Scoping (Semantic Change)** ⚠️
   - **Commit:** `64f8541ee61a796d7ecd8782f5ef143e79eb728a`
   - **Breaking:** Variables from cond guard expressions no longer leak into the body
   - **Migration:** Code relying on this undocumented behavior needs refactoring

### Soft Deprecations (Warnings Issued)

1. **EEx.TransformerEngine and EEx.AssignsEngine**
   - **Commit:** `5c7fdcc244fe47e022c99bb7f1ac0d4a7012941d`
   - **Status:** Soft deprecation with compatibility layer
   - **Timeline:** Will be removed in future version
   - **Alternative:** Use new EEx engine architecture

2. **Mix.Generator.from_file/1**
   - **Commit:** `a6b1cca91fefca3e0eaf1009bf3340c4d51985eb`
   - **Status:** Soft deprecation with migration path
   - **Reason:** Improved API in generator module

### Hard Removals

1. **--gen-debug Option Removed**
   - **Commit:** `4458ee12329fc13331f873420c50d5005366892d`
   - **Impact:** Mix no longer accepts this flag
   - **Status:** Was previously deprecated

2. **Previously Deprecated Behavior Removed**
   - **Commit:** `feb9cb645ed6f4199979e5fb9ff832b83c701a25`
   - **Scope:** Various deprecated functions and behaviors eliminated
   - **Note:** Reduces code bloat and inconsistencies

## Analysis & Key Themes

### 1. **Language Semantics Refinement**
This release focused heavily on fixing and clarifying language semantics. The transformation of `cond` into a special form and the change to `&` operator precedence represent careful refinements of core language behavior.

### 2. **Compiler Correctness**
Multiple bug fixes address compiler regressions and edge cases, demonstrating a focus on getting the generated code right. The typespec compilation timing change is particularly important for ensuring correctness of type information.

### 3. **Tooling Maturity**
Mix improvements (archive support, environment variables) and Windows compatibility work show investment in making Elixir a production-ready tool across platforms.

### 4. **Performance-Conscious Development**
The shift to iolist-based string operations demonstrates awareness of performance implications. This pattern of using intermediate representations for efficiency is characteristic of Erlang-style programming.

### 5. **Clean Deprecation Path**
Rather than sudden breaking changes, the project uses soft deprecations with clear migration paths, showing thoughtful API evolution and respect for existing codebases.

## Recommendation for Users

Users upgrading from v0.14.1 to v0.14.2 should:

1. **Test cond expressions** - Verify code relying on `cond` still works as intended
2. **Review `&` operator usage** - Check any code using capture syntax with `/`
3. **Verify Windows builds** - If on Windows, test the build system improvements
4. **Update deprecated usage** - Replace deprecated EEx engine and Mix.Generator.from_file usage
5. **Enjoy performance gains** - Benefits from iolist-based operations are automatic

This is a solid maintenance release that improves correctness and maintainability while laying groundwork for future improvements.
