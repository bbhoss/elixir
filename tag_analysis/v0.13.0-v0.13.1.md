# Changes from v0.13.0 to v0.13.1

## Release Timeline
- **v0.13.0 Release Date:** April 20, 2014
- **v0.13.1 Release Date:** April 27, 2014
- **Duration:** 7 days
- **Total Commits:** 70

This was a rapid patch release focused on stabilizing the newly released v0.13.0 and addressing critical bugs discovered early in the release cycle.

---

## Summary

v0.13.1 was a maintenance release addressing several important bugs and stability issues identified immediately after the v0.13.0 release. The main focus was on fixing compiler issues, improving Mix tooling integration with Hex, and refining recently introduced features. This release demonstrates the team's commitment to rapid iteration and quality assurance in the early days of Elixir development.

The release represents a shift toward stabilizing the Maps feature introduced in v0.13.0, improving the developer experience with better Mix tooling, and consolidating API changes around string/IO handling that began in earlier versions.

---

## Key Themes

### 1. **Critical Bug Fixes and Stability**
The v0.13.1 release addressed several critical issues that made v0.13.0 less stable:
- A compiler crash when handling certain map literal syntax
- An issue with variable scoping in comprehensions
- Windows compatibility issues in tests
- ExUnit doctest failure reporting

### 2. **Mix Ecosystem Improvements**
Significant effort was invested in improving Mix and its integration with Hex:
- Built-in Hex support (users no longer need separate Hex installation)
- New `mix iex` task for launching IEx with project context
- Improvements to dependency convergence algorithm
- Better error messaging and workflow

### 3. **API Modernization and Consolidation**
The release continued the v0.13.0 effort to modernize the Elixir API:
- Removal of deprecated record syntax from EEx and IEx engines
- Consolidation of string/binary/IO terminology (char data)
- Standardization of Regex behavior
- Simplification of API patterns (e.g., `iolist_*` to `iodata_*` naming)

### 4. **Deprecation Strategy**
The Elixir team introduced a pragmatic deprecation approach:
- "Soft deprecations" that don't emit warnings (backward compatible)
- Clear migration paths in documentation
- Focus on guiding users toward improved APIs without breaking existing code

## Major Features and Improvements

### Mix Enhancements

#### Hex Integration (Major)
- **What:** Built-in Hex support without requiring separate installation
- **Why:** Simplifies package management workflow for users
- **Impact:** Users now get prompted to install Hex when needed, making it transparent
- Commits: `c2c1ebde39`, `d8a24ba05a`

#### New `mix iex` Task
- **What:** Added a new Mix task to launch IEx with project context
- **Why:** Improves development workflow by automatically loading project code
- **Impact:** Developers can now type `mix iex` instead of manually configuring paths
- Commit: `651417a424`

#### Dependency Management Improvements
- Enhanced remote converger to properly handle package replacement messaging
- Added `top_level` field to `Mix.Dep` struct for better dependency tracking
- Improved remote converger to set children of dependencies correctly
- Commits: `1d12f3a1d0`, `26d2df6c5f`, `e667e2ec45`, `a1ff5b6440`

#### Configuration Enhancements
- **MIX_EXS Support:** Users can now override mix.exs file location via environment variable
- **Project Description:** Mix now uses `:description` from project configuration when available
- **Deprecated `:env`:** The `:env` configuration key is deprecated in favor of `MIX_EXS`

### File and IO API Standardization

#### Char Data Terminology (From v0.13.0 carried through)
- `File` and `IO` modules converted to use "char data" terminology
- New functions: `List.from_char_data!/1` and `String.from_char_data/1`
- The `+fnu` (fix null unicode) flag is now enabled by default
- **Impact:** Improves clarity and correctness when working with character streams vs binary data

### String Module Additions
- **New Function:** `String.split_at/3` - Splits a string at a specific position
- Provides convenient way to partition strings without using slicing

## Bug Fixes

### Critical Fixes

#### 1. Compiler Crash with Map Literals
- **Issue:** Certain map literal syntax caused compiler crashes
- **Fix:** Single character change in `elixir_map.erl`
- **Significance:** This was likely blocking users from using maps in certain patterns
- Commit: `c6dc65c418`

#### 2. For Comprehension Variable Scope Bug
- **Issue:** Comprehension arguments were not properly accounted for in variable scope
- **Fix:** Modified Erlang-level comprehension handling in `elixir_for.erl`
- **Impact:** Users could experience unexpected variable binding errors
- Commit: `4df91f14ee`

#### 3. Windows Test Compatibility
- **Issue:** Elixir tests were failing on Windows systems
- **Fix:** Enhanced `Path` module to better handle Windows-specific path handling
- **Significance:** Demonstrates early cross-platform development considerations
- Commit: `45427c3b33`

#### 4. ExUnit Doctest Failure Reporting
- **Issue:** Doctest failures were not being properly reported
- **Fix:** Improved doctest handling to catch and report failures correctly
- **Impact:** Users now see accurate test failure information
- Commit: `832405c2cf`

### Other Notable Fixes

- Fixed rebar error messages to be more helpful (`659a4794ed`)
- Fixed regression in deprecated function handling (`c7d96af2de`)
- Improved package replacement messaging in Mix (`e667e2ec45`)
- Fixed tabs vs spaces handling in heredocs (`31c34dc04e`)

## Breaking Changes

### Regex Behavior Changes
**Change:** Regexes are no longer unicode by default
- **Reason:** Unicode mode prevented matching against binary streams, as unicode expects valid UTF-8
- **Migration:** Users must explicitly add the `u` option to create unicode regexes
- **Impact:** Potential code breakage for users relying on implicit unicode behavior
- Commit: `ec776c7d68`

### Macro.unpipe/1 Signature Change
**Change:** `Macro.unpipe/1` now returns tuples instead of different format; `Macro.pipe/2` removed
- **New Signature:** `Macro.unpipe/3` explicitly expects the second element as a tuple
- **Reason:** Clearer semantics for pipe manipulation
- **Impact:** Code using the old pipe macros must be updated
- Commit: `915b8d60d1`

### Path Module Function Changes
**Changes:**
- Path functions now only return strings, regardless of input type (string or char list)
- Atoms are no longer supported in Path functions
- **Reason:** Simplify and standardize the API, removing deprecated patterns
- **Impact:** Code using atoms with Path or relying on output type matching input must be updated
- Commit: `45427c3b33`

### Record Removal from EEx and IEx
**Changes:**
- Records syntax removed from EEx template compiler
- Records syntax removed from IEx evaluator
- **Reason:** Part of deprecation push toward Maps as the primary composite data structure
- **Impact:** Code using records in templates/REPL may need refactoring
- Commits: `611bdbd0bc`, `0243bf1a40`

## Deprecations

### Soft Deprecations (No warnings emitted, but documented)
These are migration paths without immediate breaking changes:

1. **iolist_to_binary / iolist_size → iodata_to_binary / iodata_size**
   - More accurate terminology (iodata includes char lists and binaries)
   - Commit: `665c9b3117`

2. **String.to_char_list / String.from_char_list → char_data variants**
   - Better naming convention for string/character conversions
   - Aligns with new File/IO terminology

3. **Regex.groups/1 → Regex.names/1**
   - Clearer naming for getting named capture groups
   - Commit: `e8f976a007`

### Hard Deprecations (Configuration)
1. **:env in project configuration**
   - Deprecated in favor of environment-specific mix.exs handling
   - Commit: `89ab7a2bdf`

2. **ListDict**
   - Deprecated in favor of Map
   - Access for lists with non-atom keys deprecated
   - Commit: `7ccdb2ab29`

### Standards Adjustments
1. **function_exported?/3 with tuples**
   - No longer supports passing tuples as MFA format
   - Commit: `f932937928`

## Impact and Context

### Historical Context
This release occurred just one week after the major v0.13.0 release which introduced Maps and major API changes. The rapid turnaround indicates:

1. **Active Feedback Loop:** The team was receiving and responding to bug reports quickly
2. **Incomplete Testing:** Some bugs like the map literal compiler crash slipped through v0.13.0's testing
3. **Aggressive Development:** Multiple significant features (Hex integration) were added in the same release

### Developer Impact
For developers using v0.13.0, this patch was essential:
- **Must-have:** Map literal compiler crash fix
- **Recommended:** Comprehension scope fix for correctness
- **Important:** Mix improvements and Hex integration
- **Breaking:** Regex unicode changes required explicit updates for unicode-dependent code

### Migration Effort
Developers migrating from v0.12.x would have needed to address:
- Changes to `Macro.unpipe/1` and pipe handling
- Path module API changes
- Regex unicode handling
- Deprecation of ListDict and records
- File/IO API shifts to char data terminology

---

## Conclusion

v0.13.1 represents a focused maintenance release that stabilized v0.13.0 while continuing the platform's evolution toward a cleaner, more coherent API. The emphasis on bug fixes and developer experience (Hex integration, mix iex) demonstrates the team's commitment to both stability and usability. The breaking changes, while present, were largely confined to the deprecation paths established in v0.13.0, showing a deliberate strategy of API consolidation around Maps, char data terminology, and modern Erlang/OTP patterns.
