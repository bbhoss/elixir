# Changes from v1.8.1 to v1.8.2

## Release Timeline
- **v1.8.1 Released**: January 30, 2019
- **v1.8.2 Released**: May 11, 2019
- **Time Period**: ~3.5 months
- **Total Commits**: 7 (6 substantive commits + 1 release commit)

---

## Summary

Elixir v1.8.2 is a patch release focused on critical bug fixes and robustness improvements across core components. Rather than introducing new features, this release emphasizes stability and correctness, with particular attention to the Logger system, template engine (EEx), and compiler infrastructure. The changes reflect the Elixir team's commitment to preventing edge cases where the system could enter undesirable states or lose important metadata.

---

## Key Themes and Changes

### 1. **Logger Stability and Recovery**
The most significant change in this release addresses a critical issue in Elixir's Logger system. The Logger module introduced a "discard mode" in v1.8 as a safeguard—when the message queue grows beyond a threshold, Logger discards messages to prevent the system from being overwhelmed. However, a bug prevented Logger from properly exiting this mode even when queue pressure decreased.

This fix introduces a periodic check mechanism that actively monitors the message queue even while in discard mode, allowing the Logger to gracefully transition back to normal operation. This is particularly important for long-running production applications where temporary spikes in logging volume should not cause permanent behavioral changes.

### 2. **Enhanced Error Reporting in Distributed Systems**
Logger improvements extend to better handling of distributed Erlang systems. The translator now properly processes process crash messages that originate from remote nodes, ensuring that distributed debugging and error tracking are accurate and complete.

### 3. **Compiler Infrastructure Robustness**
Several fixes strengthen the compiler's ability to preserve important metadata and validate correctness:
- Protocols now ensure debug_info is always preserved, enabling better debugging support regardless of compile-time settings
- EEx (Elixir's template engine) now validates its internal state, catching subtle bugs in engine implementations or tools that extend it

## Bug Fixes

### Critical Fixes

**Make sure Logger v1.8 does not get stuck in discard mode (#9029)**
- **Severity**: High
- **Component**: Logger
- **Problem**: Logger could enter "discard mode" when message queue exceeded threshold, but would not automatically recover when queue pressure decreased. This could persist indefinitely, silently discarding important log messages.
- **Solution**:
  - Introduces new configuration option `discard_threshold_periodic_check` (default: 30 seconds)
  - When Logger enters discard mode, it now schedules periodic checks to evaluate if it can safely exit discard mode
  - State management refactored to centralize mode transition logic
  - Added comprehensive test coverage for recovery behavior
- **Impact**: Production systems can now recover from temporary logging spikes without manual intervention

### Quality of Life Fixes

**Ensure debug_info is kept in protocols (#8923)**
- **Component**: Compiler/Protocols
- **Problem**: Protocol modules would lose debug_info metadata when the compiler's `debug_info` option was disabled, even though this metadata is essential for protocol introspection and debugging
- **Solution**: Changed from `lists:keytake/3` to `proplists:get_value/3` to properly detect and preserve debug_info in protocol definitions
- **Impact**: Protocols now maintain debuggability regardless of global compiler settings; useful for tools and frameworks that inspect protocol implementations

**Raise on bad EEx state (#8790)**
- **Component**: EEx (Embedded Elixir)
- **Problem**: Invalid state in EEx.Engine could silently cause incorrect behavior in templates, making bugs difficult to diagnose
- **Solution**: Added `check_state!/1` validation function that verifies the engine state contains expected fields (`binary`, `dynamic`, `vars_count`)
- **Impact**: Template processing bugs are now caught immediately with clear error messages rather than causing subtle corruption

**Translate process crash on node in Logger (#9020)**
- **Component**: Logger
- **Problem**: Logger's translator couldn't properly handle process crash messages from remote nodes, losing context about where the crash occurred
- **Solution**: Added pattern matching for crashes that include node information in the error format
- **Impact**: Better error tracking and debugging in distributed Elixir systems

### Minimal Fixes

**Fix typo 'alwaus' -> 'always' (#8760)**
- Simple documentation/code comment correction with no functional impact

## Breaking Changes

**None**. This is a conservative patch release that maintains full backward compatibility.

However, note:
- New configuration option `discard_threshold_periodic_check` is added with a sensible default, so existing configurations will continue to work without changes
- The EEx state validation is a defensive measure that should only catch existing bugs, not introduce new failures in well-formed code

The most substantial change in this release. This commit:
- Refactors Logger.Config to extract `compute_mode_and_persist_state/2`
- Implements periodic checking via `handle_info/2` when in discard mode
- Ensures Logger can recover from temporary queue saturation
- 4 files changed, 68 insertions(+), 25 deletions(-)

if state.mode == :discard do

### 2. Protocol Debug Info Preservation (21f10f7296)
**Commit Date**: March 31, 2019

Addresses a subtle bug in how debug_info options are processed for protocols. By switching from `lists:keytake/3` to `proplists:get_value/3`, it ensures that:
- Explicit debug_info settings in protocol definitions are respected
- The compiler's global debug_info setting is used as a fallback only when no explicit setting is present
- 2 files changed, 19 insertions(+), 4 deletions(-)

### 3. EEx State Validation (153ec434de)
**Commit Date**: April 23, 2019

Adds runtime validation to the EEx.Engine to ensure it's always in a consistent state:
- Validates state during `handle_begin/1` and `handle_body/1`
- Provides a clear error message if state is corrupted
- Only 1 file changed (9 insertions), but significant for correctness
- 1 file changed, 9 insertions(+)

### 4. Distributed Logger Translation (fca5f1cf73)
**Commit Date**: May 7, 2019

Extends Logger's error translation capability to handle Erlang process crashes on remote nodes:
- Adds pattern matching for `{'Error in process ' ++ _, [pid, node, {reason, stack}]}`
- Properly extracts and formats node information in crash reports
- Maintains consistency with existing local crash translation
- 2 files changed, 26 insertions(+)

## Overall Assessment

v1.8.2 represents a mature approach to version management: focused on stability rather than feature growth. The fixes address real-world issues discovered in production usage of Elixir 1.8.1, particularly around:
- Long-running systems under load (Logger discard mode)
- Distributed applications (process crash translation)
- Compiler correctness (protocol metadata, EEx validation)

These changes strengthen Elixir's foundation for production use without requiring code changes from users. The patches are conservative, well-tested, and solve genuine pain points.
