# Changes from v0.12.3 to v0.12.4

## Release Information

- **Date Range**: February 2 - February 12, 2014
- **Total Commits**: 42
- **Tag Dates**: v0.12.3 (Feb 2, 2014) → v0.12.4 (Feb 12, 2014)

## Executive Summary

This release focused on **enforcing semantic versioning discipline across the build system**, **stabilizing dependency management**, and **preparing for Erlang 17.0 compatibility**. The changes represent a significant evolution in how Elixir handles version constraints and dependency compilation. This was a relatively active 10-day release cycle with critical improvements to the Mix build tool's dependency handling and broader ecosystem compatibility.

Key themes include:
- Strict semantic versioning (semver) enforcement in Version module
- Major refactoring of dependency compilation workflow
- Deprecations of older syntax patterns
- Erlang 17.0-rc1 compatibility work
- Various bug fixes and documentation improvements

## Major Features & Improvements

### 1. Semantic Versioning Enforcement (Breaking Change)

This release enforced **strict semantic versioning** across Elixir projects. This was a foundational change that affected how Mix and Version modules work:

- **"Only allow semver versions in Version"** and **"Only allow semver versions for mix projects"** commits represent a major policy shift
- Functions in the Version module that previously raised exceptions on invalid versions now return error tuples instead
- The Version interface was simplified, removing validation functions in favor of parsing functions that return error tuples
- `match?/2` and `compare/2` functions now only raise on parse errors; if given already-parsed versions/requirements, they won't raise
- Mix error messages were improved and now require proper capitalization
- The `:override` option now properly overrides version requirements

**Impact**: Projects using non-semver versions would need updates. This signals Elixir's commitment to discipline in dependency management.

### 2. Dependency Compilation Refactoring

A series of 5 commits addressed dependency compilation behavior, representing a fundamental shift in how dependencies are processed:

- **"Do not compile after deps.get and deps.update"**: Major behavior change preventing automatic compilation after fetching dependencies. This gives developers more control and prevents unexpected compilation during routine dependency updates.
- **"Mark dependencies as requiring compilation every time they are fetched"**: Ensures staleness tracking works correctly
- **"Compile dependencies when we can in deps.check"**: Optimizes the dependency checking task
- **"Ensure deps can run after mix deps.get"**: Fixes a critical issue where dependent tasks couldn't run after `mix deps.get`
- **"Fix dependency compilation order"**: Ensures proper ordering of compilation

**Impact**: Cleaner dependency management workflow with more predictable behavior. Fixes issues where transitive dependencies might be compiled out of order or when not needed.

### 3. Erlang 17.0-rc1 Compatibility

- **"Enable erlang 17.0 support and squelch some warnings"**: Core VM compatibility updates
- **"Add R16B03, R16B03-1 and 17.0-rc1 to .travis.yml"**: Extended CI matrix to test against new Erlang versions
- **"Fix test suite warnings on 17.0-rc1"**: Addressed specific warnings that appear only on Erlang 17.0-rc1 by adding indirection to prevent compiler optimizations that expose test code

**Impact**: Elixir is preparing for the next major Erlang version, showing forward compatibility focus.

### 4. Deprecation of Legacy Syntax

- **"Deprecate char lists in Regex"**: Signals move away from Erlang-style char lists in Regex operations
- **"Effectively deprecate // and deprecate ^ in anonymous function clause heads"**: Removing older operators/patterns
- **"Move to new sigils syntax"**: Transition to modern sigil syntax

**Impact**: Cleaning up legacy patterns to create a more consistent language experience.

## Breaking Changes

This release contains **at least one significant breaking change**:

1. **Semantic Versioning Enforcement**: Projects using non-semver version strings will break. The Version module no longer accepts non-compliant versions.

2. **CaptureIO Return Value**: Code explicitly checking for `nil` from `CaptureIO.capture_io/1` when no output is produced will change behavior (now returns `""`).

3. **Dependency Compilation Behavior**: The removal of automatic compilation after `deps.get` and `deps.update` may require workflow adjustments in build scripts or tooling that depends on this behavior.

4. **Error Handling in Version**: Code catching exceptions from Version module functions may need updates to handle error tuples instead.

5. **Regex Char Lists**: Use of Char lists in Regex operations is now deprecated and will show warnings.

## Technical Insights

### Design Philosophy Evident in Changes

1. **Error Handling Consistency**: Moving from exceptions to error tuples in Version module aligns with Elixir's functional approach to error handling.

2. **Workflow Clarity**: Removing automatic compilation after `deps.get` follows the Unix principle - "do one thing and do it well." Developers now have explicit control.

3. **Version Discipline**: Enforcing semver signals maturity and consistency across the ecosystem. This prevents subtle version matching bugs.

4. **Backward Compatibility Priority**: Despite breaking changes, most are for deprecated features or edge cases. The release aims for smooth migration paths.

### Code Quality Focus

- Multiple commits addressing Dialyzer warnings and type specs
- Systematic deprecation of legacy patterns before removal
- Comprehensive test suite updates to support new Erlang versions
- Documentation improvements alongside code changes

## Migration Path for Users

For developers upgrading from v0.12.3 to v0.12.4:

1. **Update version strings** in `mix.exs` to semver format (e.g., "1.2.3" instead of "1.2")
2. **Review version specifications** in dependency lists
3. **Update any version comparison code** to handle error tuples instead of exceptions
4. **Adjust build workflows** if you relied on automatic `deps.get` compilation
5. **Update tests** that check for `nil` from CaptureIO
6. **Remove deprecated Regex char list usage**

## Conclusion

Version 0.12.4 represents a maturing platform with stronger discipline around versioning and dependency management. The changes lay groundwork for more predictable builds and better ecosystem health. While breaking in a few areas, the changes are well-motivated and support long-term maintainability.
