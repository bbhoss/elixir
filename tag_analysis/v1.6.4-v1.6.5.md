# Changes from v1.6.4 to v1.6.5

## Release Overview

**Date Range**: March 26, 2018 to May 7, 2018 (42 days)
**Total Commits**: 27 commits (excluding release commits)
**Release Date**: May 7, 2018

This release focuses on bug fixes, improved code formatting behavior, and compatibility with Erlang/OTP 21. It's primarily a maintenance release addressing issues discovered in v1.6.4 rather than introducing major new features.

---

## Summary of Key Themes

v1.6.5 is a **bug fix and compatibility release** addressing several important issues:

1. **Code Formatter Intelligence**: Two significant commits improve how the formatter respects user formatting choices in specific scenarios
2. **OTP 21 Compatibility**: Critical fixes for logger and stacktrace handling to eliminate warnings on Erlang/OTP 21
3. **Kernel Robustness**: Several improvements to core language features (guard clauses, comprehensions, typespecs)
4. **Documentation Improvements**: Clarifications and corrections throughout the documentation
5. **Supervisor Process Safety**: Improved handling when parent processes die during task spawning

---

## Major Features & Improvements

### 1. Code Formatter Enhancement (User Choice Preservation)
- **Commits**:
  - `a0d5c4f4fb` - Keep the user's choice on parens call with next break fits
  - `984495fd90` - Preserve user choice on calls without parens when we have one arg per line

**Impact**: These two commits address a critical usability issue where the formatter would reformat code against the developer's explicit formatting preferences. The fixes ensure that:
- When using parentheses in function calls with the "next break fits" strategy, user formatting is preserved
- When using function calls without parentheses with one argument per line, the formatter respects the original layout

This is particularly important for developers who have strong stylistic preferences and rely on the formatter to maintain consistency without overriding their choices.

### 2. Task API Enhancement
- **Commit**: `4f634bd244` - Support infinity timeout on yield_many

**Details**: Extends `Task.yield_many/2` to support `:infinity` as a timeout value, matching the behavior of other timeout-accepting functions in Elixir. Previously, only numeric timeouts were supported.

**Use Case**: Allows waiting indefinitely for task completion without having to repeatedly poll or handle timeout edge cases.

### 3. New Mix API
- **Commit**: `e13c944ba4` - Add Mix.Tasks.Format.formatter_opts_for_file/2

**Impact**: Provides a programmatic way to retrieve formatter options for a specific file. This enables better tool integration and allows developers to programmatically determine which formatter options apply to a file without manual parsing of mix.exs.

### 4. Enhanced Deprecation Tracking
- **Commit**: `8e1ebafebc` - Add missing deprecations in v1.4

**Purpose**: Ensures proper deprecation warnings are shown for features deprecated in v1.4, improving the upgrade path for users migrating from older versions.

## Bug Fixes

### Code & Tokenization Issues

1. **Formatter with Bitstrings** (`718123157c`)
   - Fixed a bug where the formatter would incorrectly handle tilde (~) characters in the first element of bitstrings
   - This was preventing proper bitstring formatting in certain edge cases

2. **Heredoc Tokenizer Column Counting** (`6a0e9390a2`)
   - Fixed incorrect column count calculation in the tokenizer for heredoc strings
   - This bug could cause incorrect error reporting and editor position issues

3. **Sigil Modifier Tokenization** (`f6b0855d31`)
   - Fixed column position tracking in the tokenizer when sigils have modifiers (e.g., `~r/pattern/imx`)
   - Ensures accurate error messages and IDE integration

4. **Macro.to_string/2 Validity** (`8e6cc2c74d`)
   - Fixed an issue where `Macro.to_string/2` could produce invalid quoted expressions
   - Ensures round-trip conversion of AST to strings and back is reliable

### Kernel & Guard Clauses

5. **Hygienic Variables in defguard** (`705a637acf`)
   - Fixed handling of hygienic variables (those beginning with underscore) in `defguard`/`defguardp` definitions
   - Prevents unexpected variable capture and scope issues

6. **Spec Clauses with specsdiff** (`d59c801f33`)
   - Added support for the `specsdiff` flag on `__info__` spec clauses
   - Important for dialyzer and spec checking tools

### Concurrency & Supervision

7. **Task Supervisor Process Death Handling** (`a89e656a65`)
   - Fixed crash when spawning supervised tasks when the parent process dies
   - Improves robustness of the supervision tree by gracefully handling race conditions

8. **DynamicSupervisor Type Specification** (`f663b2e0de`)
   - Corrected typespec for `DynamicSupervisor.on_start_child/2`
   - Ensures proper type checking and documentation accuracy

### URI Parsing

9. **URI Query Parsing** (`65f1b2df1e`)
   - Fixed parsing of queries with just "?" in `URI.parse/1`
   - Edge case that could cause parsing failures for minimal query strings

### Warnings & Compatibility

10. **Capture Operator Warnings** (`ccc24ea5b2`)
    - Fixed warnings related to the capture operator (e.g., `&Function.func/1`)
    - Prevents spurious compiler warnings

11. **Logger & Stacktrace Warnings on OTP 21** (`f4b6375125`)
    - Critical compatibility fix for Erlang/OTP 21
    - Fixes warnings in the logger application and stacktrace handling
    - Affects multiple OTP compatibility layers

### Comprehension Improvements

12. **Bitstring Comprehension Metadata** (`e6c893cf89`)
    - Marks `for/1` comprehension clauses with bitstrings as generated
    - Prevents dialyzer warnings about generated code in comprehension patterns

## Notable Commits & Architecture Changes

### High-Impact Commits

1. **`f4b6375125` - Logger and OTP 21 Warnings Fix**
   - This is arguably the most important fix in the release
   - Addresses warnings in the logger application when running on Erlang/OTP 21
   - Changes:
     - Modified `elixir_erl_compiler.erl` to handle OTP 21 compatibility
     - Enhanced `Logger.Watcher` to properly manage deprecation and new APIs
     - Updated `Logger.app` configuration for better OTP 21 support
   - Ensures a smooth path for users upgrading to OTP 21

2. **`8291c2f795` - Task.Supervisor Independence**
   - Changed `Task.Supervisor` to not depend on `Supervisor.start_child`
   - Creates a more resilient spawning mechanism that doesn't crash when parent dies
   - Combined with `a89e656a65`, provides comprehensive fix for process death handling

3. **`984495fd90` & `a0d5c4f4fb` - Formatter User Choice Preservation**
   - These back-to-back commits represent an important philosophy shift in the formatter
   - Shows commitment to respecting developer intent rather than enforcing rigid style
   - Likely based on community feedback about formatter behavior

### Refactoring & Internal Improvements

- **`6b74116cb0` - Test Cleanup**: Removes namespaces from module names in defguard tests (cleanup before public fixes)
- **`510ac444e3` - Feature Completeness**: Adds the missing `discard_threshold` option to ensure API consistency
