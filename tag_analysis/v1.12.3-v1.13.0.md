# Changes from v1.12.3 to v1.13.0

## Overview

This document analyzes the 611 commits between Elixir v1.12.3 (released September 5, 2021) and v1.13.0 (released December 3, 2021), representing approximately 3 months of intensive development and improvements to the Elixir language and tooling.

**Date Range:** September 5, 2021 - December 3, 2021
**Total Commits:** 611
**Development Duration:** ~3 months

## Summary

v1.13.0 is a significant release focused on enhancing the compiler infrastructure, improving the developer experience through better error messages and IDE support, expanding the standard library with new utility functions, and upgrading dependencies. The release maintains backward compatibility for most use cases while introducing several deprecated features slated for removal in future versions.

### Key Statistics
- **91** commits introducing new features and functions
- **114** commits fixing bugs
- **6** deprecation-related commits
- Major themes: Compiler improvements, error/warning enhancements, standard library expansion, Mix tooling improvements, and Unicode database updates

## Major Features and Improvements

### 1. Compiler and Macro Infrastructure Enhancements

The v1.13 release significantly strengthened the compiler and macro system with several important additions:

- **Macro.prewalker/1 and Macro.postwalker/1**: Added new AST traversal utilities enabling post-order tree walking in macro code, providing more flexibility for developers who need to process Elixir's abstract syntax trees.

- **Code.Fragment API Expansion**: Added `Code.Fragment.container_cursor_to_quoted/2` and `Code.Fragment.surround_context/3` to improve IDE integration and code completion capabilities. These functions enable better understanding of code context for tools like language servers and editors.

- **Improved Module Reflection**: Added `Module.attributes_in/1`, `Module.overridables_in/1`, and record reflection capabilities, providing developers with better introspection tools for understanding module definitions.

- **Module Tracking for Compiler**: Enhanced the compiler to track module removals and dependencies removals, improving recompilation accuracy and reducing unnecessary rebuild cycles.

- **Compilation Tracer Improvements**: Added `{:on_module, bytecode, :none}` to compilation tracers, allowing developers to hook into the compilation process with more granularity.

### 2. Standard Library Expansion

The standard library received several important additions:

- **New Functions**:
  - `Enum.slide/3`: Slides elements within a range to a new offset, with support for positive/negative ranges
  - `Map.filter/2` and `Map.map/2`: New filtering and mapping functions for maps
  - `Keyword.filter/2` and `Keyword.map/2`: Corresponding functions for keyword lists
  - `URI.new/1` and `URI.new!/1`: Constructor functions for creating URI structs with validation
  - `Mix.installed?/0`: Check if Mix is installed and available
  - `Task.completed/1`: Query if a task has completed
  - `List.keyfind!/3`: Non-optional variant of keyfind that raises if no match found

- **Power Operator**: Added the `**` power/exponentiation operator for numeric computations, complementing existing arithmetic operators.

- **Calendar.ISO Enhancements**:
  - Improved and added specifications to `Calendar.ISO.parse_*/1` and `Calendar.ISO.parse_*/2` functions
  - Changed `Calendar.year_of_era/1` callback to `/3` for greater flexibility
  - Added specs and improved guards across the module

- **I/O and Stream Functions**:
  - `IO.stream/0` and `IO.binstream/0` as convenience functions for creating streams from standard I/O
  - Return `:eof` for `read(dev, :eof)` when no data is available
  - Allow `:eof` as a valid argument to `IO.getn/2`

- **Process and Task Improvements**:
  - Added more variants to `Process.spawn_opt` type specifications
  - Added guards to `IO.puts/2` and `IO.inspect/3`
  - Optimized `Enum.zip/2` and `Enum.concat/1` with improved algorithms
  - Reduced memory usage in `Enum.flat_map`

### 3. Error Messages and Developer Experience

Significant improvements to error reporting make debugging easier:

- **Error Context and Code Snippets**: Compiler now shows code snippets alongside syntax and token missing errors, making it immediately clear where problems occur in source files.

- **Column Information**: Expanded inclusion of column numbers in compiler warnings and error messages, enabling more precise error location pinpointing. This improvement is critical for IDE integration.

- **Better Error Messages**:
  - Improved error messages when applying non-function values with `apply/3`
  - Better error messages for invalid Mix aliases
  - Better error messages when arguments are reordered in `List` functions
  - Hints for comparing different but equivalent strings
  - Expanded error context for struct field errors in typespecs

- **Warning Improvements**:
  - New warning for trailing commas on function calls
  - Warning when invalid ASCII escapes are used (with proper suggestions)
  - Warning for bidirectional formatting characters that could indicate security issues
  - Warnings when `@callback`, `@macrocallback`, and `@optional_callbacks` are defined inside protocols (where they don't belong)

### 4. IEx and Interactive Development

Enhanced the interactive Elixir experience:

- **Struct Field Autocompletion**: Added automatic suggestion of struct fields during interactive development, reducing manual typing and improving discoverability.

- **Improved Autocompletion**:
  - Added sigil completion to code fragments
  - Better handling of module attributes in autocompletion
  - Path autocompletion on Windows systems
  - Fixed autocompletion with atoms containing `@` symbol

- **IEx Protocol**: Added documentation to the `IEx.Info` protocol, making it easier for library developers to customize how their types display in IEx.

- **HTML Format Support**: IEx now supports `<b>` and `<strong>` tags in Erlang HTML-formatted documentation.

- **Bug Fixes**: Fixed `.iex.exs` loading after pry sessions and improved IEx path autocompletion.

### 5. Mix Tooling Improvements

The Mix build tool received several improvements:

- **Mix.install/2 Enhancements**:
  - Added `:config` and `:system_env` options for runtime dependency installation
  - Added `:elixir` option to specify Elixir version requirements
  - Added recovery from `deps.get` failures
  - No longer reinstalls dependencies when called with same arguments
  - Improved error messaging and limitations documentation
  - Environment variables no longer stored in config on Mix.install/2 eval

- **New Mix Functions and Features**:
  - `Mix.installed?/0`: Check if Mix is available
  - `MIX_INSTALL_FORCE` environment variable support for forcing reinstallation
  - `--if-missing` option for `mix local.rebar`

- **Dependency and Compilation Improvements**:
  - Track transitive runtime dependencies from local dependencies
  - Semantic recompilation checkpoints to reduce redundant builds
  - Better handling of Rebar3 deps with `:subdir` option support
  - Only recompile necessary files when config/lock files change
  - Recompilation of only recently modified files first

- **xref Tool Enhancements**:
  - `mix xref graph` now supports `--label=compile-connected` for showing compile-time dependency edges
  - `mix xref trace` shows all dependencies for a given file
  - `--fail-above` option to fail builds when complexity exceeds threshold
  - `--exclude` option to ignore specific dependencies
  - Improved error handling and validation

### 6. Code Formatting and Normalization

The code formatter received several refinements:

- **Formatter Plugin Support**: Added support for custom formatter plugins, enabling libraries to extend the formatter with custom rules.

- **Sigil Formatting**:
  - Support for custom sigil formatting through `Code.format_string!`
  - Improved handling of uppercase sigils
  - Sigil modifiers and properties properly passed through to formatter
  - Support for escaping terminators in uppercase sigils heredocs

- **Normalization Improvements**:
  - Fixed normalization of keyword lists in blocks
  - Preserves user choice on module attribute lists
  - Keyword format preservation for tuple last elements
  - Proper handling of partial keyword list elements

- **Exposed Formatter Functions**: Code module now exposes `Code.quoted_to_algebra/2` and related formatter functions for library developers.

- **Better Formatting Behavior**:
  - Uses keyword syntax by default in tuple formatting
  - Handles EEx expressions where `->` is followed by newline
  - Respects keywords in access syntax during formatting

### 7. Unicode and Internationalization

- **Unicode Database Upgrade**: Upgraded to Unicode v14.0.0, providing support for the latest character classifications and properties.

- **Unicode Processing Optimization**: Grouped Unicode upcase/downcase operations by prefix to reduce memory footprint by approximately 33%.

- **Better Unicode Handling**: Improved handling of NFD (Canonical Decomposition) cluster columns and initial string positions.

## Breaking Changes and Deprecations

While v1.13 maintains strong backward compatibility, several items have been deprecated:

### Deprecations
1. **env options in eval functions**: Options `:env` in `Code.eval_string/3`, etc. are deprecated in favor of explicit bindings.

2. **!= and ! version requirement operators**: These operators in version requirements are deprecated, with proper operators (`<` or `>`) recommended instead.

3. **System.get_pid/0**: Hard-deprecated (was already soft-deprecated) - use alternative system introspection methods.

### Breaking Changes (Minimal)
1. **Calendar.year_of_era/1 callback signature**: Changed from `/1` to `/3` - affects protocol implementations only.

2. **Exit Status for Test Failures**: Changed exit status from 1 to 2 when test suite fails (`mix test`), allowing distinction from other error conditions.

3. **Test Partition Behavior**: `MIX_TEST_PARTITION` is now ignored when partitions are set to 1.

### Code to be Removed
- Code annotated for removal on Erlang/OTP 24+ (deprecation in preparation)

## Themes and Insights

### 1. **Developer Experience as Priority**
The most significant theme is the focus on improving the developer experience. Better error messages with code snippets, improved autocompletion, IDE support through expanded Code.Fragment APIs, and clearer compiler output demonstrate Elixir's commitment to helping developers write better code faster.

### 2. **Compiler Robustness**
v1.13 makes the compiler more intelligent about what needs to be recompiled. Tracking module removals, handling dependency changes, and checkpointing compilation state all work together to speed up incremental builds—a critical concern for large projects.

### 3. **Standard Library Maturity**
The additions of `Enum.slide/3`, `Map.filter/2`, `URI.new/1`, and others show the standard library continuing to evolve based on real-world usage patterns. These are solid, useful functions that many developers have implemented themselves.

### 4. **Unicode and Global Support**
The upgrade to Unicode v14.0.0 and optimization of Unicode processing demonstrates Elixir's commitment to first-class support for international users and text processing.

### 5. **Mix as a First-Class Tool**
Mix.install/2 enhancements, new Mix functions, and xref improvements show that Mix continues to be a central focus, with features that support modern development workflows like dynamic dependency installation.

### 6. **Backward Compatibility**
While several features are deprecated, there are very few breaking changes. The team clearly prioritizes stability and gradual migration paths for users.

### 7. **Community Contribution**
The diverse set of contributors (José Valim, Wojtek Mach, and many community members) across 611 commits shows active community participation in language development.

## Conclusion

Elixir v1.13.0 represents a mature, well-rounded release focused on refinement rather than radical change. The improvements to the compiler infrastructure, error messages, and standard library make Elixir more pleasant to use while maintaining the language's core values of productivity and reliability. The emphasis on performance optimization and better IDE support signals the project's awareness of Elixir's use in larger, more complex applications.

For most Elixir users, v1.13.0 is a smooth upgrade with immediate benefits in developer experience and no significant friction from breaking changes.
