# Changes from v0.10.1 to v0.10.2

## Overview

- **Release Date**: August 3, 2013 to September 3, 2013
- **Total Commits**: 270
- **Version**: v0.10.2-dev to v0.10.2

This release represents a significant evolution of Elixir during the middle of 2013, with a focus on enriching the standard library, improving performance, and establishing cleaner APIs through strategic deprecations.

---

## Summary

v0.10.2 is primarily a feature and refinement release focused on three main areas:

1. **Standard Library Expansion**: Major additions to Enum, Stream, String, and List modules with new functions and operations
2. **API Cleanup and Normalization**: Strategic deprecations moving towards more consistent and intuitive APIs
3. **Bug Fixes and Stability**: Important fixes for Stream operations, documentation, and edge cases
4. **Developer Experience**: Improvements to IEx, Mix tooling, testing frameworks, and error messages

The release demonstrates a maturing standard library with careful attention to naming conventions, function placement, and backward compatibility through deprecation warnings.

---

## Major Features and Improvements

### Enumerable Operations Expansion

This release significantly enhances collection handling with new functions:

- **Enum.concat/1,2**: New functions for concatenating enumerables, replacing List.concat. This represents a strategic move to make enumerable operations available across all collection types.
- **Enum.flat_map/2**: Flattening and mapping in a single operation, commonly used for expanding nested collections.
- **Enum.slice/3**: Extract a slice from a collection by index and length.
- **Enum.chunks/2**: Divide collection into fixed-size chunks (with Enum.chunks_by variant for custom grouping).
- **Enum.reduce/2**: Variant that uses the first element as the initial accumulator value, simplifying common reduce patterns.
- **Negative index support** for Enum.at/2, Enum.fetch/2, and Enum.fetch!/2, allowing counting from the end of collections.

**Stream Enhancements:**
- **Stream.concat/1,2**: Lazy equivalent of Enum.concat
- **Stream.flat_map/2**: Lazy flat mapping operation
- Important fixes for Stream.Lazy nesting and Stream.take/Stream.take_while operations to properly handle lazy evaluation

### String Processing and Formatting

Significant improvements to string manipulation:

- **String justification functions**: New ljust/2 and rjust/2 functions for left and right justification with padding characters
- **String.replace regex support**: Extended String.replace/3 to accept regex patterns, not just literal strings
- **Trim options in splitting**: Both String.split/3 and Regex.split/3 now accept a `trim` option to remove empty results
- **Unicode support in strip**: String.strip functions now handle unicode characters for removal
- **Encoding function renames**:
  - String.to_char_list/1 (replacing unicode to list conversion)
  - String.from_char_list/1 (replacing list to unicode conversion)
  - Macro.unescape_string/1 (replacing Macro.unescape_binary)

**URI/IPv6 Support:**
- Enhanced URI parsing to handle IPv6 addresses, including embedded IPv4 addresses within IPv6 format

### Integer Module Enhancements

- **is_odd/1 and is_even/1** functions moved from their previous location to the Integer module, establishing a cleaner namespace for numeric operations

### List Module Updates

- **List.replace_at/3**: New function to replace an element at a specific index, with support for negative indices
- Deprecation of List.concat/1,2 in favor of Enum.concat operations

### Macro and Quote System Improvements

- **Macro.to_string/2**: New function to convert AST back to source code strings
  - Improved handling of binary operators with better parenthesization
  - Better rendering of access patterns and keyword lists
- **Macro.escape improvements**: Now handles improper lists like [1|2]
- **Function identifiers as variables**: Allow function identifiers (like :mod.fun/2) to be used as variable names

### Regular Expression Improvements

- **Regex.compile error handling**: Explicit error returns for unsupported options, improving debugging
- **Erlang options support**: Allow passing Erlang regex options when compiling Elixir regexes

### IO Module Expansion

- **IO.stream/2 and IO.binstream/2**: New functions accepting additional options, replacing single-arity variants
  - Old IO.stream/1 and IO.binstream/1 marked as deprecated but still functional
- **Improved documentation** for iolist_to_binary and related functions

### IEx (Interactive Elixir) Improvements

- **IEx.Autocomplete rewrite**: Complete rewrite to work on string-based completions
- **h helper enhancements**: Support for string arguments in the help system
- **Erlang source support**: IEx helpers `r` and `c` can now reload and compile Erlang sources, not just Elixir
- **Documentation**: Better documentation for various helpers and options

### Mix and Compilation Improvements

- **OptionParser refactoring**: Permanent invalid option list handling for more consistent behavior
- **Compiler manifest changes**: Rename "manifest" to "manifests" to support compilers with multiple manifest files
- **Silent compilation mode**: elixirc now suppresses 'Compiled' messages by default with --docs flag behavior
- **Version-based recompilation**: Projects are now recompiled if the Elixir version changes
- **Dependency tracking improvements**: Better tracking of dependency changes with .compile.deps flag
- **Mix clean --all flag**: Better support for cleaning all artifacts including dependencies

### Process and System Functions

- **Process.info improvements**: Now returns nil instead of :undefined for consistency
- **Process.whereis documentation**: Clarified documentation
- **System.get_env/0 improvements**: More sane behavior when retrieving all environment variables
- **File.rm_rf improvements**:
  - Better error handling without stacking errors
  - Windows symlink detection support

### ExUnit Testing Framework

- **Failure reporting**: Print failures as soon as they occur during test runs
- **ExUnit.ExpectationError**: More semantic naming for expectation errors
- **DocTest enhancements**:
  - Support for testing indentation issues in docstrings and heredocs
  - Better handling of indentation mismatches

### Path and File Handling

- **Path.relative_to_cwd**: New function to get paths relative to the current working directory
- Better stacktrace generation using relative paths
- Improved file operations with better error semantics

### Exception Handling

- **Clean exception API**: Expose more complete API in Exception module
- Better handling of unsafe variables in or/and expressions
- Improved error messages for various scenarios

## Breaking Changes and Deprecations

### Deprecations (Backward Compatible)

1. **List.concat/1,2** → Prefer **Enum.concat/1,2**
   - Allows enumerable operations across all collection types
   - More consistent with Elixir philosophy

2. **%b and %B formatters** → Use **%s and %S** instead
   - Cleaner formatting syntax
   - Aligns with other formatter naming

3. **to_binary/1** → Use **to_string/1**
   - More semantically correct for string conversion
   - Unifies binary and string concepts

4. **Enum.min/2 and Enum.max/2** → Use **Enum.min_by/2 and Enum.max_by/2**
   - More explicit about using a function to derive comparison value
   - Avoids confusion with simple min/max operations

5. **Dict.update/3** → Use **Dict.update!/3**
   - More explicit about potentially raising exceptions
   - Better error handling semantics

6. **def/4 and friends** → Use **def/2 with unquote and friends**
   - Simplifies the macro system
   - More consistent with meta-programming patterns

7. **IO.stream/1 and IO.binstream/1** → Use **IO.stream/2 and IO.binstream/2**
   - Extended versions with options parameter
   - Better flexibility in stream configuration

8. **:umbrella path option in Mix** → Use **:in_umbrella**
   - Better semantic naming
   - Clearer intent in configurations

### Potentially Breaking Changes

1. **String splitting behavior**: No longer trims by default when splitting strings (option available)
2. **Regex.compile error handling**: Now returns errors for unsupported options instead of failing silently
3. **Process.info return values**: Returns nil instead of :undefined (more Elixir-idiomatic)

## Migration Guide for Users

Users upgrading from v0.10.1 to v0.10.2 should:

1. **Update deprecated functions**:
   - Replace List.concat with Enum.concat
   - Replace %b/%B formatters with %s/%S
   - Replace to_binary with to_string
   - Update Enum.min/max calls to use _by variants if applicable

2. **Test Stream operations**: Verify streaming code works with fixes, particularly Stream.take operations

3. **Update string splitting**: If relying on trim behavior, explicitly pass trim option

4. **Verify Mix projects**: Projects should automatically recompile on Elixir version changes

5. **Update IEx workflows**: New string support in help system and Erlang source handling

## Conclusion

v0.10.2 represents a significant maturation of Elixir's standard library and tooling. The release focuses on:

- **Completeness**: Major additions to enumeration, string handling, and list operations
- **Consistency**: Strategic deprecations toward more uniform APIs
- **Stability**: Important fixes for stream operations and edge cases
- **Usability**: Better developer experience through improved error messages and documentation

The release demonstrates thoughtful API design with careful attention to backward compatibility through deprecation warnings rather than breaking changes. The strategic movement of operations from List to Enum reflects a deeper understanding of functional programming patterns and encourages more polymorphic, composition-friendly code.
