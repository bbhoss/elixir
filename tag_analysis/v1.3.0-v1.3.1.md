# Changes from v1.3.0 to v1.3.1

## Overview
- **Date Range**: June 21-28, 2016
- **Total Commits**: 21
- **Duration**: 7 days
- **Release Date**: June 28, 2016

This was a rapid patch release focusing on bug fixes, OTP 19 compatibility, and minor enhancements.

## Summary

v1.3.1 is a patch release that addresses several critical bugs discovered after v1.3.0. The primary focus was on compatibility with OTP 19, fixing struct-related issues in the compiler, and improving error messages and helper functions. The release contains no breaking changes but does improve error handling in GenServer and provides better validation in the application compilation process.

## Major Changes and Themes

### OTP 19 Compatibility
A significant portion of this patch was dedicated to ensuring Elixir works properly with OTP 19, released in June 2016. This included:
- Fixing callback-related tests to use BEAM AST instead of runtime inspection
- Fixing invalid function call warnings that appeared on OTP 19
- Skipping dialyzer-related tests on OTP 19
- Fixing the IEx `h` helper to work correctly with OTP 19's new introspection capabilities
- Improving IEx h helper tests for multi-arity callbacks

The OTP 19 work demonstrates the responsiveness needed for Elixir to stay compatible with Erlang/OTP updates.

### Struct-Related Fixes
Two critical fixes addressed struct handling:

1. **Struct Announcement Deadlock** (#4844): Fixed an issue where structs could be announced too early (only when `__struct__/0` was defined but not `__struct__/1`), leading to deadlocks in the compiler. The fix ensures structs are announced properly to avoid future similar issues.

2. **Struct Expansion in Dynamic Module Names** (#4894): Ensured that structs can be properly expanded when used in dynamic module names, which is important for metaprogramming scenarios.

### Module and Type System Improvements

**Support for Module Attributes in Remote Types** (#4891): Added support for using module attributes in remote type specifications, such as `@for.t` in protocols or similar use cases. This enables more flexible type definitions and is useful for advanced metaprogramming patterns.

**LexicalTracker Import Fix** (#4871): Fixed `Kernel.LexicalTracker` not to discard alias directives on import, preventing incorrect compiler behavior when importing modules with aliases.

### IEx and Developer Tools Enhancements

1. **Import File If Available** (#4878): Added new `import_file_if_available` helper function to IEx, allowing conditional file imports without errors if the file doesn't exist. This complements the existing `import_file` function.

2. **Import If Available Helper** (#4877): Added `IEx.Helpers.import_if_available/2` function to safely import modules that may not be available, improving the interactive development experience.

3. **Binary Operator Help** (#4859): Fixed the `h` helper to properly display documentation for binary operators, improving discoverability in IEx.

### Mix and Build System

**XREF Optimization**: Changed XREF analysis to not load modules into memory, instead using BEAM file information directly. This is a performance improvement that reduces the overhead of running the `mix xref` task.

**Application Properties Validation** (#4873): Added validation of application properties before altering them during compilation, catching configuration errors earlier in the build process.

**Mix Do Command Reversion** (#4893): Reverted a recent change to the `mix do` task to enforce space after commas, maintaining backward compatibility in command syntax.

## Features and Improvements

### New Features
- `IEx.Helpers.import_if_available/2` - Safely import modules that may not be available
- `import_file_if_available` - Conditional file importing in IEx
- Support for module attributes in remote types (e.g., `@for.t`)

### Error Handling Improvements
- **GenServer.reply Error Detection** (#4876): Now generates an error if no valid PID is given to `GenServer.reply/2`. Previously, any two-tuple could be passed and would silently fail, leading to hard-to-debug issues. This is an important improvement for catching typos and incorrect usage patterns.
- **Improved Error Messages**: Better error message for `with/else` on invalid form
- **Clarified Deprecation Messages**: Clarified `Enum.group_by/3` deprecation message to guide users to the replacement API

### Performance and Optimization
- XREF no longer loads modules, instead using BEAM metadata directly
- More efficient struct announcement process to prevent deadlocks

## Breaking Changes

**None**. This is a pure patch release with no breaking changes. The GenServer.reply error detection is a strict improvement that will catch bugs rather than hide them, but won't break correctly-written code.

## Test Coverage Updates

Significant test improvements and fixes:

- Updated behavior and protocol tests for OTP 19 compatibility
- Added tests for new module attribute in remote types feature
- Enhanced IEx helper tests for multi-arity callbacks
- Added tests for GenServer.reply validation

## Notable Technical Details

1. **BEAM Metadata Instead of Module Loading**: The xref optimization shows Elixir's evolution toward more efficient tooling by leveraging BEAM file information directly rather than loading modules into memory.

2. **Struct Announcement Improvement**: The fix demonstrates the compiler's complexity - ensuring the right order of operations during the macro expansion phase to prevent deadlocks.

3. **Type System Enhancement**: Support for module attributes in remote types expands the expressiveness of Elixir's type system, particularly useful in protocol definitions.
