# Changes from v1.4.2 to v1.4.3

## Release Overview

**Date Range:** February 16, 2017 - May 15, 2017
**Total Commits:** 28
**Release Date:** May 15, 2017

This release represents a focused effort on achieving full compatibility with Erlang OTP 20-rc.1, with particular emphasis on removing regex dependencies and addressing compatibility issues with the upcoming OTP release.

## Executive Summary

Elixir v1.4.3 is primarily a **compatibility and stability release** focused on preparing the Elixir ecosystem for Erlang OTP 20. The most significant theme throughout this release is the systematic removal of regex dependencies from the Elixir standard library, replacing them with pattern matching and string parsing logic. This effort addresses concerns about regex performance and simplifies the bootstrapping process.

Key highlights:
- **OTP 20 Support:** Comprehensive preparation for Erlang OTP 20-rc.1 compatibility
- **Regex Elimination:** Removed unnecessary regex usage throughout stdlib, compiler, and tools
- **Performance Improvements:** Optimized module compilation and MapSet operations
- **Bug Fixes:** Various fixes in ExUnit, IEx, Mix, and core modules
- **New Features:** Added `Regex.recompile/1` and `Regex.recompile!/1` for archives

## Major Themes and Changes

### 1. OTP 20 Compatibility Initiative

This release contains extensive preparation for Erlang OTP 20, which introduced breaking changes affecting how Elixir handles various operations. Multiple commits demonstrate a coordinated effort to ensure smooth transition:

**OTP Version Tracking**
- Projects are now recompiled if the OTP version changes (commit: `c6f7958ae8`)
- The manifest versioning system was updated from `@manifest_vsn :v1` to `@manifest_vsn :v2` to track version changes
- Version information now includes both Elixir version and OTP release: `{System.version, :erlang.system_info(:otp_release)}`

**Log Message Handling**
- Updated Logger.Translator to properly handle OTP 20 GenServer log messages (commit: `aca50d4d86`)
- Added explicit check for OTP 20 (commit: `9074a99199`)
- Fixed various warnings that emerge when running on OTP 20 (commit: `f27df203ab`)

### 2. Regex Removal and Refactoring Campaign

A major development initiative involved removing unnecessary regex usage from the Elixir standard library. This was done for both performance and simplicity reasons. Seven commits specifically address regex elimination:

**Systematic Regex Removal:**
1. **IO.ANSI.Docs** (commit: `68c5c31f81`) - Replaced `Regex.split(~r{\s})` with character-based splitting using a whitespace list
2. **ExUnit, IEx, Mix** (commit: `e33f3002ad`) - Removed regexes from these modules
3. **Core stdlib and Logger** (commit: `dd79a3eda7`) - Further regex removal across the library
4. **Version.Parser** (commit: `812b1cdc16`) - Complete refactoring removing regex dependency

**Version.parse/1 Major Refactoring**
The most extensive regex elimination was in Version.parse/1 (commits: `812b1cdc16` and `b9e2197ae3`):
- Replaced complex regex pattern with manual string parsing using `String.split/3`
- Implemented pure string manipulation logic for parsing semantic versioning
- Added helper functions: `require_digits/1`, `parse_digits/3`, `maybe_patch/2`, `optional_dot_separated/2`, `valid_identifier?/1`
- Result: Improved maintainability and reduced bootstrapping complexity
- The regex pattern had been: `~r/^(\d+)(?:\.(\d+))?(?:\.(\d+))?(?:\-([\d\w\.\-]+))?(?:\+([\d\w\.\-]+))?$/x`

### 3. New Features and Enhancements

**Regex.recompile/1 and Regex.recompile!/1**
- Added new public functions to support archives and pre-compiled regexes (commit: `c7729df924`)
- Enables users to recompile stored regex modules when upgrading to OTP 20
- Critical for users who have serialized regex modules or use archives that need recompilation

**Module Compilation Optimization**
- Improved compilation time for modules with many clauses (mentioned in CHANGELOG)
- Introduced use of proper table types for keeping clauses (commit: `e6ed1d58d7`)
- Optimized clause storage mechanism from inefficient list reversal (commit: `1ca103d048`)
- MapSet no longer reverses lists unnecessarily during construction

**Struct Key Warning**
- Added warning when attempting to override `__struct__` key in struct definitions (commit: `f8d775cb68`)
- Prevents silent errors and improves developer experience when creating structs
- Implementation refactored struct expansion logic to detect and warn about this common mistake

### 4. Bug Fixes

**Kernel/Core Issues:**
- Fixed code generation when non-binary bitstrings are in the AST (commit: `dad832d5a3`)
- Fixed quoting of bitstring literals (commit: `dad832d5a3`)

**ExUnit Testing Framework:**
- Fixed MatchError in ExUnit when comparing maps with nil or boolean keys (commit: `094b64c13b`)
- Previously, comparing maps containing these special keys would fail unexpectedly
- Improved test report generation reliability

**IEx Interactive Shell:**
- Do not log exits on `IEx.Helpers.c/2` failures (commit: `da10a7d2dd`)
- Wrapped Elixir compilation in try-catch block to prevent error logging
- Changed test suite to capture IO and verify compile errors are properly raised
- Improves user experience by preventing spurious error messages in the shell

**Mix Build Tool:**
- Do not assume all paths in loadpaths exist (commit: `3d756ac5ad`)
- Fixed loading of non-existent paths that could cause failures

**Archive Installation:**
- Show proper path detection when using URLs with query strings (commit: `7c0f6dd121`)
- Fixed issue where `mix archive.install` couldn't properly handle URLs containing query parameters like `https://example.com/archive-0.1.0?hello.ez`
- Changed from using full URL to using only the basename for version detection

**Record Macro:**
- Properly escape fields passed to `defrecord` (commit: `16ea29d518`)
- Added `Macro.escape/1` to ensure literal values are preserved in generated code
- Added comprehensive test case for literal defaults with record in a variable

**URI Module:**
- Fixed a bug in `URI.merge/2` (commit: `176501cb62`)

**ExUnit Race Conditions:**
- Avoided race conditions on `capture_err` reuse (commit: `61bb6c147f`)

**Mix Compiler:**
- Do not set file attributes to "generated" (commit: `f252c9e00e`)
- Prevents Mix from marking files incorrectly, which could cause issues with recompilation

## Breaking Changes

**None identified.** This is a purely backward-compatible release focused on:
- Bug fixes
- Performance improvements
- Forward compatibility with OTP 20

The refactoring of Version.parse/1 is internal and maintains the same external API.

## Dependencies and Ecosystem Impact

### OTP 20 Transition
The release is explicitly positioned as "fully compatible with Erlang OTP 20-rc.1" as stated in the CHANGELOG. This is critical because:
- Users upgrading to OTP 20 can now safely use Elixir v1.4.3
- Archive and stored regex modules need to be recompiled using the new `Regex.recompile/1` function
- The manifest versioning change ensures clean rebuilds when OTP version changes

### Regex Deprecation Pattern
While not a hard deprecation, the removal of regex throughout the library suggests a direction toward reducing regex usage:
- Cleaner bootstrap process
- Better performance for core parsing
- Sets example for community libraries
