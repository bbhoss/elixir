# Changes from v1.14.1 to v1.14.2

## Overview

**Release Date**: November 11, 2022
**Date Range**: October 11, 2022 - November 11, 2022
**Total Commits**: 18

This minor release focused on improving code evaluation hygiene, enhancing ExUnit functionality, fixing formatter edge cases, and improving the Mix tooling experience. The changes maintain backward compatibility while providing better tools for developers working with dynamic code evaluation and testing.

## Summary of Changes

Version 1.14.2 is a patch release that addressed several important areas:

1. **Code Evaluation Hygiene**: Multiple commits focused on the `prune_binding` mechanism to improve variable scoping and hygiene in `Code.eval_quoted_with_env/4`, preventing variable leakage and ensuring cleaner separation between evaluated code and the host environment.

2. **ExUnit Testing Improvements**: Significant improvements to ExUnit including the ability to prevent duplicate test case registration, better formatter output, and new API functions for assertion formatting.

3. **Mix Package Manager Enhancements**: Mix.install now supports more convenient atom-based path specification, reducing boilerplate for common patterns.

4. **Code Formatter Fixes**: Fixed edge cases in bitstring formatting, particularly with the `size*unit` shortcut notation that wasn't being normalized correctly.

5. **Defguard Variable Generation**: Improved handling of variable generation in defguard to ensure uniqueness and prevent collisions.

6. **Documentation and Developer Experience**: Added documentation for tracer events, register function, and improved error messages when test directories are missing.

## Major Features and Improvements

### 1. Code Evaluation Enhancements (Most Significant)

Multiple commits (spanning October 29 - November 9) focused on improving `Code.eval_quoted_with_env/4`:

- **Added `prune_binding` parameter** (`804d03431ac427c88d4499e308b5038efce5b6ad`): This new feature allows developers to control variable binding cleanup when evaluating quoted code. This is crucial for preventing variable leakage in scenarios where code is evaluated multiple times or in different contexts. The implementation includes comprehensive tests ensuring hygienic variable handling.

- **Prune binding from env and on literals** (`fdf96ad48a42d2859ac3cf9e083a3ec29e412b4a`): Further refinement to ensure that variable pruning works correctly both in the environment and when evaluating literal values, preventing unintended variable captures.

- **Improvements to prune binding** (`2acd0949dc3aa827d899e42c4cd442f53ebbb0f1`): Additional refinements to the pruning mechanism for better performance and correctness.

- **Do not include module variables in prune_binding** (`7f70f64a01c3a3852a68ee1af73447f763618af6`): Bug fix ensuring module-level variables are handled correctly and not inappropriately pruned.

**Impact**: These changes provide safer and more predictable behavior when using `Code.eval_quoted_with_env/4`, which is critical for tools, macros, and metaprogramming features.

### 2. ExUnit Test Framework Improvements

- **Improvements to ExUnit** (`e65dae9f54bf73bcb6c0a49fdaedd08084b28fc3`): Comprehensive improvements including:
  - Prevention of duplicate test case runs in `ExUnit.run/1`
  - Option to allow test cases to not be registered on use (providing more flexibility for custom test runners)
  - Exposed `ExUnit.Formatter.format_assertion_diff/4` as a public API for custom formatters
  - Substantial refactoring of the formatter module for better maintainability

- **Add doctest metadata as tags** (`c01658b12d1add1de17df70724f4e6f90c61c093`): Doctests now include metadata tags, allowing for better test filtering, organization, and reporting capabilities.

**Impact**: These changes make ExUnit more flexible for advanced testing scenarios and improve the formatting of test output.

### 3. Mix.install Path Enhancement

- **Mix.install accepts atoms as paths** (`eb43a6a444c4aa9446ec1a7ad9801cedc897ab9d`): Previously, `Mix.install/2` required full string paths for `:config_path` and `:lockfile` options. Now developers can pass the application name as an atom, and Mix will automatically expand it to the correct path. This reduces boilerplate and makes scripts more readable.

**Example**:
```elixir
Mix.install(
  [
    {:hexpm, path: "/tmp/hexpm", env: :dev},
  ],
  config_path: :hexpm,      # Now expands to /tmp/hexpm/config/config.exs
  lockfile: :hexpm           # Now expands to /tmp/hexpm/mix.lock
)
```

**Impact**: Improved developer experience when using Mix.install with path dependencies.

### 4. Defguard Variable Hygiene

- **Generate unique vars in defguard** (`123034569f3f80a8693efb33ba8d211048b37507`): Improved variable generation in defguard to ensure variables are unique and don't collide with user-defined variables. This prevents subtle bugs in guard clause execution.

**Impact**: More reliable guard clause behavior and reduced risk of variable name collisions.

### 5. Protocol Environment Expansion

- **Expand :for in protocols with the appropriate env** (`32c2a2db62ae244c55d8ec92bdaf9ca808d9a76c`): Fixed protocol implementation to use the correct environment when expanding the `:for` clause, ensuring proper module visibility and macro expansion in protocol implementations.

**Impact**: Ensures protocol implementations have the correct compilation environment context.

## Bug Fixes

### Code Formatter

- **Fix formatter: size*unit shortcut in bitstring** (`fcb7b69cb5cdfd491388c1ea8cf4c33f8da9e08c`): Fixed an issue where the `size*unit` shortcut notation in bitstring patterns was not being normalized correctly by the code formatter. The fix ensures that patterns like `<<0::size*unit, bytes::binary>>` are properly formatted according to Elixir's style guidelines while preserving the shortcut notation.

### Mix and Test Infrastructure

- **Ensure proper error message on mix test when there is no test directory** (`c80f8b6698031c1e8f9c98c758f9b9ca3cab1e2a`): Improved error message quality when running `mix test` in a project without a test directory, providing better guidance to developers.

### Testing and Hygiene

- **Fix backported test** (`6c5d7bfe3fd3f602d8dc63106b729c1c608e0126`): Fixed a test that was incorrectly backported in the release branch.

- **Include [if_undefined: :warn] on var metadata** (`bdea27c1e38571a2cc89803b1deb3b7574c46afc`): Added proper metadata tracking for undefined variable warnings, improving diagnostic information.

## Documentation Improvements

- **Improve docs for tracer events** (`d061cb96eff3d1dbfdeb0ded5f5c488fecdbcc36`): Enhanced documentation for event tracing features, making it clearer for developers using the tracer API.

- **Document register** (`d1f74579072ce629febdcff90fb3bdadd7552070`): Added documentation for the `register` function in ExUnit.Case, improving API discoverability.

## Testing Improvements

- **Add a test for hygienic vars on eval** (`29a2bb49d01c712a54f3435347c39ac45e59d6b9`): Added comprehensive test coverage for hygienic variable handling in evaluated code, ensuring the changes to variable binding work correctly.

- **mix format** (`7996c0a9664cfce5f2d7ea29081280ef6953e55e`): Automatic code formatting cleanup.

**None**. This is a patch release with no breaking changes. All improvements are backward compatible.
