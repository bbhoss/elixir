# Changes from v0.11.1 to v0.11.2

**Release Date:** November 7, 2013 - November 14, 2013 (7 days)
**Total Commits:** 46 commits

---

## Summary

v0.11.2 represents a significant infrastructure update to Mix, Elixir's build tool, with a major focus on restructuring how build artifacts are organized and managed. This release introduces a fundamental shift in how Mix handles compilation paths and build environments, moving from ad-hoc compilation locations to a structured `_build` directory system. The changes are largely internal refactoring and infrastructure improvements, but they include one **major backwards-incompatible change** that projects must adapt to.

The release emphasizes improving developer experience in two key areas: better error handling in the interactive shell (iex) and more explicit control over build-per-environment configuration. These changes set the foundation for more robust dependency management and cleaner project structures going forward.

---

## Major Features & Improvements

### 1. **Build System Restructuring: Introduction of `_build` Directory** (Primary Theme)

The most significant change in this release is the introduction of a structured build directory system:

- **Centralized Build Artifacts:** All compiled files, dependencies, and archives are now compiled to a `_build` directory instead of being scattered across the project structure
- **Environment-Specific Builds:** Projects can opt-in to per-environment builds by setting `build_per_environment: true` in their configuration, which creates separate build directories for dev, test, and prod environments
- **Unified Dependency Management:** Dependencies and rebar packages are moved to `_build`, creating a cleaner separation between source code and build artifacts

**Impact:** This is a **breaking change**. Existing projects will automatically be updated when the build system detects the new structure, but documentation and build scripts may need updates.

### 2. **Per-Environment Build Configuration**

A new feature allowing projects to customize builds per environment:

- **Configuration Option:** `build_per_environment: true` in project configuration
- **Separate Build Directories:** Each environment (dev, test, prod) gets its own isolated build directory
- **Environment-Specific Compilation:** Enables different compilation behaviors and features per environment
- **Umbrella Project Support:** Ensures umbrella children's per-environment builds don't clash with parent builds

**Key Commits:**

**Benefit:** Developers can now have true isolation between dev, test, and prod builds without manual cleanup or configuration.

### 3. **Mix Server & Configuration Refactoring**

Significant architectural improvements to Mix's internal infrastructure:

- **Separation of Concerns:** Extract Mix.ProjectStack from Mix.Server, creating a dedicated module for project stack management
- **App Environment Configuration:** Move Mix configuration from the server to the application environment for better isolation and testability
- **TasksServer Introduction:** Split task management into a separate TasksServer module (`mix/lib/mix/tasks_server.ex`)
- **Cleaner Architecture:** Reduces the responsibilities of Mix.Server and makes the codebase more maintainable

**Key Commits:**
- `a6474aecd4` - "Extract Mix.ProjectStack from Mix.Server"
- `5c55f0fe91` - "Move mix configs to app environment and split TasksServer"

**Benefit:** Cleaner, more maintainable codebase with better separation between project management and task execution.

### 4. **Improved Compile Path Handling**

Refactored how Mix determines and uses compile paths:

- **Removed `compile_path` from Config:** The `:compile_path` configuration key is removed from general configuration
- **Required `app` Key:** The `app` key is now required when getting the compile_path to ensure proper context
- **Centralized Path Management:** All path logic is consolidated in Mix.Project

**Key Commits:**
- `343d9ef042` - "Remove :compile_path from config and move it to Mix.Project"
- `5844e29443` - "Ensure app key is required when getting the compile_path"

**Benefit:** Eliminates ambiguity and configuration errors related to compile paths.

### 5. **Enhanced Developer Experience**

Several quality-of-life improvements for developers:

- **Interactive Shell (iex) Improvements:**
  - Better error messages when attempting to compile missing files with `iex -c`
  - Cleaner error reporting to guide users to use `iex -S mix`

- **Mix Tasks UX:**
  - `mix iex` command now fails with helpful error message directing users to `iex -S mix` (preferred approach)
  - Improved success messaging in `mix new` command
  - Better documentation with fixed `@before_compile` hook examples

## Configuration & API Changes

### Backwards Incompatible Changes

1. **Build Output Location**
   - Projects now compile to `_build` instead of the default project root
   - This is a breaking change, but Mix handles the transition automatically
   - Documentation and build scripts expecting the old location need updates

2. **Mix Configuration Updates**
   - `:compile_path` configuration key has been removed
   - `:load_paths` setting was already deprecated in v0.11.1

3. **Task Changes**
   - The `mix iex` task has been changed to fail with an error message
   - Users should use `iex -S mix` instead (the preferred approach)

### New Configuration Options

- `build_per_environment: true` - Enable separate builds per environment
- This setting is optional; existing projects continue to work with shared builds

## Upgrade Notes for Developers

### For Most Projects

- Update documentation references from `ebin` or old build locations to `_build`
- Update any custom build scripts that reference the old compilation paths
- Projects will automatically work with the new `_build` structure

### For Projects Using Per-Environment Builds

- Add `build_per_environment: true` to your `mix.exs` configuration if you need separate builds per environment
- This is particularly useful if you have environment-specific compilation or configuration

### For Umbrella Projects

- Ensure all child apps point to the correct deps and lockfile paths
- The new `_build` structure handles umbrella complexity better, reducing the need for manual configuration

---

## Conclusion

v0.11.2 is primarily a **foundational release** focused on stabilizing and improving Mix's architecture. While it introduces a major breaking change (the `_build` directory), it does so to provide long-term benefits: cleaner project structures, better environment isolation, and more maintainable build system code. The per-environment build feature empowers developers with more control over their build processes, and the internal refactoring sets the stage for future improvements to Mix without disrupting user code.
