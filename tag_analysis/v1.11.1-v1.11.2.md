# Changes from v1.11.1 to v1.11.2

## Overview

- **Release Date Range**: October 16, 2020 - November 3, 2020 (18 days)
- **Total Commits**: 10 (1 release commit + 9 fixes)
- **Release Type**: Patch release (v1.11.1 → v1.11.2)

## Summary

Elixir v1.11.2 is a focused patch release addressing critical bugs discovered shortly after v1.11.1. The release concentrates on three main areas: stabilizing the new compiler tracer feature introduced in v1.11, fixing issues in Mix task aliases, and resolving edge cases in the Code module when working with releases. No new features were introduced; this release is purely maintenance-focused with 9 bug fixes and documentation clarifications.

## Key Themes and Changes

### 1. Compiler Tracer Stability (4 commits)

The compiler tracer feature, recently added in v1.11, required additional refinement to handle edge cases properly:

- **Tracer Leakage in `__ENV__` Access**: When `__ENV__` was accessed inside functions, tracers were leaking into the escaped environment, causing unintended dependency tracking. The fix ensures tracers are pruned when escaping environment entries inside function scope.

- **Manual Tracer Preservation**: A regression prevented manually set tracers (via `Code.put_compiler_option(:tracers, [...])`) from being properly combined with command-line tracer options. The fix separates tracer collection from option merging to preserve both sources of tracers.

- **Protocol Implementation Tracking**: The tracer was incorrectly capturing `__impl__` function calls within protocol modules, which are deliberately designed to invert dependencies. This undesired behavior has been filtered out to prevent false dependency warnings.

- **Protocol Implementation Checks**: A more focused fix in the ApplicationTracer to skip tracing of `__impl__` calls, making the solution "less disruptive" than the complete solution in master while addressing the immediate issue.

**Impact**: These fixes stabilize the compiler's dependency tracking, which is critical for the new application dependency validation feature in v1.11.

### 2. Mix Task Alias Recursion Fix (1 commit)

A regression in v1.11 prevented aliases from calling themselves recursively. This issue affected real-world workflows, particularly in the Nerves project where aliases use code recursion (calling Mix tasks programmatically rather than just chaining task names).

The fix involved restructuring the task scheduling logic to:
- Check aliases before task registration
- Properly track task execution state to detect recursion
- Allow both name-based recursion (`help` alias calling `help` task) and code-based recursion (functions calling `Mix.Task.run/2`)

**Impact**: Restores important Mix workflow patterns that users rely on for custom build processes.

### 3. Code Module Releases Compatibility (2 commits)

Two related fixes address issues when running Elixir in release mode:

- **Missing ERTS Documentation**: When the `erts` application directory isn't included in a release (unless explicitly listed as an extra application), calling `Code.fetch_docs/1` on preloaded modules would crash. The fix adds error handling to gracefully return `{:error, :chunk_not_found}` instead of crashing.

- **Bootstrap Issue**: A temporary refactoring issue in how documentation chunk paths were constructed was fixed, ensuring proper path joining before fetching documentation.

**Impact**: Critical for production releases that don't include full ERTS packages, allowing documentation lookups to fail gracefully rather than crashing.

### 4. Guard Clause Validation (1 commit)

Elixir now explicitly rejects `:erlang.is_record/2` and `:erlang.is_record/3` in guard clauses, providing clear error messages rather than allowing invalid code:

```elixir
defguard foo(rec) when :erlang.is_record(rec, :tag)  # Now raises CompileError
```

While these functions are recognized as compiler guards in Erlang's internal API, Elixir doesn't support record syntax and should never allow them. This prevents confusion and invalid code patterns.

**Impact**: Improves the compilation error messaging for users attempting to use Erlang record guards, making it immediately clear why their code won't compile.

### 5. Test Infrastructure (1 commit)

Fixed a race condition in test helper loading by using more specific requires instead of relative paths to `test_helper.exs`. This affects type system tests that were running in parallel:

- Changed from requiring relative paths: `Code.require_file("../../test_helper.exs", __DIR__)`
- To requiring local helpers: `Code.require_file("type_helper.exs", __DIR__)`

**Impact**: Eliminates test flakiness in the module type system tests when run in parallel mode.

### 6. Documentation Clarifications (1 commit)

Minor clarifications to the changelog regarding umbrella project behavior:
- Clarified that Modules from Elixir and Erlang/OTP are "not listed as a dependency" (removed "explicitly")
- Improved explanation that applications must "depend on the siblings they depend on" to properly reject cyclic dependencies

**Impact**: Reduces confusion for developers using umbrella projects and understanding the new dependency validation.

## Major Features/Improvements

This patch release contains **no new features**. It is exclusively focused on:
- Stability improvements
- Bug fixes
- Documentation corrections

## Bug Fixes

1. **Kernel**: Raise meaningful error for `:erlang.is_record` in guards (#10436)
2. **Kernel**: Prune tracers when fetching `__ENV__` inside functions (#10466)
3. **Code**: Do not crash when getting docs for missing `erts` appdir (#10437)
4. **Mix**: Fix regression where aliases could not call themselves recursively
5. **Mix**: Do not discard tracers set programmatically during compilation (#10451)
6. **Mix**: Do not trace protocol impl checks
7. **Mix**: Handle aliases with code recursion (Nerves issue #557)
8. **Test Infrastructure**: Fix race condition when loading test helpers (#10464)
9. **Code/Bootstrap**: Fix path construction for documentation chunks

## Breaking Changes

**None**. This is a patch release with only bug fixes and clarifications. No public APIs were changed or deprecated.

## Conclusion

v1.11.2 is a stabilization release that addresses critical issues discovered within weeks of v1.11's release. The focus on tracer stability, Mix task aliases, and release compatibility shows Elixir's commitment to robustness. All fixes target existing regressions or edge cases rather than introducing new functionality, making this a safe and recommended upgrade for all v1.11 users.

The tracer-related fixes are particularly important as they address the newly-introduced compiler feature that tracks application dependencies - a major feature in v1.11 that required fine-tuning in edge cases.
