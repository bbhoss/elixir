# Changes from v0.12.5 to v0.13.0

## Overview

**Date Range:** February 3, 2014 - April 20, 2014
**Total Commits:** 323
**Release Date:** April 20, 2014

This release represents a significant evolutionary step for Elixir, introducing major new language features while phasing out older constructs. The most notable changes include the introduction of maps and structs as first-class language features, the unification of list and bitstring comprehensions into a single `for` syntax, and substantial improvements to the standard library.

---

## Key Themes and Analysis

### 1. **Maps and Structs - A New Data Model** (Major Feature)

The v0.13.0 release introduces **maps and structs** as fundamental language features, representing a major shift in how Elixir developers work with structured data.

**What Changed:**
- Maps are now a native language construct with `%{key => value}` syntax
- Maps support pattern matching and provide efficient key-value storage
- Structs are introduced as a lightweight layer over maps for data structures
- New `Kernel.struct/2` function for working with struct instances
- New `defstruct` macro in modules for defining structured data
- Maps are automatically used in various places (Mix.Dep conversion, etc.)
- Maps gain support in pattern matching, access patterns, and comprehensions

**Commits of Note:**
- `c65dcc9b19` - Basic support for maps in the grammar
- `4d366f4688` - Implement Map module and Map as Dict implementation
- `128d82fde6` - Add defstruct and allow unquoting inside maps/structs
- `aa09359def` - Add Kernel.struct/2
- `1f0861771a` - Implement protocol support for structs
- `149091a1a1` - Define a type for structs
- `453c731f8a` - Convert Mix.Dep record to struct

**Impact:** This is a paradigm shift from Elixir's earlier reliance on records. Maps provide a more flexible, efficient data structure while structs provide the conveniences developers expect from data structures with defined fields.

---

### 2. **Comprehension Unification** (Major Language Change)

List comprehensions (`lc`) and bitstring comprehensions (`bc`) are unified into a single, more powerful `for` syntax that supports multiple generator types and filters.

**What Changed:**
- New unified `for` comprehension syntax that handles both lists and bitstrings
- Support for binary generators in comprehensions
- Support for `:into` option to collect results into different types
- Improved generator handling with support for map iteration
- Filtering expressions in comprehensions
- Automatic type inference for comprehension output
- Old `bc` and `lc` syntaxes are soft-deprecated but still functional
- Comprehensions now support collectable protocol integration

**Commits of Note:**
- `c51a2a5462` - Start expanding for comprehensions
- `8084f0a6bf` - Start translating for comprehensions
- `16c90ef97d` - Start translating for comprehensions with filters
- `33985326b1` - Support :into in for comprehensions
- `20b14b3221` - Ensure structs can be accessed from context modules
- `3512c1a860` - Start migrating lc to for comprehensions
- `0d66824965` - Soft deprecate bc and lc

**Impact:** A single, more expressive syntax reduces cognitive load and provides better flexibility for developers. The `:into` support enables collecting results into any Collectable, not just lists.

---

### 3. **Records Soft Deprecation** (Breaking Trend)

While not removed entirely, records are soft-deprecated in favor of the new struct mechanism, signaling a significant shift in data modeling.

**What Changed:**
- Records are deprecated as the primary data structuring mechanism
- New deprecation messages guide users toward structs
- Protocol support is temporarily disabled for records during this transition
- Mix.Dep and other internal structures migrate to structs
- Documentation updated to reference structs instead of records

**Commits of Note:**
- `9e96966622` - Add a deprecation note to records, split deprecated modules
- `d2530e44eb` - Tidy up new record API
- `21b1e51909` - Start new records API
- `ff0df96cfc` - Get rid of record rewriter

**Impact:** This deprecation removes one of Elixir's original data structures in favor of the more modern maps/structs approach. Existing record-based code will continue to work but developers are encouraged to migrate.

### 4. **Standard Library Expansion** (New Modules & Functions)

The standard library is significantly expanded with new modules and functions.

**New Modules:**
- **Base** - RFC4648 compliant base encoding/decoding functions (Base16, Base32, Base64)
- **Collectable** - Protocol for types that can collect values (renamed from Traversable)
- **Stream** - Lazy evaluation for potentially infinite sequences
- **File.Stream** - Streaming file I/O
- **StringIO** - In-memory I/O stream for testing and string operations

**New Functions:**
- `Enum.sum/1` - Sum numeric collections
- `Enum.group_by/2` - Group enum elements by a function
- `Process.send/3` - Send messages to processes with custom options
- `Node.ping/0` - Check if a node is alive
- `Code.eval_file/2` - Evaluate Elixir files with optional binding
- `System.delete_env/1` - Delete environment variables
- `Mix.Shell.prompt/1` - Prompt users interactively

**Commits of Note:**
- `17ddb2539d` - Added Base module implementing base encoding
- `26f5f640c9` - Initial work on traversable (Collectable)
- `efb67a8416` - Add File.Stream and Stream.into/3
- `920e056465` - Implement StringIO
- `eda13d1e41` - Add Enum.sum/1
- `d0dca93fb2` - Add support for Enum.group_by/2

**Impact:** These additions make Elixir's standard library more complete and provide developers with essential utilities for common tasks.

### 9. **Deprecations and Removals**

Beyond records, several other features are deprecated or removed to clean up the language.

**Deprecated:**
- `bc` (bitstring comprehension) and `lc` (list comprehension) - replaced by `for`
- `is_regex/1` and `is_range/1` guard functions
- Char lists in regex patterns
- Old sigil syntax
- `Exception.normalize/1` - replaced by `Exception.normalize/2`
- `MIX_GIT_FORCE_HTTPS` environment variable

**Removed:**
- GenFSM behavior
- Various deprecated functionality from Enum and Access
- Native checks and related code
- Old record rewriter

**Commits of Note:**
- `0d66824965` - Soft deprecate bc and lc
- `7f8265f85c` - Deprecate is_regex/1 and is_range/1
- `56db9fb043` - Remove GenFSM
- `5a618258a3` - Remove deprecated sigils

**Impact:** These removals clean up the language surface and encourage migration to modern idioms.

## Breaking Changes

While the release maintains significant backward compatibility, there are some breaking changes:

1. **Records as primary data structure** - Soft deprecated in favor of structs. Code using records will continue to work but is discouraged.

2. **Comprehension syntax** - Old `bc` and `lc` syntax is deprecated. New code should use `for` comprehensions.

3. **GenFSM** - Completely removed. Users must migrate to other approaches.

4. **Deprecated sigils** - Old sigil syntax no longer works; must use new syntax.

5. **Char lists in Regex** - No longer supported. Must use string-based patterns.

6. **Exception.normalize/1** - Removed in favor of `Exception.normalize/2` with arity 2.

## Notable Implementation Details

### Maps as First-Class Citizens
Maps went from being discussed concepts to fully integrated language features with:
- Grammar-level support (`%{...}` syntax)
- Pattern matching capabilities
- Struct overlay mechanism
- Complete protocol integration
- Efficiency optimizations

### Strategic Records Transition
Rather than an immediate removal, records were soft-deprecated with:
- Deprecation warnings guiding users to structs
- Parallel development of new record API
- Gradual internal migration (Mix.Dep)
- Protocol support temporarily disabled to manage complexity

### Comprehensive Comprehension Overhaul
The comprehension system was substantially refactored in two stages:
1. Grammar and parsing support for new `for` syntax
2. Translation and code generation for various generator types
3. Collectable integration for flexible result collection

### Standard Library Modernization
New modules and functions follow a pattern of:
- Addressing gaps in RFC compliance (Base)
- Supporting modern Elixir idioms (Collectable, Stream)
- Improving testing capabilities (StringIO)
- Reducing common library maintenance burdens

- **Library completeness**: New modules address common needs
- **Platform expansion**: Better Windows support broadens appeal

The 323 commits over 2.5 months (Feb-Apr 2014) demonstrate substantial architectural decisions and implementation effort. This release likely attracted more serious developers by providing the data structures and tooling they expected from a modern language.
