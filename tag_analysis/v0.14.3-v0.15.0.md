# Changes from v0.14.3 to v0.15.0

## Release Information

- **Date Range:** July 12, 2014 to August 2, 2014
- **Commit Count:** 161 commits
- **Release Date:** August 2, 2014

## Summary

v0.15.0 represents a significant release focused on improving the logging infrastructure, enhancing Mix tooling, and refining the standard library. The most notable addition is the Logger module, which provides a complete logging system for Elixir applications. This release also includes substantial deprecations to clean up the API and improvements to developer experience through enhanced Mix commands and IO formatting capabilities.

The release reflects a maturing ecosystem with emphasis on production-readiness, particularly around logging and error handling, while maintaining backward compatibility where possible through deprecation warnings.

## Major Features & Additions

### 1. Logger Module - The Centerpiece of v0.15.0

A comprehensive new Logger module was introduced as a complete logging system for Elixir applications. This addition includes:

- **Logger Core** (`lib/logger/lib/logger.ex`): Main logging API with support for different log levels (debug, info, warn, error)
- **Console Backend** (`lib/logger/lib/logger/backends/console.ex`): Output logs to the console with ANSI color support
- **Configuration System** (`lib/logger/lib/logger/config.ex`): Flexible configuration for logger behavior and backends
- **Error Handler** (`lib/logger/lib/logger/error_handler.ex`): Integration with Erlang's error handling system to capture OTP errors
- **Formatter** (`lib/logger/lib/logger/formatter.ex`): Customizable message formatting for different output targets
- **Translator** (`lib/logger/lib/logger/translator.ex`): Translation of Erlang error messages into human-readable format
- **Watcher** (`lib/logger/lib/logger/watcher.ex`): Monitoring and management of logger backend processes

This represents approximately 1,900+ lines of new code and establishes Logger as a first-class citizen in Elixir, replacing ad-hoc logging solutions previously used in applications.

### 2. ANSI Support Enhancements

Building on the Logger addition, significant improvements were made to ANSI color and formatting support:

- **New `IO.ANSI.format/2` and `format_fragment/2` functions** that return proper iodata instead of requiring string concatenation
- **ANSI support in console logger** with configurable color output for different log levels
- **Optimization of `IO.ANSI.format/2`** to avoid unnecessary remote calls
- **Improved test coverage** for ANSI functionality across different scenarios

These enhancements make it easier for developers to create visually formatted output in their applications, particularly important for command-line tools built with Elixir.

### 3. Mix Tool Improvements

Several enhancements were made to Mix to improve the development experience:

- **App Name Display**: Enhanced Mix to print application names before compiling and when running commands, improving visibility into which app is being processed in multi-app projects
- **Dynamic `elixirc_paths` Configuration**: Allow passing `:elixirc_paths` via command line with `--elixirc-paths`, giving developers more flexibility in build configuration
- **Improved `mix new` Command**:
  - Better validation of app and module names
  - Support for `--app` flag to specify custom app names
  - Improved error messages when validation fails
- **Windows PowerShell Support**: Significant improvements to `mix.ps1` for better Windows compatibility
- **IEx Improvements**:
  - New `--werl` option for Windows environments
  - Improved tab completion fallback handling
  - Better handling of terminal options

### 4. Stream Module Reorganization

Stream moved from being a module within GenEvent to its own dedicated module, improving code organization and making the streaming abstraction more prominent.

### 5. New API Additions

- **`Map.from_struct/1`**: New function to convert structs into maps, useful for serialization and data transformation
- **`Agent` MFAs**: Support for passing Module-Function-Arity tuples to Agent, improving flexibility
- **`Regex.split/3` with `:on` option**: Added ability to specify what part of the matched regex to split on, providing more control over regex splitting behavior
- **`Inspect.Algebra.format/2`**: New function returning iodata instead of plain strings for better composability

### 6. Markdown Support in Built-in Formatter

Added basic support for rendering markdown tables in the formatter used for documentation, improving documentation quality and readability.

## Deprecations

v0.15.0 includes several deprecations to clean up the API and encourage better practices:

### Deprecated Functions

1. **`IO.ANSI.terminal?/0`** - Deprecated in favor of more explicit terminal detection
2. **`IO.ANSI.escape/2` and `IO.ANSI.escape_fragment/2`** - Replaced by the new `format` functions which provide better composability
3. **Octal and upcase character syntaxes** - Language-level cleanup for character literal syntax
4. **Soft deprecations** - Some functions softly deprecated with documentation updates

### Removed Features

Previously deprecated features were removed:

- **`EEx.TransformerEngine` and `EEx.AssignsEngine`** - Legacy EEx template engines no longer needed
- **`xor/2` function in Kernel** - This operator was removed after deprecation
- **`escript` removed from elixir app** - Escript is now managed separately as a Mix task
- Various deprecated Mix tasks and utilities

These removals represent the completion of deprecation cycles started in earlier versions.

## Bug Fixes & Improvements

### Stability and Correctness

- **Struct Detection Race Condition**: Fixed race conditions in struct detection that could cause issues in concurrent compilation scenarios
- **Defoverridable Order Independence** (Issue #2615): Ensured `defoverridable` declarations are no longer order-dependent, allowing more flexible code organization
- **Rebar Dependencies Lock**: Fixed issue where rebar dependencies were incorrectly getting lock files
- **Stream Representation Leakage**: Fixed issue where Stream internals were being exposed, improving encapsulation
- **GenEvent.handle_info/2 Return Values**: Corrected documentation for invalid return values
- **Access/Update Bug**: Fixed bug where access/update operations on maps were incorrectly filling values

### Performance Optimizations

- **`IO.ANSI.format/2` Optimization**: Reduced remote function calls for better performance
- **`String.slice/2,3` Performance**: Optimized using `binary_part` for faster string operations
- **`Inspect` Traversal**: Added limits to avoid excessive collection traversal during inspection

### Platform-Specific Fixes

- **Windows Test Execution**: Fixed stdlib tests to use Command Prompt on Windows instead of shell-specific approaches
- **Path Expansion**: Properly handle tilde (~) in `Path.expand/1,2` on all platforms
- **Bash Comparison Quoting**: Fixed argument quoting in bash comparisons for cross-platform compatibility

### API Improvements

- **`System.cmd/2` Return Types**: Updated type specifications to correctly reflect actual return values
- **Private Function Enforcement** (Issue #2587): Ensured private functions are not exported
- **Protocol Convention Exposure**: Fixed issue where protocol conventions were being exposed unnecessarily
- **Regex.split Subpattern Handling** (Issue #2600): Improved handling of subpatterns in regex split operations
- **Keyword List Handling**: Changed binding to no longer use lists, improving consistency

## Breaking Changes

### Language Changes

- **Character Syntax Changes**: Octal and upcase character syntaxes were deprecated and no longer work with new code patterns
- **Kernel.xor/2 Removal**: The `xor` function was removed from Kernel after deprecation

### Library Changes

- **escript Removed from elixir App**: Applications relying on escript being part of the main elixir application will need to explicitly depend on it
- **EEx Template Engines**: `EEx.TransformerEngine` and `EEx.AssignsEngine` were removed; migrate to EEx.SmartEngine
- **IO.ANSI API Changes**: `escape/2` and `escape_fragment/2` removed; use `format/2` and `format_fragment/2` instead
- **GenEvent Stream Removed**: GenEvent.stream is still available but moved; code referencing internal Stream from GenEvent needs updating

### Configuration Changes

- **Logger Integration Required**: Applications using error logging should migrate to the new Logger module
- **Dependencies Declaration**: Crypto, compiler, and syntax_tools are now explicitly listed as dependencies

## Impact on Developers

### Migration Path for Logging

Developers should migrate from ad-hoc error printing to the Logger module:

```elixir
# Old approach
IO.puts("Error: #{reason}")

# New approach
Logger.error("Error: #{reason}")
```

### IO.ANSI Updates

Code using `IO.ANSI.escape/2` should migrate to the new format-based API:

```elixir
# Old (deprecated)
IO.ANSI.escape("<< >")

# New
IO.ANSI.format([:red, :bright, "Hello", :reset]) |> IO.write()
```

### Mix Configuration

Developers can now be more explicit about their build configuration using command-line options that were previously hardcoded.

## Context & Themes

This release marks a shift toward **production-readiness** in Elixir:

1. **Logging Infrastructure**: The addition of Logger acknowledges that production applications need robust logging, not just IO.puts
2. **Developer Experience**: Mix improvements focus on clarity and flexibility
3. **API Maturation**: Removal of deprecated code and soft deprecations to clean up the API surface
4. **Cross-Platform Support**: Continued investment in Windows compatibility
5. **Standard Library Polish**: Various optimizations and bug fixes across the library

The release positions Elixir as increasingly suitable for production use while maintaining its focus on developer happiness through improved tooling and clearer error messages.
