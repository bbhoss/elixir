# Changes from v1.6.0 to v1.6.1

## Overview

**Release Date Range:** January 17, 2018 - January 29, 2018
**Total Commits:** 24
**Release Type:** Patch release (v1.6.0 → v1.6.1)

This patch release focused on bug fixes, minor feature enhancements, and documentation improvements. The changes span across the core Elixir language, IEx (interactive shell), ExUnit testing framework, and the standard library.

---

## Summary of Key Themes

The v1.6.1 release addressed several important issues discovered during v1.6.0 usage:

1. **Critical Bug Fixes**: Focus on error handling consistency and evaluator behavior in IEx
2. **Standard Library Enhancements**: Expanding capability of protocols and collection types
3. **Code Quality Improvements**: Refinements to code formatter and OTP behavior implementations
4. **Documentation Polish**: Significant improvements to documentation examples and API docs

This was primarily a stabilization release, ensuring the v1.6.x line was robust for production use.

---

## Major Features & Improvements

### 1. DynamicSupervisor Enhancement
**Commits:** `5d7ee90c` (child_spec/1), `47f26968` (migration examples)

The `DynamicSupervisor` module received significant improvements:
- **Implemented child_spec/1**: Added proper child specification support, making `DynamicSupervisor` consistent with other OTP behaviors
- **Added migration documentation**: Comprehensive examples showing how to migrate from `Supervisor` to `DynamicSupervisor`

This enhancement improved the flexibility of supervisor patterns in Elixir applications.

### 2. Collection Type Improvements

#### Support for Bitstrings in Collectable
**Commit:** `66cf08ea`

Major expansion of the `Collectable` protocol to support bitstrings:
- **Code changes**: 190 insertions, 47 deletions across 3 files
- **Impact**: Extended comprehension support to work seamlessly with bitstring data
- **Test coverage**: Added comprehensive tests for bitstring comprehensions in `comprehension_test.exs` (106 new test lines)

This allows developers to use bitstrings more naturally within comprehension contexts.

#### Support for Zipping Any Collection
**Commit:** `b898f098`

Enhanced `Enum.zip/2` and `Stream.zip/2` to work with any enumerable collection:
- Previously limited to specific collection types
- Now supports the full `Enumerable` protocol
- Improves composability of collection operations

### 3. Code Formatter Improvements

#### Do Block Line Length Handling
**Commit:** `f2b31a6626`

Refined the code formatter's handling of do/do...end blocks:
- **Issue #7232**: Addressed inconsistent line length formatting for single-argument do blocks
- **Scope**: Updated 9 files in the standard library to conform to new formatting rules
- **Examples affected**: GenServer, MapSet, Regex, Logger, and other modules
- **Tests**: Added comprehensive formatter integration tests to verify behavior

#### Operator Formatting
**Commit:** `e89139bcf0`

Improved `not` operator handling in conditional expressions:
- Fixed parser and formatter behavior for conditionals using the `not` operator
- Added option to explicitly opt-in to rearrangement instead of default behavior
- Ensures code readability and consistency with Elixir's formatting philosophy

## Bug Fixes

### 1. IEx Evaluator Exit Handling
**Commit:** `992c240b1` - Closes #7255

**Issue**: Exit signals were being propagated incorrectly in nested evaluator contexts
**Fix**: Restricted exit propagation to only non-root evaluators
**Impact**: Improved stability of IEx sessions, especially when handling exceptions in nested evaluation contexts
**Changes**: Modified `lib/iex/lib/iex/evaluator.ex` with more precise signal handling logic

### 2. Invalid Map Syntax Error Handling
**Commit:** `79ae08f96` - Closes #7268

**Issue**: Certain invalid map syntax constructs were not being caught with proper error messages
**Fix**: Added validation in the tokenizer to raise errors on invalid map syntax patterns
**Impact**: Better error messages for users who accidentally use incorrect syntax
**Example**: Ensures constructs like `%{a: b: c}` are caught and reported clearly

### 3. Protocol Missing Chunk Handling
**Commit:** `bc9b5ea70`

**Issue**: Protocol implementation was adding missing chunks instead of filtering them
**Fix**: Refactored to filter missing chunks rather than add them
**Impact**: Reduces protocol overhead and improves memory efficiency
**Changes**: 18 insertions, 10 deletions in `Protocol.ex` - a significant code quality improvement

### 4. ExUnit Case Setup/Teardown
**Commit:** `2ba98f247` - Continuation of setup improvements

**Issue**: The `:case` context was not being properly passed through ExUnit's setup/setup_all/test macros
**Fix**: Ensured `:case` continues to be passed along the execution pipeline
**Impact**: Improves test context consistency and macro behavior
**Changes**: Modified `ExUnit.runner` to maintain context properly

### 5. Undefined Behavior Warning
**Commit:** `0eb95c9c75`

**Issue**: Module warning messages could be confusing
**Fix**: Improved the wording and clarity of undefined behavior warnings
**Impact**: Better developer experience when encountering undefined module behavior

## Code Quality & Refactoring

### OTP Behavior Cleanup
**Commit:** `ecad84931` - Closes #7230

**Issue**: OTP behaviors (Agent, GenServer, Supervisor, DynamicSupervisor, Task) were injecting `@opts` declarations unnecessarily
**Fix**: Removed automatic `@opts` injection from OTP module implementations
**Impact**: Cleaner module definitions, fewer unnecessary type specifications
**Scope**: Affected 5 files across the OTP behavior implementations
**Benefit**: Reduces boilerplate while maintaining type safety where actually needed
