# Changes from v0.15.1 to v1.0.0

## Overview

**Release Date Range:** August 2, 2014 - September 10, 2014
**Total Commits:** 194
**Release Type:** First major version (v1.0.0)

This represents a significant milestone - the first official 1.0.0 release of Elixir. Between v0.15.1 and v1.0.0, the language went through an intensive period of refinement and consolidation, marking the transition from beta status to a stable, production-ready language.

## Key Themes and Analysis

This release cycle focused on three primary areas:

1. **Stability and Correctness**: Extensive work on race condition fixes, particularly in Logger and GenEvent systems which are foundational to Elixir's concurrent capabilities
2. **API Refinement and Cleanup**: Removal of deprecated APIs that were scheduled for removal, making a clean break from older patterns
3. **Feature Consolidation**: Introduction of new streaming primitives and task management improvements to strengthen the concurrency model

The release is notable for its conservative approach to breaking changes - most removals were of explicitly deprecated features, giving users ample notice and migration paths. This careful stewardship established Elixir as a responsible language for production use.

## Major Features and Improvements

### Logger Module Enhancements

The Logger module received substantial attention as it matured toward stability:

- **New control functions**: Added `Logger.enable/1` and `Logger.disable/1` for runtime Logger control, enabling more flexible logging management in production systems
- **Race condition fixes**: Multiple commits addressed critical race conditions in Logger event handling (`Fix Logger.log/2 not to raise on Logger exit`, `Fix race condition in Logger.ErrorHandlerTest`, `Fix logger watcher race condition`). These fixes were essential for production reliability
- **Configuration improvements**: Implemented dynamic Logger mode switching based on configuration changes with `Update Logger mode after configuration`
- **Separation of concerns**: `Mix should not depend directly on Logger` - this decoupling improved the architectural independence of mix tooling

The extensive Logger work (approximately 12+ commits focused on Logger) reflects the critical importance of reliable logging infrastructure in production Elixir systems.

### Stream Module Improvements

Significant enhancements to the Stream API expanded the lazy evaluation capabilities:

- **New streaming primitives**: Added `Stream.interval/1` and `Stream.timer/1` for time-based stream generation, enabling reactive programming patterns
- **Performance optimization**: `Add special case for lists in Stream.cycle` - targeted optimization for a common pattern
- **API refinement**: `Make Stream.resource/3 more like Stream.transform/2` - improved consistency between streaming functions by aligning their return value format
- **Handler renaming**: Changed `:add_stream_handler` to `:add_process_handler` in GenEvent, providing clearer semantics

### Task Module Additions

- **New task constructors**: Added `Task.start/1` and `Task.start/3` - providing alternative task creation patterns that return `{:ok, pid}` instead of just `pid`, enabling better error handling patterns
- **Improved supervision**: These new functions integrate better with supervisor patterns and provide consistent return values across Task and other OTP modules

### Protocol and Compilation Improvements

- **Protocol consolidation in escripts**: Added full support for protocol consolidation in escript binaries with `Add protocol consolidation support to escript.build`
- **Memory efficiency**: `Purge in memory modules before consolidating` - ensures bytecode cleanup before consolidation reduces memory overhead
- **Application separation**: `Only add :elixir application for Elixir projects in compile.app task` - improves interoperability with pure Erlang projects

### New Operators for Parser Combinators

- **Operator set expansion**: Added `<~`, `~>`, `<<~`, `~>>`, `<~>`, `<|>` as reserved operators intended for use by parser combinator libraries
- **Language extensibility**: This addition indicates deliberate support for DSL-building patterns in the Elixir ecosystem

### Testing Framework Enhancements

- **Timeout support**: `ExUnit` added configurable test timeouts via tags, providing control over long-running test execution
- **Improved debugging**: `Print process mailbox on failing assert_receive` - makes it easier to debug process communication issues in tests
- **Documentation**: `Tag all doctests with the `:doctest' tag` - enables selective execution and filtering of doctests

### Supervisor Configuration

- **Default max_restarts change**: Changed default `max_restarts` from its previous value to 3, aligning with upcoming Erlang defaults. This was identified as a backwards incompatible change but represents convergence with the broader Erlang ecosystem.

## Bug Fixes and Stability Improvements

### GenEvent System Fixes

The GenEvent system received critical attention with multiple stability improvements:

- **Exit signal handling**: Fixed race conditions in exit signal processing, particularly important for reliable event propagation
- **Handler management**: Ensured handlers cannot be added more than once, preventing duplicate handler scenarios
- **Swap handler removal**: `Remove support for inner swap_handler` - eliminated problematic handler swapping patterns
- **Stream stability**: Fixed `GenEvent.stream/2` to properly handle exit notifications and removed the problematic `:duration` option

### Windows Compatibility

- **Drive letter normalization**: `Lowercase drive letters from cwd` - ensures consistent path handling across Windows systems, addressing #2747
- **Archive installation**: `Add file exists check on windows when installing archive` - Windows-specific path handling improvement

### Dialyzer Integration

- **Comprehensive type fixes**: Multiple commits addressing dialyzer warnings in core modules (elixir, iex, mix, logger)
- **Spec improvements**: `Fix mix dialyzer warnings and improve task specs` - enhanced type specifications for better static analysis

### Mix Tool Improvements

- **Dependency management**: `mix deps.unlock` now warns when given missing dependencies, preventing silent failures
- **Archive handling**: `Raise if status code != 0 and use non-verbose modes` - better error reporting during archive operations
- **Hex integration**: `Fetch Hex with wget or curl` - improved portability for Hex package fetching
- **Configuration handling**: `Ensure we don't look up inexisting variables for default args` - more robust configuration parsing

### Document Quality

- **IEx improvements**: `Make the regex type non-opaque` - allows users to inspect regex internals more easily
- **Documentation fixes**: Multiple improvements to docstrings and examples across Stream, Task, and other modules

## Deprecations

The following APIs were deprecated, signaling future removals:

### Functional Deprecations

- **`Collectable.empty/1` and `Enum.traverse/2`** - Moving toward a more consistent traversal API
- **`Integer.odd?/1` and `Integer.even?/1`** - Deprecated in favor of guard clauses `is_odd/1` and `is_even/1`
- **`nil?/1`** - Deprecated in favor of `is_nil/1` guard, aligning with the move toward guard-based type checking
- **`record?/1` and `record?/2`** - Deprecated in favor of guard forms `is_record/1` and `is_record/2`
- **`GenEvent.monitor` option** - The `:monitor` option in handler addition/swapping is deprecated in favor of `add_mon_handler/3` and `swap_mon_handler/5`, providing explicit monitored handler APIs

### Syntax Deprecations

- **`x.Alias` syntax** - This shorthand for module concatenation is deprecated in favor of explicit `Module.concat/2` calls, encouraging clearer code
- **Stream.resource return format** - Returning `{item, acc} | nil` is deprecated in favor of `{[item], acc} | {:halt, acc}`, aligning with `Stream.transform/3`

These deprecations are notable for being well-reasoned, replacing problematic patterns with clearer alternatives or guard-based approaches that align with Erlang conventions.

## Breaking Changes

The release includes carefully considered backwards-incompatible changes:

### Major Breaking Changes

1. **`List.unzip/2` removed** - Identified as broken and removed entirely rather than fixed. This suggests the function had fundamental design issues.

2. **GenEvent stream mode changes**:
   - `:mode` and `:duration` options are no longer supported in `GenEvent.stream/2`
   - The mode is now a property of the sender, not the stream configuration
   - `:linked` option removed in favor of monitored handlers
   - These changes reflect a fundamental rethinking of GenEvent stream semantics

3. **GenEvent handler swap return values**:
   - `{:swap_handler, ...}` return value from handlers no longer supported
   - This was a rarely-used feature that complicated the event handling protocol

4. **Supervisor defaults**:
   - `max_restarts` now defaults to 3 (was previously higher)
   - Convergence with Erlang defaults improves cross-language compatibility

### Impact Assessment

The breaking changes are relatively conservative for a major version release. Most are removal of deprecated features (scheduled for removal in advance) or refinements to APIs that were new enough to break without extensive ecosystem impact (GenEvent stream options, handler behavior).

## Why v1.0.0?

Several factors made this release worthy of the 1.0.0 designation:

1. **Production Readiness**: Extensive race condition fixes and stability improvements in core systems (Logger, GenEvent, Supervisor) demonstrate production maturity

2. **API Stability**: By removing previously deprecated features and carefully selecting breaking changes, the release establishes stable APIs that users can build upon

3. **Ecosystem Maturity**: Logger introduction (appeared in v0.15.0) has matured significantly, GenEvent is refined, Stream API is comprehensive

4. **Tool Completeness**: Mix has reached a high level of functionality with proper escript support, protocol consolidation, and dependency management

5. **Language Stability**: No major syntax changes, focus on refinement rather than innovation. The operator additions are carefully scoped for DSL use cases.

6. **Deprecation Clarity**: Clear deprecation paths for all breaking changes allow library authors to prepare for the release

## Development Velocity

The 194 commits over 5 weeks (approximately 39 commits per week) demonstrates intense development activity concentrated on stability rather than new features. The ratio of bug fixes to new features is notably high, indicating a "release candidate to stable" maturation process rather than a feature-addition phase.

## Technical Debt Management

Notable attention to technical quality:
- Multiple dialyzer warning fixes across all major modules
- Race condition fixes in critical systems
- Architectural decoupling (Mix from Logger)
- Code duplication removal
- Test suite cleanup and hardening

This focused effort on code quality rather than feature addition solidifies the argument for a 1.0.0 release - the language has reached a stability plateau suitable for production use.
