# Changes from v1.2.6 to v1.3.0

## Overview

This release represents a major update to Elixir, spanning **1,093 commits** over approximately **6 months** (December 24, 2015 to June 21, 2016). Elixir v1.3 brings significant improvements to the language semantics, introduces new calendar types, and substantially enhances the Mix build tool and ExUnit testing framework.

## Date Range and Commit Statistics

- **Release Date**: June 21, 2016
- **Previous Release**: December 24, 2015
- **Total Commits**: 1,093
- **Duration**: Approximately 6 months of development

## Key Themes and Analysis

This release focuses on three major areas:

1. **Language Semantics & Types** - New calendar data types and stricter variable scoping rules
2. **Developer Tooling** - Mix compilation improvements and static analysis capabilities
3. **Testing Infrastructure** - Enhanced ExUnit with diffing, selective test running, and better formatting

### Major Language Improvements

#### 1. Deprecation of Imperative Assignment (Breaking Change)

Elixir v1.3 introduces warnings when variables assigned in control flow blocks (`if`, `case`, `with`) are accessed in outer scopes. This is a semantic shift toward explicit data flow:

```elixir
# Now warns about implicit variable reassignment in if block
if condition do
  message = "modified"
end
# message is used outside the block
```

**Rationale**: This prevents subtle bugs when refactoring code and enforces more explicit variable handling. Future releases will make this a hard error.

#### 2. Calendar Types and Sigils (New Feature)

Introduction of four new built-in types for date/time handling with corresponding sigils:

- **`Date`** - Simple date representation (year, month, day)
- **`Time`** - Time representation (hour, minute, second, microseconds)
- **`NaiveDateTime`** - DateTime without timezone information
- **`DateTime`** - Full datetime with timezone support

Corresponding sigils:
- `~D[2016-05-29]` - Date literal
- `~T[08:00:00]` or `~T[08:00:00.285]` - Time literal
- `~N[2016-05-29 08:00:00]` - NaiveDateTime literal

**Impact**: Provides standardized datetime handling across the ecosystem, enabling better library interoperability. Conversions from/to strings, Erlang tuples, and Unix timestamps are supported.

#### 3. Access Module Enhancements (New Feature)

New accessors for traversing and updating nested data structures with improved ergonomics:

```elixir
user = %{name: "john", languages: [%{name: "elixir"}, %{name: "c"}]}
update_in user, [:languages, Access.all(), :name], &String.upcase/1
# Result: %{name: "john", languages: [%{name: "ELIXIR"}, %{name: "C"}]}
```

Provides functional programming patterns for deeply nested data manipulation.

## Major Features & Improvements

### A. Mix Build Tool Enhancements

#### 1. Cross-Reference Analysis (`mix xref`)

New task for static analysis and code introspection:
- **`mix xref unreachable`** - Find calls to non-existent modules/functions
- **`mix xref callers MODULE.function/arity`** - Find all callers of a function
- **`mix xref graph`** - Visualize module dependencies as DOT format
- Automatically runs as a compiler (`compile.xref`) to catch issues early

**Commits**: Multiple commits related to xref (#4818, #4811, #4808)

#### 2. Better Dependency Tracking

Improved module tracking for faster incremental compilation:
- Changes to path dependencies now only recompile affected modules (not the whole project)
- Umbrella applications are much faster to work with - changing a sibling app only recompiles what depends on it
- Internal improvements to manifest storage (using ETF format instead of text-based)

**Relevant commits**: "Store only filename of beam files in elixir manifest (#4767)", "use ETF for elixir_scm and protocols manifests (#4779)"

#### 3. Compilation Output Improvements

Cleaner build output by default:
- No longer prints every file being compiled
- Shows aggregate "Compiling N files (.ext)" instead
- Announces files taking longer than 5 seconds to compile (threshold configurable)
- Reduced compiler heuristics (only 2 instead of 5) to avoid false positives

**Related commits**: Multiple compiler heuristic and manifest simplification changes

#### 4. New Mix Tasks

- **`mix app.tree`** - Shows application dependency tree (what needs to boot)
- **`mix deps.tree`** - Shows dependency tree recursively
- **`mix escript.install`** / **`mix escript.uninstall`** - Manage command-line escripts separately from archives
- **`mix test --stale`** - Only runs tests affected by file changes (uses static analysis)
- **`mix profile.fprof --warmup`** - Profile code with warmup iterations

#### 5. Option Parser Integration

Strict option parsing in Mix tasks:
- New functions: `OptionParser.parse!/2` and `OptionParser.parse_head!/2` that raise on invalid options
- Mix tasks now validate options and provide helpful error messages
- Invalid options are no longer silently discarded

### B. ExUnit Testing Framework

#### 1. Diffing Support

Automatic diff display for failed assertions using `==`:

```elixir
# Before: Shows full values
# After: Shows highlighted diff with red (removed) and green (added)
assert "fox jumps over the lazy dog" == "brown fox jumps over the dog"
```

Uses Myers difference algorithm (`String.myers_difference/2`) for efficient comparison.

**Commits**: Related to assertion diffing and comparison enhancements

#### 2. Selective Test Running (`mix test --stale`)

Leverages `mix xref` to intelligently run only affected tests:
- If a test file changes, run that file
- If a library file changes, run tests that depend on it (directly or indirectly)
- If `mix.exs` or `test_helper.exs` changes, run all tests

Dramatically speeds up development feedback loop.

#### 3. Test Organization Improvements

- **`describe/2`** - Bundle related tests together with better output formatting
- **Named setups** - Support for named `setup` and `setup_all` blocks for clearer test structure
- **Test type registration** - Libraries like QuickCheck can register custom test types and formatters
- **Pinned variable display** - Failed `assert ^left = right` assertions show which variables were pinned

#### 4. Other ExUnit Features

- Raise helpful error on duplicate test names
- Start running tests as soon as cases load (default when using Mix)
- Double the default max case count to support both IO and CPU-bound tests
- Support for bundling tests with `describe/2`
- `ExUnit.Case.register_attribute` for custom test attributes with cleanup

### C. Standard Library Enhancements

#### Enum Module
- `Enum.group_by/3` ordering behavior documented and changed (soft-deprecated dict support)
- `Enum.take_random/2` - Optimized with corrected typespec
- Various optimizations for range-based operations

#### String Module
- `String.myers_difference/2` - Calculate differences between strings (used for diffing)
- `String.trim/2`, `String.trim_leading/2`, `String.trim_trailing/2` - New names replacing deprecated strip functions
- `String.pad_leading/3`, `String.pad_trailing/3` - Replacing deprecated ljust/rjust
- Support for empty strings in `String.contains?`, `String.starts_with?`, `String.ends_with?`

#### Date/Time/DateTime Modules (New)
Complete implementation of calendar types with:
- Constructor functions: `Date.new/3`, `Time.new/4`, `NaiveDateTime.new/7`, `DateTime.new/8`
- Sigils: `~D`, `~T`, `~N`
- Conversions: `to_iso8601`, `to_erl`, `from_erl`, `from_iso8601`
- Unix timestamp support: `DateTime.to_unix/2`, `DateTime.from_unix/3`
- Time zone handling in `DateTime`

#### URI Module
- `URI.merge/2` - Merge two URIs following RFC 3986
- URI specs updated for OTP 19 support

#### Regex Module
- `Regex.split/3` now supports `:include_captures` option
- Option `/r` (ungreedy) deprecated in favor of `/U`

#### System Module
- `System.os_time/0` and `System.os_time/1` - Get OS time at various precisions

#### Typespec Improvements
- Support for `%{required(key) => type}` and `%{optional(key) => type}` map forms (Erlang 19+)
- Support for `%{...}` to mean "any map" (Erlang 19+)
- `@optional_callbacks` attribute for marking optional protocol implementations

#### Other Modules
- `Logger.reset_metadata/0,1` - Reset logger metadata
- `Version.parse!/1` - Raise-variant of version parsing
- Range: `Range.range?/1` validates range correctness
- `Task.find/2` deprecated in favor of explicit message matching

### D. Compiler and Internal Improvements

#### Parallel Compilation
- Fixed issue where parallel compiler would send found message multiple times
- Better handling of case loading during compilation failures
- Keep full list of modules being defined for better error reporting

#### Manifest Management
- Manifest now stores only filenames instead of full paths (deterministic)
- Sorted entries to avoid non-determinism in compilation
- Use ETF (Erlang Term Format) for elixir_scm and protocols manifests for faster I/O
- Consolidated protocols nuke when changing Elixir versions

#### Variable Scoping
- Ensure variables in function clauses are not reused unexpectedly (#4815)
- Do not leak external variables used in guards in `assert_receive`
- Make sure `with/1` does not leak variables to else blocks (#4804)

#### Macro & Kernel Improvements
- `@enforce_keys` for defstruct/defexception - enforces required keys on struct creation
- Struct expansion via `__struct__/1` for more flexible struct implementations
- Improved keyword difference highlighting
- Better handling of variables captured by modules
- Support for capture operator with arguments above `&191`

#### Performance Optimizations
Multiple optimization commits improve compilation and runtime:
- Use tail-recursive implementations for `zip`, `take`, `take_while` in Enum
- Optimize range construction with integer literals
- Optimize `in/2` in match/guard contexts
- Use more efficient implementations for date/time operations
- Calculate beam files only when writing manifest data
- Only call compile_path when effectively needed

## Breaking Changes & Deprecations

### Deprecations (with warnings)

1. **String Module**
   - `String.strip/2` → Use `String.trim/2`
   - `String.lstrip/2` → Use `String.trim_leading/2`
   - `String.rstrip/2` → Use `String.trim_trailing/2`
   - `String.ljust/3` → Use `String.pad_leading/3`
   - `String.rjust/3` → Use `String.pad_trailing/3`

2. **Kernel Module**
   - `\x{H*}` in strings/sigils/charlists is deprecated
   - `defdelegate` with list arguments and `:append_first` option
   - **Variable assignment in control flow blocks** - Will warn and error in future versions

3. **Dict & Set Modules**
   - `Dict` is no longer a behavior (will be deprecated in future releases)
   - `Set` is no longer a behavior (will be deprecated in future releases)
   - Passing dict to `Enum.group_by/3` is deprecated

4. **Other Deprecations**
   - `Keyword.size/1` → Use `Kernel.length/1`
   - `Map.size/1` → Use `Kernel.map_size/1`
   - `Regex` option `/r` → Use `/U` (ungreedy)
   - `String.valid_character?/1` → Use `String.valid?/1` with pattern matching
   - `Task.find/2` → Use explicit message matching
   - `Float.to_string/2`, `Float.to_char_list/2` (soft-deprecated, no warnings)

### Soft Deprecations (no warnings)

- Function naming: `to_char_list` → `to_charlist` (aligns with Erlang/Elixir conventions)
- Typespec: `char_list` → `charlist`
- Float representation: Will attempt shortest accurate representation by default

### Semantic Changes

1. **Variable Assignment in Control Flow** - Warnings introduced for implicit variable rebinding in `if`, `case`, `with` blocks when the variable is used outside the block

2. **Float Printing** - Now prints shortest possible representation instead of always using full precision

3. **Enum.group_by/3** - Behavior change when passing dictionaries (deprecated support removed)

## Upgrade Path & Recommendations

3. **Review Dict/Set usage** - These modules will be deprecated soon; migrate to Map/MapSet

5. **Use new calendar types** - Migrate datetime handling to new Date/Time/NaiveDateTime/DateTime types

- **Better error messages** - Assertion diffs and static analysis warnings

- **Cleaner code** - Better variable scoping rules encourage explicit data flow

## Summary

Elixir v1.3.0 represents a maturation of the language with focus on developer productivity and language semantics. The introduction of calendar types brings much-needed standardization to datetime handling, while the Mix and ExUnit improvements significantly enhance the development experience. The deprecation of imperative assignment patterns, though initially disruptive, guides developers toward more explicit and maintainable code patterns.

The 1,093 commits demonstrate a comprehensive and well-structured release addressing language improvements, tooling enhancements, performance optimizations, and bug fixes across the entire Elixir ecosystem.
