# Changes from v0.13.1 to v0.13.2

## Overview
- **Release Date Range**: April 27, 2014 - May 11, 2014 (14 days)
- **Total Commits**: 187
- **Release Date**: May 11, 2014

## Summary

Version 0.13.2 represents a significant internal refactoring and infrastructure improvement for Elixir. The primary theme is a systematic conversion of internal record-based data structures to structs, which offers better performance, cleaner code, and improved tooling support. Alongside this major refactoring effort, the release includes critical improvements to configuration management, exception handling, error formatting, and compatibility with Erlang 17.0.

The release also emphasizes deprecations and soft-deprecations to prepare the codebase for future versions, removing technical debt and standardizing APIs with OTP naming conventions. These changes demonstrate Elixir's commitment to evolving its core infrastructure while maintaining backward compatibility during the transition period.

## Major Themes

### 1. **Records to Structs Migration** (Primary Focus)
The most extensive change across this release is the systematic conversion of internal Elixir records to structs. This is a foundational improvement that impacts multiple areas:

**Core Data Structures Converted:**
- `Macro.Env` - The compilation environment representation
- `ExUnit.Test` and `ExUnit.TestCase` - Test framework structures
- `Range` - Range representation
- `Regex` - Regular expression structures
- `HashSet` and `HashDict` - Collection types
- `File.Stat` - File statistics information
- `Inspect.Opts` - Inspection configuration
- `Stream.Lazy` - Lazy stream representation
- `Version.Schema`, `Version.Requirement` - Version management
- `Kernel.CLI.Config` - Command-line configuration
- `StringIO` - String I/O operations (with revert)
- `URI` and `Inspect.Algebra` - URI parsing and inspection formatting

**Benefits:**
- Improved performance through more efficient memory representation
- Better compatibility with Elixir's pattern matching
- Cleaner separation between public and private fields
- More predictable behavior with guards
- Easier debugging and introspection

### 2. **Configuration System Overhaul**
A new configuration framework is introduced to provide centralized configuration management:

**Key Additions:**
- Initial implementation of `Mix.Config` system with `persist/1` function
- `Normalize IEx and ExUnit configurations` - Unified configuration approach
- `Allow mix/apps configuration via ~/.mix/config.exs` - User-level configuration support
- Migration of Mix's internal record-based configuration to maps
- Improved configuration handling in generated applications

**Impact:** Developers can now configure Elixir tools globally and project-wide in a consistent manner, reducing boilerplate and improving maintainability.

### 3. **Exception and Error Formatting Improvements**
Significant work was done to create consistent, informative error messages:

**Key Changes:**
- `Format exceptions consistently` - Unified exception formatting across the system
- `Improve application error formatting` - Better error messages for OTP supervision tree failures
- `Rename Application.format_reason/1 to format_error` - API consistency with OTP modules
- `Add Exception.message/1` - Standardized exception message extraction
- `Improve OTP behaviour error formatting` - Better `:gen_server` exit reason formatting

**Benefits:** Users see clearer, more consistent error messages that help with debugging. The formatting now handles nested supervision tree failures and complex OTP patterns.

### 4. **String and Regex API Standardization**
Changes to align `String.split` behavior with `Regex.split`:

**Deprecations Introduced:**
- Soft-deprecate `:global` option in both `Regex.split/3` and `String.split/3`
- New `:parts` option replaces `:global` for more intuitive control
- `parts: :infinity` becomes the standard way to split globally

**Enhancement:**
- `Support functions in Regex.replace/4` - Allows dynamic replacement logic

**Impact:** More predictable and consistent API behavior between string and regex operations.

### 5. **IEx and Shell Enhancements**
Multiple improvements to the interactive shell experience:

**Features Added:**
- `Print help when --help, -h, or /h are given on windows` - Better Windows support
- `Bring the multiple .iex.exs functionality` - Support for multiple initialization files
- `Use IO.ANSI.Docs to format mix help` - Better formatted help output
- `Ensure IEx.pry works with iex -S mix test (--trace)` - Debugger support in test mode
- `Fix iex startup` - Reliability improvements
- `Disable ANSI on Windows` - Windows console compatibility

**Impact:** Improved user experience in the interactive shell, particularly on Windows, and better debugging capabilities.

### 6. **Erlang 17.0 Compatibility**
Critical fixes for compatibility with Erlang 17.0:

**Changes:**
- `Fix remote calls to work with dialyzer in 17.0` - Abstract code compatibility
- `Fix compiler abstract code` - Proper dialect handling for dialyzer
- `Fix some dialyzer warnings` - Multiple dialyzer-related fixes
- `Add a target to check minimum required Erlang version` - Build-time version verification
- Updated Erlang version references in documentation

**Impact:** Ensures Elixir works smoothly with Erlang 17.0 while maintaining compatibility with dialyzer.

## Breaking Changes

While the release maintains general backward compatibility, there are several API-level changes:

### API Renamings (Breaking)
1. **`Application.format_reason/1` → `format_error/1`** - Functions renamed for OTP naming convention alignment
2. **`symlink/2` → `ln_s/2` in File module** - File operations API update
3. **Rename of internal format functions** - `format_message` to `format_banner`, `format_reason` to `format_exit`

### Soft Deprecations (Warnings, Still Functional)
1. **`is_exception/1`** - Use `Exception.exception?/1` instead
2. **`:global` option in `String.split/3` and `Regex.split/3`** - Use `parts: :infinity` instead
3. **`Mix.project/0`** - Internal API, prefer newer approaches
4. **`Process.delete/0`** - Function marked for removal
5. **Process module functions** - Some duplicated functions soft-deprecated in favor of Kernel equivalents

### Data Structure Changes
- Internal records converted to structs - This is transparent for public APIs but may affect code that directly pattern matches on internal structures
- Mix internal configuration changed from records to maps

## Conclusion

Version 0.13.2 is primarily an **internal infrastructure release** that modernizes Elixir's codebase through systematic conversion of records to structs and introduction of a proper configuration framework. While the end-user-facing features are limited, the internal improvements provide a stronger foundation for future development and better performance characteristics.

The release carefully manages deprecations, giving users time to migrate to new APIs (like `Exception.exception?/1` and `parts: :infinity`). The focus on Erlang 17.0 compatibility and tooling improvements demonstrates Elixir's commitment to staying current with the Erlang ecosystem while improving the developer experience through better error messages, debugging support, and build system enhancements.

Key themes:
- **Infrastructure Modernization**: Records → Structs
- **Configuration System**: New Mix.Config framework
- **Error Handling**: Consistent, informative exception formatting
- **Erlang 17.0**: Full compatibility with latest Erlang
- **Developer Experience**: Better debugging, testing, and help output
