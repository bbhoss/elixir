# Changes from v1.7.1 to v1.7.2

## Overview

**Release Date:** August 5, 2018
**Previous Release:** July 26, 2018
**Duration:** 10 days
**Total Commits:** 13

This was a focused patch release addressing critical bugs discovered shortly after v1.7.1 launch. The development cycle was rapid with intensive debugging on August 3-4.

---

## Summary

Elixir v1.7.2 is a bug fix release that addressed several critical issues in core functionality and tooling. Rather than introducing new features, this release focused on stabilizing the v1.7.0 features (particularly around documentation metadata, stacktrace handling, and logging) and fixing problems in Mix, IEx, and DateTime handling.

The most impactful fixes address deadlock issues in Mix, calendar handling for edge cases with negative years, and important test suite behavior for umbrella applications.

---

## Key Themes and Changes

### 1. **DateTime/Calendar Robustness (2 commits)**

The DateTime module received critical fixes for handling negative years, which is important for historical date calculations. This was split into two commits:

- **Initial fix** (2018-08-03): Added support for negative years in `DateTime.from_iso8601/1`. This accounts for dates BC (Before Common Era).
- **Follow-up fix** (2018-08-04): Fixed an additional issue with year offsets when dealing with negative datetimes that include timezone offsets. The test suite was expanded with 38 additional test cases to ensure edge cases are covered.

**Impact:** Ensures historical and BC dates can be properly parsed and handled without errors.

### 2. **Mix Stability and Correctness (3 commits)**

Mix received several important fixes addressing both functional correctness and concurrency issues:

- **Deadlock Prevention** (2018-07-31): Fixed a critical deadlock in `Mix.ProjectStack` that occurred when a project configuration file had a timestamp later than the current system time. This is a concurrency issue that could cause Mix to hang indefinitely.

- **Dependency Resolution** (2018-08-04): Properly marked top-level optional dependencies from child dependencies. This was a significant bug where Mix would attempt to start optional dependencies that weren't actually available in the dependency tree, causing startup failures.

- **Task/Alias Disambiguation** (2018-07-31): Enhanced `mix help` to handle cases where both a task and alias share the same name. Now displays documentation for both, clearly indicating when this situation occurs.

**Impact:** Mix is more reliable and provides better developer experience when dealing with complex dependency trees and help queries.

### 3. **Test Suite Improvements (1 commit)**

- **No Failure on Missing Tests** (2018-08-04): Changed behavior so `mix test` reports information but doesn't fail when there are no test files to run. This is especially important for umbrella applications where some sub-apps may not have Elixir tests (e.g., pure Erlang applications or documentation-only packages).

**Impact:** Umbrella applications with mixed content types now work seamlessly without artificial failures.

### 4. **Compiler and Documentation Quality (2 commits)**

- **False Positive Warning Removal** (2018-07-28): Removed warnings for repeated documentation in the same clause. The warning was causing false positives when overriding the docs of overridable definitions.

- **Alias Documentation Unification** (2018-07-31): Unified how alias documentation is handled internally.

**Impact:** Developers no longer see spurious warnings when defining documented overridable functions.

### 5. **IEx Helper Refinement (1 commit added, 1 reverted)**

- **ref/4 Helper Fix** (2018-08-04): Attempted to fix errors with the `ref/4` IEx helper and added documentation and tests for it.
- **Reversion** (2018-08-04): The fix was reverted the same day (a few hours later) due to issues that emerged.

**Impact:** The helper was left in its previous state, with the team deciding a more thorough fix was needed for a future release.

### 6. **Documentation Improvements (1 commit)**

- **System.cmd() Documentation** (2018-08-04): Minor formatting improvements to documentation for `System.cmd()` parentheses handling.

## Major Features/Improvements

This release contained **no new features**. It was purely focused on bug fixes and stabilization of existing v1.7.0 features.

The most significant "improvements" are actually fixes that improve reliability:

1. **DateTime with historical dates** - Now properly handles BC dates and edge cases
2. **Mix deadlock elimination** - Prevents hangs when configuration files have future timestamps
3. **Dependency resolution accuracy** - Correctly marks optional dependencies, preventing startup failures
4. **Better help commands** - Mix help now handles name conflicts gracefully

---

## Bug Fixes

### Elixir Core

1. **DateTime.from_iso8601/1** - Fixed parsing of ISO 8601 timestamps with negative years
2. **DateTime with timezone offsets** - Fixed year calculation in negative datetimes with offset information
3. **Module documentation warnings** - Stopped emitting false positive warnings for repeated docs in overridable definitions

### Mix

1. **ProjectStack deadlock** - Fixed concurrency issue causing hangs with future-dated config files
2. **Optional dependency marking** - Properly marks transitive optional dependencies, fixing startup failures
3. **mix help disambiguation** - Shows both task and alias documentation when names conflict
4. **mix test behavior** - No longer fails when test directory is empty (important for umbrella apps)

### IEx

1. **ref/4 helper** - Attempted fix (later reverted)

---

## Breaking Changes

**None.** This was a purely backwards-compatible patch release. All changes are bug fixes that improve compatibility and stability without modifying APIs or changing behavior in breaking ways.

## Release Context

Elixir v1.7.2 came just 10 days after v1.7.1, indicating that users quickly discovered critical issues in the v1.7.0 release. The rapid turnaround (particularly with 5 commits on August 4th) suggests the team was actively addressing user-reported problems.

This patch release maintained the commitment to v1.7 stability while working towards v1.8 development. The focus on practical issues (deadlocks, test suite behavior in umbrella apps, dependency resolution) reflects the Elixir team's dedication to production stability.

---

## Conclusion

v1.7.2 represents a "stabilization" release that fixed concrete issues users encountered with v1.7.0's new features. Rather than adding functionality, it ensured that Mix, DateTime handling, and test execution work correctly in real-world scenarios. The two DateTime fixes are particularly important for applications dealing with historical data, while the Mix fixes address critical pain points in dependency management and the development workflow.
