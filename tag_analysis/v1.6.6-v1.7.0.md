# Changes from v1.6.6 to v1.7.0

## Release Information

**Release Date Range:** June 20, 2018 (v1.6.6) to July 25, 2018 (v1.7.0)
**Duration:** 35 days
**Total Commits:** 740 commits
**Notable:** This was the last Elixir release to support Erlang/OTP 19. Users are encouraged to migrate to Erlang/OTP 20+.

---

## Summary: Key Themes and Strategic Direction

Elixir v1.7 represents a significant release focused on **standards compliance, runtime integration, and developer tooling improvements**. The release implements the EEP 48 documentation standard for better interoperability across the Erlang VM ecosystem, introduces improved error reporting and diagnostics, and deepens integration with Erlang/OTP 21's new features.

The release prioritizes **developer experience** through better error messages, enhanced documentation capabilities, and improved testing infrastructure. The 740 commits reflect a **heavy emphasis on code quality** with nearly 50% of commits being bug fixes, optimizations, and documentation improvements.

---

## Major Features and Improvements

### 1. **EEP 48 Documentation Metadata (Transformative Change)**

The implementation of the Erlang Enhancement Proposal (EEP 48) is the most significant architectural change in this release. This enables standardized documentation across the entire Erlang VM ecosystem.

**Key Changes:**
- `Code.fetch_docs/1` - New function to retrieve documentation in EEP 48 format
- Documentation metadata support on `@doc`, `@moduledoc`, and `@typedoc`
- Metadata can now include arbitrary keys (`:since`, `:deprecated`, `:author`, etc.)
- IEx and ExDoc updated to display and leverage this metadata
- `Code.get_docs/2` hard-deprecated in favor of `Code.fetch_docs/1`

**Impact:** This enables better IDE support, automatic documentation generation with rich metadata, and improved version tracking of functions.

### 2. **The `__STACKTRACE__` Construct (Erlang/OTP 21 Integration)**

Introduces a lexically-scoped stacktrace mechanism replacing the side-effect dependent `System.stacktrace/0`:

```elixir
# Old way (still works but side-effectful)
try do
  something()
rescue
  e -> log(e, System.stacktrace())
end

# New way (Erlang/OTP 21+)
try do
  something()
rescue
  e -> log(e, __STACKTRACE__)
end
```

**Benefits:**
- Eliminates side-effects from stacktrace retrieval
- Enables compiler optimizations (lexical scope allows precise tracking)
- Becomes a requirement for Erlang/OTP 21+ (future-proofing)

### 3. **Enhanced Exception and Error Handling**

Error messages received significant improvements with better blame callbacks and contextual information:

- **KeyError:** Added "did you mean" suggestions for struct field access failures
- **ArithmeticError:** Provides more detailed information on Erlang/OTP 21+
- **ArgumentError:** Better context in apply/3 errors
- **Generic improvements:** Caller information, struct expansion errors, and nil dispatch errors now include more helpful context

**Real-world benefit:** Developers debugging code will see exactly which field was being accessed, what alternatives were available, and the complete context.

### 4. **Erlang/OTP 21 Logger Integration**

Deep integration with Erlang/OTP 21's new `:logger` module:

- `Logger.Translator` mechanism enhanced to export metadata
- New metadata fields: `:crash_reason`, `:initial_call`, `:registered_name`
- Log messages in crash reports now include rich contextual data
- Better interoperability with Erlang libraries and tools

**Strategic importance:** Positions Elixir libraries to work seamlessly with the broader Erlang ecosystem.

### 5. **Logger Macro Argument Evaluation Optimization**

Logger macros (`debug`, `info`, `warn`, `error`) now only evaluate arguments when the message will actually be logged:

```elixir
# Before: expensive_operation() always evaluated, even at :debug level when not logging
Logger.info("Result: #{expensive_operation()}")

# After: expensive_operation() only called if info level is enabled
Logger.info("Result: #{expensive_operation()}")
```

**Performance impact:** Significant for applications with expensive logging operations or verbose log levels.

### 6. **Compile-Time Logger Call Purging**

New `:compile_time_purge_matching` configuration allows removing entire log calls at compile time:

```elixir
config :logger,
  compile_time_purge_matching: [
    [application: :foo, level_lower_than: :info],
    [module: Bar, function: "foo/3"]
  ]
```

**Use case:** Production deployments can completely eliminate debug logging without runtime overhead.

### 7. **New `Function` Module**

Introduction of a dedicated module for function introspection:

- `Function.capture/3` - Safely capture functions
- `Function.info/1` and `Function.info/2` - Introspect function properties

**Significance:** Improves metaprogramming capabilities and provides a unified interface for function-related operations.

### 8. **ExUnit Testing Improvements**

- **Function call assertions:** `assert some_fun(arg1, arg2)` now shows the evaluated values of each argument in failure reports
- **Colored doctests:** Failed doctests now display with diffs and coloring for better readability
- **Test filtering:** New `--failed` flag runs only tests that failed in the previous run
- **Coverage summary:** `mix test --cover` now displays a formatted summary table out of the box
- **Test tags:** Better error messages when `@tag`, `@moduletag`, or `@describetag` are used incorrectly

### 9. **StringIO Enhancement**

- `StringIO.open/3` - New function for better stream handling with automatic device closure

### 10. **Calendar and Date Enhancements**

- `Calendar.months_in_year/1` callback - Supports custom calendar implementations
- `Date.months_in_year/1` function
- `Calendar.ISO` support for negative dates
- Improved Unicode support (updated to Unicode 11)

### 11. **Code Compilation and Purging**

- `Code.compile_file/2` - Compiles files without system footprints (ideal for live systems)
- `Code.purge_compiler_modules/0` - Cleans up compiler artifacts from memory
- Better support for external build tools like Rebar

### 12. **Mix Improvements**

- **Archive/escript installation:** Support for `--organization` flag for Hex organization artifacts
- **Archive/escript uninstall:** New `--force` flag for non-interactive uninstalls
- **Help command:** Now lists command aliases
- **IPv6 support:** Uses IPv6 with automatic IPv4 fallback for downloads
- **Project configuration:** `Mix.Project.config_mtime/0` caches mtime values to reduce filesystem access
- **Dependency management:** Better tracking of configuration changes in umbrella projects
- **Compiler integration:** Improved support for non-Mix build tools

### 13. **GenServer Enhancements**

- `handle_continue/2` callback for Erlang/OTP 21+
- Deprecation of `super` in GenServer callbacks
- Improved documentation and behavior clarification

### 14. **Dynamic Supervisor Improvements**

- Automatically uses supervisor name as child ID when possible
- Better count_children behavior when children are restarting
- Support for multiple DynamicSupervisor instances to be started with simplified configuration
- Child spec improvements for Task.Supervisor

### 15. **Registry Enhancements**

- `Registry.count/1` - Count total entries
- `Registry.count_match/4` - Count entries matching a pattern

### 16. **String Processing Optimizations**

- `String.starts_with?/2` - Optimized implementation
- `String.ends_with?/2` - Optimized implementation
- `String.upcase/1` and `String.downcase/1` - Performant `:ascii` mode
- Added cursor movement functions to `IO.ANSI`

## Breaking Changes and Deprecations

### Hard Deprecations (Will error in a future release)

1. **Code.get_docs/2** - Replaced by `Code.fetch_docs/1` (EEP 48 compliant)
   - Old format returned a different structure
   - New format is standardized across Erlang VM

2. **Enum.chunk/2/3/4** - Replaced by `Enum.chunk_every/2/3/4`
   - `chunk_every` doesn't discard incomplete chunks by default
   - Better semantic clarity

3. **Stream.chunk/2/3/4** - Replaced by `Stream.chunk_every/2/3/4`
   - Same reasoning as Enum.chunk changes

4. **Exception.normalize/2 and Exception.format/2**
   - Removed in favor of `Exception.message/1`

5. **OptionParser dynamic option mode**
   - Deprecated due to inconsistent atom loading behavior
   - Static parsing is now the standard

6. **GenServer.super/0** in callbacks
   - Warn if `super` is used in GenServer callbacks
   - Intended for full removal in future version

7. **`not left in right` syntax**
   - Ambiguous and deprecated in favor of `left not in right`
   - Clarifies operator precedence

### Soft Deprecations (No warnings, but encouraged to migrate)

1. **Code.load_file/2** → Use `Code.compile_file/2`
2. **Code.loaded_files/0** → Use `Code.required_files/0`
3. **Code.unload_files/1** → Use `Code.unrequire_files/1`
4. **Logger.compile_time_purge_level** → Use `Logger.compile_time_purge_matching`

### Behavioral Changes (Require code updates)

1. **Logger argument evaluation:** Arguments now only evaluated when logged
   - Side effects in log arguments will not occur if log level is disabled
   - May affect code that relied on this behavior

2. **Stream.chunk and Enum.chunk behavior:** `chunk_every` doesn't discard incomplete chunks
   - Code relying on chunk discard must handle the final incomplete chunk

3. **Access.get/3 callback removal:** Removed from Protocol
   - Simplifies access protocol

4. **Unsafe variable handling:** Raises on unsafe variables
   - Previously could silently affect tail call optimization
   - Forces explicit handling of variable binding

## Notable Technical Improvements

### Performance Optimizations (20+ commits)

- **Keyword merging:** Optimized for empty lists
- **Enum operations:** Faster `to_list/1` for maps
- **String operations:** Optimized `starts_with?`, `ends_with?`, and ASCII mode upcase/downcase
- **Metadata handling:** Reduced nil leakage in metadata merging
- **Logger argument evaluation:** Lazy evaluation prevents unnecessary computation
- **Tokenizer:** Optimized comma handling
- **Coverage tracking:** ETS-based approach instead of in-memory storage

### Memory and Resource Management

- **__info__ generation:** Refactored to generate smaller assembly
- **Compiler module purging:** Ability to clean up after dynamic compilation
- **Stack trace handling:** Lexical scoping enables better garbage collection
- **Module compilation:** Better tracking to avoid stale module issues

### Compatibility and Standards

- Updated to Unicode 11
- Erlang/OTP 21.0 support (full integration)
- EEP 48 standard documentation format
- ISO 8601 date format in system info

## Conclusion

Elixir v1.7.0 represents a maturation of the language with a strong focus on **standards compliance, developer tooling, and runtime integration**. The 740 commits span across three primary areas:

1. **Standards and Interoperability (30%):** EEP 48 documentation, Erlang/OTP 21 integration
2. **Developer Experience (35%):** Better error messages, improved testing, enhanced tooling
3. **Quality and Reliability (35%):** Bug fixes, optimizations, documentation improvements

The release demonstrates the Elixir team's commitment to working well within the broader Erlang ecosystem while maintaining backward compatibility where possible and providing clear deprecation paths for necessary breaking changes.

For developers upgrading from v1.6.6, this is a recommended release that provides significant benefits with manageable migration effort. The deprecation path is clear, and most changes are backward compatible or result in improved behavior without code changes.
