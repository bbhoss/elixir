# Changes from v0.9.1 to v0.9.2

## Overview

**Release Date**: June 13, 2013
**Previous Release**: May 30, 2013
**Development Period**: ~14 days
**Total Commits**: 142

This release focused on String API expansion, Mix/Rebar integration improvements, language feature refinements, and comprehensive documentation updates. It represents significant progress in developer experience, particularly in the Mix build system and interactive development tools.

---

## Summary of Key Themes

### 1. String API Expansion and Improvements
The v0.9.2 release introduced important new string manipulation functions and optimized existing ones. The most significant addition was `String.contains?/2`, which provides a clean API for substring detection. This complemented significant optimizations to Unicode string operations.

### 2. Mix Build System and Dependency Management
Substantial work went into improving Mix's handling of Rebar dependencies and introducing umbrella project support. These changes addressed practical build challenges faced by developers integrating Erlang dependencies with Elixir projects.

### 3. IEx Interactive Development Features
A new testing framework for IEx was introduced, along with improvements to `capture_io` and module helper functions. This reflected a commitment to improving the interactive development experience, which is critical for Elixir adoption.

### 4. Language Feature Refinements
The `=~` operator was reimplemented for better performance and consistency, using `Regex.match?` or `String.contains?` depending on context. The implicit super arguments feature was deprecated in favor of explicit syntax.

### 5. Cross-Platform Compatibility
Multiple fixes for Windows compatibility issues, including proper handling of shell commands and environment variables, improved accessibility for Windows developers.

## Major Features & Improvements

### New Functions

1. **String.contains?/2** - A new function to check if a string contains another string or list of strings
   - Implements the inverse operation to existing string predicates
   - Supports checking multiple substrings at once
   - More readable than using `String.split/2` and checking the result

2. **Regex.escape/1** - Escape special regex characters
   - Supports both standard and extended regex syntax
   - Critical for safely interpolating user input into regular expressions
   - Prevents regex injection vulnerabilities

3. **IEx Test Framework** - A basic testing framework for IEx with documentation
   - Enables testing code snippets directly in IEx sessions
   - Introduces `capture_io/1` with optional `prompt` option
   - Provides `capture_iex/1` for capturing interactive shell output
   - Makes IEx a viable testing environment, not just exploration tool

### Optimization Work

1. **Unicode String Operations**
   - `String.downcase/1` and `String.upcase/1` optimized for Unicode
   - `String.rstrip/1` optimized for Unicode
   - Removed unnecessary accumulator pattern that was causing performance overhead
   - These are fundamental operations used throughout applications, so optimizations have broad impact

2. **Doctest Generation**
   - Optimized doctest generation performance
   - Addresses #1226 - improves compilation times for documentation-heavy projects

### API Improvements

1. **Operator Reimplementation: =~**
   - Reimplemented to intelligently use `Regex.match?` or `String.contains?` based on context
   - When matching against a string, uses `String.contains?` for better performance
   - When matching against a regex, uses `Regex.match?` with proper semantics
   - Makes the operator more intuitive and performant

2. **Mix Improvements**
   - **Rebar Dependency Support**: Significant work on handling Rebar dependencies
     - Added support for raw option in rebar deps
     - Changed internal representation from `project/rebar` to `manager/source` for clarity
     - Improved load_paths handling for rebar-based dependencies
     - Properly skip deps compilation in Rebar when Mix already compiles them

   - **Umbrella Project Support**: Mix now supports umbrella projects with dependencies
     - `mix new --umbrella` now generates projects with dependency management
     - Direct dependencies can be specified for umbrella children

   - **Mix Local Installation**: Added `--force` option to `mix local.install`
     - Allows overwriting existing installed files without prompts

3. **URI Improvements**
   - Implemented `Binary.Chars` protocol for `URI.Info`
   - Fixed `to_binary/1` to not ignore the path component
   - Better string conversion for URI structures

### Documentation Enhancements

1. **Module Attribute Documentation** (Addresses #1132)
   - Added support for `h AnyModule.__info__` in IEx
   - Comprehensive documentation of `__info__/1` callback
   - Provides reference documentation for all module attributes

2. **Record Module Documentation** (Addresses #1166)
   - Moved record description from separate documentation into `Record` module documentation
   - Improved the moduledoc to be more comprehensive

3. **Core Module Documentation**
   - `ExUnit.Callbacks` documentation extended with more details and examples
   - `defoverridable` and `super` documentation updated and improved
   - Fixed Record's moduledoc with more accurate content
   - ExUnit documentation now mentions mix and testing conventions

## Bug Fixes

### Critical Fixes

1. **Path.split/1** - Fixed a bug that was affecting path splitting logic (Addresses #1168)

2. **IEx Compatibility**
   - Fixed `iex -S mix` on Windows
   - Fixed IEx module source lookup for the `r/1` helper
   - Proper handling of Windows shell (COMSPEC environment variable)

3. **ANSI Escape Code Handling**
   - Fixed IEx result display to not interpret ANSI escape sequences
   - Prevents false interpretation of escape codes in strings
   - Critical for correct display of colored output and special characters

### String Function Edge Cases

1. **String Predicate Functions** (Addresses #1195)
   - Fixed edge cases in `String.starts_with?/2`, `String.ends_with?/2`, and `String.contains?/2`
   - Refactored `String.ends_with?` for correctness
   - No longer supports nested lists (simplified API surface)
   - Better handling of empty strings and edge cases

2. **Binary.Chars.List Error Messages**
   - Better error message when `to_binary` is called on invalid data types
   - Improved error reporting for incorrect list conversions

### Type Specification Fixes

1. **Enum.uniq/2** - Fixed incorrect type specification for the uniqueness function parameter

### Hash Dictionary Fix

1. **HashDict Key Comparison** - Fixed to use exact match for key comparison
   - Prevents subtle bugs where different representations of "equal" values might be treated as the same key

### Mix and Build System

1. **Recursive Task Execution** - Fixed issue where Mix tasks could run recursively from another task
   - Prevents unexpected behavior and task duplication

2. **Rebar Integration**
   - Properly wrap rebar command on Windows inside `escript.exe`
   - Handle raw option in rebar dependencies
   - Improved error messages for diverged dependencies

3. **ExUnit Integration**
   - Fixed code escaping in `ExUnit.Callbacks` docstring

### Shell and Environment

1. **Shell Script Dependencies** - Removed use of local variables in shell scripts
   - Reduces dependency on bash, improving portability
   - Some systems only have POSIX sh available

## Deprecations

### Language Features

1. **Implicit super Arguments** (Addresses #1234)
   - Using `super` without explicit arguments is now deprecated
   - Developers must explicitly list arguments when calling `super`
   - Encourages more explicit and readable code
   - Example: `super(arg1, arg2)` instead of implicit `super`

### API Changes

1. **Regex.index/2** - Deprecated in favor of `String.contains?` and `Regex.match?`
   - These newer functions provide clearer semantics
   - Removes redundant API surface

## Breaking Changes

### Behavioral Changes

1. **Implicit super Arguments** - Code using `super` without explicit arguments will need to be updated
   - Minor breaking change as this is a relatively uncommon pattern

2. **String Function API** - `String.starts_with?`, `String.ends_with?`, and `String.contains?` no longer support nested lists
   - Simplifies the API and prevents unexpected behavior
   - Align with principle of least surprise

### Regex Behavior

1. **Regex.index/2 Deprecated** - While not removed, this function is deprecated
   - Existing code continues to work
   - New code should use `String.contains?` or `Regex.match?` instead

## Conclusion

v0.9.2 represents a focused release that addressed practical pain points in the Elixir ecosystem:

- **String operations** were expanded and optimized, with new utilities like `String.contains?` and `Regex.escape`
- **Mix improvements** brought better Rebar integration and umbrella project support, making mixed Erlang/Elixir projects more feasible
- **IEx enhancements** transformed it from a simple REPL into a more capable development environment
- **Documentation** was significantly improved, particularly for advanced features like records, module attributes, and metaprogramming
- **Cross-platform support** was strengthened with Windows-specific fixes

The release demonstrates Elixir's commitment to both language completeness and developer experience, with particular attention to the practical needs of developers building real applications.
