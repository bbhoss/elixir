# Changes from v1.0.4 to v1.0.5

**Date Range:** April 7, 2015 to June 29, 2015
**Commit Count:** 37 commits
**Release Date:** June 29, 2015

## Summary

Elixir v1.0.5 is a maintenance release focused on Erlang 18 compatibility, critical bug fixes, and performance improvements. This was a significant compatibility update, as Erlang 18 introduced breaking changes to the maps module and logger behavior that required fixes throughout Elixir's codebase. Beyond the compatibility work, the release included targeted optimizations for string operations, fixes for subtle race conditions in testing and logging, and various improvements to standard library functions.

## Major Features & Improvements

### Erlang 18 Compatibility (Major Focus)

The most significant work in this release was ensuring full compatibility with Erlang 18. This version of Erlang included several breaking changes that required adjustments in Elixir:

- **Maps module changes**: Fixed handling of `badkey` and `badmap` error tuples, which changed their structure in Erlang 18. The fix ensures proper normalization of these errors in rescue clauses and only enables the new behavior on Erlang 18+ systems.

- **Logger behavior overhaul**: Erlang 18 introduced a new logger system that changed how process crashes are reported and translated. Elixir updated its logger translator to handle the new error message formats from the Erlang emulator, particularly for temporary workers in `simple_one_for_one` supervisors that previously returned `:undefined` arity.

- **Test updates**: Moved the test suite to run against Erlang 18 with proper logger behavior expectations, ensuring the test suite accurately reflects the runtime environment.

### Performance Optimizations

Several string manipulation functions received significant performance improvements:

- **rstrip optimization**: Implemented a more efficient algorithm for the `rstrip/1` function. The new implementation achieves ~25x faster performance on 100-byte strings compared to the previous implementation, while maintaining the same behavior for smaller samples.

- **Case conversion speedup**: Optimized `String.upcase/1` and `String.downcase/1` for large strings, providing noticeable performance improvements for bulk string operations.

### Stream & Collection Improvements

- **Stream.take/1 fix**: Fixed `Stream.take/1` to ensure it doesn't consume more elements from the underlying stream than requested. This is a subtle but important fix for correct lazy evaluation behavior.

- **Stream.flat_map halt handling**: Improved outer halt consideration in `flat_map` when the operation itself is a halt, preventing incorrect behavior in complex streaming pipelines.

### Version Handling

- **Pre-release version formatting**: Fixed `Version.to_string/1` to correctly handle numeric pre-release versions. Previously, multiple pre-release parts were joined directly; now they are properly joined with dots (e.g., `1.0.0-alpha.1` instead of `1.0.0-alpha1`).

- **Pre-release typespec**: Corrected the typespec for the `Version.pre` field to accurately reflect the allowed values.

### IEx Improvements

- **Autocompletion reliability**: Fixed non-fixed table errors that could occur during IEx autocompletion by relying on `loaded_applications` instead of `running_applications`. This simplifies the code, makes completion faster, and is more reliable for detecting available modules.

### String Case Conversion

- **Acronym underscore handling**: Fixed `String.to_atom/1` and related functions to properly underscore acronyms followed by paths, improving consistency in naming conversions.

### IO Operations

- **Binary file reading**: Changed `IO.binread(:all)` to read in 4KB blocks instead of line-by-line. This fixes incorrect handling of CR+LF (0x0D0A) sequences in binary files that span multiple lines, a critical issue for cross-platform file processing.

## Bug Fixes

### Critical Fixes

1. **StringIO leak in ExUnit**: Fixed `ExUnit.CaptureIO` that was leaking `StringIO` processes, which could cause test suite failures and resource exhaustion in projects with many tests.

2. **Logger translator race conditions**: Fixed multiple race conditions in logger translator tests and real-world usage, particularly around concurrent process crashes and temporary workers.

3. **GenEvent module loading**: Fixed `GenEvent` to properly detect and handle modules that exist but aren't yet loaded in memory.

4. **Float parsing**: Delegated `Float.parse/1` to `:erlang.binary_to_float` for more reliable and consistent parsing behavior.

5. **EEx buffer contamination**: Fixed issue where blocks could clobber the EEx render buffer, causing incorrect output generation in templates with complex block structures.

### Record Extractor Enhancement

- **Macro expansion in records**: Updated the record extractor to use `:epp.parse_file/2` instead of `:epp_dodger.quick_parse_file/1`, enabling proper expansion of attributes and macros in record definitions. This provides better support for more complex record patterns.

### Configuration Handling

- **Escript config escaping**: Fixed a bug where configuration values were not properly escaped before being injected into escript files, potentially causing encoding or evaluation issues when generating standalone executables.

## Documentation Improvements

The release included several documentation enhancements:

- **Bitstring syntax docs**: Backported improvements to `<<>>` (bitstring/binary) documentation with clearer examples and better explanations.

- **Logger documentation**: Expanded documentation for Logger, including better documentation of exit reasons and behavior with simple one-for-one supervisors.

- **~> operator docs**: Added more comprehensive documentation for the `~>` (compatible release) version requirement operator.

- **Wording improvements**: Various clarifications and improvements to existing documentation across multiple modules.

## Breaking Changes

None identified. This was a pure maintenance and compatibility release.

## Technical Themes

This release demonstrates Elixir's pragmatic approach to version compatibility:

- **Proactive compatibility management**: Rather than waiting for bug reports, the team systematically updated to a new Erlang version and fixed compatibility issues preemptively.

- **Performance-conscious development**: Beyond compatibility, the team invested in optimizing critical path functions like string manipulation and autocompletion.

- **Reliability focus**: Multiple fixes target race conditions and resource leaks that could cause issues in large-scale applications.

- **Comprehensive testing**: Tests were updated alongside the compatibility work to ensure proper behavior validation.

The v1.0.4 to v1.0.5 transition marks an important milestone in Elixir's maturity, showing the project's ability to manage platform evolution while maintaining stability and performance.
