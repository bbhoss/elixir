# Changes from v1.6.2 to v1.6.3

## Overview

**Date Range:** February 28, 2018 - March 9, 2018
**Total Commits:** 8
**Release Date:** March 9, 2018

This patch release focused primarily on fixing bugs and improving the code formatter that was the flagship feature of Elixir v1.6. The release also addressed critical issues in compilation and supervisor reporting.

---

## Summary

Elixir v1.6.3 is a patch release that builds upon the stable v1.6.2 release with critical bug fixes and quality improvements. The development cycle was concentrated and focused, with all commits authored by core team members (primarily José Valim with one contribution from Johan Suleiko Allansson). The changes were minimal in scope but important for stability and usability.

**Key themes:**
1. **Code Formatter Robustness** - Multiple fixes to edge cases in the formatter that was introduced in v1.6
2. **Compilation System Reliability** - Critical fix for timeout handling during compilation failures
3. **Supervisor Error Reporting** - Improvement to error reports from named DynamicSupervisor

This release demonstrates the typical pattern of a patch version: addressing real-world issues discovered after a major feature release, with no new features introduced.

## Major Features/Improvements

### Code Formatter Enhancements

The v1.6 code formatter received several important improvements to handle complex edge cases:

1. **Comments in Pipelines and Type Expressions**
   - Fixed formatter to properly support comments in the middle of pipelines and type expressions
   - Touched 3 files with 241 insertions and 108 deletions
   - Significantly expanded test coverage for edge cases with 139 lines of new test code
   - Ensures developers can add clarifying comments without breaking formatting

2. **Operator Precedence with & (Capture Operator)**
   - Corrected precedence handling between the `&` capture operator and other operators
   - Added 46 new integration tests demonstrating proper formatting
   - Fixed cases where operator precedence was not being correctly maintained in formatted output

3. **Improved Line Breaking for Grouped Expressions**
   - Enhanced formatter logic to consider commas when deciding where to break lines in groups
   - Added 47 new test cases to verify correct breaking behavior
   - Improved overall readability of formatted code, particularly for function calls and data structures

4. **Formatter Configuration for stdin**
   - Made `.formatter.exs` configuration apply when formatting code via stdin
   - Ensures consistent formatting behavior whether formatting files or piping code through the formatter
   - Important for tool integration and IDE plugins

## Bug Fixes

### ParallelCompiler Timeout Handling (Critical)

**Commit:** 9169b6e302def8ac6e566a5b075eec68efa83a5a
**Author:** Johan Suleiko Allansson
**Impact:** High - Affects programmatic compilation usage

A critical bug was fixed in the ParallelCompiler where timeout messages were not being properly cancelled when compilation errors occurred. This had serious implications:

- **Problem:** When compilation failed, the timeout message would still be delivered to the calling process even after compilation completed
- **Consequence:** Processes using `Mix.Task.run("compile", ["--return-errors"])` could unexpectedly crash or have their mailboxes filled with stray messages
- **Solution:** Added proper timeout cancellation when compilation errors occur, mirroring the behavior in other code paths
- **Significance:** This is a subtle but important fix that improves reliability for programmatic compilation usage, particularly in build tools and CI/CD systems

### DynamicSupervisor Error Reporting

**Commit:** d16f354a3b9a04563e73cbe1edeb33fd917b522b
**Impact:** Medium - Improves error diagnostics

Fixed proper error reporting from named DynamicSupervisors:

- **Problem:** Error reports from named DynamicSupervisors weren't being generated correctly
- **Changes:** Modified `lib/elixir/lib/dynamic_supervisor.ex` to ensure proper report formatting
- **Testing:** Added comprehensive test coverage in logger translator tests
- **Benefit:** Developers using DynamicSupervisor with names now receive clearer error messages in logs
