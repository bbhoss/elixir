# Changes from v1.3.1 to v1.3.2

## Release Information

- **Date Range**: June 29, 2016 - July 15, 2016
- **Total Commits**: 27
- **Release Date**: July 15, 2016

## Summary

The v1.3.1 to v1.3.2 release is a focused patch release that primarily addresses critical bug fixes, protocol handling improvements, and several enhancements to the build and test infrastructure. This release demonstrates Elixir's commitment to stability with a mix of dependency management improvements, typespecs corrections, and important fixes for the module loading and protocol consolidation systems.

The release cycle shows active development focused on addressing real-world issues reported by the community, with particular attention to protocol consolidation edge cases, build system reliability, and test infrastructure improvements.

## Major Features and Improvements

### Mix Task Enhancements
- **`mix test --listen-on-stdin`** - A new feature for listening on stdin in test runner (#4921), allowing more flexible test orchestration. Subsequently improved to not exit on failure (#4930), making it more suitable for long-running test processes.
- **Dependency Management** - Added a filter option to `deps.unlock` (#4932), providing finer control over dependency updates.
- **Environment Variables** - Introduced `MIX_NO_DEPS` environment variable for disabling dependency loading, useful for certain build scenarios and development workflows.
- **Dependencies API Restoration** - Renamed `deps.check` back to `deps.loadpaths` (#4895), restoring the public API that projects like Nerves depend on.

### Language Enhancements
- **`with` Statement Guards** - The `else` clause in `with` expressions now properly supports guards (#4960), allowing more sophisticated pattern matching and conditional logic in this control flow construct.

### Build System Improvements
- **Dependency Compilation Flags** - Added `IS_DEP=1` environment variable when compiling `make` dependencies, allowing erlang.mk to properly disable warnings-as-errors for external dependencies.
- **Warning Configuration** - Disabled `--warnings-as-errors` for dependency compilation (#4913), preventing build failures due to warnings in third-party code.

### Documentation and Spec Improvements
- **OptionParser Documentation** - Polished and fixed documentation for OptionParser module, including style improvements and variable clarification (#4924).
- **Task Documentation** - Standardized the `mix escript` task's shortdoc for consistency (#4984).
- **Typespec Corrections** - Multiple fixes to typespecs:
  - Fixed `Kernel.pop_in/2` typespec (#4931)
  - Fixed `struct/0` typespec (#4915)
  - Fixed `OptionParser.parse_head!/2` spec
  - Fixed `@macrocallback` spec translation

### Tokenizer Improvements
- **Column Count Synchronization** - Fixed tokenizer to keep column counts in sync when numbers contain underscore separators (e.g., `123_456_789`). This ensures tools like Credo can properly map tokens back to their source locations.

## Bug Fixes

### Critical Fixes
- **Module Loading Issue (#4900)** - Fixed an issue where Elixir attempted to load modules that had not been required. This could cause unexpected behavior and errors in certain edge cases.
- **Enumerable Behavior (#5004)** - Ensured that enumerables properly return `nil` when they halt, fixing incorrect return values in enumerable operations.
- **Access.at/1 Behavior (#4911)** - Fixed `Access.at/1` to properly pop list elements, addressing an issue where list element access operations didn't behave correctly.
- **Edit Script for Maps (#4977)** - Fixed the edit script functionality when dealing with maps that have no joint elements.

### Protocol-Related Fixes
- **Protocol Dependencies (#4842)** - Two important fixes related to protocol handling:
  1. Ensured missing protocol dependencies are properly discarded during protocol consolidation.
  2. Fixed umbrella protocol consolidation to properly traverse dependencies, preventing issues with nested/dependent protocols.

### API Changes
- **`to_char_list/1` Deprecation** - Actually hid the `to_char_list/1` function, enforcing the move toward the standardized `to_charlist/1` naming convention.

### Error Messages and Flexibility
- **Error Messages** - Improved error messages for `:only` conflicts in dependency specifications, providing clearer feedback to developers.
- **Exception Typespecs** - Allowed custom fields in `Exception.t` typespec, providing more flexibility for custom exception types.

### Test and Development Fixes
- **Dialyzer Tests** - Re-enabled dialyzer "raise" tests that were previously disabled.

## Breaking Changes

**None documented in this release**, though the following are notable changes in behavior:

- **`to_char_list/1` is now hidden** - Code using the old `to_char_list/1` function should migrate to `to_charlist/1`.
- **`deps.check` renamed to `deps.loadpaths`** - This is actually a restoration of the correct API name, not a breaking change, as the incorrect name was only in the previous patch version.

The release maintains backward compatibility for the vast majority of Elixir code, with the primary breaking change being the finalization of the char list function naming convention.

## Notable Commits Worth Highlighting

### 1. Module Loading Fix (8930ea7)
```
Do not attempt to load modules that have not been required, closes #4900
```
This fix prevents Elixir from attempting to dynamically load modules that haven't been explicitly required. This could have caused unexpected behavior and cryptic errors in complex applications.

### 2. Protocol Consolidation Improvements (d92b7a3 & e2abd35)
Two commits addressing protocol consolidation:
- Traversing dependencies when consolidating umbrella protocols
- Ensuring missing protocol dependencies are discarded

These fixes are crucial for applications using multiple protocols or umbrella applications with protocol dependencies, preventing subtle issues during compilation.

### 3. Mix Test Infrastructure Enhancement (2718631 & 7f59aeb)
The introduction and refinement of `--listen-on-stdin` for mix test adds significant new capability for test orchestration and integration with other tools.

### 4. Tokenizer Column Synchronization (301aa6e)
```
keep tokenizer's column counts in sync for numbers with _ characters
```
This seemingly minor fix enables downstream tools like Credo and other linters to properly map tokens back to source locations, which is essential for accurate error reporting.

### 5. Build System Reliability (65aee00)
```
Add IS_DEP=1 env var when compiling make deps
```
This infrastructure improvement prevents build failures when compiling external C dependencies with stricter compiler settings, making Elixir projects more robust.
