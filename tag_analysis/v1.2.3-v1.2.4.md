# Changes from v1.2.3 to v1.2.4

## Date Range and Commit Count

**Release Date:** April 1, 2016
**Development Period:** March 2 - March 30, 2016
**Total Commits:** 24 commits

This release represents approximately a month of development focused on Unicode improvements, Mix tooling enhancements, and bug fixes.

## Summary

Elixir v1.2.4 is primarily a maintenance and improvement release that delivers significant enhancements to Unicode normalization support, brings improvements to the Mix build tool for dependency management, fixes several bugs, and updates core String operations. The release shows a strong focus on Unicode standards compliance (upgrading to Unicode 8.0.0) with deep optimization work on string decomposition and composition algorithms.

## Major Features and Improvements

### Unicode Normalization (Core Feature Work)

A substantial portion of this release (approximately 12 commits) was dedicated to improving Unicode normalization support:

- **Unicode 8.0.0 Upgrade**: Updated Unicode data tables from previous version to Unicode 8.0.0 standard, ensuring compliance with the latest Unicode specification for string handling and text processing.

- **Composition/Decomposition Algorithms**: Completely refactored the Unicode normalization approach to rely exclusively on UnicodeData.txt rather than mixing multiple data sources. This provides a more maintainable and standards-compliant implementation.

- **Performance Optimizations**: Multiple performance improvements to the normalization pipeline:
  - Fold decomposition recursions at compile time to reduce runtime overhead
  - Optimize combining class handling to avoid unnecessary reordering
  - Handle compositions with non-zero combining classes correctly
  - General algorithmic improvements and optimizations to the normalization process

- **Code Quality**: Cleaned up Unicode range parsing, avoiding unnecessary regular expressions in performance-critical code paths.

### Mix Tool Enhancements

Several important improvements to the Mix build system:

- **Archive Support**: Added `:archives` option to `Mix.Project`, enabling projects to specify and manage archives as part of their build system. Archive checks are now integrated into the `deps.check` task.

- **Precompilation Hooks**: Introduced `deps.precompile` hook and `--include-children` option for `mix deps.compile`, allowing better control over dependency compilation order and child dependency handling.

- **Dependency Management**: Fixed `mix deps.compile --include-children` to properly recurse on root dependencies, ensuring consistent and predictable compilation behavior across dependency trees.

### String API Changes

- **Whitespace Definition Update**: Redefined how Elixir distinguishes between whitespace and breakable whitespace:
  - `strip/1` removes all whitespace characters
  - `split/1` uses only breakable whitespace as delimiters
  - This aligns with Unicode standards and improves string splitting behavior for various languages

### Application and OTP Improvements

- **Application.spec/2 Robustness**: Fixed `Application.spec/2` to properly return `nil` for unknown applications, improving error handling in the OTP layer.

## Bug Fixes

### Critical Bugs

- **Binary Leak in Integer.parse/1** (by Andrea Leopardi): Fixed a memory inefficiency in `Integer.parse/1` where the function was creating new binaries instead of reusing sub-binaries from the original input. This is a subtle but important performance and memory fix that improves the efficiency of integer parsing operations.

### Important Bug Fixes

- **Erlang Module Recompilation** (PR #4453): Fixed an issue where Erlang modules were not being properly purged during recompilation, which could cause stale code to remain in memory after recompilation cycles. This is particularly important for development workflows using hot reloading.

- **Version Metadata Parsing** (PR #4409): Allow dots in metadata information in `Version.parse/1`, fixing a limitation that prevented parsing of version strings with dots in the metadata portion (e.g., `1.0.0+build.123`).

## Breaking Changes

**No breaking changes identified** in this release. All improvements maintain backward compatibility with v1.2.3.

The whitespace definition update in `String` operations could theoretically affect applications that relied on the previous whitespace behavior, but this is considered an improvement to Unicode compliance rather than a breaking change.

### Development Pattern Insights

The commit history reveals a deliberate development approach:
1. First, the Unicode handling was centralized to a single data source (UnicodeData.txt)
2. Then, multiple optimization commits were applied to improve performance
3. Finally, edge cases and composition rules were refined

This methodical approach suggests rigorous testing and refinement of the Unicode implementation.

## Technical Insights

### Unicode Normalization Work

The extensive Unicode normalization work in this release indicates Elixir's commitment to proper internationalization support. The shift to using only UnicodeData.txt as the authoritative source reduces complexity and makes the codebase easier to maintain when Unicode standards are updated. The compile-time optimizations (folding recursions) suggest the developers were conscious of avoiding runtime overhead while improving correctness.

### Mix Tool Evolution

The archive support and precompilation hooks represent growing sophistication in Elixir's build tool ecosystem, addressing real-world use cases like managing native code compilation and complex dependency relationships.

### Code Quality Focus

The inclusion of seemingly minor fixes (like avoiding regular expressions in Unicode parsing, fixing binary leaks) demonstrates Elixir's attention to performance and resource efficiency even in maintenance releases.
