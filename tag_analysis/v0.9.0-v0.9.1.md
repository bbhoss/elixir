# Changes from v0.9.0 to v0.9.1

## Overview
- **Release Date:** May 30, 2013
- **Date Range:** May 23 - May 30, 2013
- **Total Commits:** 113
- **Duration:** 7 days

This is a minor release following v0.9.0, containing significant feature additions, bug fixes, and internal refactoring.

## Summary

v0.9.1 represents a consolidation and enhancement of the IEx interactive shell experience, extended testing capabilities, and important internal refactoring of the module system. The release introduces user-facing configuration options for the REPL, an advanced doctest feature for interactive examples, and reorganization of the compiler's module tracking infrastructure. Several deprecated features are removed, and multiple targeted bug fixes address issues with record definitions, dependency resolution, and operator precedence.

The release also adds new string utility functions and implements internal optimizations for startup and compilation. The primary focus areas demonstrate attention to developer experience (IEx improvements), testing infrastructure (doctest extensions), and code quality (refactoring and deprecations).

## Major Features & Improvements

### 1. IEx.Options Module - Configuration for Interactive Shell
A comprehensive new feature enabling users to configure the IEx REPL through a dedicated options module. This represents significant UX improvement for interactive development.

**Commits Involved:** ~20 commits from May 23-24

Key accomplishments:
- **Initial implementation** (`63890ef0b7`) - Establishes the foundation for IEx option management
- **Full inspect_opts support** (`7ea8faeada`) - Integrates inspection customization options
- **Color configuration** - Multiple commits add granular color control:
  - Error messages color option (`5fac52bf12`)
  - Informational messages color option (`3864b04ac2`)
  - ls helper color options (`042f5e9c14`)
  - escape_fragments color options (`088753d901`)
- **Documentation** - Comprehensive doc support for IEx.Options, visible to ExDoc (`d159e4f592`)
- **get/0 and set/0** helpers (`156ead2c57`) - Convenient API for option management
- **Deprecation** - IEx.inspect_opts deprecated in favor of IEx.Options (`3e9b61855c`)

This feature allows developers to customize the interactive shell's appearance and behavior, a quality-of-life improvement for REPL-driven development.

### 2. Extended Doctest Sessions - Interactive Example Documentation
Implementation of Issue #1020, enabling doctest examples to simulate multi-line interactive sessions with intermediate results.

**Main Commit:** `5aa5268c5b` - "Implement extended doctest sessions. Closes #1020" (May 28)

Significance:
- Allows documentation examples to show interactive REPL sessions, not just input/output
- Enables testing complex workflows across multiple steps
- Makes documentation more educational and practical
- Comprehensive review of stdlib doctests to use extended format (`2fbc8682ca`)
- Test infrastructure adjustments to ensure doctests work correctly with ExUnit

This enhancement makes Elixir documentation more aligned with real-world interactive usage patterns.

### 3. Module.DispatchTracker Refactoring
Significant internal refactoring of the module compilation tracking system, originally named Kernel.LocalsTracker.

**Key Commits:**
- `c7e86b0554` - Start refactoring LocalsTracker to support more vertices (May 25)
- `c3e7543e48` - Extract imports handling to locals tracker (May 26)
- `ffc91e3004` - Rename Kernel.LocalsTracker to Module.DispatchTracker (May 26)
- `fbb06f2086` - Record each definition on tracker as soon as defined (May 26)
- `f76aeba141` - Check for imports conflicts in batches (May 26)
- `da84a797b0` - Module.DispatchTracker also records remotes (May 26)
- `d19f6beca0` - Provide source information to all dispatches (May 26)

Improvements:
- Better tracking of import/dispatch information with source location data
- Support for recording both local and remote function calls
- Batch processing of import conflicts for efficiency
- Sets stage for future enhancements to module metadata

### 4. IEx History Management Enhancement
Refactored and extended IEx's command history functionality.

**Key Commits:**
- `df94927e09` - Add :history_size option to IEx (May 26)
- `2a08277ef1` - Fix v helper to work with new :iex_history format (May 26)
- `64c58f2a3f` - Use just the process dictionary for keeping history (May 27)
- `339082053e` - Extract history management in its own module (May 27)
- `3aaaf5e916` - Implement the heuristics for garbage collection (May 27)

Features:
- New `:history_size` option to control history buffer size
- Process dictionary-based storage instead of external tracking
- Built-in garbage collection heuristics to manage memory
- Refactored into dedicated module for maintainability
- Fixed v helper command to work with new format

### 5. String Utility Functions
Addition of commonly-needed string checking functions.

**Commit:** `ce1b12422d` - "Add String.starts_with? and String.ends_with?" (May 25)

- `String.starts_with?/2` - Check if string begins with prefix
- `String.ends_with?/2` - Check if string ends with suffix
- Bug fix in related code (`478f9bbb52`)

These functions provide essential string manipulation capabilities previously requiring manual pattern matching.

### 6. Compiler & Startup Optimizations
Several optimizations targeting compilation speed and startup time.

**Key Commits:**
- `f29c6afe3d` - Reduce the number of files required for bootstrap (May 24)
- `d4609c6f4e` - Get rid of elixir_glob now that we run on > R16 (May 24)
- `c3dd4006b0` - Reduce atom footprint when compiling an elixir module (May 25)
- `32cc99767b` - Use precalculated binary size (May 26)
- `0fa06a2183` - Precompile groups regex (May 30)

These changes reduce both startup time and memory footprint of compiled modules.

## Deprecations & Cleanup

The release includes systematic removal of deprecated code and breaking changes to encourage migration to new patterns:

1. **Removed Deprecated Code** (`bcf9d814dd` - May 30)
   - Cleans up legacy implementations

2. **Access Protocol Changes** (`69a4138e8c` - May 30)
   - Remove remaining function implementation from access protocol old versions

3. **Dict Behaviour Spec Changes** (`bd1633c778` - May 30)
   - Remove get! from Dict behaviour spec (indicates get! was removed or refactored)

4. **IEx.inspect_opts Deprecation** (`3e9b61855c`)
   - In favor of IEx.Options module for more comprehensive control

5. **Mix API Changes**
   - `bbcc640760` - Rename Mix.SCM.equals? to Mix.SCM.equal?
   - Normalizes naming convention for boolean-returning functions

6. **Terminology Changes**
   - `e05448afd7` - Remove *_table terminology in favor of setup/cleanup
   - Better semantic naming for test fixtures

## Breaking Changes

1. **Dict.get! Removal** - No longer available in Dict behaviour specification
2. **Access Protocol API Changes** - Old function implementations removed
3. **Mix.SCM API** - `equals?` renamed to `equal?`
4. **IEx.inspect_opts** - Deprecated in favor of IEx.Options (though likely still functional)

While technically breaking for code using removed APIs, these are minor APIs with likely low adoption at this early stage of Elixir development (v0.9.1).
