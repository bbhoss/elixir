# Changes from v0.13.2 to v0.13.3

## Release Overview

**Date Range:** May 11 - May 24, 2014
**Commit Count:** 151 commits
**Release Date:** May 24, 2014

This release represents a significant milestone in Elixir's development, focusing on API cleanup, structural improvements, and preparing the codebase for more advanced features. The release demonstrates a mature approach to language evolution with careful deprecation patterns and substantial refactoring.

---

## Summary of Changes

v0.13.3 is a transitional release that modernizes Elixir's core architecture and API. The key theme is **structural unification and code organization**: exceptions are now first-class structs, strings and lists gain standardized conversion functions, and the module organization is rationalized. Simultaneously, the release carefully manages breaking changes through a multi-phase deprecation system, ensuring backward compatibility while guiding developers toward new patterns.

The release shows active community participation with Windows-specific fixes, documentation improvements, and bug fixes across multiple areas. The maintainers (primarily José Valim and Eric Meadows-Jönsson) drove major architectural changes while maintaining stability.

---

## Major Features & Improvements

### 1. Exception to Struct Conversion
**Commit:** `c22e8e85dc`

This is the most significant architectural change in the release. Exceptions are converted from tuple-based structures to proper Elixir structs, providing:

- Better struct inheritance and pattern matching
- Cleaner exception handling semantics
- Improved exception specifications and type safety
- More consistent exception behavior across the codebase

This change touched 14 core files and represents a fundamental shift in how exceptions are represented internally. All exception definitions now use struct syntax, making the exception hierarchy more explicit and easier to extend.

### 2. Stream Struct Simplification
**Commits:** `419e2a1d2a`, `39c84f4324`

The Stream module's struct representation was simplified to just `%Stream{}` instead of a more complex internal structure. This improves:
- Developer experience with pattern matching
- Internal consistency in the codebase
- Code clarity when inspecting stream objects

Additionally, a critical bug in `Stream.cycle/1` with inner halting streams was fixed (issue #2285), ensuring predictable behavior in complex stream processing scenarios.

### 3. Module API Reorganization
**Commits:** `540c763c85`, `3d4877ffda`, `84262257ef`, `68dd952b45`, `a068b5a4b0`

A comprehensive reorganization of module APIs moves type conversion functions to appropriate modules:

- **String conversions:** Binary conversions moved to `String` module
- **List conversions:** List conversions moved to `List` module
- **Integer/Float conversions:** Type-specific conversions moved to `Integer` and `Float` modules
- **BitString deprecation:** `BitString` module deprecated with conversions consolidated elsewhere

New convenience functions added:
- `String.to_char_list/1` for converting strings to character lists
- `List.to_string/1` for converting lists back to strings
- `Atom.to_string/1`, `Atom.to_char_list/1`, and `BitString.to_list/1`

These changes group related functionality logically and reduce cross-module dependencies.

### 4. Macro Improvements
**Commit:** `860ca5b5cb`

Two new AST manipulation functions added to the `Macro` module:
- `Macro.prewalk/2` and `Macro.prewalk/3` - walk AST before processing children
- `Macro.postwalk/2` and `Macro.postwalk/3` - walk AST after processing children

These provide essential utilities for compile-time code transformation and meta-programming.

### 5. OptionParser Enhancements
**Commits:** `cb0c3d8a2a`, `c0bc64fb19`, `40a384aef6`, `76260b057f`, `142ebc3ec`, `339c57f1c6`, and multiple related commits

The option parser received significant improvements:

- **Strict mode support:** `Support :strict option on parse` allows validation of known options
- **Better boolean handling:** Fixed boolean option value normalization
- **End-of-options handling:** Changed to properly handle `--` as end-of-command-options marker
- **Improved error messages:** Better reporting of invalid options with proper types
- **Option value parsing:** Fixed handling of `--no-*` options to accept values properly

These improvements make Mix and command-line tool development more robust and user-friendly.

### 6. Regex Improvements
**Commits:** `4d66ac72e1`, `e566d7cda0`

A dedicated inspect implementation for regexes was added (fixing issue #2250), improving the developer experience when debugging regex-related code with cleaner output.

### 7. IO Utilities
**Commit:** `3bb8e17e9e`

New conversion functions added to the `IO` module:
- `IO.iodata_to_binary/1` for converting iodata structures to binary
- `IO.chardata_to_string/1` for converting chardata to strings

These standardize conversion patterns and reduce boilerplate code.

### 8. Windows Support Improvements
**Commits:** `a6b9d2ed72`, `df1366c1d6`, `0bcc02d816`, `1c9dff1fee`, `82f800e1c5`

Multiple fixes to `elixir.bat` and `mix.bat`:
- Fixed quoting issues to prevent argument corruption
- Improved help option handling
- Better command-line argument forwarding
- Support for deferring to Mix for help option processing

These changes improve the Windows developer experience and ensure consistent behavior across platforms.

## Breaking Changes & Deprecations

### Soft Deprecations (Warnings in Compiler)

These items emit compiler warnings but code still works:

1. **`set_elem/3`** → Use `put_elem/3` instead
   - `Commit: f92d8393da` - Deprecated in favor of more consistent naming

2. **Record-based APIs**
   - `Commit: 489b1e04c7` - `defrecord/3` deprecated
   - Record backend dependency removed (commit `a80f9d9ae1`)
   - Transition toward struct-based records

3. **`:hygiene` disabling in quote**
   - `Commit: be34a75124` - Disabling `:hygiene` in quote is deprecated
   - Encourages proper scope handling in macros

4. **`Dict.Behaviour`**
   - `Commit: fb49aa1e99` - Deprecated in favor of `Dict` module
   - Rationalizes behavior protocol usage

5. **Behavior Modules (xgen)**
   - `Commit: 9f0a30de43` - Merge xgen and soft deprecate existing behaviours
   - Consolidates behavior module patterns

### Previously Soft-Deprecated Code → Hard Deprecated
**Commits:** `580107d29c`, `ef67a9527a`, `bb8f3aaa8d`

A significant cleanup removed code that was previously soft-deprecated:
- Old API patterns are now fully removed
- Migration path was provided in earlier versions
- Final cleanup of legacy code

### API Changes

1. **Quote context behavior**
   - `Commit: 78c16c0e89` - Do not allow nil context to be set on quote
   - More strict context validation for macros

2. **Variable restrictions in `in` operator**
   - `Commit: cd8f52aa92` - Disallow variables on the right side of `in`
   - Prevents misuse of the `in` operator for complex expressions

3. **Keyword argument validation**
   - `Commit: 8652ee5838` - Do not allow keyword on containers without pos args
   - Prevents invalid keyword list usage

4. **OptionParser breaking changes**
   - `Commit: c0bc64fb19` - Removes `--` from parsed options
   - `--` properly marks end-of-options instead of being included in results

### Deprecation Infrastructure
**Commits:** `4977ec8c05`, `ca6788113e`, `095e4a7d2e`

The deprecation system itself was improved:
- Deprecations now emit compiler warnings (not just IO messages)
- Deprecation messages routed to standard error for better visibility
- Faster expansion and processing of deprecation rewrites

## Themes & Architectural Insights

### 1. **Structural Modernization**
The release focuses on bringing Elixir's core data structures (exceptions, streams) into line with modern language patterns. Moving from tuple-based representations to proper structs makes the language more consistent.

### 2. **API Rationalization**
Functions are being organized by semantic grouping rather than implementation details. Type conversion functions now live with their target types, making the API more discoverable.

### 3. **Staged Deprecation Strategy**
The release demonstrates a mature approach to API evolution with clear stages:
- Soft deprecations with compiler warnings (guides developers)
- Hard deprecations (removes old code)
- Provides new alternatives in same release

### 4. **Community-Driven Development**
Multiple pull requests from community contributors (particularly around Windows support and documentation) show Elixir's growing ecosystem.

### 5. **Quality & Reliability Focus**
43 bug fixes across diverse areas (parsing, I/O, streaming, configuration) show attention to stability over just adding features.

### 6. **Metaprogramming Enhancements**
Addition of `Macro.prewalk` and `Macro.postwalk` indicates growing sophistication in compile-time code generation capabilities.

## Migration Guide for Users

For developers upgrading from v0.13.2 to v0.13.3:

### Critical Changes
- Exception handling code may need updates if relying on tuple structure
- Stream struct access patterns may change due to simplification
- OptionParser code handling `--` flag needs review

### Recommended Updates
- Replace `set_elem/3` with `put_elem/3`
- Update record-based code to use structs
- Enable `:hygiene` in macro code (or expect compiler warnings)

### Optional Modernizations
- Use new `String.to_char_list/1` instead of `Kernel` functions
- Use new `Atom.to_string/1` convenience functions
- Leverage new `Macro.prewalk/3` and `Macro.postwalk/3` for AST manipulation
