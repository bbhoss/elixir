# Changes from v1.4.1 to v1.4.2

## Overview

This document analyzes the changes between Elixir v1.4.1 and v1.4.2, a maintenance release that focused on bug fixes, Unicode updates, and minor feature enhancements.

**Date Range:** January 26, 2017 to February 16, 2017 (21 days)
**Total Commits:** 10 commits (excluding release commit)
**Release Date:** February 16, 2017

## Summary

Version 1.4.2 is a patch release that addresses several important bug fixes and introduces minor improvements. The release cycle focused on:

1. **Stability and Correctness:** Multiple compiler and runtime fixes to improve code correctness, particularly around function redefinition tracking and alias expansion
2. **Unicode Standards Compliance:** Updated to Unicode 9 grapheme rules
3. **Feature Refinement:** Enhancements to Stream processing and EEx templating
4. **Configuration Optimization:** Performance improvements in Mix configuration caching
5. **API Enhancements:** New options for OptionParser to handle edge cases better

The changes reflect a mature platform iterating on stability rather than introducing breaking new features.

## Bug Fixes

### 1. **Function Redefinition Source Location Fix** (Jan 31, 2017)
- **Commit:** 8533df25a9 - "Fix redefined function source location (#5720)"
- **Issues Closed:** #5719, #5720
- **Problem:** When functions were redefined in a different file, the compiler would use the first definition's source location for all subsequent definitions, causing warnings to be attributed to the wrong file
- **Solution:** Updated the function definition tracking in the Erlang backend (lib/elixir/src/elixir_def.erl)
- **Impact:** Compiler warnings now correctly identify the file where an issue actually occurs
- **Importance:** Critical for debugging, as developers were receiving misleading error locations

### 2. **Alias Expansion at Compile Time** (Jan 30, 2017)
- **Commit:** 9e8ac51fb3 - "Only expand aliases known at compile time, closes #5721"
- **Issues Closed:** #5721
- **Problem:** IEx autocomplete was attempting to expand aliases that weren't known at compile time
- **Solution:** Added guard to only expand aliases that have been defined
- **Files Modified:** lib/iex/lib/iex/autocomplete.ex, lib/iex/test/iex/autocomplete_test.exs
- **Impact:** Prevents errors in IEx autocomplete for undefined aliases
- **Benefit:** More robust interactive development experience

### 3. **Mix Configuration Caching** (Feb 5, 2017)
- **Commit:** 8618d8effa - "Properly cache apps_paths configuration, closes #5622"
- **Issues Closed:** #5622
- **Problem:** The apps_paths configuration wasn't being properly cached, leading to repeated I/O operations
- **Solution:** Implemented proper caching in Mix.Project.Stack
- **Files Modified:** lib/mix/lib/mix/project.ex, lib/mix/lib/mix/project_stack.ex
- **Impact:** Improved performance of build operations, especially on systems with many packages or slow I/O
- **Benefit:** Faster Mix operations overall

### 4. **Archive Installation Cleanup** (Feb 1, 2017)
- **Commit:** bd1c3ab8d7 - "Delete previous .ez archives"
- **Problem:** Old .ez archives weren't being cleaned up after new ones were installed
- **Solution:** Added cleanup logic to remove previous archive versions
- **Files Modified:** lib/mix/lib/mix/tasks/archive.install.ex
- **Impact:** Prevents disk space accumulation from old archive files
- **Benefit:** Cleaner system state and reduced disk usage
