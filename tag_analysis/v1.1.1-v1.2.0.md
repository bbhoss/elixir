# Changes from v1.1.1 to v1.2.0

## Overview

**Date Range:** September 28, 2015 (v1.1.1) to January 1, 2016 (v1.2.0)
**Commit Count:** 593 commits
**File Changes:** 312 files changed, 14,371 insertions (+), 6,637 deletions (-)

This release marks a significant evolution of the Elixir language with substantial improvements to control flow, dependency management, data structures, and tooling.

---

## Summary of Key Themes

This release cycle focused on four major areas:

1. **Language Features & Semantics** - Introduction of the `with` special form, improved module system, and variable scoping
2. **Data Structure Evolution** - Deprecation of legacy collection types (Dict, Set) in favor of Map/MapSet, addition of new utility functions
3. **Build System & Dependency Management** - Rebar3 support, improved Mix tooling, better Windows support
4. **Standard Library Expansion** - Enhanced System module with time functions, new Stream/Enum functions, improved protocol support

---

## Major Features & Improvements

### 1. Introduction of the `with` Special Form

One of the most significant language improvements in v1.2.0 is the introduction of the `with` special form, which replaces the deprecated `if_ok` construct. This provides a more elegant and composable way to handle pipelines of operations that may fail.

**Key Commits:**
- Drop `if_ok` in favor of new `with` special form
- Use private context for generated variables inside `with`
- Make sure variables are not leaking from `with`
- Properly handle import with invalid options

The `with` form provides better error handling semantics and improved variable scoping to prevent unintended variable leakage across clause boundaries.

### 2. Collection Type Modernization

A major shift toward using modern collection types (Map, MapSet) instead of legacy Dict and Set:

**Deprecations:**
- Soft deprecate Dict, HashDict, Set and HashSet
- Document and remove Map dependency from Dict
- Document and remove Keyword dependency from Dict
- Do not bypass warnings_as_errors on `Dict` and `defdelegate` warnings

**New Collection Functions:**
- Add `new/1` and `new/2` to Map and MapSet (mirroring the Keyword variant)
- Optimize `Keyword.new/2` function
- Optimize functions in MapSet
- Document functions in MapSet

This transition prepares users for the eventual removal of legacy collection types and promotes using the more efficient and modern alternatives.

### 3. Enhanced Time and System Functions

The System module received substantial enhancements for time-related operations:

- Add `System.time_offset/0-1` - Query system time offset
- Add `System.convert_time_unit/3` - Convert between time units
- Add monotonic and system time functions to System
- Add `unique_integer/0-1` - Generate unique integers for identifiers

These additions provide better control over system timing, which is critical for distributed systems and performance monitoring.

### 4. Enum and Stream Enhancements

**New Functions:**
- Implement `Enum.with_index/2` - Add indices to enumerable elements
- Implement `Stream.with_index/2` - Lazy version of with_index

These are frequently-requested utility functions that simplify working with indexed collections.

### 5. IEx and Introspection Improvements

- Implement the IEx.Info protocol for all data types
- Add tests for the IEx.Info protocol
- Pedantic improvements to the output of the `i/1` helper in IEx
- Update the spec for the generated `__info__/1` function to please Dialyzer

These changes improve the interactive development experience and provide better introspection capabilities for debugging.

### 6. String Manipulation Functions

- Introduce `String.trim_{prefix,suffix,leading,trailing}/2` - More flexible string trimming
- Add NFC support to `String.normalize/2` - Better Unicode normalization

These additions provide more granular control over string processing operations.

### 7. Rebar3 Dependency Support

Major improvements to Mix's dependency management:

- Rebar3 dependency support - Full Rebar3 backend integration
- Make Rebar 3 support opt-in - Allow projects to choose between Rebar 2 and 3
- Add support for HEX_CDN var in mix local.{hex,rebar} tasks - Customize hex/rebar sources
- Add --build flag to deps.clean mix task - Better cache management

This represents significant work in supporting the Rebar3 ecosystem while maintaining backward compatibility.

### 8. Mix and Build Tooling Enhancements

**Debugging & Configuration:**
- Add mix debug mode to troubleshoot build issues
- Add pages about typespecs and docs, closes #4079
- Configuration file now supported - Better integration with external tools
- Add documenation about env variables to Mix module

**Windows Support:**
- Use IEX_WITH_WERL environment variable to enable --werl by default
- Add environment variable to iex.bat for Windows users
- Adding code to the Windows batch files to make it easier to diagnose issues on Windows with Elixir

**Proxy Authentication:**
- Support for proxy auth with mix calls to httpc - Handle authenticated proxies

### 9. Protocol System Improvements

- The Access is not a protocol - Clarification of protocol semantics
- Clarify the new default behaviour for protocol consolidation
- Use nil for resetting env vars instead of false
- Make import with conflicting options to raise - Better error handling

### 10. Error Messages and Diagnostics

- Improve error message on invalid map definition
- Check for :name or :id in Logger translator
- Provide better error message for keywords access with non-atom keys
- Emit proper error if parsetools is not available
- Support raising and formatting of errors in ExUnit

## Breaking Changes

While v1.2.0 is primarily a feature release, there are notable deprecations that signal future breaking changes:

### Dict, HashDict, Set, and HashSet Soft Deprecation

The soft deprecation of Dict, HashDict, Set, and HashSet represents the most significant semantic shift. Code using these types will generate deprecation warnings, encouraging migration to:
- **Map** (replaces Dict/HashDict)
- **MapSet** (replaces Set/HashSet)
- **Keyword** (for key-value pairs with ordered, non-unique keys)

This is not a hard breaking change in v1.2.0, but users are strongly encouraged to migrate.

### API Changes:
- `if_ok` control flow deprecated in favor of `with`
- Import with conflicting options now raises errors instead of silently failing
- defdelegate with default arguments now raises at definition time

### Behavioral Changes:
- Variables in `with` statements use private context to prevent leakage
- Map/MapSet `new/1,2` now available with consistent API

## Analysis & Interpretation

### Language Maturation
v1.2.0 represents a maturing language with thoughtful improvements to core abstractions. The introduction of `with` shows the language designers listening to community pain points around error handling and function composition. Rather than introducing multiple competing approaches, they deprecated `if_ok` and provided a superior alternative.

### Ecosystem Standardization
The deprecation of Dict/Set in favor of Map/MapSet is a crucial standardization move. This unifies the collection API and improves performance by making Map the canonical key-value container. The decision to soft-deprecate (warn but don't break) shows a commitment to backward compatibility while guiding users toward best practices.

### Practical Improvements
The additions to Stream/Enum (with_index), String manipulation (trim variants), and System (time functions) reflect attention to frequently-used patterns and real-world needs. These are pragmatic additions that reduce boilerplate in common scenarios.

### Build System Evolution
The comprehensive Rebar3 support represents significant infrastructure work to keep Elixir compatible with the broader Erlang ecosystem. Making it opt-in shows wisdom in supporting gradual migration.

### Developer Experience Focus
Multiple improvements to error messages, IEx introspection, Mix debugging, and Windows support indicate a focus on making Elixir more accessible and pleasant to use across different platforms and skill levels.

## Impact Summary

**For Application Developers:**
- Better control flow with `with`
- Cleaner string manipulation with new String functions
- More efficient time handling with System enhancements
- Smoother debugging experience with mix debug mode

**For Library Authors:**
- Need to update collection-heavy code from Dict/Set to Map/MapSet
- Opportunity to adopt `with` for better error handling patterns
- Better tools for introspection via IEx.Info protocol

**For DevOps/Build:**
- Rebar3 support opens new dependency management options
- Improved Windows support benefits broader deployment scenarios
- Better control over artifact caching with deps.clean flags

This release successfully balances innovation (with special form, new functions) with pragmatic improvements (better errors, Windows support, ecosystem compatibility) while laying groundwork for future simplifications through soft deprecations.
