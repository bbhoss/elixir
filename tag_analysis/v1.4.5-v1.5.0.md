# Changes from v1.4.5 to v1.5.0

## Release Information

- **v1.4.5 Released**: June 22, 2017
- **v1.5.0 Released**: July 25, 2017
- **Development Period**: 33 days
- **Total Commits**: 935 commits

## Summary

Elixir v1.5.0 represents a significant milestone as the first release to fully leverage Erlang/OTP 20 features while being the last to support Erlang/OTP 18. This release focused on modernizing the language syntax, improving developer tooling, adding enhanced debugging capabilities, and streamlining supervisor and process management patterns. The release demonstrates a strong commitment to Unicode support, performance optimization, and developer experience improvements.

## Major Features and Improvements

### 1. UTF-8 Support for Identifiers

One of the headline features of v1.5.0, this release introduces support for non-quoted atoms and variables in UTF-8 when using Erlang/OTP 20+. This aligns Elixir with Unicode Annex #31 recommendations, making the language more accessible to international communities.

- Atoms like `:こんにちは世界` are now valid
- Variables like `saudação = "Bom dia!"` are supported
- Follows Unicode Annex #31 standards for valid identifiers (letters followed by digits and combining marks)

### 2. IEx Enhancements and Debugging

IEx received substantial improvements making interactive development and debugging significantly more powerful:

**New Helpers:**
- `exports/1` - Lists all exported functions and macros from a module
- `runtime_info/0` - Displays system information (cores, VM version, memory allocation)
- `open/1` - Opens module/function source directly in your editor
- `open/0` - Opens editor at current breakpoint location

**Breakpoint System for Debugging:**
- `break!/2` and `break!/4` - Set breakpoints for specific `Mod.fun/arity`
- `breaks/0` - Lists all active breakpoints
- `continue/0` - Resume execution until next breakpoint
- `remove_breaks/0` and `remove_breaks/1` - Clear breakpoints
- `reset_break/1` and `reset_break/3` - Reset breakpoint hit counts
- `whereami/1` - Show current location during breakpoint
- `respawn/0` - Start new shell session preserving breakpoints

**Autocompletion Improvements:**
- Now supports variable name autocompletion
- Handles manual imports with `import Mod, only: [...]` syntax
- Better map key navigation with atom keys

### 3. Exception.blame/3 and Enhanced Error Messages

A powerful debugging feature that attaches detailed metadata to exceptions, particularly `FunctionClauseError`. This shows:
- All attempted function clauses
- Which parts of clauses matched/didn't match (highlighted with hyphens or red ANSI)
- Argument values that were provided
- Guard conditions that failed

Example output highlights successful and failed matches in exception messages, significantly improving debugging experience.

### 4. Streamlined Child Specifications

A major refactoring of how supervisor hierarchies are defined, simplifying from the old `Supervisor.Spec` approach:

**Old Style:**
```elixir
import Supervisor.Spec
children = [supervisor(MyApp.Repo, []), supervisor(MyApp.Endpoint, [])]
```

**New Style:**
```elixir
children = [MyApp.Repo, MyApp.Endpoint]
```

**Key Benefits:**
- Modules define their own `child_spec/1` function
- Less error-prone (no forgetting task temporal settings)
- `use Agent`, `use GenServer`, `use Supervisor`, `use Task` automatically generate overridable `child_spec/1`
- Child specs are now maps instead of tuples
- Aligns with Erlang/OTP 18+ supervisor configuration

**Modules Updated:**
- `Agent`
- `Registry`
- `Task`
- `Task.Supervisor`

### 5. @impl Attribute for Callbacks

New `@impl` attribute clarifies which functions implement behavior callbacks:

**Benefits:**
- Increases code readability - clearly marks callback implementations
- Automatically adds `@doc false` unless explicitly overridden
- Raises compilation error if `@impl` is used on non-callback functions
- Forces consistency - if used once, must be used for all implementations

```elixir
defmodule MyApp do
  @behaviour Plug

  @impl true  # or @impl Plug
  def init(_opts), do: opts

  @impl true
  def call(conn, _opts), do: Plug.Conn.send_resp(conn, 200, "hello")
end
```

### 6. Calendar System Enhancements

Significant improvements to date/time handling:

**New Functions:**
- `Time.diff/3`, `Date.add/2`, `Date.diff/2`, `DateTime.diff/3` - Arithmetic operations
- `Date.range/2` - Create date ranges
- `Date.new/4`, `DateTime.utc_now/1`, `NaiveDateTime.new/8`, `Time.new/5` - Calendar specification
- Conversion functions: `Date.convert/2`, `Time.convert/2`, `NaiveDateTime.convert/2`, `DateTime.convert/2`
- `Calendar.ISO` improvements with readable error messages for year 10000 restriction

**Internal Changes:**
- New "ISO days" internal format for calendar conversions
- Added `:calendar` field to `Time` struct
- Better handling of timezone offsets and precision

### 7. Enum/Stream Improvements

**New Collection Processing Functions:**
- `Enum.chunk_by/4` and `Stream.chunk_by/4` - Chunk by predicate condition
- `Enum.chunk_every/2` and `Enum.chunk_every/4` - More explicit chunking API
- `Enum.filter_map/3` - Deprecated in favor of `filter/2` + `map/2` or comprehensions

**Performance Optimizations:**
- `Enum.count/2` optimized
- String binary pattern matching optimized in `String.split/1` and `String.trim_*/1`
- `String.replace_*` functions optimized
- `Base.encode/decode` optimized

### 8. Task.async_stream Enhancements

**New Options:**
- `:ordered` option (default false) - Control result ordering
- `:on_timeout` option - Control task termination behavior on timeout
- Better backwards compatibility maintained

### 9. String Module Evolution

**New Functions:**
- `File.read_link/1` and `File.read_link!/1` - Read symbolic links

**Optimizations:**
- `String.replace_*` functions significantly faster
- Binary pattern matching in String operations optimized

**Deprecations:**
- `String.strip/1,2` → `String.trim/1,2`
- `String.lstrip/1` → `String.trim_leading/1`
- `String.rstrip/1` → `String.trim_trailing/1`
- `String.ljust/3`, `String.rjust/3` → `String.pad_leading/3`, `String.pad_trailing/3`

### 10. Map and Keyword Improvements

**New Functions:**

**Optimizations:**

### 11. File System and Security Improvements

**New Capabilities:**

- `System.get_env/0` and `System.get_env/1` validate environment variables

## Breaking Changes and Deprecations

### Deprecations (No Warnings Yet)

**Soft Deprecations:**
- `not left in right` syntax (soft deprecation only)

### Character List Deprecations

A systematic renaming from `*_to_char_list` to `*_to_charlist`:
- `Atom.to_char_list/1` → `to_charlist/1`
- `Float.to_char_list/1` → `to_charlist/1`
- `Integer.to_char_list/1,2` → `to_charlist/1,2`
- `Kernel.to_char_list/1` → `to_charlist/1`
- `List.Chars.to_char_list/1` → removed
- `String.to_char_list/1` → `to_charlist/1`
- `char_list/0` type → `charlist/0`
- `:as_char_lists` Inspect option → `:as_charlists`
- `:char_lists` Inspect option → `:charlists`

### Functional Deprecations

**Enum/Stream:**
- `Enum.filter_map/3` → Use `filter/2` + `map/2` or comprehensions
- `Stream.filter_map/3` → Use `filter/2` + `map/2`

**String:**
- `String.strip/1,2` → `String.trim/1,2`
- `String.lstrip/1` → `String.trim_leading/1`
- `String.rstrip/1` → `String.trim_trailing/1`
- `String.ljust/3` → `String.pad_leading/3` with binary padding
- `String.rjust/3` → `String.pad_trailing/3` with binary padding

**Kernel:**
- `()` meaning `nil` - Deprecated
- Erlang parse transforms via `@compile {:parse_transform, _}` - Deprecated

### GenEvent Deprecation

`GenEvent` module is now deprecated with alternatives documented in its docs.

### EEx Deprecation

`<%= ` in "middle" and "end" expressions now soft-deprecated (e.g., `<%= else %>`, `<%= end %>`)
