# Changes from v1.7.4 to v1.8.0

## Overview

**Release Date**: January 14, 2019
**Previous Release (v1.7.4)**: October 24, 2018
**Duration**: ~2.5 months of development
**Total Commits**: 595

This was a significant release focused on infrastructure improvements, performance enhancements, and expanded calendar/timezone support. The v1.8.0 release emphasized making Elixir faster, better instrumented, and more capable for working with dates, times, and different deployment targets.

---

## Executive Summary

Elixir v1.8.0 represented a major quality-of-life release with several key pillars:

1. **Performance**: ~5% faster compilation on average, improved template rendering, optimized calendar operations, and better range checks in guards
2. **Time Zone Support**: Introduction of the `Calendar.TimeZoneDatabase` behavior allowing developers to plug in custom time zone databases
3. **Better Inspection**: Derivable `Inspect` protocol with field filtering for safer data structure logging
4. **Process Instrumentation**: Addition of `$callers` tracking to `Task` for better monitoring and ownership tracking
5. **Developer Experience**: Mix improvements for cross-target development, ExUnit enhancements, and IEx tool improvements

The release maintained strong backward compatibility while strategically deprecating older patterns and APIs in favor of more modern approaches.

---

## Major Features & Improvements

### 1. Custom Struct Inspections with Derivable `Inspect` Protocol

One of the most user-visible improvements was making the `Inspect` protocol derivable. This allows developers to control which fields are displayed when a struct is inspected, crucial for security and privacy:

```elixir
defmodule User do
  @derive {Inspect, only: [:id, :name, :age]}
  defstruct [:id, :name, :age, :email, :encrypted_password]
end
```

Now when inspected, sensitive fields like `:encrypted_password` are hidden, showing only `...` instead. This prevents accidental leakage of sensitive data in logs and error reports. The feature supports both `:only` and `:except` options for flexible control.

**Impact**: Significant security improvement for applications handling sensitive data.

### 2. Time Zone Database Support - `Calendar.TimeZoneDatabase` Behavior

A major infrastructure improvement was formalizing time zone support. Prior to v1.8, the `DateTime` module was limited because there was no pluggable time zone database mechanism. This release introduced:

- **`Calendar.TimeZoneDatabase` behavior**: A standardized contract for time zone data providers
- **`Calendar.UTCOnlyTimeZoneDatabase`**: Built-in implementation handling only UTC
- **New DateTime functions**: `DateTime.shift_zone/3` for seamless time zone conversion
- **Extended Calendar callbacks**: `day_of_year/3`, `quarter_of_year/3`, `year_of_era/1`, `day_of_era/3` on both `Date` and the Calendar behavior

This enables third-party packages like `tzdata` to provide comprehensive time zone support while Elixir maintains a minimal, zero-dependency core implementation.

**Related commits**:
- Added `TimeZoneDatabase` behaviour
- Calendar callbacks and Calendar.ISO implementations
- Extended DateTime API with timezone-aware operations

### 3. Improved Instrumentation with `$callers` Tracking

The `Task` module gained automatic tracking of process relationships through the new `$callers` key:

```
[your code] -- calls --> [supervisor] ---- spawns --> [task]

Stored as:
[your code] (in $callers)
[supervisor] (in $ancestors) -- [task]
```

This enables better tracing in monitoring systems and fixes a critical gap: when tasks are spawned through supervisors, the original caller's relationship is now preserved. This is particularly important for:

- **Ecto Sandbox**: Can now properly track database connections across spawned tasks
- **Concurrent testing**: Allows tests using tasks to run concurrently
- **Monitoring/APM tools**: Better visualization of process relationships and call chains

## Performance Improvements

### Compilation Speed

- **Overall ~5% faster compilation** through accumulated optimizations in the compiler pipeline
- Improvements focused on hot paths in the compiler

### Specific Optimizations

1. **Range checks in guards**: Optimized comparison operations like `x in y..z`, resulting in more efficient compiled code
2. **Charlist interpolation**: More efficient compilation of charlist patterns with interpolation (e.g., `'foo #{bar} baz'`)
3. **Record updates**: Memory optimization when updating multiple fields in records via the `Record` module using `dsetelement` optimization
4. **Map operations**: Optimized nested map `put` and `merge` operations
5. **EEx template rendering**: Default template engine now compiles and executes more efficiently with more compact code generation
6. **Calendar operations**: Optimization of common date/time paths and internal calendar calculations

**Note**: These improvements mean code that compiled in v1.7.4 will compile faster in v1.8.0 with zero code changes.

## New Functions & APIs

### Date & Time Enhancements

- `Date.day_of_year/1` - Get ordinal day of year (1-366)
- `Date.quarter_of_year/1` - Get quarter (1-4)
- `Date.year_of_era/1` - Years since era start
- `Date.day_of_era/1` - Days since era start
- `DateTime.from_naive/3` - Create DateTime from NaiveDateTime with time zone
- `DateTime.now/1` - Get current time in specified time zone
- `DateTime.shift_zone/3` - Shift DateTime to different time zone
- `DateTime.add/4` - Add duration to DateTime with unit handling
- `File.touch/2` and `File.touch!/2` - Now accept POSIX time as integer (not just datetime)

### List & Range Improvements

- `List.improper?/1` - Detect improper lists (lists not ending in `[]`)
- `List.myers_difference/3` - Calculate difference using Myers algorithm (useful for diffs)
- `List.to_charlist/1` - Convert list to charlist (complementary to existing `String.to_charlist/1`)
- `Range.disjoint?/2` - Check if two ranges don't overlap

### String & Text Processing

- `String.bag_distance/2` - Calculate similarity between strings using bag distance metric
- Improved `List.ascii_printable?/2` - Revamped implementation with better character detection

### Kernel & Meta-programming

- `Macro.struct!/2` - Proper struct resolution during compile time
- `:reduce` option for `for` comprehensions - Enable functional reduction patterns in comprehensions
- `floor/1` and `ceil/1` guards - Allow these functions in guard clauses
- Improved error messages for various edge cases

### Mix & Build System

- `Mix.target/0` and `Mix.target/1` - Support for cross-compilation and target-specific dependency management
- Enhanced dependency path tracking with `:depth` and `:parents` options in `deps_paths/1`
- Timeout support for `mix archive.install` and `mix escript.install`

### ExUnit Testing Framework

- `ExUnit.after_suite/1` - Callback to run after all tests complete
- `--max-failures` flag in `mix test` - Stop test run after N failures
- Improved `assert_receive` to show last N messages instead of first N (more relevant in concurrent tests)

### IEx Interactive Shell

- `port/1` and `port/2` helpers - Introspection tools for port information
- `IEx.Server.run/1` - Public API for running custom IEx sessions with pry brokering support
- Improved `b/1` helper - Now uses typespec information for better callback formatting

## Bug Fixes

### Compiler & Semantics

- **Fixed cond scope leak**: Variables in `cond` clauses no longer leak at compile-time (Issue #8542)
- **Undefined variable detection**: Proper error on undefined variables in bitstring segments (Issue #8598)
- **Circular struct dependencies**: Fixed deadlock when typespecs have circular struct dependencies (Issue #8368)
- **Bitstring expansion**: Expanded operands in `size*unit` bitstring modifiers instead of requiring literal integers
- **Counter propagation**: Counters in quote inside another quote no longer propagate incorrectly
- **Unquote in remote calls**: Fixed handling of unquote expressions in remote calls (Issue #8588)

### Platform & Integration

- **Erlang compiler flags**: Proper error when passing invalid flags to Erlang compiler that Elixir cannot handle (Issue #8344)
- **Git working directory**: `git` SCM now properly sets working directory for system calls (Issue #8279)
- **Race conditions**: Fixed race conditions in behavior checking and device re-registration
- **Manifest drift**: Avoided time drift when checking/updating compiler manifest files

### Calendar & Date/Time

- **Leap seconds**: NaiveDateTime and DateTime no longer accept leap seconds in builders and parsing
- **ZWJ handling**: Fixed proper handling of Zero-Width Joiner in Unicode grapheme clusters (Issue #8361)
- **DateTime map conversion**: `DateTime.truncate/1` now returns DateTime when passed a map struct
- **Negative years**: Proper handling of negative years in DateTime operations

### String & I/O

- **StringIO non-printables**: StringIO now handles non-printable arguments gracefully
- **Unicode atoms**: Updated handling of Unicode characters in atoms and variables (Issue #8603)

### Testing & Logging

- **Logger backends**: Fixed Logger backend removal during application shutdown
- **Umbrella tests**: Changed error to info message for unmatched tests in umbrella projects
- **Logger purge matching**: Fixed `Logger.log/2` calls in compile-time purge matching (Issue #8391)

### Mix & Build

- **Dependency changes**: Fixed umbrella projects not recompiling when dependencies change - a long-standing issue requiring full `_build` cleanup (Issue #8323)
- **Protocol consolidation**: Protocols are reconsolidated if local dependencies are stale
- **Module naming**: `mix new --module` now correctly uses provided module name for filenames
- **Dependency tracking**: Proper divergence detection for dependencies with different `:system_env` values
- **Optional dependencies**: Optional dependencies now properly included in `:extra_applications`

## Breaking Changes & Deprecations

### Hard Deprecations (with warnings)

1. **`System.cwd/0` and `System.cwd!/0`** → Migrate to `File.cwd/0` and `File.cwd!/0`
   - System module functions are for system configuration; file-related operations should be in File module
   - Full removal expected in future release

2. **Time unit atoms** → Singular forms preferred
   - Old: `:seconds`, `:milliseconds`, `:microseconds`, `:nanoseconds`
   - New: `:second`, `:millisecond`, `:microsecond`, `:nanosecond`
   - This aligns with Erlang/OTP conventions

3. **Enum.into/2 with non-empty list** → Use `Kernel.++/2` or `Keyword.merge/2`
   - Inconsistent behavior with maps; recommend explicit operators for clarity
   - Example: `list ++ another_list` instead of `Enum.into(another_list, list)`

4. **for comprehension with `:into` and non-empty list** → Use `Kernel.++/2` or `Keyword.merge/2`
   - Same rationale as Enum.into deprecation

5. **Inspect.Algebra functions** → Modern alternatives provided
   - `surround/3` → `Inspect.Algebra.concat/2` and `Inspect.Algebra.nest/2`
   - `surround_many/6` → `container_doc/6`
   - Provides more composable and flexible API

6. **`Kernel.ParallelCompiler` functions**
   - `files/2` → `compile/2`
   - `files_to_path/2` → `compile_to_path/2`
   - Names better reflect actual functionality

7. **`Kernel.ParallelRequire.files/2`** → `Kernel.ParallelCompiler.require/2`
   - Consolidates related functionality in ParallelCompiler module

8. **`@since` attribute** → Use `@doc since: "1.8.0"` instead
   - More explicit and integrates better with documentation tooling

9. **`mix compile.erlang` callback return values**
   - Old: `{:ok, contents}` or `:error`
   - New: `{:ok, contents, warnings}` or `{:error, errors, warnings}`
   - Enables better error/warning reporting in Erlang builds

### Soft Deprecations (no warnings, but discouraged)

None explicitly mentioned in this release, but the upgrade of Mix compile callbacks was a major deprecation cycle.

### Notable Changes (not strictly breaking)

- **File.exists?/2, File.regular?/2, File.dir?/2**: Now support `:raw` option for raw filesystem calls
- **Code.Formatter**: Now preserves user's choice of newline after most operators (more intuitive formatting)
- **IEx.Helpers.b/1**: Now uses typespec information instead of docs chunk for more accurate callback formatting

## Conclusion

Elixir v1.8.0 was a focused, professional release emphasizing quality and infrastructure. Rather than flashy new syntax, it delivered:

1. **Performance**: Tangible 5% compilation improvement and optimized runtime patterns
2. **Reliability**: Fixed long-standing issues in umbrella projects and process instrumentation
3. **Capability**: Opened new domains (embedded systems via Mix.target, time zones via pluggable databases)

The release maintained exceptional backward compatibility while strategically deprecating APIs in favor of more coherent alternatives. With 595 commits over 2.5 months, it represents steady, methodical improvement typical of Elixir's development philosophy.
