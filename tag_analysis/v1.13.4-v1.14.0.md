# Changes from v1.13.4 to v1.14.0

## Overview

- **Date Range**: November 1, 2021 – September 1, 2022 (10 months of development)
- **Total Commits**: 697 commits
- **Release Date**: September 1, 2022

This is a major version bump that represents significant enhancements to the Elixir language and ecosystem. The release focused on improving developer experience, adding powerful new debugging capabilities, strengthening security through Unicode improvements, and performance optimizations.

## Summary: Key Themes and Changes

Elixir v1.14.0 introduced a comprehensive set of improvements across multiple dimensions:

### Major Themes

1. **Developer Experience & Debugging**: Introduction of `Kernel.dbg/2` with full IEx integration, providing a powerful interactive debugging tool that transforms how developers debug Elixir code. This was a significant effort spanning multiple commits to ensure tight IDE/editor support and parity with the pry functionality.

2. **Language Security & Conformance**: Extensive Unicode security improvements aligned with Unicode Technical Standard 39 (UTS-39) for safe identifier usage, preventing confusable characters in code and restricting character mixing in identifiers. This represents a proactive stance on code security.

3. **Collections & Enumeration**: Major improvements to slicing operations across Enum, String, and a new binary_slice module. Includes step-based slicing, numerous bug fixes in edge cases, and performance optimizations across multiple enumeration functions.

4. **Build System Maturity**: Significant refactoring of Mix.State to use proper process-based storage with ETS backing, improved compile-time dependency tracking, better diagnostic information during compilation, and enhanced xref analysis tools.

5. **Module System Enhancements**: Addition of `@after_verify` callback for post-module verification hooks, improved compile-time module attributes handling, and better semantics around compile-time dependencies in macros and protocols.

6. **Performance**: Targeted optimizations including 100% faster Base encoding/decoding, optimized Enum operations (sort_by with desc, with_index for lists), and smarter variable loading in eval contexts.

7. **Backward Compatibility Breaks**: Removal of Rebar 2 support, dropping Erlang/OTP 22 support, and several deprecation cleanups to prepare the codebase for future development.

## Major Features & Improvements

### Interactive Debugging with `Kernel.dbg/2` and `Kernel.dbg/0`

This is the centerpiece feature of v1.14.0. The release introduces comprehensive debugging support:

- **`Kernel.dbg/2`**: A new function that debugs code in context, printing values with proper syntax highlighting and formatting. It can be called inline with expressions and supports pipeline integration.
- **`Kernel.dbg/0`**: Quick variant that captures and displays all bindings at the current point in code.
- **IEx Integration**: Full integration with IEx's pry functionality through a new dbg callback system. Developers can debug code interactively with pry directly from the REPL.
- **Line-by-line Breakpoints**: IEx now supports evaluating code line-by-line at breakpoints, enabling true step-through debugging.
- **Mix Project Support**: The dbg callback is properly tracked and managed within Mix projects, with configuration options to enable/disable as needed.
- **Shared Syntax Colors**: IEx and dbg share the same syntax coloring system for consistent visual feedback across debugging workflows.

**Commits**: `a8bf3498d9`, `2c61d41d9b`, `85d5dc5793`, `c22c909228`, `95dcce01c5`, `2e1381d430`, `ffa6bd844e`, `55eee6723b`, `eead8deeab` and others.

### Unicode Security Improvements (UTS-39 Compliance)

Elixir v1.14.0 implements comprehensive Unicode security measures to prevent code injection and confusion attacks through identifier naming:

- **Restriction 1 (C1)**: Prevents restricted characters in identifiers, blocking control characters and other dangerous Unicode sequences.
- **Restriction 2 (C2)**: Warns developers about confusable non-ASCII identifiers that could be visually mistaken for ASCII equivalents (e.g., Cyrillic 'А' vs Latin 'A').
- **Restriction 3 (C3)**: Enforces single-script and highly restricted mixed-script identifiers, preventing random mixing of different writing systems in the same identifier.

The implementation includes tokenizer normalization of Unicode characters and comprehensive linting on all relevant tokens. This proactive security measure addresses supply chain security concerns.

**Commits**: `4a5fcbe04a`, `a4689262d8`, `9e0ae6140a`, `e7001455d7`, `5deafbdc89`, and related commits.

### Enhanced Slicing Operations with Step Support

Major improvements to slicing semantics across the standard library:

- **`Enum.slice/2` with Steps**: Support for step parameter in list slicing, e.g., `Enum.slice(1..10, 0..-1//2)` for every other element.
- **`String.slice/2` with Steps**: Equivalent functionality for strings with proper Unicode codepoint handling.
- **`binary_slice/2` and `binary_slice/3`**: New functions for efficient byte-level slicing of binaries with comprehensive edge case handling.
- **`Access.slice/1`**: New Access protocol implementation allowing slicing through access operations.
- **Comprehensive Bug Fixes**: Multiple commits fixing edge cases in slice operations:
  - Fixing infinite loops in `Enum.take/2`
  - Fixing `Enum.drop/2` edge cases
  - Fixing selection of extra elements in `Enum.slice/2`
  - Proper overflow handling on both starting and ending positions

These improvements provide more powerful and flexible collection manipulation while maintaining performance.

**Commits**: `d04bcd4624`, `14ad5eaaae`, `75540648d9`, `e81e9f79bf`, `db7c28f0e7`, `f5810492b0`, `185689a8b1`, `3dd54ad3f3`, and others.

### New Collections & Data Structure Functions

- **`MapSet.filter/2` and `MapSet.reject/2`**: Filtering operations for MapSet, completing the functional toolkit for set operations.
- **`MapSet.symmetric_difference/2`**: (Renamed from `disjoint`) Returns elements in either set but not both, useful for set comparison operations.
- **`Float.min_finite/0` and `Float.max_finite/0`**: Constants providing the minimum and maximum finite float values for safer boundary checks.
- **`Range.shift/2`**: Shift a range by a given number of steps, useful for iterator manipulation and calendar operations.
- **`Stream.transform/5`**: More powerful transformation primitive allowing both an accumulator and state threading through stream transformations.
- **Calendar Improvements**: Addition of day, hour, and minute functions to `Calendar.add/3` and `Calendar.diff/3` for finer-grained time manipulation.

### Mix.install Enhancements

New options for `Mix.install/1`:

- **`:config_path`**: Specify custom configuration file paths for installation contexts.
- **`:lockfile`**: Support for lockfiles during installation, enabling reproducible dependency resolution.

These enhancements make `Mix.install` suitable for more complex scripting and dependency management scenarios.

### Logger Enhancements

- **`Logger.put_process_level/2`**: New function to set log levels per-process, enabling fine-grained control over logging verbosity.
- **Logger.enable/1 and Logger.disable/1 Rewrite**: Cleaner and more efficient implementation of process-level logging control.
- **`:warning` Level Support**: Logger console can now be configured with `:warning` level as the threshold, improving log output filtering.
- **Deprecations**: Deprecated `Logger.Formatter.levelpad` option, streamlining the logging API.

### Mix Improvements: Process-Based State Management

The Mix.State subsystem underwent major refactoring:

- **Converted from Atom to ETS-Backed Process**: `Mix.State` is now a proper OTP process using ETS for storage instead of an atom-based implementation, providing better concurrency semantics.
- **Lock for Concurrent Safety**: Added locking for `mix compile.elixir` to avoid concurrent usage issues that could lead to race conditions.
- **Better Compile-Time Dependency Tracking**:
  - Lazy expansion of module attributes to avoid unnecessary compile-time dependencies
  - Proper tracking of requires from local macros as compile-time deps
  - Improved tracking of imports inside describe blocks
- **xref Enhancements**:
  - New `--group` option for `mix xref graph` to organize output by module groupings
  - Better error handling for `--exclude` option with non-existent files
  - Improved consolidation warning suppression during tracing

### PartitionSupervisor Enhancements

The new PartitionSupervisor module received polishing and feature additions:

- **Improved Naming**: Now accepts any valid name format, not just specific patterns.
- **Better Specs**: Added comprehensive type specs including `t:Supervisor.sup_flags/0`.
- **Implementation Notes**: Clearer documentation about internal implementation details and use cases.

### New/Enhanced Mix Commands

- **`mix eval`**: New command for evaluating Elixir expressions from the command line with proper project context and dependency loading.
- Enhanced `mix format` to support reading from stdin with proper filename specification.

### @after_verify Callback

A new callback for module verification:

- **`@after_verify`**: Define compile-time verification hooks that execute after a module is fully compiled.
- Enables post-compilation module inspection and validation without the limitations of `@after_compile`.
- Properly tracks compile-time dependencies for required modules.
- Stores IO.warn messages from verification hooks for proper error reporting.

### Application Compilation Environment

New functions for safer compile-time configuration:

- **`Application.compile_env/4` and `Application.compile_env!/3`**: Retrieve compile-time configuration with default values and strict variants, improving error handling and configuration safety.

### Code Fragment Improvements

- **Multi-line Fragment Support**: Code.Fragment functions now properly work across newline boundaries.
- **Unicode Support**: Proper handling of Unicode sequences in fragment parsing.
- **Module Name Support**: `__MODULE__` now supported in Code.Fragment for better IDE/editor integration.
- **Consistent Windows Line Endings**: Fragment analysis now works consistently with Windows (CRLF) line endings.

### File Operations

- **`File.cp_r!` improvements**: Better handling of the `on_conflict` option parameter.
- **`File.dereference_symlinks` option**: New option for `File.cp*` functions to control symlink handling during copying.
- **Type Checking**: `File.rename/2` and `File.copy/2` now validate path types for safer operation.

### Type System Improvements

- **Fixed Infinite Loop in Type Unification**: Resolution of issue #11658 where complex type variable unification caused infinite loops.
- **Better Type Diagnostics**: Improved error messages and column information for type specification errors.
- **Enhanced Specs**: More comprehensive type specifications for various modules, improving IDE support and static analysis.

## Bug Fixes

### Enum & Collections (Multiple Commits)

- **Multiple slice/drop/take bugs**: Fixed cascading bugs in list slicing operations that were causing incorrect element selection, infinite loops, and overflow issues. These were addressed across commits `f5810492b0`, `185689a8b1`, `db7c28f0e7`, `e81e9f79bf`.
- **`Enum.slide/3` edge cases**: Fixed edge cases in the slide operation with comprehensive spec addition.
- **Range step handling**: Fixed issue where step was being set to `nil` in range operations.

### Compilation & Type System

- **Type variable unification infinite loop** (closes #11658): Fixed critical bug where certain type variable patterns caused infinite loops during compilation.
- **Better error handling for overflowing floats**: `Float.parse/1` no longer raises on overflowing floats, returning appropriate error codes instead.
- **Macro.to_string with empty list attributes**: Fixed incorrect handling of module attributes containing empty lists.

### IEx & Interactive Features

- **Pry parsing** (closes #12072): Fixed issue where `--no-pry` flag wasn't allowing proper continuation of parsing.
- **Sigil handling in IEx help**: Improved sigil resolution in IEx help system.
- **Binary modifier autocompletion**: Better handling of binary modifier completion in IEx.

### Code Analysis

- **Unclosed backquotes** (closes #12061): Fixed parsing of unclosed backquotes in Code.Fragment and Macro analysis.
- **Backslash identifier regression**: Fixed regression where `identifier\\` was being interpreted as a single token.
- **Pipeline expansion** (closes #12070): Fixed issue with pipeline expansion on the right-hand side of `|>` operator.

### Module System

- **`@after_verify` compilation deps** (d522f96fa5, e281427cb8): Fixed proper listing of compile-time dependencies for modules using `@after_verify`.
- **Module attribute with empty list** (closes #12097): Corrected `Macro.to_string` handling of empty list module attributes.

### File System

- **File.cp_r! on_conflict parameter** (closes #12015): Fixed incorrect passing of the on_conflict option.
- **Path handling on notification scripts** (ed076eb2fe): Fixed script path issues.

### Other Notable Fixes

- **URI.append_query/2 trailing ampersand** (closes #12069): Proper handling of trailing ampersands in query string operations.
- **System.put_env/1 enhancements** (d71de51332): Now allows key-deletions and atom keys for more flexible environment manipulation.
- **GenServer continue argument** (122cc003a0): Renamed `continue` argument in `handle_continue/2` for consistency (though this is primarily a documentation improvement).
- **EEx tokenization** (32cde7f78a): Fixed CaseClauseError in EEx tokenizer.
- **Version parsing** (feb9884a3e): Fixed `Version.parse/1` incorrectly stripping dots from version field.
- **Date.Range typespec** (12116a52be): Fixed incorrect typespecs for `first_in_iso_days` and `last_in_iso_days`.
- **ExUnit assertion operators** (990d76f1a7): Fixed assertions when operators are overridden in user code.

## Breaking Changes

### Removed: Rebar 2 Support

- **Complete Removal**: Rebar 2 support has been removed entirely. Projects must migrate to Rebar 3.
- **Deprecation Warning Added**: A deprecation warning was added in earlier releases to alert users.
- **Impact**: Projects still using Rebar 2 dependencies will need to migrate or find alternatives.

**Commits**: `e6b5a91760`, `5cca5e5fbb`, `b5f9f071f4`

### Removed: Erlang/OTP 22 Support

- **Dropped Compatibility**: Elixir v1.14.0 no longer supports Erlang/OTP 22.
- **Minimum Version**: Erlang/OTP 23+ is now required.
- **Test Coverage**: CI has been updated to test against OTP 24.3 and 25 (latest at release time).

**Commits**: `12981b15df`, `c99025f88c`, `2d62dd5a62`

### Deprecations (Still Supported But Will Be Removed)

- **`Logger.Formatter.levelpad`** (f20c0172b0): Deprecated option for log formatting. Use configuration through the logger system instead.
- **`Map.map/2` Deprecation** (9bb1202138): Remains deprecated; use `Map.new/2` with enumeration instead.

### Semantic Changes

- **Pipeline Expansion Behavior** (42ecc84e87): Fixed how pipelines are expanded on the right-hand side of `|>`, which could affect code that was relying on the incorrect behavior.
- **Macro.unpipe/2 Undeprecated** (d5a2233cc4): This function is no longer marked as deprecated after being removed from planned removal.
- **Type Unification Behavior** (407391d13a): Fixed infinite loop conditions that may have allowed some previously-compiling code to work differently.

### Compiler/Mix Behavior Changes

- **Compile-Time Dependency Tracking**: Stricter and more accurate tracking of compile-time dependencies. Code that was accidentally working without properly declaring dependencies may now fail to compile.
  - Example: Using macros or requires without proper dependency declarations
  - **Commits**: `45b17afc13`, `6106a37d02`, `562113720c`, `828c6026a8`

- **Module Attribute Expansion**: Module attributes are now lazily expanded to avoid spurious compile-time dependencies. This is generally more correct but could affect edge cases.
  - **Commit**: `562113720c`

## Migration Guide Notes for v1.13.4 Users

1. **Rebar 2 Projects**: Must migrate to Rebar 3 or update dependency management approach.

2. **Erlang/OTP 22 Users**: Must upgrade to Erlang/OTP 23 or later (OTP 25+ recommended for best performance).

3. **Compile-Time Dependencies**: Review code using macros and protocols to ensure proper dependency declarations. Stricter checking may reveal missing declarations.

4. **Logger Configuration**: Update any code using `Logger.Formatter.levelpad` option to use new logger level management functions.

5. **Unicode Identifiers**: Code with complex mixed-script identifiers may receive new warnings or errors. Align identifiers with UTS-39 C3 restrictions.

6. **Debugging Workflow**: Adopt new `Kernel.dbg/2` for better interactive debugging instead of `IO.inspect` or manual inspection.

7. **Slicing Operations**: Existing slice calls continue to work, but consider leveraging new step support in Enum.slice/2 and String.slice/2 for cleaner code.

## Summary

Elixir v1.14.0 represents a significant step forward in language maturity and developer experience. The addition of powerful debugging capabilities through `Kernel.dbg/2`, security improvements through Unicode conformance, and numerous quality-of-life enhancements across collections, the module system, and build tooling make this a compelling upgrade. While the removal of Rebar 2 and Erlang/OTP 22 support requires migration effort, the improvements to the development workflow and language security justify the effort.
