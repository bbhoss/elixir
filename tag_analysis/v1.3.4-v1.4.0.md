# Changes from v1.3.4 to v1.4.0

## Overview

- **Release Date Range**: October 9, 2016 - January 5, 2017 (approximately 3 months)
- **Total Commits**: 808 commits
- **Release Type**: Major version update with significant new features, deprecations, and improvements
- **Status**: v1.4.0 released January 5, 2017 with v1.4.0-rc.0 (Nov 28) and v1.4.0-rc.1 (Dec 5) release candidates

---

## Summary

Elixir v1.4.0 represents a significant milestone release with a strong focus on enhancing the standard library, improving developer experience through better tooling, and laying groundwork for future development through strategic deprecations. The release introduced over 800 commits that span multiple areas: new library modules (Registry), expanded concurrency primitives (Task.async_stream), improved date/time handling, substantial deprecation of legacy modules, and considerable improvements to error messages and documentation throughout.

This release maintains a pragmatic approach to backwards compatibility while aggressively deprecating outdated modules and features that have accumulated from earlier Elixir versions. The team also invested heavily in reducing technical debt through code cleanup, improved error messaging, and enhanced test coverage.

---

## Major Features and Additions

### 1. **Registry Module - New Process Registry System**
One of the most significant additions is the new `Registry` module, a robust process registry that replaces older patterns and provides better performance characteristics. This module supports:
- Named process registration and lookup
- Multiple registrations per process
- Match-based lookups for more powerful queries
- Built-in supervision patterns via Supervisor.Spec

The Registry implementation went through multiple refinements during the release cycle, including optimizations like using ranges instead of `:lists.seq/2` for better performance.

### 2. **Task.async_stream/3 and Task.async_stream/5 - Concurrent Stream Processing**
New functions for concurrent stream processing that combine the power of `Task` concurrency with `Stream` operations. These functions allow developers to:
- Process streams of items concurrently
- Control concurrency with configurable limits
- Properly handle task lifecycle and exit messages
- Integrate seamlessly with existing stream-based code

The implementation includes careful handling of child task linking after parent unlinks and proper cleanup of exit messages.

### 3. **DateTime and Date/Time Enhancements**
Significant expansion of date/time functionality:
- `DateTime.from_iso8601/1` - Parse ISO 8601 datetime strings
- `DateTime.from_naive/2` - Convert naive datetimes to aware datetimes
- `Date.day_of_week/1` - Get the day of the week for a date
- `Date.leap_year?/1` - Check if a year is a leap year
- `Date/Time/NaiveDateTime.compare/2` - Comparison functions for date/time types
- Support for `add()` and `diff()` operations on NaiveDateTime

These additions make date/time manipulation more complete and align Elixir with common requirements in web applications and data processing.

### 4. **Stream and Enumeration Improvements**
- `Stream.uniq_by/2` - Get unique elements based on a function (replacing deprecated `Stream.uniq/2`)
- `Stream.zip/1` and `Enum.zip/1` - Zip multiple enumerables together
- Significant performance optimizations for `Enum.reduce/3` when used with ranges
- Improved documentation for `Stream.interval/1` and other stream operations

### 5. **Process and Concurrency Enhancements**
- `Process.send_after/4` - Schedule message delivery with more control
- `Process.sleep/1` - New recommended replacement for `:timer.sleep/1`
- Better error messages for `Process.register/2` failures
- Improved linking behavior in Task operations

### 6. **MapSet Type Addition**
- Added `MapSet.t/1` type specification
- Expanded documentation for "set" datatype in MapSet module
- Made MapSet the recommended collection for unique unordered values

### 7. **IEx Enhancements**
- **Syntax Highlighting of IEx Results** - Results are now syntax-highlighted for better readability
- **Improved Autocomplete** - Support for navigating map atom keys in autocompletion
- Better handling of struct key autocomplete (no longer raises errors)
- Documentation improvements for IEx helpers

### 8. **Mix and Build System Improvements**
- **Automatic Application Inference** - Mix can now automatically infer the list of applications from dependencies
- **Better Default Test Task Behavior** - Improved handling of test task defaults
- **`:extra_applications` Support** - New way to specify applications in escript.build (replacing :applications)
- **--formatter Option for Mix Test** - Ability to specify test formatters via command line
- **ExUnit Formatter Improvements** - Support for GenServer in new ExUnit formatters
- **Umbrella Application Warnings** - Better validation and warnings for invalid umbrella child applications

### 9. **Unicode 9.0.0 Support**
Updated Elixir to support the latest Unicode standard (9.0.0), including updated character classifications and properties for improved string handling.

### 10. **Port Module Documentation**
Comprehensive documentation additions for the Port module, which had previously lacked detailed documentation. Includes proper specifications and usage examples.

## Deprecations and Removals

### Hard Deprecations (Removal Planned for v1.5+):

1. **Set Module - HARD DEPRECATED**
   - The Set module is completely deprecated
   - Users should migrate to MapSet
   - This removes a legacy data structure from early Elixir history

2. **Dict, HashDict, and HashSet - HARD DEPRECATED**
   - These modules are deprecated in favor of Map and MapSet
   - Represents a major cleanup of data structure options
   - Part of standardizing on modern hash-based collections

3. **Behaviour Module and Macros - DEPRECATED**
   - The Behaviour module (deprecated in v1.1) is formally hard-deprecated
   - Users should use `@callback` and `@macrocallback` instead

### Soft Deprecations (Warnings in v1.4):

1. **Stream.uniq/2 - Soft Deprecated**
   - Replaced by `Stream.uniq_by/2` for consistency with Enum
   - Will be hard deprecated in future versions

2. **Access.key/1 - Soft Deprecated with Warning**
   - Behavior changed; soft deprecation in v1.4
   - Users should use Access.key/2 instead

3. **import_file/2 - Deprecated**
   - Removed from the public API

4. **-pr CLI Option - Deprecated**
   - Removed from Mix.Tasks.Run

5. **Private Function Overrideability - Deprecated**
   - Making private functions overridable is no longer supported
   - Enforces better encapsulation

### Removals:

1. **Erlang Version Support** - Code for outdated Erlang versions removed
2. **Module Compile Time Information** - Deprecated module compile time information removed
3. **Kernel.rand/0 and Kernel.rand/1** - Removed (replaced by better random functions or removed as redundant)
4. **Dict Revert** - A previous hard deprecation of Dict was reverted, then re-deprecated

## Breaking Changes

### Type System and Validation (Minor but Important):

1. **Keyword.merge/2 and Keyword.merge/3** - Now properly raise when given non-keyword-lists instead of silently accepting other types. This is a breaking change for code that relied on lenient type coercion.

2. **Access Module Behavior** - Access.key/1 behavior changed, requiring migration to Access.key/2

3. **:applications vs :extra_applications** - New distinction for escript.build between applications and extra_applications

### Data Structure Changes:

1. **Dict, HashDict, HashSet Deprecation** - Code using these modules will generate deprecation warnings and must migrate to Map/MapSet

2. **Set Module Deprecation** - Code using Set must migrate to MapSet

### Module Removal:

1. **Behaviour Module** - Code using the old Behaviour module will need to migrate to callback annotations

## Migration Path for Users

### Recommended Actions:

1. **Update date/time code** - Take advantage of new DateTime and Date functions for cleaner code
2. **Migrate from Set to MapSet** - Before Set is hard-deprecated
3. **Replace :timer.sleep/1 with Process.sleep/1** - Use recommended APIs
4. **Update Behaviour modules** - Convert to `@callback` annotations
5. **Validate Keyword usage** - Ensure Keyword.merge is only called with proper keyword lists
6. **Test thoroughly** - Even though v1.4 is mostly backwards compatible, the deprecations may affect your code

### What Stays Compatible:

- Most application code continues to work without changes
- Function signatures generally preserved (deprecations added with warnings)
- Core language features unchanged
- Backward compatibility maintained where possible

## Conclusion

Elixir v1.4.0 is a mature release that demonstrates the language's evolution toward stability and completeness. While introducing 808 commits across nearly three months of development, the release maintains pragmatic backwards compatibility while aggressively cleaning up technical debt through strategic deprecations. The addition of Registry, Task.async_stream, and expanded date/time support represents meaningful additions to the standard library. The heavy investment in documentation, error messages, and developer tooling shows the project's commitment to usability. The hard deprecations of legacy modules (Set, Dict, HashDict, HashSet, Behaviour) mark a clear break with the past and a push toward modern Elixir patterns, making this a significant milestone in the language's maturation.
