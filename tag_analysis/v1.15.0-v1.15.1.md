# Changes from v1.15.0 to v1.15.1

## Date Range and Commit Summary

- **Release Period**: June 19, 2023 to June 30, 2023 (11 days)
- **Total Commits**: 30 commits (plus 1 release commit)
- **Release Type**: Patch release (v1.15.0 → v1.15.1)

## Summary

Elixir v1.15.1 is a focused patch release addressing critical bugs and compatibility issues identified shortly after v1.15.0. The release concentrates on stability improvements across the compiler, testing framework, logging infrastructure, and dependency management. Most changes are defensive bug fixes targeting edge cases and runtime assumptions that could fail under specific conditions or with different Erlang/OTP versions.

## Key Themes and Changes

### 1. Compiler Robustness and Error Handling
The compiler received several improvements to handle edge cases and fail more gracefully:

- **Better error reporting**: Changed `mix compile` to return errors instead of raising exceptions, allowing better integration with build systems and error recovery
- **Path assumptions**: Fixed assumptions about project paths in the compiler invocation process
- **Custom compiler support**: Improved handling of yecc and leex tools for custom compiler configurations, ensuring proper availability checks before execution
- **Windows compatibility**: Fixed a path-related issue on Windows systems

### 2. Dependency and Module Tracking
Enhanced dependency resolution and module tracking across different dependency types:

- **Transitive dependencies**: Fixed issues with included dependencies that are transitive from path dependencies not being properly loaded
- **Optional dependencies**: Ensured optional dependencies are correctly included when build mode changes
- **Module tracking**: Improved tracking of removed modules and exports across local dependencies, preventing stale references

### 3. Testing Framework Improvements
Several fixes address doctest and test execution issues:

- **Doctest enhancements**:
  - Variables defined in doctests can now be used in expectations, enabling more complex test scenarios (#12730)
  - Fixed handling of non-result doctests terminated with fences (code block markers)

- **Test configuration**: Fixed an issue where `:test_type` configuration was incorrectly affecting test execution
- **Race conditions**: Fixed a race condition in the doctest runner affecting test reliability

### 4. Logger and Logging Fixes
Critical fixes to the Logger module and logging utilities:

- **Runtime assumptions**: Fixed assumptions that Logger had been loaded at compile-time, preventing crashes in certain execution contexts
- **capture_log reliability**:
  - Fixed options not being respected when calling `capture_log`, affecting test setup
  - Fixed a concurrent access race condition in `capture_log` that could cause test flakiness

- **dbg debugging**: Fixed `dbg/1` macro compatibility with Erlang/OTP 25 and earlier versions

### 5. Parser and Code Generation
Improvements to the parser and code generation for special syntax:

- **Sigil encoding**: Parser now properly honors the `:static_atoms_encoder` option for multi-letter sigils, ensuring consistent atom encoding across different compilation scenarios
- **Metadata handling**: Fixed proper handling of `:function` metadata during code generation

### 6. Developer Experience
Various improvements to error messages, documentation, and tooling:

- **Error messages**: Added a tip about `compile_env` that helps developers fix compilation environment errors across all contexts (#12702)
- **Documentation**: Added reference to Erlang's `:math` module in the Float documentation for better discoverability
- **Shell compatibility**: Fixed a subtle bug in shell flag output by using `printf` instead of `echo`, which properly handles flags like `-e` that echo interprets as options (#12704)
- **External resources**: Fixed assumption that external resources (like documentation) are always available during compilation

### 7. Release and Platform Support
Maintenance updates for Erlang/OTP compatibility:

- **OTP 26 support**: Removed `--werl` flag from Erlang/OTP 26 release scripts due to compatibility changes
- **Documentation handling**: Fixed assumption that Erlang/OTP was built with documentation available

## Major Features/Improvements

- **Enhanced doctest capabilities**: Variables can now persist across test boundaries within doctests
- **Improved error handling**: Compiler now returns errors instead of raising, improving integration with build pipelines
- **Better dependency resolution**: More robust handling of transitive and optional dependencies
- **Platform compatibility**: Windows path handling and cross-OTP version support improvements

## Notable Commits Worth Highlighting

### Critical Fixes
1. **Fix race condition on concurrent capture_log** (`1ca5d789bb`) - This fixes a threading issue that could cause test flakiness in concurrent test scenarios. Important for test reliability.

2. **Track removed modules and exports across local deps** (`a89f8a9913`) - Prevents stale module references when dependencies are updated, improving build correctness.

3. **Do not assume Logger has been loaded at compile-time** (`785c29210e`) - A critical assumption fix that prevents runtime crashes in certain execution contexts.

## Conclusion

Version 1.15.1 is a stability-focused patch that addresses edge cases and assumptions from the initial v1.15.0 release. The changes are predominantly defensive, fixing issues that would surface under specific conditions: concurrent test execution, different Erlang/OTP versions, custom compiler configurations, or certain dependency structures. No new features are introduced, but the overall reliability and compatibility of Elixir are improved.

This release is recommended for all v1.15.0 users, particularly those experiencing:
- Test flakiness related to logging or doctests
- Compilation issues with custom compilers or Windows systems
- Dependency resolution problems with transitive or optional dependencies
- Cross-version compatibility issues with Erlang/OTP 25+ environments
