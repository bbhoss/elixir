# Changes from v0.9.2 to v0.9.3

## Release Information

- **Release Period**: June 13, 2013 to June 23, 2013 (10 days)
- **Total Commits**: 180 commits
- **Previous Version**: v0.9.2 (released 2013-06-13)
- **Current Version**: v0.9.3 (released 2013-06-23)

## Summary

This release represents a significant iteration on Elixir 0.9, encompassing 180 commits focused on stabilizing the language, improving the Mix build tool, enhancing the macro system, and ensuring Windows compatibility. The release introduces important API refactoring for consistency, implements new features in the standard library, and significantly improves developer experience through better error messages and tooling support.

Key themes include:
- **API Standardization**: Systematic renaming and refactoring of APIs for consistency
- **Mix Tool Enhancement**: Introduction of Mix.Version and package/archive management
- **Macro System Improvements**: Enhanced quoting capabilities and binding support
- **Developer Experience**: Better error reporting, Windows support, and documentation
- **Code Quality**: Operator table reorganization and internal refactoring

## Major Features & Improvements

### 1. Mix Build System Enhancements

#### Mix.Version Implementation (Closes #1115)
A new `Mix.Version` module was implemented to handle semantic versioning throughout the Mix ecosystem. This provides:
- Structured version parsing and comparison
- Support for semantic versioning standards
- Better dependency version management
- Documentation and proper module organization with version as first argument

**Impact**: This is a foundational feature that improves Mix's ability to manage dependencies and versions across projects.

#### Mix Package and Archive System
The Mix local package system was completely redesigned with new mix tasks:
- `mix package` - Creates installable packages from projects
- `mix local.install` - Installs local packages
- `mix local.uninstall` - Uninstalls packages with warnings
- Support for `.ez` archive files as the package format
- Automatic handling of project `.ebin` directories and `priv` folders
- Better documentation and user guidance after creating new repositories

This addresses issue #1124 and provides a mechanism for sharing and distributing Elixir code locally.

#### Improved Mix Escript Support
- Better documentation for `mix escript_app`
- Ensured escript_app doesn't break the app structure
- Fixed recursive escriptization (Closes #1296)
- Escript no longer tries to read directories as files
- No longer supports .beam files in mix local, only proper Elixir code

### 2. API Refactoring and Standardization

#### Code Module Refactoring
- **`Code.string_to_ast` → `Code.string_to_quoted`**: Renames the function to better reflect its purpose (returning quoted expressions, not an AST)
- Updated all documentation and internal references
- Cleanup of related functionality

#### Macro Module Updates
- **`Macro.to_binary` → `Macro.to_string`**: More consistent naming with Elixir conventions
  - Deprecation warning provided for backward compatibility
- **New Functions Added**:
  - `Macro.expand_once/2` - Expand macros one level
  - `Macro.expand_all/2` - Recursively expand all macros
- **Enhanced Documentation**: Better explanation of Macro.expand functionality

#### Sigil Renaming (Closes #1301)
- **Old Style**: `__identifier` (double underscore prefix)
- **New Style**: `sigil_identifier`
- This makes the sigil system more explicit and discoverable
- Consistent with Elixir's naming conventions

### 3. Macro and Quoting System Enhancements

#### Enhanced Quote Functionality
- **`:binding` Option Support**: The `quote/2` macro now accepts `:binding` as an option
  - Allows capturing and using bindings inside quoted expressions
  - Useful for metaprogramming that needs access to runtime bindings
- **IO.ANSI Updates**: Now uses binding internally for better ANSI code generation

#### Macro Escaping Improvements
- **`Macro.escape/2`**: Added support for `unquote: true` option
  - Allows selective unquoting within escaped expressions
  - Provides more flexibility in quoted expression manipulation

#### Binding Access Functions
- **`binding/0`**: New function to retrieve all current bindings as a keyword list
- **`binding/1`**: Enhanced version that filters bindings across different contexts
  - Supports retrieval from specific scopes
  - Closes issue #1238 by providing programmatic access to binding
  - Both functions validate their input arguments

### 4. File Module Enhancements

#### New File Permission Functions (Closes #1300)
Added three new functions for file permission management:
- **`File.chmod!/2`**: Change file permissions (mode)
- **`File.chown!/2`**: Change file owner
- **`File.chgrp!/2`**: Change file group

These functions complete the file system API with proper error handling via exceptions.

#### File.rm_rf Improvements
- Fixed bug on Windows where `File.rm_rf` would fail on invalid entries
- `File.rm_rf!` now gracefully handles invalid entries
- Improved error messages pinpointing exact location of failures
- Better error handling with regex-based exception matching

#### File Documentation Updates
- Cleaned up File module documentation
- Better @moduledoc wording and explanations

### 5. Record System Updates (Closes #1288)

#### Record Type Visibility
- **Record types are now private by default**
- Previously record types were public, now they're internal to the module
- Applies to both `defrecord` and `defrecordp`
- Types can be explicitly made public if needed
- Improves encapsulation and API boundaries

#### Record Enhancement
- Support for providing types to `defrecordp` (previously only in `defrecord`)
- Better alignment between record/1 and record/2 functionality

### 6. Operator Table Reorganization

A comprehensive reorganization of the operator precedence and associativity table was completed (multiple commits across the release):

**Changes Made**:
- **Unary Operators**: Moved to new schema for better organization
- **Comparison Operators (comp_op)**: Reorganized in new table structure
- **Logical Operators**: `and` and `or` operators moved to new table
- **Arrow-like Operators**: Grouped together for clarity
- **Arithmetic Shift Operators**: `++`, `--`, `**`, `//` reorganized
- **Final Cleanup**: Finished operator table with sensible, clean organization

**Purpose**:
- Provides clear extension points for custom operators in the future
- Makes the operator table in `elixir_parser.yrl` more maintainable
- Documentation was added explaining the table structure

**Breaking Change**: The precedence of operators used by the Bitwise module was changed as part of the cleanup.

### 7. ExUnit Testing Framework Improvements

#### Better Assertion Output (Closes #1276)
- **Enhanced error messages**: When assertions fail, the original unevaluated statement is now shown
- **Error type change**: Switched from `AssertionError` to `ExpectationError` for clearer messaging
- **Applies to both**: `assert/1` and `refute/1` macros
- Example: If `assert x > 5` fails, you see the statement `x > 5` in the error message

#### Other ExUnit Improvements
- `Enum.take/2` fixed to not peek ahead (avoids unwanted side effects)
- Test cleanup and organization improvements
- Better error message formatting in ExUnit

### 8. Compilation and Build Improvements

#### Warnings as Errors Feature (Closes #898)
A comprehensive feature to treat warnings as compilation errors:
- **New Option**: `--warnings-as-errors` flag for `mix compile`
- **Per-compiler Support**: Works across all elixirc compilation options
- **Proper Handling**:
  - Warnings output to stderr consistently
  - Compilation status properly tracked when warnings become errors
  - Only changes status if `warnings_as_errors` is set
  - Proper exit codes returned to callback mechanisms

#### Parallel Compiler Enhancements
- Updated callback documentation for parallel compilation
- Better status passing to main process
- Exit status now available in callbacks for decision-making
- Improved handling of partial compilation states

#### Enhanced Error Reporting
- Parser now attaches metadata to `->` clauses for accurate error location reporting
- Arrow-like operator clauses can now point to exact source locations
- Improves debugging experience

## Bug Fixes

### Core Language

1. **Caret Variables (^x)** (Closes #1307)
   - Fixed: Caret variables now always refer to the value before the expression
   - Important for correct pattern matching semantics

2. **When Clause Enhancement** (Closes #1313)
   - Support for `(x, y) when z` pattern syntax
   - Enables guards on tuple patterns
   - Added comprehensive tests for nested when clauses

3. **Module Imports in Quotes** (Closes #1225)
   - Fixed imports inside quoted expressions not being properly registered
   - Ensures that macros using quoted code with imports work correctly

4. **defmodule with Atom** (Fixed)
   - `defmodule :atom` no longer incorrectly defines an alias
   - Proper atom handling in module definition context

5. **__MODULE__ Reference Outside Module**
   - Now returns `Foo` for `__MODULE__.Foo` when used outside a module context
   - Better handling of module references

6. **Module Clashing Prevention** (Fixed)
   - Avoid naming clashes between modules and generated code
   - Namespace isolation improvements

### Data Structures

1. **HashDict.equal? Bug** (Closes #1245)
   - Fixed: `equal?/2` was not properly comparing two dictionaries
   - Now correctly compares values in both dicts

2. **HashDict Contract Efficiency** (Closes #1240)
   - Improved efficiency of HashDict contraction when downsizing
   - No longer needs to relocate key-value pairs unnecessarily
   - Deepest nodes become buckets containing all relevant pairs

3. **Record Inspection in Tuples** (Fixed)
   - Fixed bug when inspecting records nested within tuples
   - Better Inspect protocol support

4. **Dict.drop Documentation** (Fixed)
   - Removed documentation of .split, .drop and .take from HashDict/ListDict
   - These are documented on Dict module instead
   - Avoided documentation duplication

### String and Binary

1. **String Matching Optimization**
   - Now uses `:binary.match(left, right)` directly instead of going through `String.contains?`
   - More direct and efficient implementation

2. **Regular Expression Support**
   - `=~` no longer needs to be a macro
   - Refactored to support dynamic calling: `mod.+(1, 2)` now works
   - Operators +, -, and friends can now be called dynamically

### Windows Compatibility

Multiple commits addressing Windows-specific issues:

1. **elixir.bat Fixes**
   - Now works from any directory, not just ./bin folder (Closes #1269-1270)
   - Proper handling of drive prefixes in path comparisons
   - Parameter validation for Erlang and Elixir commands
   - Proper path separator handling in MSYS environments
   - Removed "*.ex/file" parameter checking, now passes unknown parameters through
   - Fixed echo prefix removal

2. **Rebar Integration on Windows**
   - Fixed rebar wrapper detection (.cmd files should not be wrapped as escript)
   - Use .bat executables instead of .cmd when appropriate
   - Proper system executable resolution

3. **File Path Testing**
   - Fixed path tests that included drive prefixes (e.g., C:\)
   - IO tests now accept alternate error codes on Windows

4. **Git Configuration**
   - Added .gitattribute files to prevent CRLF auto-conversion in test fixtures
   - UTF-8 directories not checked into source control (build artifacts)
   - Proper line ending handling across platforms

### Parsing and Compilation

1. **Command-line Parsing** (Closes #1294)
   - Fixed: Stopped parsing on `-S` flag
   - Proper handling of script arguments

2. **Eval Options Validation** (Closes #1238)
   - Added proper validation of eval options
   - Better error messages for invalid options

3. **Module Attribute Warnings** (Closes #963)
   - New warning for undefined module attributes
   - Helps catch typos and mistakes in module attributes

4. **Default Clause Collision Detection** (Closes #1244)
   - Now raises proper warnings when default clauses from different definitions collide
   - Prevents silent bugs from conflicting defaults

5. **Guard Warnings**
   - Added warning for useless pattern `'x in []'` in guards
   - Helps developers catch incorrect patterns

## Breaking Changes

### API Changes

1. **`Code.string_to_ast` → `Code.string_to_quoted`**
   - Direct rename affecting code that imports this function
   - Both functions available temporarily; old one should be migrated away from
   - The new name better reflects what the function returns

2. **`Macro.to_binary` → `Macro.to_string`**
   - Deprecation warning provided for backward compatibility
   - Code should be updated to use `Macro.to_string`

3. **Sigil Naming Convention**
   - `__identifier` → `sigil_identifier`
   - Any custom sigils need to be renamed
   - Makes sigil system more explicit and aligned with Elixir naming

4. **Record Type Visibility**
   - Record types now private by default
   - May break code that relied on accessing generated type definitions
   - Explicit opt-in required if public types are needed

5. **Operator Precedence Changes**
   - Bitwise operators have changed precedence
   - Code relying on specific operator precedence for bitwise operations may need updating
   - Mostly affects unusual patterns mixing bitwise and other operators

### Deprecations

1. **Fun Spec Style**: `(fun(...) -> ...)` style function specifications are deprecated
   - Ambiguous syntax that reads as "function receiving another function as argument"
   - New style should be used for clarity

2. **Code.string_to_ast**: While still available with deprecation warning, migrate to `Code.string_to_quoted`

### Behavioral Changes

1. **Mix Local .beam Support**: No longer support .beam files in `mix local`
   - Only Elixir source code packages are supported
   - Improves package consistency

2. **Dependency Tracker EXIT Messages**: EXIT messages from dependency tracker no longer bubble up
   - Prevents pollution in IEx and script execution
   - Cleaner execution environment

## Upgrade Recommendation

For users on v0.9.2:
1. **Test thoroughly** - Multiple API changes require code updates
2. **Update custom sigils** - Rename from `__` prefix to `sigil_` style
3. **Migrate Code/Macro calls** - Update to new function names
4. **Review operator usage** - If using bitwise operators with mixed precedence
5. **Update Mix scripts** - If using packages/archives, review new system
6. **Take advantage of new features** - binding/0, binding/1, Mix.Version, etc.

The v0.9.3 release represents steady maturation of Elixir with focus on stability, consistency, and developer experience.
