# Changes from v1.12.0 to v1.12.1

## Release Overview

**Release Date:** May 28, 2021

**Date Range:** May 19 - May 28, 2021

**Commit Count:** 15 commits

**Release Type:** Patch Release (Bug Fixes)

## Summary

v1.12.1 is a patch release focused on stabilizing the features introduced in v1.12.0. Released just 9 days after v1.12.0, this release addresses critical bugs and regressions that emerged in real-world usage. The updates span across multiple areas: the experimental `Mix.install/2` feature, code formatting, string/Unicode handling, and build infrastructure. This was not a release of new features, but rather a focused effort on quality and stability.

The patch release demonstrates the Elixir team's commitment to shipping stable code and responding quickly to issues found in early versions. Each fix is carefully targeted at specific problems reported by users, with no broad API changes or deprecations introduced.

## Bug Fixes and Improvements

### Mix.install/2 Stability (2 commits)

The newly introduced `Mix.install/2` feature in v1.12.0 received critical fixes:

1. **Ensure Mix.install/2 can be called after errors with deps (#11011)**
   - Problem: If an error occurred during dependency resolution, subsequent calls to `Mix.install/2` would fail
   - Solution: Improved error state management to allow recovery from dependency errors
   - Impact: Users can now retry or run different scripts after encountering dependency issues

2. **Mix.install/2: Expand paths for path deps (#11012)**
   - Problem: Path-based dependencies in `Mix.install/2` were not properly expanding relative paths
   - Solution: Added path expansion logic for path dependencies
   - Impact: Relative paths in dependency declarations now work as expected

These fixes were crucial because `Mix.install/2` was marked as experimental and needed to prove reliability for the scripting use case.

### Code Formatting Fixes (2 commits)

The code formatter received targeted improvements:

1. **Format multiline inside interpolation on first run (#10996)**
   - Problem: Multiline expressions inside string interpolations were not formatted correctly on the first run, requiring multiple passes
   - Solution: Improved the formatter's handling of interpolated expressions
   - Impact: Code formatting is now consistent and single-pass for interpolation cases
   - Files modified: `lib/elixir/lib/code/formatter.ex`, integration tests

2. **Fix formatter integration test**
   - A test was failing that validates formatter behavior
   - This was likely exposed by the interpolation fix above

### String and Unicode Handling (2 commits)

1. **Revert keeping of underscores between digits in camelize (#10995)**
   - Problem: A previous change in v1.12.0 preserved underscores between digits when calling `Macro.camelize/1` (e.g., `"foo_10"` became `"Foo_10"` instead of `"Foo10"`)
   - Solution: Reverted this behavior to maintain backward compatibility with v1.11 behavior
   - Impact: The `camelize` function now behaves as it did in v1.11, preventing breaking changes
   - Note: This is an important decision showing the team's commitment to backward compatibility for patch releases

2. **Split on \r\n and \n accordingly during unicode compilation (#10991)**
   - Problem: Unicode property files were not being parsed correctly when they contained Windows-style line endings (\r\n)
   - Solution: Updated the parser to handle both Unix (\n) and Windows (\r\n) line ending styles
   - Impact: Compilation on Windows systems is now handled more reliably, and generated code is consistent across platforms

### Build and Bootstrap Fixes (2 commits)

1. **Fix bootstrapping issue**
   - Problem: During bootstrapping (initial build of Elixir itself), undefined references to the Logger module would cause warnings
   - Solution: Added a compile directive `@compile {:no_warn_undefined, Logger}` to suppress warnings during bootstrap
   - Impact: Cleaner bootstrap process without spurious warnings in the build output

2. **Remove unnecessary copying of priv/include for Rebar 3 deps**
   - Problem: Mix was unnecessarily copying include files for Rebar 3 dependencies
   - Solution: Removed redundant file copying operations
   - Impact: Faster dependency compilation, cleaner build artifacts

### Configuration and Error Handling (2 commits)

1. **Improve error message on invalid config**
   - Problem: When users provided invalid configuration values, error messages were unclear
   - Solution: Enhanced error messaging to provide better context about what configuration is invalid
   - Impact: Users get clearer guidance when they misconfigure their applications

2. **Fix spec for which_children (#11005)**
   - Problem: The typespec for the `which_children` function was incorrect
   - Solution: Corrected the function specification
   - Impact: Better type checking and IDE support for code using this function

### Warnings and Compatibility (2 commits)

1. **Silence httpc warnings**
   - Problem: Spurious warnings from Erlang's `httpc` module were appearing during Mix operations
   - Solution: Added code to suppress these false-positive warnings
   - Impact: Cleaner output from `mix` commands, less noise in CI/CD logs

### Test Infrastructure (1 commit)

1. **Revert "Run all available tests if there are no pending --failed tests"**
   - Problem: The feature added in v1.12.0 to automatically run all tests when no `--failed` tests were pending broke expected behavior in umbrella projects
   - Solution: Reverted the commit to restore the original behavior
   - Impact: `mix test` behavior is now consistent with earlier versions, fixing workflow expectations
   - Note: This shows that even small workflow changes can have unintended consequences in complex projects like umbrellas

## Major Themes in the Patch

### 1. **Stability Over Features**
This release prioritizes getting the newly introduced v1.12.0 features working correctly. No new features are added in v1.12.1; instead, the focus is entirely on fixing issues in existing code.

### 2. **Backward Compatibility**
The revert of the `camelize` underscore behavior and the `mix test` behavior show a strong commitment to backward compatibility. The team chose to revert rather than deprecate, prioritizing user experience in a patch release.

### 3. **Cross-Platform Concerns**
The Unicode/line-ending fixes and the Windows-specific configuration improvements show attention to cross-platform compatibility, ensuring Elixir works reliably on different operating systems.

### 4. **Experimental Features Need Stability**
The two `Mix.install/2` fixes show that newly experimental features need rapid iteration. The team was responsive to issues with this feature, addressing them within days.

### 5. **Build System Polish**
Multiple commits address bootstrapping, warnings, and build efficiency, indicating that the team paid attention to the developer experience during the build process.

## Breaking Changes

**None.** v1.12.1 is a pure bug fix release with no breaking changes or API modifications.
