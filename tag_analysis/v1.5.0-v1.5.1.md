# Changes from v1.5.0 to v1.5.1

## Overview

**Release Date Range:** July 25, 2017 (v1.5.0) - August 1, 2017 (v1.5.1)
**Time Between Releases:** 7 days
**Total Commits:** 19 commits (excluding release commit)

## Summary

Elixir v1.5.1 is a patch release focused on fixing critical regressions and bugs introduced in v1.5.0. The release addresses several significant issues discovered in the new EEx engine implementation, the revised Supervisor child spec system, and various type checking and compilation problems. This was a rapid follow-up release with concentrated effort on stabilizing core features that changed in the minor version release.

The key areas of focus include:
- **EEx Engine Breaking Changes:** v1.5.0 introduced breaking changes to the EEx engine callback mechanism that had to be addressed
- **Supervisor Spec Compatibility:** Ensuring backward compatibility and proper error messaging for the new child spec system
- **Type System Improvements:** Fixing regressions in type inference for tuple variables and struct handling
- **Performance and Compatibility:** Addressing Task stream timeouts and Windows-specific issues

## Major Features/Improvements

### 1. EEx Engine Enhancements - handle_begin and handle_end Callbacks

**Commits:** `039ca64890`

A significant improvement to the EEx (Embedded Elixir) templating engine. v1.5.0 attempted to repurpose the `init` value to be used throughout the entire engine lifecycle, which proved to be a breaking change. v1.5.1 properly addresses this by introducing dedicated `handle_begin` and `handle_end` callbacks designed specifically for managing inner buffers.

**Benefits:**
- Custom EEx engines can now use any data structure as state (not just quoted expressions)
- Cleaner separation of concerns between initialization and buffer management
- Maintains backward compatibility with existing engines
- Closes issue #6391

### 2. Task Streams - Infinity Timeout Support

**Commits:** `f5e4635087`

Fixes a regression introduced in v1.5.0 where `Task.async_stream/3` and related functions did not properly support `:infinity` as a timeout value. This is critical for long-running tasks that should never timeout.

**Impact:** Restores expected behavior for task streaming operations with no timeout constraints

### 3. Profile Tasks - Project Independence

**Commits:** `6ce02e6a8c`

Enhanced profile tasks to run without requiring an active project context. This improves flexibility for command-line tool usage and project-agnostic operations.

### 4. Supervisor Spec Documentation and Error Messages

**Commits:** `42f8a069c5`, `9aeaa614110`

Two commits improving the developer experience around Supervisor child specs:
- Better error messages when invalid Supervisor.Spec patterns are used
- Clearer documentation that new child specs don't support certain legacy patterns
- Ensures developers understand the boundaries of the new specification system

## Bug Fixes

2. **Do not always write tuple vars as tuple types (closes #6411)**

## Breaking Changes

**None for end users.** However, this release addresses breaking changes that were introduced in v1.5.0:

- **EEx engine API:** v1.5.0's attempted repurposing of the `init` value was breaking. v1.5.1 fixes this by introducing proper `handle_begin` and `handle_end` callbacks while maintaining compatibility with properly-designed custom engines.

- **Supervisor specs:** v1.5.0 introduced new child spec format, but v1.5.1 ensures better backward compatibility messaging and mixed-spec support.

## Notable Commits Worth Highlighting

1. **`039ca64905` - Add handle_begin and handle_end to EEx**
   - The most significant functional addition. This properly addresses the EEx engine architecture issues discovered post-release.
   - Enables users to create custom EEx engines without being constrained by the engine's internal state requirements.

2. **`b27db522e0` - Make sure both old and new specs can play together at the supervisor level**
   - Critical for users upgrading from Elixir 1.4. Ensures projects with mixed supervisor spec styles continue to work.

3. **`288fb9ec73` - Fix compiler and dialyzer warnings on with**
   - Addresses static analysis false positives that would block some projects from using dialyzer with Elixir 1.5.

4. **`e060a458cb` - Do not always write tuple vars as tuple types**
   - Important for type system correctness. Fixes dialyzer's ability to properly infer tuple types.

5. **`f5e4635087` - Support :infinity timeout on Task streams**
   - Regression fix that restores critical functionality for streaming operations with unbounded execution time.
