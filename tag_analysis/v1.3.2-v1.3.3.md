# Changes from v1.3.2 to v1.3.3

## Release Information

- **Date Range**: July 15, 2016 (v1.3.2) to September 17, 2016 (v1.3.3)
- **Duration**: ~2 months
- **Total Commits**: 22 commits (21 feature/fix commits + 1 release commit)
- **Release Date**: September 17, 2016

## Summary

The v1.3.2 to v1.3.3 release represents a focused patch release addressing critical bugs, performance improvements, and enhancements across multiple subsystems. The release demonstrates Elixir's commitment to stability with a high proportion of bug fixes (9 out of 21 changes), alongside thoughtful performance optimizations and feature additions. Key areas of focus include compilation performance, cross-platform compatibility (Windows support), string handling, and build system improvements.

The release is primarily driven by José Valim and the Elixir core team, with contributions from the community, particularly around git integration and standard library enhancements. The timeframe between v1.3.2 and v1.3.3 shows a gradual accumulation of fixes addressing real-world usage patterns discovered by Phoenix framework developers and other ecosystem users.

## Major Features and Enhancements

### Git Sparse Checkout Support
- **Commits**: `091ce84e18`, `fc8314508f`
- Added support for git sparse checkout in Mix, enabling efficient handling of large repositories
- This feature allows developers to work with sparse repositories and migrate to/from sparse checkout modes seamlessly
- Particularly valuable for monorepo setups and reducing clone times for large projects

### DateTime Enhancements
- **Commit**: `13b432c48d`
- Added negative integer support in `DateTime.from_unix/2`
- Enables handling of Unix timestamps before the epoch (dates before January 1, 1970)
- Expands the temporal capabilities of Elixir's date/time handling

### Logger Color Metadata Support
- **Commit**: `bbce69b58e`
- Enhanced logger to support ANSI color information from metadata
- Allows more flexible and dynamic control over log output styling
- Improves integration with custom logging solutions

### ExUnit Server Timeout Configurability
- **Commit**: `3610d59214`
- Made ExUnit server timeout configurable
- Addresses issues in test environments with varying performance characteristics
- Allows tests to adapt to different execution contexts

### Struct Update Syntax Improvements
- **Commit**: `46cab56dfd`
- Marked struct update syntax as generated code for improved dialyzer integration
- Reduces spurious dialyzer warnings when using patterns like `%Foo{struct | bar: :baz}`
- Better interoperability with Erlang's OTP 19 (which enhanced dialyzer)

## Bug Fixes

### Cross-Platform Issues
- **Commit**: `87da507c24` - Use NUL instead of /dev/null on Windows
  - Fixed critical Windows compatibility issue where shell commands incorrectly referenced Unix-specific device files
  - Affects developers using Elixir on Windows for the first time in proper manner

### External Resources Handling
- **Commit**: `f73e6f8711` - Also store external resources that are not part of the cwd
  - Fixes issue where external resources (e.g., used by phoenix_live_reload) outside the current working directory were not properly tracked
  - Prevents stale cache issues when using relative external resources
  - Resolves: https://github.com/phoenixframework/phoenix_live_reload/issues/37

### IEx Autocompletion
- **Commit**: `56779fc25b` - Resolves issue with autocompletion on structs not working in IEx
  - Fixed critical IEx feature where struct field autocompletion was broken
  - Essential for developer experience improvements in interactive Elixir sessions

### String Processing
- **Commits**: `effb685854`, `7aebe55236`
  - `effb685854` - Do not re-compile a compiled pattern for String.split/3: Prevents unnecessary recompilation of regex patterns
  - `7aebe55236` - Fix String.split when parts and trim is used: Corrects behavior when both options are specified together
  - These ensure String.split/3 operates efficiently and correctly with various option combinations

### Logger Test Suite
- **Commit**: `7c5abe35e6` - Fix order dependency in logger suite
  - Removes test order dependencies that could cause intermittent test failures
  - Improves test reliability and CI stability

### Manifest and Compilation
- **Commits**: `8a226218e0`, `a51c1beb77`
  - `8a226218e0` - Always include the compiled file source in manifests: Ensures manifests contain complete source information needed for proper rebuilds
  - `a51c1beb77` - Do not consider remote typespecs as a compile-time dependency: Prevents unnecessary recompilation when remote type specifications change
  - Together, these improve compilation caching and speed

## Performance and Optimization

### Compilation Improvements
- **Commits**: `cb4310111b`, `8aab3ce628`
  - `cb4310111b` - Do not wait for self in parallel compiler: Eliminates unnecessary blocking in the parallel compilation pipeline
  - `8aab3ce628` - mix xref: loadpaths before compile: Ensures cross-reference analysis happens with proper load paths, improving accuracy and speed

### Dependency Handling
- **Commits**: `982aba3519`, `72eb5c73a5`
  - `982aba3519` - Always skip deps with MIX_NO_DEPS: Ensures dependencies are properly skipped in minimal build scenarios
  - `72eb5c73a5` - Do not unload deps for MIX_NO_DEPS=1: Maintains consistent dependency state in restricted build environments
  - These improvements enable cleaner, faster builds in CI and development environments using MIX_NO_DEPS flag

## Bug Fixes (Minor/Testing)
- **Commits**: `6243fb275543`, `59d6c803df`
  - `6243fb275543` - Fix failing backported test: Ensures backported tests pass properly
  - `59d6c803df` - Remove accidental file: Cleanup of repository

## Documentation Improvements
- **Commit**: `a9559ef045` - Document that the :consolidate_protocols option is true by default
  - Added clarification in documentation about protocol consolidation behavior
  - Improves understanding of Elixir's protocol compilation strategy

## Breaking Changes

**None identified** in this release. The v1.3.2 to v1.3.3 release is a pure patch release without any breaking changes to the public API or behavior. All changes are backward compatible.

## Theme Analysis

This release demonstrates several key themes in Elixir's development:

1. **Ecosystem Responsiveness**: Many fixes (Windows support, phoenix_live_reload) address issues found by ecosystem users, showing Elixir's commitment to supporting popular libraries

2. **Compilation Performance**: Multiple commits focus on improving compile times and reducing unnecessary recompilation, reflecting growing codebase sizes in production use

3. **Developer Experience**: Fixes to IEx autocompletion, string handling, and timeout configurability all directly improve day-to-day development experience

4. **Cross-Platform Support**: Explicit Windows support addition shows maturation of the platform beyond Unix-centric development

5. **Standards Compliance**: Enhanced datetime support, struct dialyzer integration, and better protocol documentation show attention to interoperability with Erlang ecosystem tools (OTP 19)

6. **Build System Maturity**: Multiple improvements to Mix's dependency handling and cross-reference checking demonstrate a maturing build system
