# Changes from v1.4.4 to v1.4.5

## Release Overview

**Date Range:** May 15, 2017 to June 22, 2017 (38 days)
**Total Commits:** 8 commits
**Release Date:** June 22, 2017

## Summary

v1.4.5 is a maintenance and bug-fix release focused on stability, compatibility, and code quality. The primary emphasis is on preparing Elixir for compatibility with OTP 20, which introduced changes to crash report structures. This release also includes targeted bug fixes for the Registry and DateTime modules, along with minor code quality improvements.

## Key Themes

1. **OTP 20 Compatibility** - The most significant change addresses structural changes in OTP 20's crash report format
2. **Targeted Bug Fixes** - Several precision fixes for edge cases in core modules (Registry, Calendar)
3. **Code Quality** - Minor improvements to code formatting and consistency
4. **Documentation** - CHANGELOG updates to reflect changes

## Major Features & Improvements

### OTP 20 Compatibility

The standout change in this release is comprehensive support for OTP 20's modified crash report structure. The Logger module's crash report translator was updated to handle:
- New fields: `:message_queue_len` and `:current_stacktrace` added in OTP 20
- Conditional handling: `:messages` and `:dictionary` fields that are no longer always present

**Impact:** This ensures Elixir continues to properly parse and display crash reports when running on OTP 20, maintaining debugging visibility and error tracking capabilities.

**Commit:** `0b30f6495b` - Handle changes to crash reports in OTP 20 (#6185)

## Bug Fixes

### 1. DateTime.from_iso8601/2 Offset Parsing

**Issue:** The function failed to properly parse ISO 8601 timestamps when the timezone offset was formatted without a colon (e.g., `+0100` instead of `+01:00`).

**Fix:** Added support for both colon and non-colon separated offset formats, improving compatibility with various ISO 8601 implementations.

**Impact:** Users working with diverse ISO 8601 sources will encounter fewer parsing failures.

**Commit:** `600ca02749` - Fix DateTime.from_iso8601/2 when offset has no colon

### 2. Registry EXIT Message Leakage

**Issue:** The Registry module was leaking EXIT messages during dispatch operations, which could cause unexpected message handling in monitored processes.

**Fix:** Added proper message containment during registry dispatch to prevent EXIT messages from escaping to the caller.

**Impact:** More reliable message isolation in Registry operations, preventing subtle bugs in applications using Registry monitoring.

**Commit:** `20621d41c6` - Do not leak EXIT messages on Registry dispatch
