# Changes from v1.0.3 to v1.0.4

## Release Overview

- **Release Date**: February 12, 2015 to April 7, 2015
- **Duration**: 54 days
- **Total Commits**: 33 commits

This release marks a significant step forward in Elixir's maturation, with a strong focus on OTP 18 compatibility, production deployment features, and quality improvements across the test framework and standard library.

## Summary of Key Themes

This release period was dominated by three major initiatives:

1. **OTP 18 Compatibility**: As Erlang/OTP 18 was in release candidate stages, Elixir invested heavily in compatibility to ensure smooth transition for users. This included fixing typespec changes and Erlang 18-specific compilation issues.

2. **Production Deployment Features**: New `build_embedded` and `start_permanent` options were introduced, enabling better control over application compilation and startup behavior in production environments. This was a critical addition for deploying Elixir applications in containerized and cloud environments.

3. **ExUnit Reliability**: Several race condition fixes and test framework improvements ensure tests run more reliably, particularly around async test handling and process cleanup.

## Major Features & Improvements

### 1. Production Deployment Support

**Commits**: `c4e8ad0d65`, `ce77fa54b9`, `db61109495`

The most significant feature additions in this release are two new deployment options:

- **`start_permanent`**: Controls whether the supervision tree should bring down the entire application if it crashes. This is essential for production environments where you want strict failure semantics.

- **`build_embedded`**: Allows applications to be compiled in a self-contained, embedded mode. This consolidates protocols and includes all dependencies in the application artifact, making deployments more predictable and enabling better isolation in containerized environments.

New applications generated with `mix new` now automatically include these options, indicating their importance for the modern Elixir deployment story.

### 2. OTP 18 Compatibility

**Commits**: `193e85882e`, `4d6670342b`, `a58c007e0c`

Comprehensive support for Erlang/OTP 18.0-rc1 ensures Elixir users can upgrade to the latest Erlang runtime without issues:

- Fixed compatibility with OTP 18's typespec changes
- Fixed Erlang 18.0-rc1 specific issues
- Added warning avoidance for missing behaviour declarations when compiling Erlang files
- Protocol consolidation improvements to prevent unnecessary compilations

### 3. ExUnit Framework Improvements

**Commits**: `e9887a760e`, `fe5ff41514`, `ce6f4e6d15`

Critical improvements to test reliability:

- **Race Condition Fix**: Fixed a subtle but important race condition where the next test would start before linked processes from the previous test were fully killed. This was causing spurious "already registered" errors.
- **Async Test Tagging**: Tests are now properly tagged as async tests, allowing the test runner to better manage concurrent test execution.
- **Documentation Cleanup**: Improved ExUnit.Assertions documentation for clarity.

### 4. Performance Enhancements

**Commits**: `09498422d0`, `9e2c5a29a4`

Two targeted performance improvements to URI handling:

- **`URI.decode_query/1`**: Optimized query string decoding for faster parsing of URL parameters
- **`decode_www_form`**: Faster form URL decoding for HTTP request processing

These optimizations benefit any web application handling significant query strings or form data.

### 5. Mix Tool Enhancements

**Commits**: `eee921bf7b`, `fab917dba3`

- **`mix help --search PATTERN`**: Added search functionality to Mix's help system, allowing developers to find relevant mix tasks by keyword without knowing the exact task name
- **Improved `IEx.pry/1` Error Messages**: Better error reporting when using IEx's interactive debugger

## Bug Fixes

### Compiler & Build System

- **`a58c007e0c`**: Avoid missing behaviour warnings when compiling Erlang files - prevents false warnings during mixed Elixir/Erlang projects
- **`321096665a`**: Do not propagate protocol consolidation to children - fixes an issue where protocol consolidation changes would unnecessarily force recompilation of child dependencies
- **`a5030694794`**: Ensure we consolidate only when there was a change - optimization to avoid redundant protocol consolidation work
- **`6a594e2bba`**: Ensure changes in child deps force parent recompilation - fixes a bug where updates to child dependencies might be missed during builds

### Runtime & Exceptions

- **`b93aae9f86`**: Ensure we quote proper file on exceptions - fixes exception handling to correctly attribute errors to source files
- **`53ecea8b03`**: Do not erase stacktrace on bad configs - prevents loss of important stack trace information when configuration errors occur
- **`10dd8f843b`**: Fallback to undocumented API only if necessary - improves Erlang compatibility by using public APIs when available

### HTTP & URIs

- **`efba8d8bfa`**: Fix httpc proxy option profile - corrects HTTP client proxy configuration handling
- **`a697bab7f2`**: Store relative paths in erlang manifest - fixes path handling in generated Erlang manifests for better portability

### ExUnit Test Framework

- **`e9887a760e`**: Wait until test process is down in ExUnit runner - critical race condition fix ensuring clean process teardown between tests
- **`17a0abd57a`**: Added test for markup ending with period - fixes documentation test edge case
- **`36e81d587e`**: Increase elixir_counter timeout - addresses timing issues in counter-based tests

### Error Messages & Debugging

- **`e6cfc20556`**: Produce clearer messages for syntax errors before a sigil - improved error reporting for common syntax mistakes
- **`906f03102b`**: Return value when matching with `_` on last line of block - fixes edge case where match expressions with `_` weren't properly returning values

### Miscellaneous

- **`fab917dba3`**: Do not print app name as a filename - fixes misleading error messages showing app names as if they were filenames
- **`5a201065dc`**: Update new major.minor instructions - improves documentation for version bump procedures

## Breaking Changes

**None identified**. This appears to be a purely additive release with no deprecated or removed functionality. The new `build_embedded` and `start_permanent` options are new additions to existing configuration, not breaking changes to existing APIs.

## Developmental Timeline

The release period shows interesting development patterns:

- **Feb 12 - Feb 16**: Initial v1.0.3 release period, foundational fixes
- **Feb 16 - Mar 17**: Steady progress with performance optimizations and bug fixes, spreading across multiple subsystems
- **Mar 24 - Apr 2**: Concentrated push toward v1.0.4 with major feature additions and OTP 18 fixes
- **Apr 2 - Apr 7**: Final polish, final CHANGELOG updates, and release

The concentrated effort from April 2-7 suggests that several related features (build_embedded, start_permanent) and major improvements were bundled together deliberately for a coordinated release.
