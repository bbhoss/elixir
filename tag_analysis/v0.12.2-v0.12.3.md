# Changes from v0.12.2 to v0.12.3

## Overview

**Release Date Range:** January 15, 2014 - February 2, 2014
**Commit Count:** 96 commits
**Release Date:** February 2, 2014, 19:52:10 UTC+1

This release represents a significant maintenance and quality improvement cycle for Elixir, with a focus on code cleanup, error handling improvements, and preparations for future language features like maps.

---

## Summary of Key Changes

The v0.12.2 to v0.12.3 release cycle was primarily focused on:

1. **Language Syntax Refinements** - Major changes to operator handling and string syntax
2. **Error Handling & Developer Experience** - Improved error messages and IEx exception formatting
3. **Infrastructure & Cleanup** - Removal of deprecated code paths and compilation improvements
4. **API Improvements** - New utility functions and better module documentation
5. **Bug Fixes** - Numerous fixes for edge cases and compatibility issues

The release reflects a maturing language with increased attention to usability and preparing the ground for maps (a major upcoming feature).

## Major Features & Improvements

### Language Syntax Changes

- **Operator Capture Enhancement** (50e479332c)
  - `Allow operators to be captured, example: &+/2`
  - Enables functional programming patterns like `Enum.map(list, &+/2)` for chaining operations

- **New Version Handling APIs**
  - `Add Version.valid_requirement?/1` (6f3c635f6f) - New public API for version requirement validation
  - `Add Version.compare/2` (bcb7cff5f2) - Direct version comparison function
  - Improves dependency management in Mix

- **String Operator Migration** (fe2e4a1010, b3cf44631c)
  - Major change: `Move from // to \` and removal of deprecated `//` syntax
  - The `//` operator is fully replaced with `\` for string handling
  - This indicates a cleanup of legacy operator syntax

- **Operator Precedence Refinement** (0d4655d1db)
  - `Generalize unary operators followed by int have higher precedence`
  - Better handling of expressions like `-1` in parsing

### Process & Concurrency Enhancements

- **New Process Functions** (bfc30274ff)
  - `Add Process.send/2 and Process.send_after/3`
  - New public API methods for improved process communication

### IEx Improvements

- **Exception Formatting & Colorization** (3f30bf156c, 84561408d1)
  - `Add exception formatting and colorization to iex`
  - `Respond to review comments` - Refinements to exception display
  - Merged Dave Thomas's extensive work on IEx exception handling

- **IEx Configuration Changes** (eb62c3bd27)
  - `IEx now loads the .iex.exs file instead of the .iex one`
  - Improved configuration file naming for compatibility

- **Stacktrace Display** (cf84ed3881)
  - `Only justify applications in IEx stacktraces`
  - Better formatted error output in interactive shell

### Data Structure Improvements

- **HashDict Optimization** (d311e10bea, 8ac132fee1)
  - `Change HashDict implementation to use tries with compound nodes`
  - `Fix HashDict.pop signature`
  - Performance improvements through new trie-based implementation

- **HashSet Modernization** (b1915b1ad6)
  - `Convert HashSet to use the new trie implementation`
  - Aligns with HashDict improvements

- **Range Refactoring** (b3e07652cc)
  - `Range is no longer a record`
  - Structural change moving away from record-based implementation

### Mix & Build System Enhancements

- **Build Environment Configuration** (294885be1a)
  - `Default build_per_environment to true`
  - Better isolation of build artifacts for different environments

- **Dependency Management** (b326fe12d9, 263f0d1c81)

  - Cleaner dependency management architecture

### Compiler & Optimization

- **Function Inlining** (8023c29c3f, fe8fc1be25)

- **Compiler State Management** (dc393ed14a, 674f4a2cb3)

## Breaking Changes & Deprecations

### Removed Features

- **Deprecated `//` Operator** (fe2e4a1010, b3cf44631c)
  - **Change:** `//` operator completely removed and replaced with `\`
  - **Impact:** Code using `//` for string operations will not compile
  - **Migration:** Update all `//` usage to use `\` instead

- **Deprecated Code Removal** (4ade0f98aa)
  - `Remove deprecated code`
  - Cleanup of legacy code paths

- **`m/0` Helper Removal** (cbae2aecfc)
  - `Remove m/0 helper`
  - The m/0 helper in IEx was removed with goal to provide a general IEx module for runtime statistics

- **@hidden Directive Removal** (6b511cc844)
  - `Remove @hidden in mix tasks`
  - Simplified Mix task documentation

- **Pre-copying of Dev Dependencies** (b659ecfa7e)
  - `Remove pre-copying of dev dependencies`
  - Build process simplification

- **Mix Task Fixtures** (49c3770d87)
  - `Remove uneeded mix fixtures`
  - Test infrastructure cleanup

### Deprecations (Still Supported, but Discouraged)

- **Record Functions Deprecation** (04c8ca9718, 82cdc51ca8)
  - `Deprecate keywords, getter and list getter functionalities of defrecordp`
  - `Deprecate Record.import/2`
  - **Reason:** Preparation for introducing maps as the primary key-value data structure
  - **Recommendation:** Start migrating to new patterns (maps in future versions)

- **`@behavior` Attribute** (5f682023a6)
  - `Deprecate usage of @behavior in favor of @behaviour`
  - **Change:** Correct spelling emphasized
  - **Migration:** Use `@behaviour` (British spelling)

- **Binary/Term Conversion Functions** (ce61c60af5)
  - `Deprecates binary_to_term and term_to_binary in Kernel`
  - These low-level term serialization functions are deprecated
  - **Reason:** Moving toward better serialization APIs

- **Regex Pattern Operator** (e42e3e55ca, 66e0c53593)
  - `Deprecate =~` was deprecated but then **reverted** in same release
  - `Revert "Deprecate =~"`
  - The `=~` operator remains valid for regex matching

### Syntax Changes

- **Generator Operator Precedence** (f671e1204c)
  - `Change precedence of <- to be the same as other generators`
  - Clarifies behavior of list comprehensions and other generator contexts

- **Sigil Restrictions** (ae24cad4b8)
  - `Limit the allowed sigils`
  - Only specific sigils are now permitted

### Guard Clause Changes

- **Guard Type Checks** (a8eab99e44)
  - `Make explicit is_range / is_regex are allowed in guards`
  - Clarifies what type checks can be used in guard clauses

- **Guard Nullary Functions** (67a672e6ed)
  - `Guarantee nullary funs/macros are allowed in guards, closes #1997`
  - Allows parameterless functions/macros in guards

**Description:** Transition from traditional hash implementation to trie-based data structures

**Commits:** fe2e4a1010, b3cf44631c
**Description:** Complete migration from `//` to `\` for string operators
This was a significant breaking change that consolidated operator syntax, requiring all user code to be updated. The complete removal (not just deprecation) indicates this was a critical cleanup before stabilization.

### Version Management API Expansion

**Commits:** 6f3c635f6f, bcb7cff5f2
**Description:** New Version module functions for dependency management
The addition of `Version.valid_requirement?/1` and `Version.compare/2` shows Elixir's maturing dependency and version management capabilities, critical for Mix and library ecosystem growth.

### Preparation for Maps

**Commits:** 82cdc51ca8, 04c8ca9718
**Description:** Deprecation of Record-based key-value storage
Multiple deprecations of record-related features signal the planned introduction of maps as a first-class data structure. This is foundational work for a major language feature arriving in subsequent versions.

## Migration Guide for Users

### Critical (Breaking Changes - Must Update)

1. **String Operator** (`//` → `\`)
   ```elixir
   # Old (no longer works)
   "hello" // "world"

   # New
   "hello" \\ "world"
   ```

2. **@behavior → @behaviour**
   ```elixir
   # Old
   @behavior SomeBehaviour

   # New
   @behaviour SomeBehaviour
   ```

### Recommended (Deprecations - Plan to Update)

1. **Record.import/2** - Avoid using; prepare for maps
2. **binary_to_term/term_to_binary** - Use alternative serialization
3. **defrecordp keywords/getter functions** - Plan migration away from records

### Enhanced Features (Optional - Can Benefit From)

1. Use new `Version.valid_requirement?/1` and `Version.compare/2` in Mix-based tools
2. Leverage new `Process.send/2` and `Process.send_after/3` for better process communication
3. Use operator capture `&+/2` for more idiomatic functional code

## Conclusion

The v0.12.2 → v0.12.3 release represents a significant quality and polish cycle for Elixir. While not introducing groundbreaking new features, it demonstrates the language's evolution toward stability and maturity through:

- **Better error handling and developer experience** (IEx improvements, better error messages)
- **Performance optimization** (inlining, trie data structures)
- **Strategic cleanup** (removal of deprecated syntax and code paths)
- **Foundation laying** (Record deprecation preparing for maps)
- **API enrichment** (new Process and Version functions)

The consolidation of operator syntax (// → \) and removal of record functionality shows a commitment to consistency and preparing for upcoming features. For library developers and users, this was a release requiring attention to breaking changes but offering cleaner, more efficient code in return.
