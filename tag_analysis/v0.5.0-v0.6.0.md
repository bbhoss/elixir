# Changes from v0.5.0 to v0.6.0

## Overview

This release spans **137 days** (May 24, 2012 to October 8, 2012) with **454 commits**. v0.6.0 represents a significant maturation of Elixir's tooling, REPL experience, and type system capabilities. This release is particularly notable for establishing Mix as the official build tool and significantly improving the interactive development experience.

**Date Range:** May 24, 2012 - October 8, 2012
**Total Commits:** 454
**Bug Fixes:** 40+ commits
**Breaking Changes:** 6 major deprecations, 6 removals

## Summary

The v0.5.0 to v0.6.0 transition represents Elixir moving from an experimental language to one with serious tooling and developer experience considerations. The primary focus areas were:

1. **Build System Maturation**: Mix evolved from a basic build tool into a comprehensive package management system with dependency locking via `mix.lock`, local package management, and improved Rebar integration.

2. **Interactive Development Enhancements**: The IEx REPL received substantial improvements including autocompletion for Elixir and Erlang modules, remote shell support (`--remsh`), and better helper utilities.

3. **Type System Expansion**: Typespecs gained macro support, enabling more sophisticated type annotations. Guards became more powerful with support for the `!` operator.

4. **API Cleanup**: Several early APIs were deprecated or removed in favor of cleaner, more consistent alternatives—notably the defdelegate redesign and the removal of the special `<& &>` tags for special forms.

5. **Language Feature Refinement**: Comprehension syntax was adjusted for better Erlang compatibility, and various macro expansion and scope-handling improvements were made.

## Major Features & Improvements

### Mix Build System - Complete Redesign
- **mix.lock file**: Initial implementation of dependency locking to ensure reproducible builds. This was a critical feature for projects relying on external dependencies.
- **Mix as Elixir**: Converted Mix itself from shell scripts to pure Elixir (`Make mix an Elixir script`), eliminating platform-specific issues and improving maintainability.
- **Local Package Management**:
  - `mix local.install`: Install local archives and escript packages
  - `mix local.uninstall`: Remove installed packages
  - `mix local.listing`: View installed packages
- **Project Generation**: `mix new` command for scaffolding new Elixir projects with proper directory structure and build configuration.
- **Dependency Improvements**:
  - Support for raw dependencies (non-Hex packages)
  - Custom SCM (Source Code Management) support for Mercurial, Git, and other VCS
  - `Allow custom SCM to be added, closes #411`
  - `Pass deps_dir by default to rebar, closes #414`
  - `Support raw dependencies, closes #410`
  - `deps.unlock` command for removing lock file entries
  - `Ensure deps.get also updates locks`
- **Rebar Integration**:
  - Improved Rebar path handling
  - Better option passing to Rebar
  - `Use local rebar, closes #515`
- **Mix Utilities**:
  - `Mix.loadpaths` shortcut for easier path management
  - Mix.Deps refactoring for cleaner dependency logic
  - Mix.Dep record for better data structure

### IEx Interactive Shell - Substantial Enhancements
- **Autocompletion System**: Complete rewrite of autocompletion to support both Elixir and Erlang modules:
  - Module name autocompletion (e.g., `Enum.`)
  - Function autocompletion within modules
  - Macro support in autocompletion
  - Proper handling of Erlang alias syntax
  - Fixes for nested module display
- **Remote Shell Support (Remsh)**:
  - `--remsh` option to connect to running Erlang/Elixir nodes
  - Full autocompletion support for remote nodes
  - Better documentation of use cases
  - `Tidy up remsh support in iex via --remsh option, closes #368`
- **IEx Helpers Refactoring**:
  - Better `h()` function for viewing documentation
  - `d()` function for printing docs in console
  - New `reload` helper for reloading modules during development
  - Improved `m()` function with better size formatting
- **Node Name in Prompt**: Display connected node name in the IEx prompt for better context awareness
- **Architecture**: Break IEx into multiple files and move to root namespace for better organization

### Type System & Macro Improvements
- **Macro Support in Typespecs**: `Typespecs now support macros, closes #385` - enabling more sophisticated type annotations
- **Guard Clause Enhancements**:

- **Macro Expansion**:

- **Typespec Improvements**:

  - Function type syntax changes

### Language Feature Refinements

  - Deprecated old `defdelegate` syntax
  - New syntax integrating with modern Elixir patterns
- **Module and Scope Improvements**:

  - `Use cannot be called outside modules` limitation removed
  - Better handling of module redefinitions with warnings instead of exceptions

- **Macro System**:

### Build & Compilation Improvements

- **Build Consistency**: Ensure repeatability in repository builds

## Breaking Changes

The v0.5.0 to v0.6.0 transition includes several breaking changes and deprecations:

### Deprecated (6 major items)
1. **defdelegate** - Old syntax is deprecated in favor of new syntax that better integrates with modern Elixir
   - `Deprecate defdelegate`
   - Later: `Bring defdelegate back with new syntax, closes #412`
   - Provides migration path with new implementation

2. **loop** - `Deprecate loop, used named functions to recur instead`
   - Encourages better recursive patterns using named functions

3. **add_compile_callback** - `Deprecate add_compile_callback in favor of the attributes API`
   - Shift to module attributes for compile-time configuration

4. **refer** - `Deprecate refer in favor of alias, use atom aliases throughout source code`
   - Consolidation to `alias` for module aliasing

5. **in_guard special form** - `Deprecate in_guard special form in favor of the more flexbible __CALLER__.in_guard?`
   - Shift to more powerful macro inspection via `__CALLER__`

6. **Module.function_defined?** - `Deprecate Module.function_defined? in favor of Module.defines?`
   - API consistency improvement

### Removed (6 items)
1. **Special `<& &>` tags** - `Remove the need for special <& &> tags, closes #393`
   - Special forms no longer require special delimiters

2. **Range.new/2 API** - `Remove Range.new/2 api for now`
   - Simplified range construction

3. **use outside modules** - `Remove limitation use cannot be called outside modules`
   - Greater flexibility in macro usage

4. **Extended access protocol semantics** - `Remove extended semantics from the access protocol`
   - Simplified protocol definition

5. **__MAIN__ references** - `Remove remaining __MAIN__ from erlang code`
   - Rename to Kernel module hierarchy (`Rename __MAIN__ to Elixir, closes #390`, `Rename Elixir.Builtin to Kernel`)

6. **Incorrect binary conversion** - `Remove incorrect conversion to binary`
   - Type safety improvements

## Impact & Significance

This release marks a critical inflection point for Elixir:

1. **From Experimental to Production-Ready**: The addition of `mix.lock` and comprehensive Mix tooling signals readiness for dependency management at scale.

2. **Developer Experience Priority**: Significant IEx improvements (autocompletion, remsh) show focus on daily developer workflows.

3. **Type System Maturation**: Macro support in typespecs and guard enhancements make the type system more expressive for complex validations.

4. **Self-Hosting Milestone**: Making Mix a pure Elixir application is symbolically important—the language can now bootstrap itself for its primary development tool.

5. **API Stabilization**: The deprecations and removals demonstrate thoughtful API design, removing early mistakes while providing clear migration paths.

## Conclusion

v0.6.0 represents Elixir's transition from a proof-of-concept to a viable development platform. The focus on Mix, IEx improvements, and type system enhancements provides the foundation for real-world projects. The breaking changes are minimal and well-justified, showing the language designers' commitment to thoughtful evolution. This release likely made Elixir significantly more attractive to developers considering it for production use.
