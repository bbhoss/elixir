# Changes from v1.8.2 to v1.9.0

## Overview

- **Release Period**: May 11, 2019 - June 24, 2019
- **Duration**: ~6 weeks
- **Total Commits**: 533
- **Release Date**: June 24, 2019

This release represents a significant evolution of Elixir with major emphasis on release management, configuration improvements, and various standard library enhancements.

---

## Summary of Key Themes

The v1.8.2 to v1.9.0 transition was characterized by four major themes:

1. **Maturation of Mix Releases Feature** - Significant refinement and stabilization of the new Mix.Release API introduced in v1.8, with numerous bug fixes, documentation improvements, and Windows compatibility enhancements.

2. **Configuration System Overhaul** - Introduction of Config Providers for runtime configuration, enforcement of atom keys in config, and improved configuration loading mechanisms.

3. **Standard Library Polish** - Addition of new sigils (~U for UTC DateTime), new functions (Registry.select/2, System.fetch_env/1), and improvements to existing modules with better error messages and type specifications.

4. **Performance and Code Quality** - Optimization of protocol dispatching, formatter improvements, and various refactorings to reduce compilation time and improve IDE integration.

---

## Major Features & Improvements

### Mix Releases (Primary Focus)

The Mix.Release system received the most attention during this cycle, with over 30 commits dedicated to improving this feature:

- **Config Provider System** (#8957): Added a new `Config.Provider` mechanism allowing runtime configuration. This enables applications to read configuration from external sources (environment variables, files, remote services) at startup time rather than compile time.

- **Release Templating** (#8967): Added templating support to release scripts, allowing for dynamic script generation based on configuration and system properties.

- **Release Steps** (#8966): Introduced a `:steps` option for releases, providing hooks for custom actions during the release lifecycle.

- **Windows Compatibility**: Multiple fixes for Windows releases:
  - Support for paths with white spaces in release scripts (#9065)
  - Fixed boot script naming issues (#9135)
  - Proper backslash handling in paths (#9035)

- **Release Variables**: Added `RELEASE_BOOT_SCRIPT` and `RELEASE_BOOT_SCRIPT_CLEAN` environment variables for better script customization (#9132).

- **VM Configuration**: Developers can now choose between short names (`sname`) and long names (`name`) for released applications (#9024).

- **Environment Management**: Improved how the runtime environment is managed and exposed through `release/RELEASE_VSN/env` files.

- **Timestamp Removal** (#9127): Removed timestamps from release artifacts for reproducible builds.

- **Multiple App Versions** (#9102): Better handling of multiple versions of the same app during release creation.

### Configuration System

- **Config Provider Architecture** (#8957): Flexible, pluggable architecture for loading configuration from external sources at application startup time. Includes documentation and examples for creating custom providers.

- **Enforce Atom Keys**: Configuration now strictly enforces atom keys, eliminating potential sources of confusion and errors (#8036).

- **Runtime vs Compile-time Config**: Improved separation between runtime configuration (loaded by Config.Provider) and compile-time configuration.

- **Mix.Config Transition**: Internal use of `Mix.Config` module during configuration import to reduce confusion.

### Standard Library

#### New Sigil: ~U for UTC DateTime
- **~U Sigil** (#8824): Introduced `~U` sigil for creating UTC DateTime literals with improved performance and clarity
- Example: `~U[2019-06-24 12:30:45Z]`

#### New and Enhanced Functions
- **Registry.select/2** (#8963): Added select/2 function to Registry for more efficient querying of registered processes without retrieving all entries.

- **System.fetch_env/1 and System.fetch_env!/1** (#8846): Added new functions for fetching environment variables that return `{:ok, value}` tuples instead of raising errors, providing better error handling semantics.

- **String.replace/4 with Unary Functions** (#9073): Extended String.replace to accept unary replacement functions, enabling more flexible string transformations.

- **Access.at/1 with Negative Index** (#8843): Access.at/1 now supports negative indices for accessing elements from the end of the collection.

#### Improved Functions
- **List Functions**: Improvements to `List.duplicate/2`, `List.flatten/1,2`, and `List.delete/2` for better performance and clearer semantics (#9044, #9045, #9043).

- **Enum Type Specifications**: Improved typespecs for Enum.*reduce functions for better type inference (#8951).

- **DateTime.from_unix**: Added support for integer time units and improved precision handling for units not divisible by 10 (#8801, #8823).

- **Kernel.in/2**: Simplified and improved the in/2 operator with bug fixes for edge cases like empty lists (#8911, #8946).

### Code Generation & Compilation

- **Relative File Storage** (#9099): Module definitions now store relative file paths instead of absolute paths, improving portability of compiled code.

- **Macro Safety**: Raise errors for recursive macros and disallow invocation of macros before their definition (#9111, #8822).

- **Lexical Tracking Improvements** (#8893 and related): Enhanced lexical scope tracking for better compiler integration with IDEs and analysis tools.
  - Improved file tracking instead of just module tracking
  - Better process management during compilation
  - Proper lexical context propagation through compiler callbacks

- **Super Optimization** (#8962): Optimized code generation for `&super/arity` and `&super(&1)` patterns (#8962).

- **Parallel Compilation**: Fixed race conditions and improved error handling in ParallelCompiler to prevent main process blocking (#8661).

### Formatter

- **Force Do-End Blocks**: Added `:force_do_end_blocks` option to formatter for projects preferring do-end syntax over inline one-liners (#8978).

- **Sigil Handling**: Fixed formatter crashes on false positive sigil detection (#9123).

- **Multiline Trimming**: Consistent trimming behavior on multiple lines (#8792).

### Dialyzer & Type System

- **Type Visibility**: Made `Version.Requirement` module public for better IDE and type checking support (#8920).

- **Protocol Debug Info**: Ensured debug_info is kept in protocol modules for better introspection (#8923).

- **Struct Validation**: Improved validation of struct definitions to ensure the struct name matches the given module (#8864).

- **Type Variable Handling**: Proper handling of underscore variables in typespecs with warnings if used multiple times (#8891).

### Logger & Monitoring

- **Persistent Term Config** (#8977): Logger configuration now uses `:persistent_term` for better performance and to reduce memory overhead.

- **Cross-Node Messages**: Fixed Logger to not discard messages from other nodes in distributed systems.

- **Process Crash Translation** (#9020): Improved translation of process crashes on remote nodes in Logger output.

## Bug Fixes

### Critical Fixes
- **ETS Leak in Registry.register**: Fixed memory leak in Registry.register that could cause unbounded memory growth (#8721, 649339aa95).

- **Kernel.in/2 with Empty List**: Fixed regression where `in` operator failed with empty list as right argument (#8946).

- **Config Loading Race**: Fixed race condition in loading project configuration during release initialization.

### Compiler & Parsing
- **Metadata Handling** (#9152): Fixed incorrect passing of Meta to Erlang AST structures.

- **End Metadata Renaming** (#c30b6d675b): Renamed `:end` metadata key to `:closing` to reduce ambiguity with actual code terminators.

- **Null Byte Handling**: Improved error messages for null bytes in source code.

- **Heredoc Error Messages** (#9048): Better error reporting for heredoc syntax errors.

- **Undefined Locals** (#9005): Improved consideration of `@file` attribute when reporting undefined locals.

- **Deadlock Detection**: Improved handling of deadlocks during ensure_compiled, avoiding false positives (#8661, #8661).

### Windows-Specific
- **Null Redirection**: Fixed null redirection issue on Windows (#9130).

- **Release Script Naming**: Fixed bad naming of release scripts on Windows (#9135).

- **Path Handling**: Support for paths with white spaces in Windows release scripts (#9065).

### Documentation & Error Messages
- **Umbrella App Name Validation** (#9072): Added validation that umbrella app directory name matches the app name in mix.exs.

- **Module Definition Error**: Improved error message when wrong test invocation is attempted.

- **Invalid Clauses Error**: Added article 'a' to {invalid_clauses, Name} error for grammatical correctness (#9090).

- **Dependency Name Typos** (#8904): Better error messages when dependency names are misspelled.

- **Module Attribute Retrieval** (#8908): Raise error when attempting to retrieve capitalized module attributes (which are always atoms).

## Breaking Changes

### Function Removals
- **Integer.to_string/1 and Integer.to_charlist/1** (#8777): Removed these deprecated functions. Users should use `Integer.to_string/1` or convert directly with `to_string/1`.

- Note: This removal was actually reverted in #9042, restoring backwards compatibility.

### Deprecations
- **Enumerable Keys in Map Operations** (#8999): Deprecated use of Enumerable protocol keys in `Map.take/2`, `Map.drop/2`, and `Map.split/2`. These operations now expect explicit lists of keys.

### Behavior Changes
- **Module Attribute Default Values** (#9041): Support for default values when reading non-existent module attributes with `@attribute || default_value` pattern.

- **defmodule/2 in Format Locals**: Added `defmodule/2` to default `locals_without_parens` list in formatter.

- **Config Key Type**: Enforced atom keys for configuration to eliminate a source of potential bugs and confusion.

- **Doc Attribute Validation** (#8814): Now raises error if `:doc` attribute is set to `true` instead of a string or `false`.

- **Macro Definition Order** (#8822): Macros must now be defined before they are invoked, preventing subtle scoping bugs.

## Impact Assessment

### For Library Developers
- Config Providers enable better separation of concerns and more flexible configuration strategies
- Registry.select/2 improves performance for applications with many registered processes
- Improved error messages and validation help catch bugs earlier

### For Release Managers
- Config Providers system is transformative for managing configuration across environments
- Release templating and steps provide significant customization capabilities
- Windows improvements make Elixir releases more viable on Windows platforms

### For Language Users
- ~U sigil provides convenient UTC datetime syntax
- System.fetch_env/1 improves environment variable handling
- Better compiler error messages and validation catch more issues at compile time
- Improved protocol performance benefits all protocol-heavy code

### Performance Impact
- Logger configuration via persistent_term reduces memory overhead
- Protocol dispatch optimization benefits all code using protocols
- Unicode grapheme optimization improves string processing
- Lexical tracker improvements reduce compilation time in IDE scenarios

---

## Conclusion

Elixir v1.9.0 represents a significant maturation of the language, particularly in the areas of release management and configuration. The introduction of Config Providers marks a major shift in how Elixir applications handle configuration, moving from purely compile-time configuration to a more flexible runtime model. The numerous standard library improvements, combined with better error messages and validation, make the language more accessible and the development experience smoother. The emphasis on Windows compatibility and reproducible builds demonstrates the project's commitment to serving diverse deployment scenarios.
