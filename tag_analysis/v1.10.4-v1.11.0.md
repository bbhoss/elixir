# Changes from v1.10.4 to v1.11.0

## Release Overview

**Release Date Range:** January 7, 2020 - October 6, 2020 (9 months of development)
**Total Commits:** 627 commits
**Release Status:** Major version release with significant compiler and language improvements

---

## Executive Summary

Elixir v1.11 represents a major milestone focused on **compiler enhancements** and **Erlang integration**. The release demonstrates the Elixir team's commitment to catching more errors at compile time and improving compilation performance. This version introduces sophisticated type checking capabilities, deeper Erlang/OTP integration, runtime configuration improvements, and enhanced calendar functionality. The release brings 627 commits with a balanced mix of features (new guards, APIs, and tooling), significant bug fixes (95+ fixes identified), and strategic soft-deprecations to guide users toward modern practices.

---

## Key Themes and Analysis

### 1. **Compiler Intelligence and Type Checking** (Most Significant Theme)
The most prominent theme across the 627 commits is the introduction of an advanced **type hint system** and compile-time verification. This represents a fundamental shift in how Elixir validates code correctness.

- **Type Tracking**: The compiler now tracks structs, map fields, and binary constructors across function bodies, providing early warnings for undefined fields and type mismatches
- **Application Boundaries**: New warnings for invoking functions from undeclared dependencies or unintended umbrella siblings
- **Data Constructors**: Enhanced checking of map/struct field access patterns and binary segment type compatibility
- **Error Messages**: Significantly improved error messages with file:line information, better hints, and clearer guidance

This theme represents roughly 15-20% of commits and reflects a fundamental improvement to the developer experience.

### 2. **Compilation Performance Optimization**
A significant focus area with multiple dependency tracking improvements:

- **Dependency Graph Refinement**: Replaced "struct dependencies" with more granular "exports dependencies", reducing transitive compile-time dependencies
- **Path Dependencies**: More intelligent tagging of modules from path dependencies (particularly impactful for umbrella projects)
- **Profiling Enhancements**: Added granular file-by-file compilation timing with `--profile=time`
- **Parallel Compiler Improvements**: Better handling of file dependencies to minimize unnecessary recompilation

Real-world impact: In the Hex.pm project, changing a single user.ex file went from recompiling 90 files to recompiling only 16 files.

### 3. **Tighter Erlang/OTP Integration**
Following up on v1.10's logger integration, v1.11 deepens the relationship:

- **New Log Levels**: Added `notice`, `critical`, `alert`, and `emergency` to match Syslog standard
- **Structured Logging**: Support for maps and keyword lists in log messages
- **Per-Module Log Levels**: `Logger.put_module_level/2` for granular control
- **Erlang Documentation**: IEx now displays documentation from Erlang modules (requires Erlang/OTP 23+)
- **Logger Metadata**: Better integration of Erlang-style metadata in Logger

### 4. **Language Feature Additions**
Several new language capabilities to improve expressiveness and type safety:

- **New Guards**: `is_struct/2`, `is_exception/1`, `is_exception/2`, and `map.field` syntax in guards
- **Guard Improvements**: Better error handling for invalid guard expressions (e.g., list operators)
- **Custom Operators**: Added `+++` and `---` with right associativity
- **Language Safety**: Warnings for unused variables that look like compiler variables (e.g., `__MODULE__`)

### 5. **Configuration and Runtime Management**
Major improvements to how applications handle configuration at different stages:

- **`config/runtime.exs`**: New unified configuration file loaded at runtime (not compile time), applicable to all environments
- **`config_env()` and `config_target()`**: New functions for environment-aware configuration without Mix
- **`mix app.config`**: New task for loading applications and configuration without starting them
- **Deep Merge**: `config/runtime.exs` now supports deep merging of configuration

This addresses a long-standing pain point for non-release deployments.

### 6. **Calendar and DateTime Enhancements**
Substantial additions to calendar functionality:

- **`Calendar.strftime/3`**: datetime formatting with `strftime` format strings
- **Gregorian Conversions**: Linear integer representations with functions like `Date.from_gregorian_days/2`, `Date.to_gregorian_days/1`, `NaiveDateTime.from_gregorian_seconds/3`, `Time.from_seconds_after_midnight/1`
- **Month/Week Functions**: `Date.beginning_of_month/1`, `Date.end_of_month/1`, `Date.beginning_of_week/2`, `Date.end_of_week/2`
- **Custom Week Starting**: Support for custom starting day of week in `Date.day_of_week/2`
- **Constructors**: New `new!` functions for Date/Time/NaiveDateTime/DateTime

### 7. **Testing and Development Tools**
Enhanced testing and development experience:

- **`mix test.coverage`**: Aggregated coverage reports for umbrella projects and partitioned test suites
- **ExUnit Improvements**: Temp directory support via `@tag :tmp_dir`, colored output on Windows 10, `--trace` enhancements with file:line info
- **`register_test/6`**: Faster compilation of custom test definitions
- **Doctest Tags**: Ability to add tags to doctests

### Compiler and Build System
- **Type Hint System** - Introduction of sophisticated compile-time type checking for function bodies
- **Application Boundary Checking** - Warnings for undeclared dependencies and cyclic relationships in umbrellas

- **`mix xref` Enhancements** - Transitive dependency labels with `--sink` and `--source` flags, cycle detection via `--format cycles`

### Language and Guards
- **`is_struct/2` Guard** - Check for specific struct types
- **`is_exception/1` and `is_exception/2` Guards** - Type-safe exception checking
- **`map.field` Syntax in Guards** - Access map fields in guard clauses

- **Custom Operators** - `+++` and `---` with right associativity for user-defined operators

### Calendar and Date/Time
- **`Calendar.strftime/3`** - Standard C format string support for date/time formatting
- **Linear Integer Representations** - Gregorian days and seconds conversions for all calendar types
- **Extended Date Functions** - Month and week boundary functions with customization options
- **Constructor Functions** - New `new!` family of constructors across all calendar types

### Configuration and Runtime
- **`config/runtime.exs`** - Unified runtime configuration file (replaces `config/releases.exs` conceptually)
- **`config_env()` and `config_target()`** - Environment-aware configuration functions that work without Mix
- **`mix app.config`** - Load and configure applications without starting them
- **Deep Configuration Merge** - `config/runtime.exs` supports deep merging of nested configurations

- **New Log Levels** - `notice`, `critical`, `alert`, `emergency` (Syslog-compliant)

## Breaking Changes

### Hard Deprecations (No Longer Supported)
1. **Supervisor API Changes**
   - `Supervisor.start_child/2` - Migrate to `DynamicSupervisor`
   - `Supervisor.terminate_child/2` - Migrate to `DynamicSupervisor`
   - **Impact**: Code using these functions will need to refactor supervisor usage

### Soft Deprecations (Warnings Emitted or Deprecated Alternatives Available)

1. **Logger Log Level Changes**
   - `warn` log level deprecated in favor of `warning`
   - **Impact**: Code using `:warn` should migrate to `:warning` for future compatibility
   - **Action**: No breaking change yet, but migration recommended

2. **Configuration File Evolution**
   - `config/releases.exs` deprecated in favor of `config/runtime.exs`
   - **Impact**: Releases preferring `config/runtime.exs` when both exist
   - **Migration Path**: Move configuration to `config/runtime.exs` (more universal)
   - **Compatibility**: Old `config/releases.exs` continues to work for now

3. **Exception and Type Checking**
   - `Exception.exception?/1` soft-deprecated in favor of `Kernel.is_exception/1`
   - `Regex.regex?/1` soft-deprecated in favor of `Kernel.is_struct/2`
   - **Impact**: No immediate breaking change, but new guards are preferred
   - **Action**: Gradually migrate to new guards for better type safety

### Behavior Changes (Subtle Breaking Changes)

1. **URI Parameter Parsing**
   - `URI.decode_query/2` now emits empty strings for valueless parameters (WHATWG compliance)
   - **Impact**: Parsing URLs like `?foo=&bar=value` will have different behavior
   - **Rationale**: Aligns with modern web standards

2. **Map Operations**
   - Keyword and Map replace functions now more consistent
   - **Impact**: Behavior normalization, likely to affect little code

3. **Logger Metadata**
   - Logger now includes `erl_level` in metadata from Erlang sources
   - **Impact**: Logger handlers may see new metadata keys
   - **Rationale**: Better Erlang integration

4. **List Literal Guard Restrictions**
   - Attempting to use list operators in guards now raises `CompileError` instead of silently failing
   - **Impact**: Invalid guard code now caught at compile time (improvement)
   - **Rationale**: Better error catching

## Migration Guide for Users

### From v1.10.4 to v1.11.0

**For Most Users:**
- Update dependencies - most code will work without changes
- Review compiler warnings - v1.11 catches more errors at compile time
- Migrate from `config/releases.exs` to `config/runtime.exs` if using releases
- Consider using new guards (`is_exception/1`, `is_struct/2`) instead of older type checks

**For Release Users:**
- Migrate configuration to `config/runtime.exs` (more universal than `config/releases.exs`)
- Use `config_env()` and `config_target()` instead of `Mix.env()` in runtime configuration
- Consider using `mix app.config` task in custom Mix tasks instead of only `mix app.start`

**For Supervisor Users:**
- Plan migration away from `Supervisor.start_child/2` and `Supervisor.terminate_child/2`
- Move to `DynamicSupervisor` for dynamic process management

**For Testing Developers:**
- Adopt `@tag :tmp_dir` for temporary file handling
- Use `register_test/6` if implementing custom test types
- Update test discovery to leverage new coverage report aggregation

**For Umbrella Project Users:**
- Review compiler warnings about undeclared dependencies
- Fix any cyclic dependencies between sibling apps
- Benefit from improved recompilation behavior (fewer files recompiled)

## Conclusion

Elixir v1.11.0 represents a mature phase of language evolution, focusing on **correctness**, **performance**, and **developer experience** rather than radical new features. The introduction of the type hint system marks a significant shift toward compile-time verification, similar in spirit to gradual typing systems. Combined with tighter Erlang integration, enhanced configuration management, and calendar improvements, v1.11 provides a more robust and productive development environment for Elixir developers.

The 627 commits across 9 months demonstrate sustained focus on quality and the elimination of paper cuts that developers encounter in daily development. The soft deprecations provide a gentle migration path, while the compiler improvements deliver tangible benefits without requiring developer action—making this a high-value upgrade for the ecosystem.

**Key Takeaway:** v1.11.0 is a polish and optimization release that makes Elixir development safer, faster, and more predictable. It's a recommended upgrade for most users with minimal breaking changes.
