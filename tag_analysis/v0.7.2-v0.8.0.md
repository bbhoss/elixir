# Changes from v0.7.2 to v0.8.0

## Release Timeline
- **Start Date**: December 4, 2012 (v0.7.2)
- **End Date**: January 28, 2013 (v0.8.0)
- **Duration**: ~2 months
- **Total Commits**: 219
- **Version Consolidation**: Moved to unified VERSION file

## Summary of Major Changes

This release represents a significant milestone in Elixir's development with a focus on **language stability, operator refinement, standard library expansion, and build tooling maturity**. The 219 commits span improvements across nearly every area of the platform, with particular emphasis on path handling, data structures, string processing, and the build system.

The most notable breaking change is the **pipeline operator replacement** (`/>` to `|>`), which required updates across the entire codebase and signals the language's move toward stability. This release also marks substantial improvements in Unicode/UTF-8 support, making Elixir more robust for international applications.

## Major Features & Improvements

### 1. **Path Module Refactoring** (Path Abstraction)
One of the most significant organizational changes in this release is the creation of a dedicated `Path` module and migration of path-related functions from `File` to this new module.

**Key Commits:**
- `fda6f0ce09` - Move path related functions from File to Path
- `cb1b4c5bc5` - Add Path.absname and expand ~ on Path.expand
- `77755f9831` - Use the new Path.expand on mix
- `67154735f7` - Add Path.relative and Path.type
- `a3d1ee67d7` - Use the new Path.relative_to and ensure it won't fail for equals paths
- `9e742e50dc` - Path.join merges second path regardless if it is an absolute or relative path

**Impact:** This organizational improvement provides better separation of concerns, with path operations now having a dedicated, focused API. The addition of `Path.type`, `Path.relative`, and improved `Path.expand` (with tilde expansion support) makes path manipulation more flexible and Pythonic.

---

### 2. **Pipeline Operator Syntax Overhaul** (Breaking Change)
A fundamental language change: the pipeline operator is renamed from `/>` to `|>`.

**Key Commits:**
- `c9908a23dd` - The pipeline operator is now '|>' (Fixes #718)
- `531e64c66a` - Add back /> as a deprecated operator
- `5d285ae7f8` - Add a stacktrace to /> deprecation
- `caf2d82e90` - Merge pull request #751 from alexrp/pipeline-operator

**Impact:** This is a **critical breaking change** affecting every Elixir program using the pipeline operator. The new `|>` syntax is more visually distinctive and aligns better with community expectations. The deprecation of `/>` provides a migration path, but all code must be updated. This change affects approximately 27 files in the codebase itself, as evidenced by the extensive updates across the library, Mix, IEx, and ExUnit.

**Rationale:** The `|>` operator provides clearer visual distinction from division (`/`) and better semantics. This is likely influenced by discussions in issue #718.

## Breaking Changes

### 1. **Pipeline Operator: `/>` → `|>`** (CRITICAL)
   - The most significant breaking change affecting all code using the pipeline operator
   - Old `/>` operator deprecated with stacktrace guidance
   - All library code updated across ~27 files

### 2. **Dictionary Deprecations**
   - `OrdDict` deprecated (replace with `Dict`)
   - `Binary.Dict` deprecated
   - Migration path provided but code must be updated

### 3. **String.first and String.last Return Value**
   - Changed from returning empty string to nil
   - Improves consistency with Keyword/List behavior
   - Minor but affects code expecting empty strings

### 4. **Raw Option Deprecation** (e353b1ad15)
   - `:raw` option deprecated in favor of `:path` option
   - Affects command-line argument parsing

## Migration Guide for Users

### High Priority
1. **Update pipeline operator syntax**: Change all `/>` to `|>`
2. **Replace deprecated dictionaries**: Use `Dict` instead of `OrdDict` and `Binary.Dict`
3. **Update function calls**: Check if `String.first` and `String.last` return values affect your code

### Medium Priority
1. **Adopt new Path module**: Move path operations from File to Path
2. **Update System timeouts**: Consider using `System.services_timeout/0`
3. **Use new String functions**: Leverage `String.slice/3` and `String.capitalize/1`

### Low Priority
1. **Review command-line parsing**: Update any code using `:raw` option
2. **Explore new Dict API**: Use `Dict.put_new` and `Keyword.put_new` for convenience
3. **Implement behaviors**: Consider using `Application.Behaviour` and `Supervisor.Behaviour`

## Conclusion

v0.8.0 represents a major leap forward in Elixir's maturity, introducing critical breaking changes (pipeline operator) while simultaneously expanding capabilities across the standard library, build tools, and testing framework. The release establishes several patterns that would become cornerstones of Elixir:

- Unified pipeline syntax with `|>`
- Proper separation of concerns (Path module abstraction)
- Comprehensive Unicode/UTF-8 support
- Mature build system with Mixed Erlang/Elixir projects
- Codified application and supervisor patterns

This release signals Elixir's transition from experimental to production-ready, with thoughtful API design and a commitment to both backward compatibility (where possible) and forward progress.
