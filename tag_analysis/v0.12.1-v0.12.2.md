# Changes from v0.12.1 to v0.12.2

## Overview

**Release Period:** January 4, 2014 to January 15, 2014
**Commit Count:** 68 commits
**Release Date:** January 15, 2014

v0.12.2 represents a focused patch release with attention to language semantics, API improvements, and bug fixes. This release demonstrates Elixir's commitment to API stability through careful deprecations while addressing runtime issues and improving developer experience.

---

## Summary of Key Themes

The v0.12.2 release concentrated on four main areas:

1. **API Modernization via Deprecations:** A comprehensive set of deprecations guiding developers toward more idiomatic and consistent APIs (6 major deprecations)
2. **Stream and Enumeration Enhancements:** New higher-order operations (`flat_map_reduce/3`, `Stream.transform/3`) and better Dict flexibility
3. **ExUnit Testing Improvements:** Better module-level tagging support and corrected setup/teardown behavior
4. **Core Language Fixes:** Important parser improvements, binary handling corrections, and operator precedence refinements

---

## Major Features and Improvements

### 1. **Stream and Enumeration APIs**
   - **`Stream.transform/3`** - New function for transforming stream elements with stateful operations, providing more flexibility than traditional map/filter operations
   - **`Enum.flat_map_reduce/3`** - Adds reduce capability to flat mapping, enabling accumulation during element flattening
   - **Enhanced EEx flexibility** - `EEx.AssignsEngine` now accepts any Dict implementation, not just specific types, improving template compatibility

### 2. **Testing Framework Improvements**
   - **`@moduletag` Support in ExUnit** - Module-level test tagging for better test organization and filtering at the module scope
   - **Fixed `include`/`exclude` behavior** - The `:include` option now correctly applies standalone, previously requiring prior `:exclude` directives
   - **Conditional test lifecycle execution** - `setup_all` and `teardown_all` now only execute if the test case actually contains tests, preventing unnecessary fixture setup/teardown

### 3. **Developer Experience Enhancements**
   - **Improved Error Messages** - Better stacktraces that include application context (using `:application.get_application/1`), making production errors more traceable
   - **Relative Path Compilation** - Compilation now uses relative paths, improving reproducibility and reducing path-dependent issues
   - **Parallel Unicode Compilation** - Unicode modules compile in parallel, improving build performance

### 4. **Keyword Dictionary Enhancements**
   - **`Keyword.delete/3`** - New function to delete specific key-value pairs, not just keys, allowing more precise list manipulation

## Bug Fixes

### ExUnit
- **Include/Exclude Interaction:** Fixed a regression where `:include` in ExUnit only worked after a test had been excluded with `:exclude`. Now `:include` filters properly work independently
- **Test Lifecycle:** Resolved issue where `setup_all` and `teardown_all` callbacks would execute even for test cases without any tests

### Kernel/Parser
- **Bitstring Modifiers:** Ensured that modifier arguments in bitstring patterns (e.g., `<<x::utf8-size(n)>>`) are properly expanded during compilation
- **Binary Handling:** Improved handling of string literals inside bitstring patterns when using `utf8`, `utf16`, or `utf32` specifiers, fixing edge cases in binary pattern matching
- **Float Rounding:** Fixed float rounding error in midpoint calculations where certain decimal values would round incorrectly
- **Compiler Blocking:** Corrected an issue where the compiler could block on missing modules, improving build reliability
- **Case Clause Rewriting:** Re-enabled case clause rewriting optimization (issue #1972), improving performance of case expressions

### Mix/Dependencies
- **Git Dependency Locking:** Ensured git SCM properly compares dependencies without taking lock information into account, preventing false mismatches
- **Path Dependencies:** Restricted path dependencies to only work with Mix projects, preventing misuse with non-project targets
- **Recursive Copy:** Fixed issue where recursive copy of build dependencies didn't account for the proper target directory on Windows builds

### Build Process
- **Bootstrap Safety:** Fixed bootstrapping issues that could occur during initial builds
- **Git Repository Handling:** Fixed issue where the build would fail when `get_rev_info` command is executed outside a git repository

## Deprecations

The release includes 6 significant deprecations guiding developers toward modern idioms:

### 1. **`<-/2` Operator**
   - **Deprecated in favor of:** `send/2`
   - **Rationale:** The `<-` operator was confusing and inconsistent with other message passing in Erlang/Elixir. Use `send/2` for explicit clarity

### 2. **`Enum.first/1`**
   - **Deprecated in favor of:** `Enum.at/2` or `List.first/1`
   - **Rationale:** Splitting into more specific functions provides better semantics - use `List.first/1` for lists (specialized) or `Enum.at/2` for enumerables (flexible)

### 3. **Continuable Heredocs**
   - **What was deprecated:** The ability to continue parsing on the same line where a heredoc started
   - **New behavior:** Heredocs must now be properly closed, improving syntax clarity and preventing confusing multi-line constructs

### 4. **`is_alive/0` Kernel Function**
   - **Deprecated in favor of:** `Node.alive?`
   - **Rationale:** Better organization of node-related functions in the `Node` module

### 5. **`Kernel.inspect/2` with `Inspect.Opts[]`**
   - **Deprecated in favor of:** `Inspect.Algebra.to_doc/2`
   - **Also deprecated:** The `:raw` option (use `:records` instead)
   - **Rationale:** Refactoring inspect API toward more explicit and composable functions

## Backwards Incompatible Changes

### **`String.next_grapheme/1` and `String.next_codepoint/1` Return Values**
   - **Previous behavior:** Returned the next character(s) and remaining string, or an atom `:nomatch` at the end
   - **New behavior:** Returns `{grapheme/codepoint, rest}` or `nil` at string end
   - **Impact:** Code checking for `:nomatch` will break; must now check for `nil`
   - **Benefit:** More consistent with Elixir conventions (using `nil` instead of atoms for empty results)

## Notable Language Semantics Changes

### **Operator Precedence Unification**
Commits 96a1628033 and 53b68887b6 refined operator precedence:
- **`| and when` precedence** - Inverted to provide more consistent parsing (e.g., in pattern matching and guards)
- **Binary operators** - Unified precedence of `++`, `--`, `**`, `..`, `<>` operators for consistent evaluation order

### **Syntax and Scoping**
- **Variable Export in Case/Receive:** Case and receive clause variables no longer leak into outer scope (deprecated in v0.12.1, now enforced with rewrites disabled)
- **Remote Container Calls:** Removed `:[]` as a valid atom and disallowed remote container calls (e.g., `Module.[]()`) for cleaner semantics
- **Pattern Variable Handling:** Improved handling of annotated types to prevent issues with guard variables

## Analysis: What This Release Tells Us

v0.12.2 represents Elixir's evolution toward API stability and developer clarity:

1. **Consolidation:** The language is consolidating APIs - moving from multiple ways to do things (`<-` vs `send`, `Enum.first` vs `List.first`) toward single canonical approaches

2. **Consistency:** Both operator precedence changes and the nil-based return values show a push toward consistency with Elixir's functional style and conventions

3. **Testing Focus:** ExUnit improvements (moduletags, include/exclude fixes, lifecycle corrections) indicate growing emphasis on robust testing infrastructure for production applications

4. **Performance Awareness:** Changes like parallel Unicode compilation and operator precedence unification show attention to runtime and compile-time performance

5. **Careful Deprecation Strategy:** Rather than breaking changes, the release uses thorough deprecation warnings to guide migration, enabling smooth upgrades for production code

This is a mature approach to language evolution - improving the language while respecting existing codebases.

## Migration Guide for Users

### High Priority (Breaking Changes)
- Update `String.next_grapheme/1` and `String.next_codepoint/1` call sites to check for `nil` instead of `:nomatch`

### Medium Priority (Deprecations)
- Replace `<-` with `send/2` for message passing
- Update `Enum.first/1` calls to `List.first/1` (for lists) or `Enum.at/2` (for other enumerables)
- Replace `is_alive/0` with `Node.alive?`
- Remove continuable heredocs (format properly on new lines)
- Update `Kernel.inspect/2` calls using `Inspect.Opts[]`

### Low Priority (Improvements to Adopt)
- Use `@moduletag` instead of per-test tags for module-wide test configuration
- Leverage `Enum.flat_map_reduce/3` for stateful transformations
- Use `Stream.transform/3` for complex stream operations
