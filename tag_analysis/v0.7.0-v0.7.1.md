# Changes from v0.7.0 to v0.7.1

## Overview

**Date Range:** October 20, 2012 to November 18, 2012
**Total Commits:** 198
**Release Type:** Minor version patch with significant feature additions

This release represents a critical stabilization and enhancement phase for Elixir, with major improvements to the type system, testing framework, and core libraries. The release demonstrates a strong focus on static analysis, developer experience, and performance optimization.

---

## Summary of Key Themes

### 1. Typespec System Overhaul

The most significant theme in this release is the comprehensive overhaul and stabilization of Elixir's type specification system. This work modernized how types, callbacks, and specifications are defined and compiled within Elixir, directly addressing Dialyzer integration and static type checking capabilities.

**Key Accomplishments:**
- Merged Typespec and Kernel.Typespec modules into a unified system for better organization
- Implemented a two-phase compilation process for typespecs to properly handle dependencies
- Added comprehensive type definitions for core modules, establishing standard practices for library authors
- Introduced support for opaque types (@opaque) for better encapsulation
- Enhanced record type specifications with field-level type annotations

### 2. Testing Infrastructure Enhancement

ExUnit received significant improvements to support more sophisticated testing workflows and user configurations, making it easier for projects to customize test execution.

### 3. Unicode and String Processing

Substantial improvements were made to string handling and Unicode support, including full Unicode 6.2.0 compliance for case conversion operations.

### 4. Performance and Optimization

Multiple optimizations were implemented throughout the codebase, reducing memory footprint and improving compilation speed.

## Breaking Changes

### 1. **Behaviour.defcallback/1 Deprecation** (Commit: fdc2657af8)
- Old style: `defcallback function(arg) :: type`
- New style: `@callback function(arg) :: type` via @spec syntax
- Migration: Update any modules using Behaviour.defcallback to use @callback
- Behavior modules should use new callback syntax from @specs

### 2. **Enum.times Deprecation** (Commit: 12d14edab5)
- `Enum.times/2` is deprecated
- Use alternative approaches like ranges with Enum.each or custom recursion
- Function removal expected in future releases

### 3. **halt/0 Moved to System Module** (Commit: 743213d8c1)
- Old: `Kernel.halt`
- New: `System.halt`
- Rationale: halt is specialized for system shutdown, not a general kernel function
- Migration: Update any calls to `halt` to use `System.halt`

### 4. **Record Default Values** (Commit: b9692fc2fe)
- Record extracted values now default to :undefined instead of :nil
- Important for Erlang record compatibility
- Affects code that depends on nil defaults for extracted records

### 5. **Protocol Compilation Changes** (Commit: bd8648d49, 591b95bfb9)
- Protocols now compile with fewer unnecessary clauses
- Should be transparent but impacts generated code volume
- Protocols should define @callback implementations explicitly

### 6. **Module.__info__(:module)** (Commit: 925ab81ca2)
- Changed from `__info__(:self)` to `__info__(:module)`
- Affects introspection code that queries module information
- More semantically correct naming

## Notable Technical Improvements

### Compiler Efficiency

1. **Atom Footprint Reduction** (Commit: 40efeb48d7)
   - Atoms generated during compilation are now pooled
   - Used module names are returned to pool for reuse
   - Significantly reduces memory consumption during compilation
   - Important for large codebases with many modules

2. **Two-Phase Typespec Compilation** (Commit: 3b33478cc0)
   - Typespecs now compile in two phases
   - First phase: collect type definitions
   - Second phase: resolve references
   - Fixes circular dependency issues

3. **Compilation Order Improvements** (Commits: 6a9a3b3efe, d75fb11dc4)
   - Reorder core modules for proper compilation
   - Disable internal phase earlier to allow callback compilation
   - Better dependency resolution during bootstrap

### Code Quality and Type Safety

1. **Dialyzer Integration** (Commits: f95529b7b3, 2b9d67dd9d, 87391a5832)
   - Added make dialyze target for build system
   - Fixed numerous dialyzer warnings in core modules
   - Improved boolean return checks
   - Better clause handling for type checking

2. **Variable Rebinding Tracking** (Commit: 01f95188993)
   - Variables now tracked with @1, @2 suffixes internally
   - Better debugging information
   - Foundation for future rebound variable warnings

### Build System and Development Experience

1. **Faster First Compilation** (Commit: f7490bd5af)

## Conclusion

Version 0.7.1 represents a major milestone in Elixir's development. The release demonstrates a mature approach to language design with significant improvements to:

- **Type System**: Introduction of comprehensive type specifications for all core modules
- **Developer Experience**: Better debugging, introspection, and testing capabilities
- **Performance**: Optimizations in compilation and runtime behavior
- **Quality**: Removal of dialyzer warnings and improved code correctness
- **Compatibility**: Better integration with Erlang ecosystem

The focus on the typespec system and Dialyzer integration shows a commitment to static analysis and type safety, setting the foundation for Elixir's evolution toward a more type-aware language while maintaining its dynamic flexibility.
