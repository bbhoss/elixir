# Changes from v0.8.0 to v0.8.1

## Release Overview

- **Date Range**: January 19, 2013 - February 17, 2013
- **Total Commits**: 86 commits
- **Release Date**: February 17, 2013

This patch release represents approximately one month of active development, introducing significant new features, important breaking changes, and numerous quality-of-life improvements across the Elixir ecosystem.

---

## Summary

Version 0.8.1 is a feature and refinement release that marks a pivotal moment in Elixir's development. The most significant addition is the introduction of **IO.ANSI**, a comprehensive color and styling system for terminal output. This feature, while new, involved multiple iterations to handle various edge cases including ANSI sequence handling, terminal detection, and compatibility with older OTP releases (pre-R16).

The release also introduces **breaking changes** that affect how module compilation hooks work, requires code adjustments for deprecation warnings around `Process.self`, and enhances **ExUnit** with new metadata capabilities and callback improvements. The release shows strong focus on improving the **Mix build tool**, particularly with better CLI argument handling and filesystem compatibility.

Key themes across this release:
1. **Terminal Output Capabilities**: Major new ANSI/color support system
2. **API Modernization**: Deprecating older patterns, moving to cleaner abstractions
3. **Build Tool Enhancement**: Mix improvements for better developer experience
4. **Testing Infrastructure**: ExUnit enhancements for more flexible test management
5. **Language Refinement**: Quote API cleanup and aliases handling improvements
6. **Platform Compatibility**: Work towards OTP R16 support and fixing cross-platform issues

## Major Features & Improvements

### 1. IO.ANSI - Color and Styling Support (Most Significant Feature)

A new comprehensive **IO.ANSI module** was implemented to provide structured terminal color and styling capabilities. This was a substantial addition involving approximately 16+ commits across the release cycle:

**Core Features:**
- `IO.ANSI.escape/1` and `IO.ANSI.escape/2` functions for generating ANSI escape sequences
- `IO.ANSI.escape_fragment/1` for generating escape sequences without reset codes
- Color definitions and ANSI control sequences
- Terminal detection with `IO.ANSI.terminal?/1` function
- Compatibility layer for OTP versions prior to R16

**Implementation Highlights:**
- The implementation changed ANSI escape format from `#[]` to `%{}` syntax during development
- Special handling for terminals that don't support ANSI codes (automatic detection)
- Pre-R16 warning system to alert users when ANSI sequences are used in unsupported environments
- Proper reset sequence handling to avoid leaving terminal in invalid state

**Related Commits:**
- Initial implementation (Jan 19)
- Test coverage additions
- Terminal detection improvements
- Format refinements and documentation
- Integration with Mix CLI for colored output

**Impact**: Enables Elixir developers to create colorful and styled terminal output, critical for developer tools, Mix output, and IEx REPL experience.

### 2. ExUnit Enhancements

#### Callback Return Value Requirements
ExUnit callbacks (setup, teardown, etc.) now **must return `:ok` or `{:ok, data}`** format. This standardization improves consistency across the testing framework and makes error detection more reliable.

#### Metadata Support for ExUnit
New metadata support added to ExUnit, enabling tests and modules to be tagged with custom metadata for organizational and filtering purposes. This provides developers with more flexibility in organizing and running subsets of tests.

#### Deprecation of `after_spawn` Callbacks
The `ExUnit.after_spawn` callback mechanism is being deprecated, likely to be replaced with cleaner patterns in future versions.

**Impact**: These changes provide ExUnit with more explicit, predictable behavior and enable advanced test organization capabilities.

## Breaking Changes

### 1. `before_compile` and `after_compile` Callbacks

**Breaking Change**: Both `@before_compile` and `@after_compile` callbacks **now receive the environment as the first argument instead of the module**.

**Before:**
```elixir
def __before_compile__(mod) do
  # mod was the module being compiled
end
```

**After:**
```elixir
def __before_compile__(env) do
  # env is now the compilation environment
end
```

**Impact**: Any code using `@before_compile` or `@after_compile` callbacks will need to be updated. This is a moderate breaking change affecting library developers and advanced metaprogramming use cases.

**Affected Code**: Mix.Project and module compilation hooks throughout the ecosystem needed updates.

---

### 2. `:local.(args)` Syntax Deprecation

The old `:local.(args)` function call syntax has been deprecated:

**Before:**
```elixir
:some_function.(arg1, arg2)
```

**After:**
```elixir
# Use named functions or regular syntax
```

This syntax was a remnant from earlier Elixir versions and is being phased out in favor of cleaner alternatives.

---

### 3. `Process.self/0` Deprecation

`Process.self` is being deprecated in favor of **`Kernel.self/0`** to improve import hygiene and reduce namespace pollution (closes #832).

**Before:**
```elixir
Process.self  # Get current process ID
```

**After:**
```elixir
self  # or Kernel.self
```

**Impact**: Minimal breaking change; the function still works but will show deprecation warnings. Users should update to use `Kernel.self` or the simpler `self` shorthand.
