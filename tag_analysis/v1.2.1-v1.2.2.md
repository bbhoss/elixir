# Changes from v1.2.1 to v1.2.2

## Overview

**Release Date Range:** January 14, 2016 (v1.2.1) to January 31, 2016 (v1.2.2)
**Commit Count:** 10 commits
**Release Type:** Patch release (bug fixes and minor enhancements)

## Summary

v1.2.2 is a focused maintenance release addressing critical issues discovered shortly after v1.2.1. The release centers around three primary concerns: improving build system reliability in Mix, enhancing compilation control in the Elixir compiler, and fixing test framework edge cases. All changes were authored by José Valim within a 17-day window.

The changes reflect the refinement phase following the major v1.2.0 release, targeting production stability and addressing edge cases that emerged during real-world usage. Total code changes span 196 insertions and 76 deletions across 19 files, primarily in the Mix build tool and Elixir compiler infrastructure.

## Major Features & Improvements

### 1. Compiler Control: Disabling Autoload After Compilation

**Commit:** `7180b98f474f79f0ad4d0de0bb6874f56c9b9dde`

Added support for `@compile {:autoload, false}` directive, allowing developers to disable automatic module loading after compilation. This enhancement addresses a specific use case where modules may depend on NIFs (Native Implemented Functions) and should be loaded only when explicitly needed, not immediately after compilation.

**Impact:**
- Provides finer control over module loading timing
- Prevents issues with NIF-dependent modules being loaded prematurely
- Improves initialization order control in complex projects

**Related Changes:**
- `0b78f86f08511393c337cb438162f9fdc7b9b07e`: Refactored Mix to not rely on compiled functions for autoload operations, ensuring the build system can function independently
- `021cca436d500403ed5ac84c060f12bd3681e45f`: Fixed metadata to exclude debug_info in String modules, preventing bloat in module metadata

### 2. Build System Reliability Improvements

Several commits strengthened the Mix build tool's compiler orchestration:

**Automatic Manager Priority Merging (Issue #4230)**
**Commit:** `31aebcdc59c9c8e0f558f277b052a0c510a3b6d3`

Implemented automatic merging of dependency managers according to internal priority order: Mix > Rebar3 > Rebar > Make. This prevents configuration conflicts when multiple manager directives are specified and ensures consistent build behavior.

**Impact:**
- Reduces manual configuration needed for complex multi-dependency projects
- Prevents build failures from conflicting manager specifications
- Establishes clear precedence when multiple managers could apply

**Manifest Compilation Robustness (Issue #4228)**
**Commit:** `afbac81918e3257ac5b8bb186e2bda19c9ba7246`

Fixed a critical issue where Mix would fail if not all compilers were available when retrieving compile manifests. The fix allows the manifest retrieval process to gracefully handle missing compilers.

**Impact:**
- Improves build reliability when compiler tools are not fully available
- Prevents crashes in incomplete development environments
- Enables partial builds to proceed without complete toolchain presence

**Dependency Freshness Recompilation**
**Commit:** `a825f5a0c8fe25fc71b23237f37b61e110f3e56b`

Added logic to force recompilation if a dependency was recently fetched. This ensures that newly downloaded dependencies are properly compiled even if timestamps might suggest no recompilation is needed.

**Impact:**
- Fixes edge cases where fresh dependencies weren't being recompiled
- Improves consistency of incremental builds
- Prevents hard-to-debug issues from stale compiled artifacts

## Bug Fixes

### 1. Reserved Tag Override Protection (Issue #4236)

**Commit:** `3c0d26cb749f765f1c8ca1cd3dbc87d37a34be37`

ExUnit now raises an error if code attempts to override reserved tags in `setup` blocks. This prevents accidental shadowing of framework-reserved attributes and catches user errors early.

**Commit:** `e2463a55892928ad12760a8f4c9cc523c4d9482d`

Limited the list of attributes considered "reserved" to a more precise set, refining the protection mechanism to avoid false positives while maintaining framework integrity.

**Impact:**
- Prevents hard-to-debug test framework issues from reserved attribute overrides
- Provides clear error messages when violations occur
- Protects ExUnit internals from being inadvertently modified

### 2. String Metadata Optimization

**Commit:** `021cca436d500403ed5ac84c060f12bd3681e45f`

Removed debug_info from metadata in String modules, reducing the metadata payload that gets embedded in compiled modules.

**Impact:**
- Reduces binary size of compiled String modules
- Improves memory efficiency
- Speeds up module loading

## Breaking Changes

**None identified.** This is a pure maintenance release with no breaking changes to the public API or documented behavior.

## Technical Insights

### Compilation System Maturation
The commits reveal ongoing refinement of Elixir's compilation system, particularly around:
- Decoupling the build tool from runtime behavior (removing compiled function dependencies)
- More sophisticated loading control (autoload support)
- Better handling of edge cases in incremental compilation

### Mix Build Tool Resilience
Multiple commits address Mix's reliability, suggesting these issues emerged in production use:
- Compiler availability assumptions were too strict
- Manager configuration conflicted in complex projects
- Dependency fetching wasn't triggering necessary recompilation

### Test Framework Hardening
The ExUnit changes show attention to framework integrity, ensuring user code cannot accidentally corrupt reserved internal state.

## Release Context

This patch release follows the major v1.2.0 release (which introduced Maps, `with` statements, and other significant features) and the initial v1.2.1 patch. The concentrated nature of v1.2.2 (just 10 commits in 17 days) suggests these were critical issues discovered shortly after v1.2.1's release, warranting quick resolution while the team had the context fresh.

The focus on build system reliability and compiler control indicates that users were encountering edge cases in real-world scenarios that the initial testing hadn't caught, leading to this focused maintenance release prioritizing stability over new features.
