# Changes from v1.4.0 to v1.4.1

## Overview

**Date Range:** January 5, 2017 to January 26, 2017
**Commit Count:** 16 commits (excluding the release commit)
**Release Date:** January 26, 2017

This was a relatively focused patch release that addressed critical bugs, improved dependency management, and enhanced the standard library with useful additions.

## Summary

v1.4.1 represents a maintenance release addressing several important issues identified after the v1.4.0 release. The release cycle was brief (approximately 3 weeks), indicating focused attention on bug fixes and refinements rather than major new features. Key themes include:

1. **Dependency Management Improvements** - Refinements to how rebar and rebar3 dependencies are handled, particularly around overrides and package declarations
2. **Standard Library Enhancements** - New time utility functions and regex improvements
3. **Build System Fixes** - Improvements to build tooling and erlang.mk integration
4. **Warning Reduction** - Elimination of noisy warnings that were overly strict for legitimate use cases
5. **Documentation Corrections** - API documentation fixes and improvements

## Major Features/Improvements

### Time API Extensions
- **Added `Time.utc_now/0`** - New function to get current UTC time (companion to existing datetime functions)
- **Added `NaiveDateTime.utc_now/0`** - New function to get current UTC naive datetime
- These additions provide more convenient shortcuts for common time operations and improve API completeness

### Rebar3 Support Enhancements
- **Support rebar3 dependency package declaration** (Commit: 49af97a800)
  - Extended rebar3 compatibility to support simplified package declarations
  - Previously only `{app, "~> 1.0.0", {pkg, hex_package}}` was supported
  - Now also supports `{app, {pkg, hex_package}}` (without version spec)
  - This makes Elixir projects using rebar3 more flexible in dependency specification

### Regex Improvements
- **Add `-` to Regex.escape/1** (Commit: 7f61b0ff05)
  - The hyphen character (`-`) was not being properly escaped
  - This is important when the hyphen appears in character classes where it could be misinterpreted
  - Now correctly escapes the hyphen to prevent regex interpretation issues

### Documentation Improvements
- **Improve task docs** - Enhanced documentation for Mix task definitions
- **Fix documentation for System.schedulers_online** - Corrected arity reference from `/1` to `/0`
- **Path.join/1 documentation refinement** - Clarified that the function accepts a list of paths, not strings, and that the list must be non-empty

## Bug Fixes

### Path Handling
- **Fix Path.join/1 for lists of one element** (Commit: 67f77ec1cd)
  - Resolved edge case where joining a list containing a single path would fail
  - Updated typespec and documentation to clarify that Path.t (not strings) are expected
  - Ensures consistent behavior across different list sizes

### Calendar/Time
- **Fix typespecs in Calendar** (Commit: 8a91f648a8)
  - Corrected type specifications in the Calendar module
  - Improves type checking accuracy for time-related operations

### Terminal/ANSI Output
- **Disable ansi detection for powershell to avoid false positives** (Commit: 097fe87eb7)
  - Resolves issue #5615 where Windows PowerShell environment was incorrectly detected as supporting ANSI colors
  - Prevents garbled output when running Elixir tools on Windows PowerShell
  - Conservative fix that prioritizes correct output over capability detection

### Testing Infrastructure
- **Wait for message before crash in exception tests** (Commit: 7d09c2b857)
  - Improves test reliability by ensuring proper message synchronization
  - Prevents intermittent test failures due to timing issues

## Dependency Management Refinements

### Override Attribute Handling
The release includes several improvements to how dependency overrides are handled, addressing issues with rebar's override mechanism:

1. **Only pass overrides from parent to child rebar dep** (Commit: 74f9a340155)
   - Fixes issue #5687 by ensuring overrides don't cascade incorrectly through the dependency tree
   - Prevents unintended dependency conflicts in nested dependencies
   - Only parent dependencies' overrides are now passed to direct children

2. **Remove warning when making private functions overridable** (Commit: 12edab720c)
   - Removed an overly strict warning that was triggered when making private functions overridable
   - Private function overrides are legitimate in certain Rebar use cases
   - Reduces noisy warnings without compromising correctness

3. **Do not warn on unused override attribute** (Commit: f38646781b)
   - Eliminated warning about unused override attributes
   - Override attributes may be intended for specific build configurations
   - Improves developer experience by reducing false-positive warnings

### Build System
- **Run `make clean` for erlang.mk** (Commit: b87e58e7e3)
  - Ensures proper cleanup when using erlang.mk based builds
  - Prevents stale artifacts from interfering with builds

## Breaking Changes

**None identified.** This is a pure maintenance release with backward-compatible bug fixes and enhancements.

## Notable Commits Worth Highlighting

### #1: Rebar3 Package Declaration Support (49af97a800)
**Significance:** Improves Elixir's rebar3 compatibility, making it easier for Erlang/OTP projects that depend on Elixir packages to specify dependencies in a more concise way. This reduces configuration overhead.

### #2: Path.join/1 Edge Case Fix (67f77ec1cd)
**Significance:** Fixes a subtle but important edge case in path manipulation. While single-element lists are rare, the fix improves overall API robustness and predictability.

### #3: PowerShell ANSI Detection Fix (097fe87eb7)
**Significance:** Critical for Windows developers. Fixes a regression where output was corrupted on Windows PowerShell due to incorrect capability detection. This directly impacts user experience on a major platform.

### #4: Override Cascade Fix (74f9a340155)
**Significance:** Addresses a potentially serious dependency resolution issue where overrides could incorrectly propagate through the dependency tree, causing confusing conflicts. This was likely a real-world pain point for projects with deep dependency chains.

### #5: Warning Reduction Changes (12edab720c, f38646781b)
**Significance:** These commits reflect a philosophy shift toward trusting developers. Rather than warning about potentially valid uses of features, the compiler now allows these patterns. This reduces compilation noise while maintaining safety through static analysis.

## Analysis

v1.4.1 demonstrates a maintenance-focused approach with emphasis on:

- **Pragmatism**: Removing overly strict warnings in favor of trusting developer intent
- **Robustness**: Fixing subtle bugs in core functionality (Path handling, type specs)
- **Compatibility**: Improving support for ecosystem tools (rebar3)
- **User Experience**: Fixing platform-specific issues (PowerShell) and reducing compilation warnings
- **API Completion**: Adding convenient shortcuts for common time operations

The release was relatively quick (3 weeks), suggesting these were identified and prioritized issues that needed urgent attention. The focus on dependency management suggests the team was actively addressing concerns from the Erlang/OTP ecosystem integration efforts.

The reduction in warnings (3 commits specifically addressing overly strict warnings) suggests the team was listening to community feedback about compiler output noise and found opportunities to be less pedantic while maintaining correctness.
