# Changes from v1.2.5 to v1.2.6

## Overview

**Release Date Range:** April 30, 2016 → June 6, 2016 (37 days)
**Total Commits:** 11 commits
**Release Type:** Patch release

This patch release focused primarily on bug fixes and forward compatibility with Erlang 19, while introducing a single notable language feature: support for the `generated: true` attribute in the `quote` special form.

## Summary

v1.2.6 is a maintenance release that strengthens Elixir's compatibility with the latest Erlang VM releases and fixes several critical bugs discovered in the v1.2.x series. The release demonstrates a focused approach to patch development, addressing specific issues in path handling, string normalization, type specifications, and generated code handling. The single substantive feature addition—support for `generated: true` in `quote`—represents a refinement of Elixir's code generation capabilities, enabling macros and code generators to better mark their output as auto-generated.

## Major Features & Improvements

### 1. Support for `generated: true` in Quote Special Form

**Commits:**
- `55a4c5980d` - Support generated: true in quote
- `9d95a0bcbf` - Propagate generated: true in Elixir definitions
- `a77b85665a` - Mark variables captured by modules as generated

**Analysis:**
This was the primary feature addition in this release. The `generated: true` flag allows developers to mark code produced by macros and generators as auto-generated. This is important for:
- Distinguishing between hand-written and auto-generated code
- Improving stack traces and error messages
- Assisting developers in understanding which code was written directly versus generated

The implementation involved three commits working in concert:
1. First, adding support for the attribute in the `quote` special form itself
2. Second, ensuring the flag propagates correctly through Elixir definition compilation
3. Third, automatically marking variables captured by modules as generated to reduce noise in error reporting

This was a carefully integrated feature that required coordination across multiple compilation layers.

### 2. Enhanced Annotation Terminology

**Commit:** `e415148d3a` - More explicitly use the term annotation throughout

**Analysis:**
A refactoring commit that standardized terminology throughout the codebase. This wasn't a breaking change but rather a documentation and code clarity improvement, establishing "annotation" as the standard term for metadata applied to code during compilation.

## Bug Fixes

### 1. Binary Typespec Syntax Fix
**Commit:** `30cbdb8fbf` - Fix binary typespecs
**Issue:** Incorrect syntax support for binary size/unit specifications
**Before:** `<<_::size*unit>>`
**After:** `<<_::size, _::_*unit>>`
**Impact:** Developers using binary pattern matching in typespecs could not correctly express certain patterns. This fix allows proper type specification of binaries with variable sizes and unit multipliers.

### 2. Path.join Bug Fix
**Commit:** `d1773cf96d` - Fix bug in Path.join. Fix #4252.
**Issue:** Path.join failed to handle "/" followed by empty segments correctly
**Impact:** This was a specific edge case bug where constructing paths with empty string segments after a "/" prefix produced incorrect results. Common scenarios that triggered this bug would include:
```elixir
Path.join("/", ["", "path"])  # Now works correctly
```

### 3. String NFD Normalization Bug
**Commit:** `41b5091073` - Fix nfd normalization bug (#4606)
**Issue:** NFD (Canonical Decomposition) normalization in String module failed when a one-byte grapheme immediately followed a normalized character
**Additional Change:** The commit also refined `String.normalize/2` return type specification
**Impact:** Unicode text normalization is critical for correct text comparison and display. This fix ensures that strings with specific Unicode compositions are normalized correctly, which is particularly important for international applications.

### 4. Erlang 19 RC Compatibility
**Commit:** `5754da26f2` - Fixes for Erlang 19 RC
**Issue:** Forward compatibility issues with Erlang 19 release candidate
**Impact:** Elixir needed adjustments to work with Erlang 19's new features and API changes. This commit proactively ensures users can adopt the new Erlang version without compatibility problems.
