# Changes from v1.6.5 to v1.6.6

## Overview

**Date Range:** May 7, 2018 - June 20, 2018 (44 days)
**Total Commits:** 15
**Release Date:** June 20, 2018

This minor patch release focused on stabilizing Erlang/OTP 21.0 compatibility, fixing critical bugs, and introducing performance improvements across the logging system and standard library.

---

## Summary

The v1.6.6 release was primarily driven by the need to ensure compatibility with the newly released Erlang/OTP 21.0, which introduced breaking changes in how the logger system works. The major undertaking was porting the complete logger implementation from the master branch to v1.6. Beyond that, the release addressed various bug fixes in string handling, code formatting, task supervisors, and dynamic supervisor functionality.

The theme of this release is **stability and compatibility**: ensuring Elixir 1.6 works seamlessly with the latest Erlang/OTP 21.0 while fixing accumulated issues from the community.

---

## Major Features & Improvements

### Erlang/OTP 21.0 Compatibility (Critical)

**Commits:**
- `c9d6ea5` - Port Erlang/OTP 21.0 logger from master
- `462a9de` - Add missing erlang handler
- `a9a271e` - Update to OTP 21.0-rc2

**Impact:** This was the heavyweight change in this release. Erlang/OTP 21.0 fundamentally changed how the logger system works—only certain events are forwarded to the `error_logger`, requiring a complete reimplementation of Elixir's logger interface.

**Details:**
- Ported the full logger implementation from the master branch to maintain feature parity
- Added a new `ErlangHandler` module (133 lines) to properly integrate with OTP 21.0's logger
- Rewrote the `Logger.Translator` module significantly (348 lines changed) to handle the new event forwarding model
- Updated `Logger.App` with 82 lines of changes to support the new logger behavior
- Updated `ExUnit.CaptureLog` to work with the new logger system
- These changes ensure that applications using Elixir 1.6 can run on the latest Erlang/OTP 21.0

### Performance Optimization: String Operations

**Commit:** `62697df` - Add performant impl for string upcase/downcase `:ascii` mode

**Impact:** String case conversion for ASCII mode is now **2.5x faster** than the previous implementation.

**Details:**
- The previous implementation used binary comprehensions which proved to be slower
- Introduced an optimized implementation specifically for `:ascii` mode
- This improvement benefits applications that frequently perform ASCII-only string transformations
- Changes were minimal (20 insertions) but high-impact for performance-sensitive code

## Bug Fixes

### Base.decode32! Error Handling

**Commit:** `132b80a` - Add bad digit clause to Base.decode32!/1,2 for case: :mixed

**Impact:** Fixes a critical error reporting bug where `Base.decode32!/2` with `:mixed` case was throwing a `CaseError` instead of the expected `ArgumentError`.

**Details:**
- Previously, invalid digits in mixed-case decoding would trigger an internal case error
- Now properly catches and reports invalid digits with appropriate error types
- Ensures consistent error handling across different case modes

### Code Formatting Enhancements

**Commits:**
- `d0694b5` - When fn is followed by a newline, use multi-clause formatting style
- `f5e35da` - Match files starting with dot in "mix format"

**Impact:** Improved developer experience with better code formatting.

**Details:**
- **Anonymous function formatting:** When a `fn` keyword is followed by a newline, the formatter now correctly uses multi-clause formatting style, producing more readable code
- **Dot-file handling:** Fixed `mix format` to properly include configuration files like `.formatter.exs`. Previously, `Path.wildcard` was not matching files starting with a dot, so `.formatter.exs` wouldn't be formatted even when explicitly listed in the format configuration

### Task.Supervisor Type Specification

**Commit:** `16fe53b` - Fix type spec for Task.Supervisor.start_child/4

**Impact:** Corrects the type specification to accurately reflect the function's behavior, improving IDE support and type-checking.

**Details:**
- Minor fix ensuring type specifications match implementation
- Helps developers using static analysis tools

### Logging Performance

**Commit:** `3d72978` - Avoid calling truncate_n/2 if truncate is :infinity

**Impact:** Eliminates unnecessary function calls in the logging path when truncation is disabled.

**Details:**
- Simple but effective optimization for log message processing
- Reduces overhead when no truncation is configured
- Typical in high-throughput logging scenarios

### IEx Helper Compatibility

**Commit:** `51d61cb` - Only test the open/1 IEx helper on Erlang source if it exists

**Impact:** Fixes test failures on systems where Erlang source code is not available.

**Details:**
- Prevents test failures on minimal Erlang installations
- Makes the test suite more robust across different deployment scenarios

## DynamicSupervisor Improvements

### API Change: Removing Opaque Type

**Commit:** `4d3084b` - No longer make DynamicSupervisor sup_flags opaque

**Impact:** Makes the `sup_flags` type public, allowing users to construct and work with supervisor flags directly.

**Details:**
- Closes issue #7666
- Users can now inspect and construct `sup_flags` structures without relying on internal APIs
- This is a **non-breaking change** as the type is being exposed, not removed
- Improves API flexibility for users working with supervisor configurations

### Bug Fix: Child Counting

**Commit:** `762b5c0` - Count children restarting on exit in DynamicSupervisor max_children

**Impact:** Fixes a logic error in dynamic supervisor child counting.

**Details:**
- Previously, children in the "restarting on exit" state weren't being counted correctly against the `max_children` limit
- This could cause supervisors to exceed their configured child limits
- Fix ensures accurate tracking of all child states
- Refactored the counting logic for clarity (22 lines changed)

### Documentation Improvements

**Commits:**
- `5f96a9b` - Improve docs for DynamicSupervisor.count_children
- `09a13b0` - Improve docs for IEx.Helpers.open

**Impact:** Better developer understanding of API behavior through enhanced documentation.

## Breaking Changes

**None identified.** This is a minor patch release that maintains backward compatibility while adding OTP 21.0 support.

Note: The changes to the Logger system to support OTP 21.0 are internal implementation details and do not affect the public API that application developers depend on.

## Notable Technical Highlights

### 1. Logger Refactoring (Largest Change)

The logger system changes represent the most significant code modifications in this release:
- Total lines affected: ~388 insertions, ~251 deletions
- Reorganized event translation to match OTP 21.0's model
- The `Logger.Translator` module was substantially rewritten to handle new event formats
- This shows the complexity of maintaining compatibility with OTP releases

### 2. Strategic Porting Approach

Rather than creating a new implementation, the Elixir team strategically ported the entire logger from the master branch (future Elixir 1.7/1.8) to ensure:
- Feature parity with newer versions
- Reduced maintenance burden long-term
- Community gets stable, tested code

### 3. Focus on Correctness

Several commits focus on fixing subtle bugs:
- Base.decode32! error types
- DynamicSupervisor child counting
- File matching in code formatter

This suggests community feedback drove many of the fixes.

### 4. Incremental Performance Improvements

Rather than major refactoring, small targeted optimizations:
- 2.5x faster string upcase/downcase
- Avoiding unnecessary truncate calls
- These compound across the ecosystem

## Conclusion

v1.6.6 is a focused release addressing a critical need: Erlang/OTP 21.0 compatibility. The team took a pragmatic approach by porting the complete logger system from master rather than attempting to patch the existing implementation. This decision ensures reliability and reduces future maintenance burden.

Beyond the logger work, the release tackled accumulated bug reports and small performance improvements, demonstrating responsiveness to community feedback. While this is technically a patch release, the internal changes are substantial—particularly in the logging infrastructure.

For Elixir 1.6 users, this release is essential for upgrading to Erlang/OTP 21.0. For those staying on older Erlang versions, the bug fixes and performance improvements make this a worthwhile update.
