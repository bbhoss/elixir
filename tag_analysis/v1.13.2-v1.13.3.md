# Changes from v1.13.2 to v1.13.3

## Date Range and Commit Count

**Release Period:** January 13, 2022 - February 9, 2022 (27 days)
**Total Commits:** 13 commits

## Summary

Version 1.13.3 is a patch release focused on bug fixes and incremental improvements across multiple areas of the Elixir ecosystem. The release demonstrates a strong emphasis on **formatter robustness and extensibility**, alongside critical fixes in **core language features** and **build tooling**. The changes are primarily maintenance-oriented with no breaking changes, making this a safe upgrade for all users on v1.13.x.

The commits reveal a pattern of iterative refinement—addressing reported issues, enhancing formatter plugin capabilities, and fixing edge cases that could cause crashes or unexpected behavior. This reflects Elixir's commitment to stability and reliability in its patch releases.

## Major Features and Improvements

### 1. **Enhanced Formatter Plugin Support** (2 commits)
The formatter plugin system received significant enhancements to improve both developer experience and capabilities:

- **Supply file and line information to formatter plugins** (#11591): Formatter plugins now receive accurate file and line information when processing sigils. This allows plugins to generate precise error messages and diagnostics, improving the debugging experience for formatter plugin developers.

- **Support for Embedded Elixir Expressions in Formatter Plugins** (#11587): Formatter plugins can now properly handle sigils that contain embedded Elixir expressions within formatted files. This extends the formatter's ability to correctly process more complex code structures.

**Impact:** These improvements make the formatter plugin system more powerful and developer-friendly, enabling plugins to provide better error reporting and handle more complex formatting scenarios.

### 2. **Module Tracking Improvements**
- **Track all stale modules from config/lock as exports** (#11600s): Enhanced module tracking now captures all stale modules from both config and lock files as exports. This improvement helps prevent issues with stale module references in the build process.

**Impact:** More reliable build behavior when dealing with configuration and lock file changes.

## Bug Fixes

### Critical Fixes

1. **Duplicate Bindings in IEx/Debugger** (#11584): Fixed a serious bug where duplicate bindings would cause unexpected evaluation behavior. When evaluating code with duplicate bindings (e.g., `b = a` with assignments `a: 1, a: 2, c: 3`), the system would incorrectly evaluate to `^c = a` instead of the correct binding. The root cause was improper version number generation during binding normalization that exceeded the total number of bindings, causing conflicts. **This was a critical correctness issue affecting interactive debugging.**

2. **Code.quoted_to_algebra/Macro.to_string Crash** (#11572): Fixed an edge case that caused crashes when converting the `Elixir` atom to algebra form. This occurred in both `Code.quoted_to_algebra/2` and `Macro.to_string/1` with a MatchError. **This fix prevents crashes when processing certain valid code patterns.**

3. **Guard Recursion with Map Fields** (#11602): Fixed infinite recursion that occurred when processing guards containing map field patterns. **This prevents hard hangs in specific guard clause scenarios.**

### Non-Critical but Important Fixes

4. **Coverage Report Display** (#11571): Fixed the coverage threshold check for the "Total" line in coverage summary reports. An incorrect variable was being passed to the display function, causing the Total line to always show in red regardless of the configured threshold. **Improves accuracy of coverage reporting in mix test.**

5. **Unicode Sequence Handling** (#11617): Enhanced `String.split_at/2` to handle more unicode sequences correctly. **Improves string manipulation reliability with diverse character sets.**

6. **Formatter Indentation of Options** (#11600s): Fixed indentation calculation when formatting function options. **Improves code formatting consistency.**

7. **Function Arity Validation in Formatter** (#11600s): Added proper arity checking for function references in the formatter to prevent formatting errors. **Prevents formatter crashes on certain valid syntax.**

8. **Signature Formatting** (#11600s): Improved formatter behavior to prevent breaking function signatures over multiple lines when unnecessary. **Produces more readable formatted code.**

## Performance Improvements

- **Map.new/2 Optimization**: Optimized the `Map.new/2` function for better performance. **Minor but measurable performance gain for common operations.**
