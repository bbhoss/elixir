# Changes from v1.11.4 to v1.12.0

## Overview

**Release Period:** March 16, 2021 (v1.11.4) → May 19, 2021 (v1.12.0)
**Total Commits:** 562 commits
**Duration:** 65 days

Elixir v1.12 is a focused, quality-of-life release that strengthens scripting capabilities, deepens Erlang/OTP 24 integration, introduces stepped ranges, and adds numerous convenience functions across the standard library.

---

## Key Themes and Changes

### 1. Scripting and Automation Enhancements (Major)

One of the standout features of v1.12 is improved support for scripting and single-file Elixir scripts. This reflects a strategic shift to make Elixir more accessible for automation and tooling tasks:

**Mix.install/2** - The flagship feature enabling dependency management within `.exs` scripts without requiring a full Mix project structure. This is a game-changer for reproducible scripts:
- Automatically downloads, compiles, and caches dependencies
- Performs protocol consolidation for optimal performance
- Marked as experimental but represents significant infrastructure investment
- Several supporting commits for error recovery and configuration handling

**System.trap_signal/3 and System.untrap_signal/2** - New signal handling capabilities allowing scripts to gracefully handle system signals (SIGQUIT, SIGTERM, etc.):
- ExUnit leverages this to display running tests when interrupted
- Essential for long-running script management
- Includes safety warnings against library misuse

### 2. Erlang/OTP 24 Integration (Major)

v1.12 provides tight integration with Erlang/OTP 24's capabilities and expects this as the minimum version:

**Require Erlang/OTP 22+** - Official minimum version bump removes legacy compatibility layers and allows for more aggressive optimizations.

**Extended Error Information (EEP 54)** - Erlang/OTP 24 provides detailed error context for standard library functions:
- ArgumentError now shows which specific argument failed and why
- Dramatically improved debugging experience for Erlang interop
- Integration committed across exception handling and error reporting

**JIT Compilation** - While transparent to developers, v1.12 is built to leverage Erlang/OTP 24's JIT compiler:
- Performance improvements across evaluation and execution
- Code evaluation optimizations for REPL and dynamic code

**Rebar3 Default** - Rebar2 incompatibility with OTP 24 forces migration:
- Mix defaults to Rebar3 (since v1.4, so minimal breaking impact)
- Removal of old Rebar v2 support code

### 3. Stepped Ranges (Major Language Feature)

Introduction of `first..last//step` syntax resolves a long-standing limitation:

**Before:**
- Ranges could only be created with implicit direction inference
- `1..0` creates a decreasing range with two elements, not empty
- No explicit control over step size

**After:**
- Explicit `1..10//2` creates ranges with specific steps
- Solves the empty range problem elegantly
- Negative steps for decreasing ranges: `10..1//-1`
- Soft deprecation of implicit decreasing ranges signals future improvements

**Implementation scope:** Range modifications include `Range.new/3` and `Range.size/1`, plus fixes to `Range.member?/2` for edge cases.

### 4. Comprehensive Standard Library Expansion

v1.12 adds 25+ new functions across multiple modules, showing a maturing standard library:

**Enum Module Enhancements:**
- `Enum.count_until/2,/3` - Early termination for counting large sequences
- `Enum.product/1` - Calculate product of numeric collections
- `Enum.zip_with/2,/3` - Flexible zipping with custom functions
- `Enum.zip_reduce/3,/4` - Combine zipping with reduction patterns
- Support for functions in `Enum.with_index/2` mapper argument

**Kernel Module Utilities:**
- `Kernel.tap/2` - Execute side effects in pipelines without changing value
- `Kernel.then/2` - Convenient chaining in pipelines
- Both designed specifically for ergonomic pipeline patterns

**Numeric Functions:**
- `Integer.pow/2,/extended_gcd/2` - Bitwise and mathematical operations
- `Float.pow/2` - Floating-point exponentiation
- `Tuple.sum/1,product/1` - Aggregate operations on tuples

**I/O and System:**
- `IO.stream/0,binstream/0` - Convenient defaults for STDIO operations
- `System.shell/2` - Shell command invocation with proper interpretation
- `List.first/1,last/1` - Default value support for safer operations

**String and URI:**
- `:turkic` mode for Unicode case operations
- Unicode 13.0 support
- RFC3986 compliant URI query encoding/decoding via `:rfc3986` option

**Registry and Metadata:**
- `Registry.values/3` - Key-pid pair value retrieval
- `:compression` option for Registry tables
- Date and DateTime range enhancements with `Date.range/3` steps

**Code Analysis:**
- `Code.cursor_context/2` - IDE/editor support for context-aware completions
- `Module.reserved_attributes/0` - Introspection of language-reserved attributes
- `Module.get_definition/2,delete_definition/2` - Definition manipulation

### 5. Extensive Optimization Work

The Enum module received particular attention with performance optimizations for common operations:

- `Enum.unzip/1` - Specialized list handling
- `Enum.join/3` - List optimization
- `Enum.intersperse/2` - Reduced allocations
- `Enum.scan/2,/3` - Improved iteration
- `Enum.dedup/1` - Optimized comparison
- `Stream.zip,zip_with` - List-specific fast paths
- `String.codepoints` - Unicode handling acceleration
- `String.valid?` - Validation performance
- `List.last/1` - O(n) operation improvement

These systematic optimizations indicate investment in common-path performance rather than major algorithmic changes.

### 6. Error Messages and Developer Experience

Significant effort on error reporting and compiler diagnostics:

- **Erlang/OTP 24 Integration:** Show detailed error info from Erlang functions
- **Improved Messages:** Better explanations for common mistakes:
  - Expressions after keywords
  - Unused type variables
  - Invalid characters after numbers
- **Compiler Diagnostics:** Translation of Erlang compiler errors to Elixir diagnostics
- **ExUnit Enhancements:** Faster doctest compilation, better error messages, SIGQUIT interception

### 7. Breaking Changes

**Hard Removals:**
- `Integer.to_string/1` and `Integer.to_charlist/1` - These functions are simple wrappers and were likely considered redundant (requires explicit `Integer.to_string(n, 10)` pattern instead)
- `Range.empty?/1` - Made obsolete by stepped ranges
- `Enum.zip_reduce_while/4` - Functionality available via `Stream.zip + Enum.reduce_while`

**Hard Deprecations (will generate warnings):**
- `^^^` operator in favor of `Bitwise.bxor/2` - Clearer naming convention
- `@foo()` in favor of `@foo` - Simpler syntax for attribute access
- `System.stacktrace/0` - Increasingly unreliable with modern debugging

**Compiler Deprecations:**
- `:xref` compiler option - Unused in modern Mix workflows

**Soft Deprecations (future warnings):**
- Implicit decreasing ranges (`10..1`) - Explicit steps coming
- Range pattern matching on `first..last` - Will require `first..last//step` syntax

**Minimum Requirements:**
- Erlang/OTP 22+ now required (was 20+)

### 8. ExUnit and Testing Improvements

Testing infrastructure received notable enhancements:

- **SIGQUIT Interception:** `Ctrl+\` now shows list of running tests before abort
- **Async vs Sync Timing:** Report breakdown of async and sync execution time
- **Faster Doctests:** ~2x compilation speedup for documentation tests
- **Async Support:** `ExUnit.async_run/0` and `ExUnit.await_run/1` for programmatic test execution
- **Better Diffs:** Interpolated module attributes in assertion diffs
- **Module Attributes:** `@tag tmp_dir` now creates absolute paths

### 9. IEx Interactive Mode Enhancements

Several ergonomic improvements for interactive development:

- **Configurable Parser:** Support for custom IEx commands and extensions
- **Function Signatures:** Tab completion shows function signatures after opening parens
- **Auto-piping:** Binary operators like `|>` at expression start auto-pipe previous result
- **Remote Shell:** Fixed auto-completion in remote shell sessions

### 10. Mix Task Improvements

- **mix compile.erlang:** Parallel file compilation for faster Erlang builds
- **mix release:**
  - `RELEASE_PROG` environment variable for executable name
  - `remote.vm.args` support for customizing VM boot
  - Improved compatibility with minimal Linux installations
  - File mode preservation for non-beam files
- **mix test:**
  - Smarter `--failed` flag handling (resets if no failures)
  - Better workflow for iterative testing
- **mix escript.build:** Deep merge configuration, runtime.exs enhancements
- **Debug Support:** Task timing with `MIX_DEBUG=1`

### 11. Code Formatting and Parsing Improvements

- **Interpolation Handling:** No extra newlines around string interpolation
- **Keywords in Access:** Don't add unnecessary brackets for keyword access syntax
- **Multiline Pipe Expressions:** Copy-paste from IEx now works correctly for piped expressions
- **Binary and Map Guards:** Complex guards no longer crash the compiler
- **Heredoc Improvements:** Support nested heredocs, preserve CRLF

### 12. Documentation and Compliance

- **Calendar.ISO:** Support for basic datetime format parsing
- **EEP48 Alignment:** Undocumented public functions now appear as empty maps instead of `:none`
- **Improved Docstrings:** Better documentation for edge cases (ranges, operators, pipes)
- **EEx:** New `c:EEx.Engine.handle_text/3` callback with metadata

## Performance Characteristics

v1.12 shows a systematic approach to performance:

1. **Evaluation Performance:** Erlang/OTP 24 leverages faster code evaluation
2. **List-Specific Optimizations:** Fast-path implementations for common list operations
3. **Stream Improvements:** Parallel zip operations and optimizations
4. **String Operations:** Codepoint and validity checking speedups
5. **Compilation:** Parallel Erlang compilation support

No major algorithmic improvements, but rather consistent optimization of frequently-used functions.

## Migration Guide Summary

**For Most Users:**
- Update to Erlang/OTP 22+ (recommended 24+)
- Run `mix local.rebar` if using dependencies with Rebar
- No code changes required for most projects

**For Scripts Using Ranges:**
- Start explicitly using `//` operator: `1..10//2` or `10..1//-1`
- Future versions will warn on implicit direction inference

**For Script Developers:**
- Consider adopting `Mix.install/2` for dependency management
- Use `System.trap_signal/3` for graceful shutdown handling

**Deprecated Functions:**
- Replace `Integer.to_string/1` calls with explicit `Integer.to_string(n, 10)`
- Replace `^^^` with `Bitwise.bxor/2`
- Replace `@foo()` with `@foo`
- Remove `:xref` compiler option if present

## Architectural Impact

v1.12 represents three strategic shifts:

1. **Scripting First:** Mix.install/2 and signal handling make Elixir competitive for automation tasks
2. **Erlang Integration:** Tight coupling with OTP 24 features raises the platform floor
3. **API Maturity:** Systematic expansion of standard library with pipeline-friendly functions indicates stable, production-ready libraries

The release is conservative in scope but strategic in direction, building on established foundations rather than introducing major new paradigms.
