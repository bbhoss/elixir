# Changes from v1.13.0 to v1.13.1

## Release Overview

- **v1.13.0 Release Date**: December 3, 2021
- **v1.13.1 Release Date**: December 14, 2021
- **Duration**: 11 days
- **Total Commits**: 17 (including release commit)

## Summary

v1.13.1 is a patch release focused primarily on bug fixes and stability improvements following the v1.13.0 release. The release addresses critical issues across multiple subsystems including string handling, async streams, CLI argument parsing, and error message formatting. Additionally, the release includes a significant decision to reverse a previously planned deprecation of `URI.parse/1`, indicating community feedback influenced the release priorities.

The patch demonstrates the Elixir team's commitment to rapid iteration and addressing regressions discovered in the initial v1.13.0 release. Key improvements focus on correctness and reliability rather than new features.

## Major Features & Improvements

### 1. Async Streams Concurrency Fix
**Commit**: `8afac93a05` - Ensure async streams can be consumed from a separate process

This is a critical improvement to the Task/async stream functionality. The fix ensures that asynchronous streams created via `Task.stream` can be safely consumed from processes other than the one that created them. This was a significant limitation that would have restricted the use of async streams in common patterns where stream consumption might happen in a different context.

**Impact**: Enhances the flexibility and usability of async streams in multi-process applications.

### 2. URI.parse/1 Deprecation Reversal
**Commit**: `a0b77bd884` - Do not deprecate URI.parse/1

This commit reverses a deprecation of the `URI.parse/1` function that was introduced in v1.13.0. The function was overhauled but kept available to ensure backward compatibility. This decision reflects community feedback and pragmatism about the importance of maintaining stable APIs.

**Impact**: Ensures backward compatibility and removes uncertainty for users upgrading to v1.13.x.

### 3. Macro Output Formatting Improvements
**Commit**: `b725b8c055` - Set a max line_length for Macro.to_string (#11471)

This improvement addresses long macro output formatting by introducing a maximum line length parameter to `Macro.to_string/2`. This makes the output more readable and prevents extremely long lines in generated code representations.

**Impact**: Better developer experience when inspecting or working with macro expansions.

### 4. Protocol Consolidation Caching
**Commit**: `ebb347a34e` - Make protocol consolidation part of the Mix.install cache

This optimization improves the performance of `Mix.install` by including protocol consolidation in the caching mechanism. This reduces startup time for scripts that use `Mix.install`.

**Impact**: Faster script execution for users relying on `Mix.install`.

### 5. Type Specification Improvements
**Commit**: `cbba61a386` - Specific base typespecs (#11449)

Minor improvement to typespec definitions for base-related operations, improving type precision in the standard library.

**Impact**: Better type checking and IDE support for base conversion functions.

## Bug Fixes

### 1. Improper List Handling in apply/2
**Commit**: `edafcc4e9a` - Handle improper lists on apply, closes #11465

Fixes a critical issue where improper lists (lists that don't end in `[]`, such as `[1 | 2]`) were not properly handled by the `apply/2` function. The fix adds proper error handling in the Exception module.

**Impact**: Prevents crashes when improper lists are inadvertently passed to apply operations.

### 2. String.slice/3 Byte Counting Error
**Commit**: `31e24b3a12` - Fix codepoint byte counting in slice, closes #11461

Fixes an off-by-one error in `String.slice/3` where codepoint byte counting was incorrect. This caused incorrect string slicing behavior with multi-byte UTF-8 characters.

**Impact**: Correct string slicing for non-ASCII characters.

### 3. CLI Version Flag Behavior
**Commits**: `2efc1e5cac`, `d3b38fb472` - Make sure --version flag halts elixir and iex, closes #11453

Two related commits addressing the `--version` flag not properly halting the Elixir and iex processes. The commits update both shell scripts (`bin/elixir`, `bin/elixir.bat`, `bin/elixirc`, `bin/elixirc.bat`) and the CLI parser in `Kernel.CLI`.

**Impact**: Ensures version flag works correctly and doesn't hang processes.

### 4. Module Attribute List Formatting
**Commit**: `233fc09e67` - Fix formatting of lists in module attributes (#11462)

Fixes incorrect formatting of list literals in module attributes (e.g., `@attr [1, 2, 3]`). The normalizer was not properly handling list formatting in this context.

**Impact**: Correct AST normalization and code generation for module attributes.

### 5. Error Message Handling for Empty Lines
**Commit**: `47171d934d` - Change approach: never show error if line is empty (#11466)

Improves error message display by preventing error messages from being shown when the source code line is empty. This avoids confusing error output when the actual problematic code isn't visible.

**Impact**: Clearer, less confusing error messages for users.

## Breaking Changes

**None identified**. This is a standard patch release that maintains full backward compatibility with v1.13.0. The reversal of the `URI.parse/1` deprecation actually *removes* a potential breaking change that was introduced in v1.13.0.

## Notable Commits Worth Highlighting

### Critical Stability Fixes

1. **String Slicing Fix** (`31e24b3a12`) - Any application using `String.slice/3` with non-ASCII characters would have produced incorrect results. This is a correctness-critical fix.

2. **Async Streams Concurrency** (`8afac93a05`) - Enables a common concurrency pattern that was previously broken. This directly impacts applications using `Task.stream`.

3. **Improper List Handling** (`edafcc4e9a`) - Prevents crashes in edge cases. While less common, improper lists can occur in metaprogramming scenarios.

### Strategic Decisions

4. **URI.parse Deprecation Reversal** (`a0b77bd884`) - Shows responsiveness to community feedback. The complete rewrite of URL parsing while maintaining the original API demonstrates good API stewardship.

5. **Protocol Consolidation Caching** (`ebb347a34e`) - A small but meaningful optimization for `Mix.install` users, who benefit from reduced script startup times.

## Conclusion

v1.13.1 serves as a polishing release for v1.13.0, addressing several important bug fixes and stability issues. The patch demonstrates active maintenance and responsiveness to edge cases and community concerns. While not a feature release, the fixes (especially around string handling and async streams) are important for production stability.

The decision to reverse the `URI.parse/1` deprecation shows pragmatism in API design—maintaining stability and minimizing upgrade friction. Overall, this is a recommended upgrade for all v1.13.0 users, particularly those using async streams or non-ASCII string operations.
