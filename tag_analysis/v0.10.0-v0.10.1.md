# Changes from v0.10.0 to v0.10.1

## Release Overview

**Release Date Range:** July 15, 2013 (v0.10.0) to August 3, 2013 (v0.10.1)
**Total Commits:** 232 commits over 19 days
**Release Type:** Maintenance and feature release

This release focused on enhancing the capture syntax, introducing new standard library functions, improving Mix's dependency management and Windows compatibility, and refactoring core protocol handling. The high commit velocity reflects active community engagement with numerous bug fixes and documentation improvements.

---

## Summary of Key Themes

This release demonstrates Elixir's continued evolution through several interconnected themes:

1. **Capture Syntax Enhancement** - The most significant theme, expanding the capture mechanism (`&`) from simple partial application to a general-purpose mechanism supporting local functions, remote functions, and even macro invocations.

2. **Standard Library Expansion** - Strategic additions to core modules (String, Enum, List) that address common use cases without major breaking changes.

3. **Mix Build System Improvements** - Refined dependency management, better Windows support, and new command capabilities.

4. **Protocol System Refinement** - Architectural improvements to protocol definitions for better code organization and introspection.

5. **Windows Compatibility** - Deliberate focus on cross-platform consistency, fixing shell escaping issues and path handling.

6. **Stabilization & Bug Fixes** - 62 bug fix commits addressing issues in Stream composition, String validation, Regex normalization, and IEx parsing.

## Major Features & Improvements

### 1. Capture Syntax Evolution

The capture operator (`&`) underwent significant enhancement, becoming more powerful and flexible:

- **`&local/arity` and `&Remote.fun/arity` syntax** - Direct function references as atoms, providing a cleaner alternative to lambda syntax for simple function forwarding. This is a fundamental improvement to code expressiveness.

- **`&()` as a general capture mechanism** - Introduced the ability to use `&()` to capture entire expressions, not just simple variable placeholders. This generalizes partial application.

- **Macro-aware captures** - Extended capture to work correctly with macros (closes #1534), ensuring consistency across different code forms.

- **`&1.foo` syntax support** - Allows field access within capture expressions, enabling composition patterns previously requiring explicit lambdas.

These changes make Elixir's capture syntax more consistent and powerful, reducing boilerplate for common functional programming patterns.

### 2. New Standard Library Functions

Strategic function additions enhance common operations:

- **`String.to_char_list/1` and `String.from_char_list/1`** - Explicit string-to-character-list conversions with comprehensive documentation. Addresses a common need in string processing and Erlang interop.

- **`String.reverse/1`** - Simple but essential string reversal function, complementing existing string operations.

- **`Enum.shuffle/1`** - Random shuffling of collections, useful for games, simulations, and randomized algorithms.

- **`List.keysort/2`** - Sorts a list of tuples by a specific key position, essential for working with structured data without converting to maps.

### 3. GenFSM Module Introduction

A significant addition to the standard library: the first version of `GenFSM.Behaviour`, providing Erlang/OTP's Finite State Machine abstraction to Elixir. This is a major feature for building state-based systems and protocols.

### 4. Protocol System Refinement

Breaking changes to protocol architecture for better design:

- **Split of `@protocol` attribute** - Separated into `@protocol` (protocol being implemented) and `@for` (module being extended), providing clearer semantics and better error messages.

- **`__impl__(:for)` introspection** - Added standardized way to query which module a protocol is implemented for, following Elixir's convention of `__info__` functions.

- **`@protocol` attribute in `defimpl`** - Allows protocol implementations to query which protocol they're implementing, improving meta-programming capabilities.

### 5. Mix Enhancements

Significant improvements to the build and dependency management system:

- **`mix cmd` task** - New command for executing shell commands within the Mix environment, useful for scripts and automation.

- **Dependency update refinement** - `mix deps.update` no longer updates all dependencies by default; requires explicit `--all` flag. This prevents accidental cascading updates.

- **Path dependency recompilation** - Ensured path dependencies are recompiled when needed during `mix deps.get`.

- **Manifest-based compilation** - Enhanced manifests for Erlang, Yecc, and Leex compilers to track dependencies more precisely, enabling faster incremental compilation.

- **Environment handling** - Explicit setting of environment before task execution, fixing issues with `MIX_ENV` not being properly propagated.

- **`umbrella: true` option** - Added support for umbrella projects in dependency specifications.

### 6. Windows Compatibility Overhaul

Multiple commits addressing Windows-specific issues:

- **elixir.bat improvements** - Fixed exclamation mark handling and ERL_LIBS path configuration using `-pa` flag instead of environment variables.

- **Shell escaping** - Proper handling of double quotes in shell commands on Windows.

- **Path normalization** - Windows home directory path normalization (closes #1462).

- **Test environment fixes** - Updated test suite to properly handle Windows-specific environment variable handling.

The focus on Windows support demonstrates commitment to cross-platform usability.

## Bug Fixes

### String Module Fixes

- **`String.contains?`** - Fixed to properly raise on non-string arguments instead of silent failures.

- **`String.starts_with?` and `String.ends_with?`** - Fixed edge cases in raising behavior for invalid arguments.

### Capture and Function Handling

- **Macro-aware capture** - Fixed capture operator to work correctly with macros (closes #1534).

- **Macro.to_string with `&`** - Fixed serialization of capture expressions.

- **Nested binaries in `Macro.to_string/1`** - Fixed incorrect handling of binary structures in macro-to-string conversion (closes #1522).

### Regex Improvements

- **Regex.scan/3 captures** - Normalized and enabled proper capture groups in regex scanning (closes #1526).

- **Regex documentation typos** - Fixed and clarified documentation examples.

### Stream Fixes

- **Stream composition bugs** - Fixed issues with composing Stream operations that were causing incorrect results.

### Code & Macro Handling

- **Shadowing warnings** - Fixed spurious shadowing warnings in case expressions with functions (closes #1524).

- **Local macro conflict detection** - Only raises on macro conflicts if the macro was previously defined, preventing false positives.

- **Invalid syntax samples** - Removed incorrect syntax examples from documentation.

### Mix & Build System

- **Manifest cleanup** - Fixed only deleting beam files with no corresponding source (closes #1440).

- **Compiler output in stacktraces** - Prevented internal compiler output from appearing in user-facing stacktraces.

- **IEx parser stalls** - Reduced cases where IEx parser could get stuck (closes #1443).

- **OptionParser** - Fixed bug where missing options appeared in the final result.

- **ExUnit server registration** - Fixed race condition when checking if ExUnit.Server is registered (closes #1472).

### IEx Improvements

- **Stacktrace reuse** - Fixed incorrect stacktrace reuse in IEx error handling (closes #1486).

### System Module

- **`System.halt/2` removal** - Got rid of a buggy/undocumented function that was causing issues.

### Record & Protocol Handling

- **Undocumented `Record.new(tuple)` feature** - Removed unsupported feature that was not documented.

- **Protocol error messages** - Improved error messages and renamed Protocol.UndefinedError keys for better clarity.

## Deprecations & Removals

### Deprecations

- **`function/1` and `function/3`** - Deprecated in favor of more explicit syntax. These were Kernel functions related to function specification and needed to be phased out.

### Removals

- **`Mix.Tasks.IEx`** - Removed in favor of simpler task handling mechanisms.

- **Old pre-0.10.0 deprecations** - Cleaned up code that had been deprecated before the 0.10.0 release, removing technical debt.

- **Hard-coded Mix project defaults** - Removed to allow for more flexible configuration.

### Behavior Changes

- **Atom syntax** - Properly treated `:<<>>`, `:[]`, and `::{}` as atoms rather than special forms, fixing parsing inconsistencies.

## Breaking Changes

### Protocol Implementation Architecture

The refactoring of `@protocol` and introduction of `@for` represents a **minor breaking change** for code that directly inspects protocol attributes:

```elixir
# Before: both attributes were `@protocol`
# After: clearer separation
defimpl MyProtocol for MyType do
  @for MyType        # What we're implementing for
  @protocol MyProtocol  # Which protocol we're implementing
end
```

Code relying on the old attribute names would need updating.

### Mix Dependency Update Behavior

`mix deps.update` no longer updates all dependencies by default. This is a **behavioral breaking change**:

```bash
# Before: Updated everything
mix deps.update

# After: Only updates specific deps, need explicit flag
mix deps.update some_dep
mix deps.update --all  # To get old behavior
```

This change prevents accidental widespread dependency updates but requires script updates.

### Macro Conflict Detection

Changed to only raise on local macro conflicts if the macro was previously defined. Code relying on the old behavior of always raising might be affected.
