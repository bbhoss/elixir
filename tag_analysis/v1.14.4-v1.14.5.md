# Changes from v1.14.4 to v1.14.5

## Overview

**Release Period**: April 3, 2023 to May 22, 2023 (49 days)
**Total Commits**: 9 commits (4 core functional changes + 3 release commits + 2 CI/infrastructure updates)

This is a patch release addressing several important bugs and compatibility issues discovered in v1.14.4, particularly around Erlang/OTP 26 support, deterministic code generation, and SSL verification improvements.

---

## Summary of Key Changes

v1.14.5 is primarily a bug fix and compatibility maintenance release for the v1.14.x series. The changes focus on three critical areas:

1. **Deterministic Code Generation**: Fixing non-deterministic behavior in map-to-Erlang AST conversion that could cause test flakiness
2. **Erlang/OTP 26 Compatibility**: Properly handling encoding configuration for the newly released OTP 26
3. **SSL/TLS Improvements**: Modernizing SSL certificate verification to use updated httpc APIs

These are targeted fixes that improve stability and compatibility without introducing new features. The release maintains backward compatibility while ensuring proper functioning with newer Erlang/OTP versions.

---

## Bug Fixes

### 1. Deterministic Map-to-Erlang AST Conversion
**Commit**: `2d71e7144b` (May 19, 2023)
**Scope**: Compiler (`lib/elixir/src/elixir_erl.erl`)

**Problem**: When converting Elixir maps to Erlang Abstract Syntax Tree (AST), the order of map fields was non-deterministic. Since `maps:to_list/1` doesn't guarantee any particular order, this meant that the same code could generate different AST representations across different runs or environments.

**Solution**: Added explicit sorting of map entries before conversion to AST using `lists:sort(maps:to_list(Map))`. This ensures that all maps are converted to the same AST representation regardless of internal map storage order.

**Impact**:
- Eliminates potential test flakiness in code generation tests
- Ensures reproducible builds and consistent compiler output
- Critical for systems relying on deterministic code generation (e.g., binary diff analysis, incremental compilation)

---

### 2. Erlang/OTP 26 Encoding Configuration
**Commit**: `0c1395c215` (May 18, 2023)
**Scope**: Elixir core (`lib/elixir/src/elixir.erl`)

**Problem**: Erlang/OTP 26 was released in May 2023 with changes to how encoding is handled. The previous approach of setting encoding for standard I/O no longer works as expected on OTP 26, causing issues with I/O handling during startup.

**Solution**: Added version detection (OTP >= 26) to conditionally skip the encoding setup on OTP 26, where the default binary mode is already applied:

```erlang
set_stdio_and_stderr_to_binary_and_maybe_utf8(OTP) when OTP >= 26 ->
   ok = io:setopts(standard_io, [binary]),
   ok;
set_stdio_and_stderr_to_binary_and_maybe_utf8(_OTP) ->
   %% Original behavior for OTP 23-25
```

**Impact**:
- Enables Elixir to work properly with Erlang/OTP 26
- Prevents I/O configuration errors on newer OTP versions
- Maintains backward compatibility with OTP 23-25

---

### 3. SSL/TLS Certificate Verification Improvements
**Commit**: `1b3f9f8d5c` (April 7, 2023)
**Scope**: Mix utilities (`lib/mix/lib/mix/utils.ex`)

**Problem**: The previous approach checked for `public_key:cacerts_get/0` to obtain system certificates for HTTPS verification. This API became problematic and was being replaced in newer OTP versions.

**Solution**: Updated to use the `httpc:ssl_verify_host_options/1` API instead, which is the official, forward-compatible way to handle SSL host verification:

```elixir
# Old approach
if Code.ensure_loaded?(:public_key) and function_exported?(:public_key, :cacerts_get, 0) do
  apply(:public_key, :cacerts_get, [])

# New approach
if Code.ensure_loaded?(:httpc) and function_exported?(:httpc, :ssl_verify_host_options, 1) do
  apply(:httpc, :ssl_verify_host_options, [true])
```

**Impact**:
- Uses official, standardized APIs for SSL verification
- Better forward compatibility with future Erlang/OTP versions
- Improved SSL/TLS handling in Mix (especially for dependency downloads)
- Updated TODO comment from "OTP >= 25" to "OTP >= 25.1" for future reference

## Infrastructure & Maintenance Updates

### CI/CD Improvements: Ubuntu Version Bump
**Commit**: `29067a0a7d` (August 8, 2022 - backported)
**Scope**: GitHub Actions workflows

**Changes**: Updated CI/CD pipelines from Ubuntu 18.04 to Ubuntu 20.04:
- `.github/workflows/ci.yml`
- `.github/workflows/notify.yml`
- `.github/workflows/release.yml`

**Reason**: Ubuntu 18.04 (Bionic Beaver) reached end of standard support and was deprecated in the GitHub Actions virtual environments.

**Impact**:
- Ensures CI/CD pipelines run on a actively maintained Ubuntu version
- Access to newer build tools and system libraries
- Better security posture for the CI environment

## Technical Themes

### 1. Erlang/OTP Compatibility
This release demonstrates Elixir's commitment to supporting new Erlang/OTP versions quickly. With OTP 26's May 2023 release, these fixes enabled Elixir 1.14 users to upgrade without breaking their applications.

### 2. Build Reproducibility & Reliability
The deterministic AST generation fix addresses a subtle but critical issue: non-determinism in build artifacts can make debugging harder, cause test flakiness, and create issues in CI/CD environments. This fix ensures consistent behavior across machines and runs.

### 3. Standards Compliance & Future-Proofing
Migrating from `public_key:cacerts_get/0` to `httpc:ssl_verify_host_options/1` shows a preference for official, supported APIs over undocumented ones. This reduces technical debt and ensures compatibility with future OTP versions.

## Recommendations

Users on v1.14.4 should upgrade to v1.14.5 if:
1. **They are using or planning to use Erlang/OTP 26**
2. **They have flaky tests related to code generation**
3. **They are using Mix for dependency management with HTTPS**

The release is particularly important for teams that have upgraded to Erlang/OTP 26 and experienced compatibility issues.
