# Changes from v1.2.2 to v1.2.3

## Release Overview

**Release Date**: January 31, 2016 - February 21, 2016
**Total Commits**: 16 development commits (plus 1 release commit)
**Duration**: 21 days
**Version Type**: Patch Release (Bug fixes and minor improvements)

## Summary

Elixir v1.2.3 is a patch release focused on fixing bugs and adding small enhancements discovered after v1.2.2. The release includes critical fixes for dependency resolution in Mix, improvements to Base64 encoding/decoding functionality, and various bug fixes in string handling and documentation. The changes emphasize stability and developer experience improvements rather than introducing new language features.

The main themes of this release are:
- **Dependency Resolution Fixes**: Addressing issues with optional dependencies in complex dependency trees
- **Base64 API Enhancement**: Adding support for ignoring whitespace in base64 decoding
- **Bug Fixes**: Fixing edge cases in string handling and correcting documentation
- **Developer Tooling**: New Mix utilities for dependency management

## Major Features and Improvements

### 1. Base64 Whitespace Handling Feature (Commits: 498057c51b, 6dc523074d, c3df6806b3)

A new option was added to `Base.decode64/2` to allow ignoring whitespace during decoding, which resolves issue #4186. This is a common requirement when dealing with base64-encoded data from various sources that may include formatting whitespace.

**What changed:**
- Added `:ignore` option to `Base.decode64/2` with support for `:whitespace` value
- Simplified and refactored padding rules to be more maintainable
- Comprehensive tests added covering various whitespace scenarios
- Documentation updated with examples of the new ignore parameter

**Impact**: Developers can now easily handle base64 data with embedded whitespace without pre-processing, improving the standard library's usability for real-world data handling scenarios.

### 2. Mix.Project.deps_paths Addition (Commit: 56fbf2a399)

A new public API function `Mix.Project.deps_paths/0` was added to allow developers to programmatically access the paths where dependencies are installed.

**What changed:**
- New function added to `Mix.Project` module
- Returns a map of dependency names to their installation paths
- Includes tests demonstrating the functionality

**Impact**: Enables custom tooling and build scripts to query dependency locations without parsing configuration files, improving extensibility of Mix-based projects.

## Bug Fixes

### 1. Optional Dependency Resolution Fix (Commit: c3582f9617)

A critical bug in Mix's dependency resolver was fixed that caused failures when optional dependencies appeared in complex dependency graphs. The issue occurred when an optional dependency (like postgrex) was required by multiple parents with different optional dependency statuses.

**The Problem:**
```
parent
  * child
    * ecto
    * postgrex (optional)
  * ja_serializer
    * ecto
```

When postgrex was marked as optional by one parent but not required by another, the converger would prematurely reject the dependency, causing the dependency graph to fail topological sorting.

**The Fix**: Deferred the rejection of unfulfilled optional dependencies until later in the resolution process, allowing the resolver to first build a complete dependency graph and then intelligently prune optional dependencies.

**Impact**: Fixes a real-world issue where developers couldn't use libraries with optional dependencies in certain configurations, improving library compatibility.

### 2. String.replace_trailing Edge Case Fix (Commits: 75d679cdc8)

Fixed a bug in `String.replace_trailing/3` where the function would fail to properly handle cases when the entire string consisted only of the match pattern.

**The Problem:**
The guard clause used `when prefix_size > 0`, which prevented the function from handling the case when `prefix_size == 0` (i.e., when the entire remaining string matches the replacement pattern).

**Example cases that were broken:**
- `String.replace_trailing("t", "t", "")` should return `""` but failed
- `String.replace_trailing("aaaaaaaaaa", "a", "")` should return `""` but failed

**The Fix**: Changed the guard from `when prefix_size > 0` to `when prefix_size >= 0`, allowing the function to process the final match.

**Impact**: Ensures edge cases in string manipulation work correctly, improving reliability of text processing code.

### 3. ExUnit Assertions Documentation Fix (Commit: b3c26a8633)

Improved documentation in ExUnit helpers to clarify assertion behavior and usage patterns.

**Impact**: Better guidance for developers writing tests.

### 4. Code Generation Line Numbers Fix (Commit: 52dc944cfb)

Fixed handling of negative line numbers in code generation annotations, ensuring that the compiler properly validates line number metadata.

**What changed:**
- Added validation to prevent negative line numbers without appropriate generated/1 annotation
- Improves compiler robustness when dealing with macro-generated code

### 5. Unicode Cleanup (Commit: 2c9f28ecc3)

Removed outdated `debug_info` metadata from unicode data, reducing binary size and removing unnecessary debugging information.

## Documentation and Code Quality Improvements

### 1. Typespecs Table Formatting (Commit: bd83a45215)

Fixed the formatting of the Typespecs documentation table to properly display the `iolist()` type definition. The original table had a line break in the middle of a type definition, making it hard to read and potentially confusing.

**Original (broken):**
```
`iodata()`  | `iolist()` | `binary()`
`iolist()`  | `maybe_improper_list(byte()` | `binary()` | `iolist(), binary()` | `[])`
```

**Fixed:**
```
`iolist()`  | `maybe_improper_list(byte() | binary() | iolist(), binary() | [])`
`iodata()`  | `iolist()` | `binary()`
```

### 2. IEx Helpers Documentation (Commit: b3c26a8633)

Clarified documentation in IEx helpers to improve usability.

### 3. Canonical URLs for Documentation (Commit: 9dcc0e140b)

Added support for canonical URLs in the documentation generation system. The Makefile was updated to specify canonical URLs for generated documentation.

**What changed:**
- Added `CANONICAL := stable` variable to Makefile
- Updated documentation generation to include canonical URL parameter pointing to `http://elixir-lang.org/docs/stable/`
- Ensures search engines treat the "stable" version as canonical, improving SEO for documentation

**Impact**: Improves search engine optimization for the official Elixir documentation.
