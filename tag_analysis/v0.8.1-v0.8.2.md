# Changes from v0.8.1 to v0.8.2

## Release Timeline
- **Release Date:** April 20, 2013
- **Date Range:** February 17, 2013 - April 20, 2013
- **Total Commits:** 151 commits

## Summary

The v0.8.1 to v0.8.2 release represents a significant evolution of Elixir's core systems, with major focus on improving the macro system, implementing comprehensive doctest support, enhancing the record system, and refining import/dispatch mechanisms. This was a 2-month development cycle that brought considerable improvements to code quality, testing infrastructure, and language consistency.

The release reflects a mature approach to language design: strengthening fundamentals (macro hygiene, import semantics), introducing powerful new features (DocTests), and streamlining APIs (deprecating older patterns in favor of cleaner syntax).

## Major Features and Improvements

### 1. ExUnit.DocTest - New Testing Framework
**Commits:** 0b0bbdee (initial implementation) through 7be936eb (Kernel conversion), spanning ~15+ commits

ExUnit.DocTest was introduced as a complete implementation for doctest support:
- **Initial Implementation:** Allows documentation examples to be tested as code
- **Exception Tracking:** Full support for testing code that raises exceptions
- **Dynamic Doctests:** Ability to define doctests dynamically
- **Kernel Conversion:** Comprehensive doctest conversion of the entire Kernel module (~800+ test examples)
- **Configuration Options:** Added `import:` option to doctests (default: false) for flexible module context
- **Enhanced Error Reporting:** Better line number reporting and expression capture for failed tests
- **Special Output Handling:** Support for testing code that produces standard output

**Impact:** This was a major feature that improves documentation-driven development and ensures examples in documentation remain correct and executable. The fact that Kernel was fully converted to doctests shows confidence in the feature.

### 2. Macro System Hygiene Improvements
**Commits:** c125636 (imports hygiene), 531bd8d (direct calls), a4d8fc2 (function/partial applications)

Three critical commits strengthened macro hygiene:
- **Import Hygiene:** Fixed issue #875 - the macro system now properly respects import scoping
- **Direct Function Calls:** Ensured `Kernel.function` calls respect hygiene rules
- **Function/Partial Applications:** Extended hygiene to cover function references and partial applications (e.g., `is_atom/1`)

**Impact:** These changes prevent subtle bugs in macros where variables or functions could inadvertently shadow imported names, making metaprogramming more reliable and predictable.

### 3. GenEvent.Behaviour Implementation
**Commits:** 507fda5 (implementation), cfc21d0 (merge)

A new `GenEvent.Behaviour` was introduced, providing structured support for event handling behaviors in Elixir:
- Implements behavior specification for GenEvent handlers
- Enables more robust event-driven architectures

**Impact:** Provides standardized patterns for event handling in concurrent applications.

### 4. Record System Enhancements
**Commits:** 8d2034f (Record.import), ca456200 (Record.options), e01f958 (match syntax)

Major improvements to the record system:
- **Record.import Macro:** New macro allowing use of private macros on public records, improving encapsulation
- **Record.options:** Automatically generated function defining allowed options for each record
- **Match Syntax on Nested Records:** Added support for pattern matching on nested records (fixes #871)
- **Type Definitions:** Made record types public in addition to fields (@record_types)

**Impact:** Records became more flexible and easier to work with, especially for more complex use cases.

### 5. Sigil Enhancements - %w and %W with Modifiers
**Commits:** b82b51a (add support), d3238b8 (merge), 2c36d8f (runtime optimization)

New support for word sigils with return type modifiers:
- `%w` and `%W` sigils now support modifiers for different return types
- Runtime optimization to reduce work at runtime when processing words
- Enables more concise syntax for creating word lists with specific types

**Impact:** Provides a more consistent and flexible sigil system, aligned with other Elixir sigils.

### 6. Import System Refinement
**Commits:** a34f38e (ambiguous call errors), f859c9d (clarify semantics), ca0250a (dispatch refactoring)

Important fixes and improvements to import conflict handling:
- **Only Error on Calls, Not Imports:** Changed behavior - ambiguous imported function calls now raise errors, but the imports themselves don't (fixes #788)
- **Better Semantics:** Clarified import conflict semantics for users
- **Dispatch Optimization:** Refactored find_dispatch to loop functions and macros lists only once, improving performance

**Impact:** More intuitive and predictable import behavior, with better performance characteristics.

### 7. Unquote System Expansion
**Commits:** 01cc9ed (unquote fragments), 2817b2e (allow in def*/2), affc44d (closest quote), f9e74f9 (Macro.escape_quoted), ff825b8 (support in Macro.escape)

Multiple commits improving unquote capabilities:
- **Unquote Fragments:** Uncommented features related to unquote fragments
- **In Function Definitions:** Allow unquote in `def*/2` and similar constructs
- **Scope Resolution:** Fixed unquote to apply to the closest quote
- **Macro.escape_quoted:** New function instead of Macro.escape with options
- **Macro.escape Support:** Support unquoting on Macro.escape for dynamic macro generation

**Impact:** More powerful and flexible metaprogramming capabilities.

### 8. File and Path APIs
**Commits:** a8c89e3 (File.listdir), 27d9580 (File.listdir!), 4ad1ca3 (fix return), 1c2d419 (rename to ls), 34da5f8 (add tests), 4612877 (improve File.ls), e27707e (Path.t/Path.r)

New file listing and path type annotations:
- **File.listdir/File.listdir!:** New APIs for listing directory contents
- **File.ls/ls!:** Clean rename from listdir with improved implementation
- **Path Type Annotations:** Added `Path.t` (for input types) and `Path.r` (for output types)
- **Path.expand Fix:** Fixed bug in Path.expand

**Impact:** Cleaner APIs for file operations and better type documentation.

### 9. IEx Improvements
**Commits:** 3a98369 (split introspection), 8d6aa70 (make private), 81d406 (improve docs), 824168a (ANSI output), 07a228 (merge ANSI), ae6a51f (color changes), 5a84ac (pwd/cd helpers)

Multiple enhancements to the interactive shell:
- **Introspection Module:** Split IEx introspection functions into dedicated IEx.Introspection module
- **Helper Functions:** Made h/2, h/3, s, and t helpers private
- **ANSI Output:** ANSIified helper output for colored text
- **Result Colors:** Changed the color of result printouts
- **Shell Navigation:** Added pwd and cd helpers
- **ANSI Documentation Fix:** Fixed h helper to not render ANSI codes in documentation, making IO.ANSI docs readable

**Impact:** Better interactive experience with cleaner organization and visual improvements.

### 10. ExUnit Enhancements
**Commits:** 8a58722 (ANSI formatter), 24ca9c0 (user config warning), 6a24bc4 (elapsed times), 179b18a (cover support), 01d7e21 (cover tests fix)

Testing framework improvements:
- **ANSI Formatter:** Colorized ExUnit output for better readability
- **User Config Validation:** Warnings for invalid user configuration with sensible defaults
- **Elapsed Times:** Display elapsed times for test runs
- **Cover Support:** Added test coverage support to Mix.Test

**Impact:** Richer feedback during testing and better coverage analysis.

### 11. Tuple/List Element Operations
**Commits:** 0fad188 (insert_elem/delete_elem), 728d08c (revert split_while), 1ffda62 (split_with)

New tuple operations and enum fixes:
- **insert_elem/3 and delete_elem/2:** New functions for manipulating tuple elements
- **setelem Deprecation:** Old `setelem` deprecated in favor of `set_elem` (consistency)
- **split_with vs split_while:** Fixed Enum.split_while API - now correctly provides Enum.split_with

**Impact:** Cleaner, more consistent API for tuple manipulation.

### 12. Kernel Improvements and Deprecations
**Commits:** f2e78d3 (function syntax deprecation), de06764 (apply as macro), 7b9f2bd (deprecate old sigils), 0c50664 (deprecate :+.() syntax)

Streamlining and modernization:
- **Function Call Syntax:** Deprecated old `function(:is_atom, 1)` in favor of `function(is_atom/1)`
- **apply as Macro:** Changed apply to be a macro for better metaprogramming
- **Old Sigil Deprecation:** `{}`, `[]` and similar are now purely deprecated
- **Atom Function Calls:** Deprecated `:+.()` style calls in favor of function references

**Impact:** Language modernization, moving towards cleaner, more consistent syntax.

### 13. Error Messages and Documentation
Multiple commits improving user experience:
- **Better Error Messages:** Improved messages for common mistakes:
  - Grammar mistakes in `else do` blocks (#888)
  - Unclosed string/interpolation (#794)
  - Invalid bit string comprehension generators
  - Deadlock detection with helpful hints
- **Documentation Improvements:** Various doc improvements across multiple modules
- **Record Documentation:** Added documentation on `@record_fields` and `@record_types` attributes

**Impact:** Better developer experience with clearer error messages and documentation.

## Breaking Changes

1. **Kernel Function Call Syntax:** `function(:is_atom, 1)` is now deprecated in favor of `function(is_atom/1)`. While not immediately breaking, code using the old syntax is now deprecated.

2. **Old Sigil Syntax:** `{}`, `[]` and similar are now purely deprecated.

3. **Atom Function Calls:** `:+.()` style calls are deprecated - use function references like `&+/2` instead.

4. **setelem Deprecation:** Use `set_elem` instead of deprecated `setelem`.

5. **Enum.split_while Reversion:** This function was reverted and Enum.split_with is now the recommended function for the intended behavior.

6. **IEx Helper Functions:** h/2, h/3, s, and t are now private - direct usage in code would no longer work.

## Technical Analysis

This release showed Elixir's focus on:

1. **Metaprogramming Safety:** Heavy investment in macro hygiene and proper scoping
2. **Testing Infrastructure:** Introduction of DocTest represents a shift toward documentation-driven testing
3. **API Consistency:** Deprecating old patterns (function syntax, atom calls, sigils) in favor of consistent modern approaches
4. **Developer Experience:** ANSI colors, better error messages, improved help/documentation
5. **Feature Completeness:** Record system matured with import and options capabilities; Import system refined with better semantics

The 151 commits over 2 months represents focused, incremental development addressing fundamental language issues while introducing significant new features.
