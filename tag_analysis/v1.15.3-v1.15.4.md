# Changes from v1.15.3 to v1.15.4

## Overview

**Release Date:** July 15 - July 18, 2023
**Commit Count:** 6 commits (excluding release commit)
**Release Type:** Patch Release

This is a focused patch release addressing several bugs, improving compatibility with Erlang/OTP 26, and fixing documentation issues across multiple components.

## Summary

v1.15.4 is a maintenance release that builds on the v1.15.3 foundation with a concentrated focus on stability improvements and documentation fixes. The release addresses critical issues in the Mix compiler's dependency handling, improves the archive building process, and enhances compatibility with Erlang/OTP 26. The remaining changes focus on documentation cleanup and removing redundant examples.

## Key Themes

1. **Bug Fixes in Build System** - Focused fixes to Mix compiler and archive handling
2. **Documentation Improvements** - Cleaning up duplicates and fixing formatting
3. **Erlang/OTP 26 Compatibility** - Explicit support for OTP 26 features
4. **Code Quality** - Removing redundant examples and consolidating logic

## Major Improvements

### Mix Compiler Enhancement: Dependency-Level Remove Entries Tracking
**Commit:** `7ff97fb930` - "Compute remove entries per dependency, closes #12801"

This is the most significant change in this release. The fix reorganizes how the Elixir compiler tracks removed entries within the Mix build system. Previously, remove entries were computed globally, which could lead to incorrect handling when multiple dependencies were involved. This fix changes the logic to compute remove entries on a per-dependency basis, ensuring more accurate tracking and rebuilding.

**Impact:**
- More reliable incremental compilation in projects with multiple dependencies
- Fixes edge cases where dependency updates could cause unnecessary recompilation
- Particularly important for umbrella projects and complex build configurations

**Files Changed:** `lib/mix/lib/mix/compilers/elixir.ex` (116 lines refactored)

### Archive Installation: Consolidation Protocol Handling
**Commit:** `bdbdf52122` - "Disable consolidation on archive.install"

The archive build process is refined to disable protocol consolidation during archive installation. This prevents issues where archived code might inadvertently consolidate protocols, which could cause conflicts in the target environment.

**Impact:**
- Safer archive creation and installation workflow
- Prevents unexpected protocol consolidation side effects
- Better behavior when deploying archived Elixir applications

### Erlang/OTP 26 Support
**Commit:** `4fbed9fe12` - "Consider significant chunks from Erlang/OTP 26"

Updates the Mix release module to properly recognize and handle "significant chunks" from Erlang/OTP 26. This ensures that when users are running OTP 26, the build system respects the new artifact handling introduced in that version.

**Impact:**
- Full compatibility with Erlang/OTP 26
- Proper handling of OTP 26's enhanced release artifacts
- Future-proofs builds for users on the latest Erlang runtime

## Notable Commits Worth Highlighting

### 1. **Compute remove entries per dependency** (Most Important)
The refactoring of remove entry computation is the substantive technical change that addresses real user issues. This fix is particularly valuable for developers working with:
- Umbrella projects with interdependent applications
- Complex dependency graphs
- Projects relying on incremental compilation for fast iteration

### 2. **Erlang/OTP 26 Compatibility**
While a small change (2 lines), this is strategically important as OTP 26 introduces new release artifact handling. This ensures Elixir releases continue to work seamlessly across Erlang versions.

### 3. **Archive Installation Consolidation Handling**
This addresses a subtle but important issue in the deployment workflow. Archive consolidation is a powerful feature, but it should be controlled by the end user, not applied automatically during package creation.
