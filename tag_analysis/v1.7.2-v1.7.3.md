# Changes from v1.7.2 to v1.7.3

## Release Information

- **Release Date**: August 24, 2018
- **Date Range**: August 6 - August 24, 2018
- **Total Commits**: 4 (including release commit)
- **Functional Changes**: 3 bug fixes across 2 main areas

## Summary

v1.7.3 is a targeted bug fix release for Elixir v1.7. This is a patch release with minimal changes, focusing on resolving three critical issues that were discovered after v1.7.2 was released. The changes span two main areas: Mix dependency management and ExUnit assertion handling. These were relatively quick fixes to address regressions and edge cases in the v1.7 release cycle.

## Key Themes

The v1.7.3 release addresses issues in two distinct areas:

1. **Mix Dependency Management**: Refinement of how Mix handles runtime and application flags for dependencies, particularly those coming from Hex packages. This required adjusting the logic for reading these metadata values from `mix.exs` files.

2. **Elixir Core Functionality**: Fixes for the special form metadata and protocol compilation edge cases that could cause test failures and assertion errors.

## Bug Fixes

### Mix Component

#### 1. Dependency Runtime Flag Handling (#8109)
**Commit**: `af64fe7e98` (August 17, 2018)
**Files Modified**: 4 files (36 insertions, 51 deletions)
**Author**: José Valim

**Issue**: The Mix dependency compiler was incorrectly handling the `:runtime` and `:app` flags for dependencies. When dependencies were cached from Hex packages, these metadata values were not available, as Hex doesn't store this information. This caused the compiler to make incorrect assumptions about which applications should be included as runtime dependencies.

**Solution**: The fix changes the approach by traversing the `mix.exs` file directly to extract the `:runtime` and `:app` information from the original dependency declarations, rather than relying on the cached dependency information. This ensures that applications marked with `runtime: false` are properly excluded from being started as runtime dependencies for applications from Hex.

**Impact**: This is an important fix for users with optional dependencies or dependencies with specific runtime behavior. The change simplifies the dependency tracking logic and reduces unnecessary complexity in the dep test suite.

**Files Affected**:
- `lib/mix/lib/mix/dep.ex`: Core dependency logic
- `lib/mix/lib/mix/tasks/compile.app.ex`: App compilation task
- `lib/mix/lib/mix/tasks/deps.ex`: Dependency listing task
- `lib/mix/test/mix/dep_test.exs`: Test suite

#### 2. Protocol Consolidation Race Condition
**Commit**: `d38a189907` (August 6, 2018)
**Files Modified**: 1 file (10 insertions, 4 deletions)
**Author**: José Valim

**Issue**: During protocol consolidation (the compile-time optimization of protocol implementations), the code was using protocols themselves, which created a race condition in the test suite. This manifested as intermittent test failures due to timing issues.

**Solution**: The fix modifies the protocol consolidation task to avoid using protocols during the consolidation process itself. This eliminates the circular dependency and race condition.

**Impact**: This fix improves the stability of the test suite and compilation process, particularly for projects with many protocols or in CI environments with high concurrency.

**Files Affected**:
- `lib/mix/lib/mix/tasks/compile.protocols.ex`: Protocol compilation task

### Elixir Core

#### 3. Try/1 Arity Declaration Fix (#8079)
**Commit**: `28cf40fe03` (August 14, 2018)
**Files Modified**: 1 file (1 insertion, 1 deletion)
**Author**: Fernando Tapia Rico
**Signed-off by**: José Valim

**Issue**: The `try/1` special form had an incorrect arity declaration in the `:elixir_import` module. This caused issues with ExUnit assertions when they attempted to expand `try/1` incorrectly, leading to assertion failures.

**Solution**: A simple one-line fix correcting the arity metadata for the `try/1` special form.

**Impact**: This is a minimal but critical fix that prevents ExUnit from mishandling `try/1` in assertion expansions. The fix ensures that exception handling code within assertions works correctly.

**Files Affected**:
- `lib/elixir/src/elixir_import.erl`: Special form metadata definitions
