# Changes from v1.9.4 to v1.10.0

## Overview

This release spans from **June 3, 2019 to January 27, 2020** with **619 commits** introducing substantial improvements across the entire Elixir ecosystem. Version 1.10.0 represents a major release with significant enhancements to the language runtime, libraries, and developer tooling.

## Key Statistics

- **Total Commits**: 619
- **Date Range**: June 3, 2019 – January 27, 2020 (approximately 8 months)
- **Bug Fixes**: ~75 commits
- **New Features/Additions**: ~102 commits
- **Deprecations**: 14 commits
- **Release-related Changes**: 38 commits
- **Documentation Improvements**: 150+ commits

## Major Themes and Changes

### 1. Logging Infrastructure Overhaul

One of the most significant changes in this release is the complete overhaul of the logging system. The Elixir logger was refactored to use **Erlang's native logger** as its main implementation rather than building on top of Erlang's error_logger.

**Key Commits:**
- `67dec4683d` - Use Erlang's logger as main logging implementation (#9333)
- `71caf1f599` - Remove calls to error_logger (#9469)
- `620ed20210` - Fix: do not log that logger application is stopping (#9468)
- `4d0ccc7545` - Translate logger level on startup (#9466)
- `9e8749b7c6` - Allow start_options to be configured on Logger (#9438)

**Impact**: This modernizes Elixir's logging to align with Erlang/OTP 21+ standards, improving reliability and enabling better integration with Erlang's logging system. This is a significant architectural change that improves logging performance and consistency across the Erlang ecosystem.

### 2. Enhanced Release Tooling

Multiple improvements were made to `mix release`, making it more flexible and robust for production deployments:

**Key Features:**
- Support for **overlays in releases** (#9651) - allowing customization of release artifacts
- **:tar option for releases** to create tarballs (#9290)
- **MIX_DEPS_PATH environment variable** for setting :deps_path (#9301)
- Ability to **disable reboot in releases** (#9552)
- Support for **releases as anonymous functions**
- Fixed issues with ERTS copying and release configuration files
- Made release boot scripts **deterministic** (#9387)

**Impact**: These changes significantly enhance the flexibility and reliability of Elixir's built-in release tooling, reducing the need for third-party solutions like Distillery.

## Major Features Worth Highlighting

### Erlang Logger Integration
The migration to Erlang's native logger is a watershed moment, improving integration with Erlang/OTP ecosystems and leveraging modern logging capabilities built into recent Erlang versions. This removes the legacy error_logger dependency and aligns with industry best practices.

### Mix Release Enhancements
With overlays, tarball support, and more configuration flexibility, Elixir's built-in release tooling becomes more competitive with external tools, reducing operational complexity for deployments.

### Enumerable Improvements
New functions like `frequencies/1`, `map_intersperse/3`, and enhanced `sort/2` with comparison functions make Elixir more expressive for common data manipulation tasks, reducing boilerplate code.

### Compiler Tracing and Profiling
The introduction of compiler tracing and profiling capabilities enables developers to optimize and understand their build processes better, crucial for large codebases.

### Struct Pattern Matching
Support for struct patterns in matching expressions makes code more elegant and type-safe when working with structured data.

## Breaking Changes

While most changes are backward compatible, there are some notable deprecations and behavioral changes:

1. **Logger Configuration** - Projects using custom logger configurations may need adjustments due to the Erlang logger migration
2. **error_logger Removal** - Code relying on error_logger functions is deprecated
3. **Mix.Task.Compiler API** - Change from `after_compile/1` to `after_compiler/2`
4. **Deprecations**:
   - `Code.ensure_compiled?/1` - use `Code.ensure_compiled/1` with pattern matching
   - `System.get_pid/0` - OS-specific PID access is deprecated
   - `Mix.Config.persist/1` - documented as soft deprecated
   - Keyword and Map API changes for pop operations

5. **Release Configuration** - Some configuration options for releases may have changed or been reorganized

## Summary

Elixir v1.10.0 represents a mature and well-rounded release that strengthens both the language core and its ecosystem. The shift to Erlang's native logger aligns Elixir with modern OTP practices, while enhanced release tooling and improved standard library functions make the language more practical for production systems. The introduction of compiler tracing, improved error messages, and better pattern matching support demonstrate a commitment to developer experience and code quality. The extensive CI/CD infrastructure improvements signal a professional approach to quality assurance and release management. This release solidifies Elixir's position as a modern, pragmatic language for building scalable, maintainable systems.
