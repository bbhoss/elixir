# Changes from v0.14.2 to v0.14.3

**Release Date:** 2014-07-12
**Previous Release:** v0.14.2 (2014-06-29)
**Duration:** 13 days
**Total Commits:** 160

## Summary

v0.14.3 represents a continuation of the rapid iteration cycle from early Elixir development, introducing a significant number of enhancements, bug fixes, and breaking changes. This release focuses on improving the standard library with new utility functions, enhancing the Mix build system with better tooling, and refining language semantics around records, typespecs, and error handling. The release demonstrates a commitment to performance optimization (particularly for String operations) and cleanup of the API surface (deprecating older patterns in favor of modern approaches).

## Major Features and Improvements

### 1. **Record System Enhancements**

The record system received substantial improvements with better support for typespecs and field access:

- **Typespec Support:** Records can now be used in typespecs with new `record(:record, fields)` syntax, bringing them more in line with struct capabilities
- **Field Retrieval:** Added `record(some_record)` syntax to convert a record to a keyword list, making records more interoperable with the rest of the language
- **Compile-Time Optimization:** Added compile-time optimization to record field macros, reducing runtime overhead

This represents a maturation of the record system as the language moved toward eventual struct dominance.

### 2. **String Performance Optimization**

A critical performance improvement was made to `String.split/1`:

- **Native Implementation:** Replaced regex-based splitting with a native implementation, resulting in significant performance improvements
- **Cross-Platform Support:** Enhanced documentation and handling of Windows path splitting behavior
- **Addition of `String.chunk/2`:** New utility function for chunking strings (carried over from v0.14.2 context)

This optimization was important for early Elixir adoption, as string manipulation is a fundamental operation.

### 3. **Floating-Point Arithmetic Precision**

New precision parameters were added to floating-point functions:

- **`Float.ceil/1` and `Float.floor/1`:** Now accept optional precision argument for rounding to specific decimal places
- **Always Returns Floats:** These functions now consistently return floats (breaking change from returning integers in some cases)
- **Improved Documentation:** Enhanced docs with examples and performance notes

### 4. **New Enumeration Utilities**

- **`Enum.sort_by/3`:** Added three-argument version of sort_by with custom comparison function support
- **Improved `Enum.join/2` Performance:** Used iolists internally for better performance (from v0.14.2 carry-over)

### 5. **Mix Build System Improvements**

Several critical improvements to Mix tooling:

- **`Mix.compilers/0`:** New function returning all default compilers used by mix tasks, enabling better introspection
- **Task Aliases:** Support for aliases in `Mix.Task.run/2`, allowing custom task shortcuts
- **File Monitoring:** Issue warning and reset mtime for source files from the future to prevent stale compilation
- **Windows Symbolic Links:** Use absolute symbolic links on Windows for `_build` instead of copying files, saving disk space
- **Dependency Recompilation Fix:** Ensures dependencies are not unnecessarily recompiled on every invocation
- **Umbrella Project Fixes:** Fixed bug where umbrella project tasks were not properly re-enabled

### 6. **System Command Handling**

New `System.cmd/3` replaces older approaches:

- **`System.cmd/3`:** New function providing better control over system command execution
- **Exit Signal Handling:** Uses `exit({:shutdown, int})` pattern instead of raw integers for clearer semantics
- **Process Isolation:** Command line and escripts run in new process without trapping exits, improving error handling

### 7. **I/O Enhancements**

- **`IO.(bin)read` with `:all`:** Added support for reading entire device content with `:all` atom
- **Better IO Documentation:** Clarified behavior of various IO operations

### 8. **OptionParser Improvements**

- **`OptionParser.split/1`:** New function to split command-line strings into argv format
- **Boolean Switch Validation:** Now only accepts `--no-SWITCH` for declared boolean switches, preventing misuse
- **Cleaner Configuration:** Removed "keep all" behavior that was confusing

### 9. **Typespec and Type System Refinements**

- **Struct Typespecs:** Support `%Struct{}` syntax directly in typespecs (breaking change removed automatic `@type t` generation)
- **Shorthand Notation:** Added `nonempty_list()` shorthand syntax for `[non_empty_list()]`
- **Multiple Clause Defaults:** Function heads with multiple clauses must now have default arguments defined in the head itself (breaking change)
- **Improved Type Rendering:** Fixed rendering of `list` typespec that was incorrectly shown as `[]`

### 10. **Access Module Enhancements**

- **Function-Based Access:** `get_in/2` and `get_and_update_in/3` now accept functions for custom access logic
- **No Implicit Map Creation:** Breaking change—no longer fills in missing intermediate values with empty maps

### 11. **Sigil and Macro Improvements**

- **Sigil Preservation:** `Macro.to_string/1` now correctly displays sigils instead of expanding them
- **Escape Handling:** Fixed issue where interpolation escapes on uppercase sigils were incorrectly removed (e.g., `~S`)
- **Macro Expansion:** Allow expansion of local macros via `Macro.expand/2` for better metaprogramming

## Bug Fixes

### Critical Bug Fixes

1. **Flat Map Enumeration:** Fixed bug where `flat_map` used inside another `flat_map` with an Enumerable produced incorrect results
2. **Protocol Loading:** Fixed mix paths priority issue preventing proper protocol consolidation loading
3. **Inspect Loop Prevention:** Ensured `Inspect.Algebra.to_doc/2` doesn't infinite loop when printing structs with errors
4. **EEx Line Numbers:** Properly preserved line numbers in EEx template compilation
5. **Remote Call AST:** Fixed AST generation for remote function calls

### Important Fixes

- **Umbrella Task Re-enablement:** Fixed bug preventing proper re-enabling of tasks in umbrella projects
- **ANSI Escape Handling:** Fixed IEx clear command to respect ANSI sequence support detection
- **Regex Compilation:** Fixed regex compilation with proper Unicode support (ucp flags)
- **External Resources:** Ensure multiple `@external_resource` entries are properly read by Mix compilers
- **Defoverridable Functions:** Fixed spurious unused function warning for overridable functions
- **Guard Analysis:** Improved analysis of guards to give correct "evaluates to false/true" warnings
- **Windows Paths:** Fixed path handling on Windows with spaces in path to bin/mix
- **Struct Expansion Errors:** Better error messages when struct expansion is used in invalid contexts

### Documentation and Error Message Improvements

- **Docstring Validation:** Ensure `@doc` clauses without function definitions trigger warnings
- **Pipe Error Messages:** Improved error messages for pipe operation issues
- **Operator Table:** Fixed operator precedence table to use correct associativity for bitwise operators and comparison operators
- **Warning Clarity:** Warnings for underscored variables appearing twice in patterns for better code hygiene

## Breaking Changes

This release introduced several backward-incompatible changes requiring migration:

### 1. **Type System Changes**

- **Struct Type Removal:** `defstruct` no longer automatically generates a `@type t` definition. Users must explicitly define types.
- **Multiple Clause Default Arguments:** Functions with multiple clauses must define default values in the function head, not in the clause body

### 2. **Module Behavior Changes**

- **Access Implicit Values:** `get_in/2` and `get_and_update_in/3` no longer automatically create intermediate empty maps
- **Float Type Consistency:** `Float.ceil/2` and `Float.floor/2` now always return floats (previously could return integers)

### 3. **Command Execution Changes**

- **Exit Signal API:** Scripts must use `exit({:shutdown, integer})` instead of `exit(integer)` for proper exit code signaling
- **Escript Process Model:** Command line and escripts run in isolated processes without exit trapping for better error isolation

### 4. **Command-Line Parsing Changes**

- **Boolean Switches:** `--no-SWITCH` syntax now only allowed for explicitly declared boolean switches (previously more permissive)

### 5. **Build System Changes**

- **Archive Behavior:** `mix archive.build` now replaces old `mix archive` functionality; `mix archive` now lists installed archives instead
- **Shell Info ANSI:** `Mix.shell.info/1` no longer auto-escapes ANSI sequences (must use `ansi: true` option)

### 6. **Bitstring Syntax Change (Soft Deprecation)**

- **New Syntax Required:** Using lists for bitstring modifiers (e.g., `<<x :: [little, utf16]>>`) is soft deprecated in favor of `-` separator syntax (e.g., `<<x :: little-utf16>>`)

## Deprecations

### Formal Deprecations (with warnings)

- **Mix Tasks:**
  - `mix escriptize` → use `mix escript.build`
  - `mix local.install/uninstall` → use `mix archive.install/uninstall`
  - `:embed_extra_apps` in escripts → list dependencies in `def application`

- **System Functions:**
  - `System.find_executable/1` with char lists (use binaries instead)
  - `System.cmd/1` → use `System.cmd/3`

### Soft Deprecations (no warnings yet)

- Bitstring modifier list syntax: `<<x :: [little, utf16]>>` → `<<x :: little-utf16>>`
