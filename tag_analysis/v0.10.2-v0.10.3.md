# Changes from v0.10.2 to v0.10.3

**Release Date:** October 2, 2013
**Previous Version:** v0.10.2 (September 3, 2013)
**Commits:** 84 total commits
**Date Range:** August 21, 2013 - October 2, 2013

---

## Summary

This release represents a significant maintenance and improvement cycle for Elixir v0.10.x, focusing on robustness, documentation capabilities, and quality-of-life improvements for developers. The release introduced better type documentation support, improved error handling, important performance optimizations for Mix dependency compilation, and numerous bug fixes across the core libraries. While introducing four breaking changes, the release maintains a good balance between forward compatibility and necessary modernization.

The period between v0.10.2 and v0.10.3 shows Elixir moving toward more mature tooling and APIs, with attention to both compiler correctness and developer experience.

---

## Major Enhancements

### Type Documentation with @typedoc Attribute

A major addition in this release was the introduction of the `@typedoc` attribute, enabling developers to document their custom types directly in their source code. This mirrors the existing documentation capabilities for functions and modules. The implementation includes:

- New `@typedoc` attribute for documenting types
- New `Kernel.Typespec.beam_typedocs/1` function to retrieve type documentation from compiled modules
- Integration with Elixir's existing documentation infrastructure
- Proper storage of type documentation in BEAM files

This enhancement brings first-class documentation support to custom types, improving code discoverability and making APIs more self-documenting.

**Relevant commits:** `1be3335f0b`, `2f5afcaab9`, `262e8b5f22`, `c3bdfc9ba7`

### Stream.unfold/1

A new stream generation function was added, enabling the creation of potentially infinite streams through an unfold pattern. This is a common functional programming primitive for generating sequences based on an accumulator, similar to what appears in other languages' standard libraries.

**Relevant commit:** `7b1b0d93d8`

### Enum.take_every/2

A new enumeration function for selecting every nth element from a collection, providing a convenient way to sample or thin out sequences without manual accumulation logic.

**Relevant commit:** `307198c750`

### Mix Improvements

#### Default Supervision Tree in `mix new`

The `--sup` flag (supervisor) is now the default for new projects created with `mix new`. Users wanting the previous behavior (without a supervision tree) must now explicitly use the `--bare` flag. This change reflects a shift toward encouraging best practices in project setup.

**Relevant commit:** `3d583e7cdc`

#### App Selection in Umbrella Projects

Developers can now select specific applications within umbrella projects, improving the developer experience when working with monorepo-style projects.

**Relevant commit:** `d221e9a161`

### Record Enhancement: String and Atom Keys

Generated record functions (`new` and `update`) now accept both string and atom keys as options, providing flexibility in how records are initialized and updated. This enhancement includes safeguards:

- String and atom keys are normalized through the same lookup mechanism
- Mixed use of strings and atoms is explicitly disallowed to prevent ambiguity
- Proper error handling for invalid key usage

**Relevant commits:** `7649a5dba4`, `cc1d7c5823`, `e2be2579c5`

### IEx Improvements

IEx now properly respects signals sent from the `Ctrl+G` menu, improving terminal experience and allowing better control over the IEx process from the user interface.

**Relevant commit:** `b161d80b4c`

## Bug Fixes

### Critical Fixes

#### Kernel.raise as a Macro

A significant improvement to error handling: `Kernel.raise/2` was converted from a function to a macro. This prevents the macro itself from appearing in stack traces, giving developers cleaner and more accurate error diagnostics. This is particularly important for debugging complex error chains.

**Relevant commit:** `bcf8563d38`

#### Dict Equality Bug

Fixed a critical bug in `HashDict` comparison where a dictionary could be incorrectly marked as equal to another when it was actually a proper subset. This type of bug could lead to silent logic errors in applications relying on dictionary comparisons.

**Relevant commit:** `eff51e4045`

### String and Regex Improvements

- **String.split/2 with empty pattern:** Now correctly handles the edge case where an empty binary is used as the split pattern
- **String.split/2 Unicode support:** Improved handling of unicode strings in split operations
- **Regex.scan/3 with capturing groups:** Fixed a bug where the function didn't properly handle capturing groups when the regex had no groups at all

**Relevant commits:** `0e725fb906`, `769b69ad69`, `e00eedec45`

### Mix Dependency Management

Fixed several issues with how Mix manages and compiles dependencies:

- **Dependency Compilation Order:** Ensured dependencies are compiled in the correct order when specified across different projects in an umbrella
- **Preserve Dependency Order:** Fixed regression where dependency order wasn't preserved when dependencies were overriding each other
- **compile: false Option:** Restored the `compile: false` option as a valid way to disable compilation of specific dependencies
- **Avoid Redundant Compilation:** Reduced unnecessary recompilation of dependencies

**Relevant commits:** `63ed270c68`, `b2e32e4ccd`, `0c80905f63`

### EEx Template Handling

Fixed an issue where `do` blocks inside EEx templates were not properly aligned, preventing correct code generation for template logic.

**Relevant commit:** `0267f312b1`

### Kernel Improvements

- **Multiple Heredocs:** Fixed handling of multiple heredocs on the same line
- **Error Messages:** Significantly improved error messages for match, guard, and quoting errors, making debugging easier
- **Quoted Block Capture:** Ensured `&()` syntax works correctly on quoted blocks with only one expression
- **Typespec Line Numbers:** Fixed typespec attributes to be saved with proper line numbers for accurate error reporting

**Relevant commits:** `8b56252e1b`, `14272c98b4`, `60b2928678`, `4b317a75d8`

### ExUnit Improvements

Better doctest handling:
- Improved stripping of doctests
- Better error reports for poorly aligned doctests
- More accurate position reporting

**Relevant commits:** `fc0af0542b`

### Documentation Improvements

- Added validity checking for Inspect.Algebra documents
- Improved guards on IEx.Helpers
- Better error messages for invalid unquote arguments
- Better error message for `mix -e` option
- Improved documentation for various modules

**Relevant commits:** `7b025dd982`, `2977a46865`, `212acf437a`, `e90b877575`

## Deprecations

### Previous Partial Application Syntax

The old partial application syntax (without the `&` operator) has been deprecated. Developers should use the modern `&` operator for creating partial applications and captures.

**Relevant commit:** `9839bfa4ad`

### Regex and String Functions

- **Regex.captures/3:** Deprecated in favor of `Regex.named_captures/3`, which provides a clearer API for accessing named capture groups
- **String.valid_codepoint?/1:** Deprecated in favor of pattern matching with `<<_ :: utf8 >>`, which is more idiomatic and composable

**Relevant commit:** `3f0c583045`

## Breaking Changes

This release includes four backwards incompatible changes that may require updates for existing projects:

### 1. IEx Helper `r/0` Removed

The `r/0` helper has been removed as it caused surprising behavior when many modules with interdependencies accumulated. Users who relied on reloading all modules should manage module reloading more explicitly through other means.

**Relevant commit:** `acdc55bd90`

### 2. Mix.Version Renamed to Version

The `Mix.Version` module was moved and renamed to `Version` in the kernel. Code using `Mix.Version` should be updated to use the new `Version` module location.

**Relevant commit:** `c6f117d60f`

### 3. File.IteratorError Renamed to IO.StreamError

`File.IteratorError` has been renamed to `IO.StreamError`, reflecting its broader applicability to all IO stream operations, not just file operations.

**Relevant commit:** `5bb4f43e9d`

### 4. mix new Defaults to --sup

The `mix new` command now defaults to creating a supervision tree (`--sup` option). Projects that don't need supervision must now explicitly use the `--bare` flag to get the previous behavior. This change encourages following Elixir/OTP best practices from the start.

**Relevant commit:** `3d583e7cdc`

## Upgrade Path

For users upgrading from v0.10.2 to v0.10.3:

1. **Required Changes:** Update any code using the four breaking changes listed above
2. **Recommended:** Take advantage of `@typedoc` for improved API documentation
3. **Optional:** Update to new functions like `Stream.unfold/1` and `Enum.take_every/2` as they become useful
4. **Deprecations:** Begin migrating away from deprecated functions before they're removed in a future release

The release is primarily backwards compatible with a few specific breaking changes that are necessary for language/tool improvement.
