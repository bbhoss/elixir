# Changes from v1.14.5 to v1.15.0

## Overview

**Release Date:** June 19, 2023
**Previous Release:** May 22, 2023
**Time Span:** 28 days
**Total Commits:** 11,848
**Files Changed:** 414 files with 21,355 insertions and 12,619 deletions

Elixir v1.15.0 is a focused release emphasizing performance improvements, particularly in compilation and boot times, along with deeper integration with Erlang/OTP's logger system. This release requires Erlang/OTP 24 and later.

---

## Summary Analysis

Elixir v1.15 represents a maturation step in the language's ecosystem with three primary strategic focuses:

1. **Performance as Priority**: Rather than adding numerous new features, this release concentrates on making Elixir applications compile faster and boot more quickly. The introduction of code path pruning and caching mechanisms shows a pragmatic approach to addressing real-world performance bottlenecks.

2. **Deeper OTP Integration**: The soft deprecation of Elixir's Logger backends in favor of Erlang/OTP's logger handlers demonstrates a maturing relationship with the Erlang ecosystem. This enables users to leverage advanced features like log rotation and compaction out-of-the-box.

3. **Developer Experience**: Improvements to compiler diagnostics, error messages, and new convenience functions across multiple modules show a commitment to making Elixir more approachable and enjoyable for developers.

## Major Features & Improvements

### 1. Compile and Boot-Time Performance

The cornerstone of this release centers on dramatically improving how projects compile and start up:

#### Code Path Pruning and Caching
- **What Changed**: Previously, Mix would continuously add entries to the Erlang VM's code path but never prune them. With 20+ dependencies, the code path would contain 20+ entries plus all Erlang and Elixir applications, causing the VM to search through more paths to find modules.
- **The Solution**: Elixir now actively prunes code paths to only include actual dependencies, mirroring the behavior of `mix release`. This ensures your project compiles in an environment closer to production.
- **Impact**: Projects compile faster and recompilation is reduced when switching branches since Mix now tracks digests of `@external_resource` files.

#### OTP 26 Concurrency
- Erlang/OTP 26 allows applications to start concurrently and caches code path lookups
- Combined with Elixir v1.15, boot times for applications can reduce by **5-30%** depending on the project (e.g., `iex -S mix`, `mix test` on single tests)
- Applications can now use `:start_concurrently` configuration to leverage this capability

#### Compiler Intelligence Improvements
- `@behaviour` declarations no longer add compile-time dependencies, reducing unnecessary recompilation
- Alias references in patterns and guards add no runtime dependencies since they don't trigger dispatching
- Dependencies now automatically recompile when their compile-time configuration changes, ensuring consistency

**Potential Breaking Change**: Code path pruning may break applications or dependencies that don't properly specify their Erlang and Elixir application dependencies. Users can temporarily disable this with `prune_code_paths: false` in `mix.exs`.

### 2. Enhanced Compiler Error Reporting

A significant improvement in developer experience through better error messages:

#### Multiple Error Collection
- **Previous Behavior** (v1.14): Compilation would immediately fail on the first error with a single message:
  ```
  ** (CompileError) undefined function foo/0 (there is no such import)
      my_file.exs:1
  ```

- **New Behavior** (v1.15): Compiler now collects and reports multiple errors in a single compilation pass:
  ```
  error: undefined function foo/0 (there is no such import)
    my_file.exs:1
  error: another undefined function bar/0
    my_file.exs:5

  ** (CompileError) my_file.exs: cannot compile file (errors have been logged)
  ```

#### Undefined Variables as Errors
- **Breaking Change**: Undefined variables now raise an error instead of attempting to invoke a function of the same name. This was a source of confusion for newcomers.
- Developers can restore the previous behavior via `Code.compiler_options(on_undefined_variable: :warn)` at the top of `mix.exs`
- New `:on_undefined_variable` compiler option allows per-project customization

#### New Diagnostics API
- Introduced `Code.with_diagnostics/2` for programmatic access to compilation diagnostics
- Enables editors and IDE plugins to display multiple errors simultaneously, significantly improving the development experience

### 3. Erlang/OTP Logger Integration

This release completes Elixir's integration with Erlang's logger system, introducing enterprise-grade logging features:

#### Logger Handlers Over Backends
- Soft deprecation of Elixir's Logger backends (`add_backend/2`, `remove_backend/2`, `configure_backend/2`)
- Automatic migration from `:console` backend configuration to new handler-based configuration
- **Example Migration**:
  ```elixir
  # Old (v1.14)
  config :logger, :console,
    level: :error,
    format: "$time $message $metadata"

  # New (v1.15)
  config :logger, :default_handler, level: :error
  config :logger, :default_formatter, format: "$time $message $metadata"
  ```

#### New Logger Capabilities
- Global logger metadata support via `Logger.expose_metadata/1`
- File logging with rotation and compaction support through standard Erlang handlers
- New `Logger.add_handlers/1` for programmatic handler management
- New `Logger.default_formatter/1` for accessing formatter configuration
- New `:always_evaluate_messages` configuration for debug logging optimization

#### Backward Compatibility
- Existing Logger backends remain fully functional and supported
- Custom backends continue to work; migration to `logger_backends` is optional and gradual
- Elixir automatically converts console configuration to new format

### 4. Standard Library Enhancements

Expanded functionality across multiple modules with new convenience functions:

#### Collection Operations
- **Map**: New `Map.split_with/2`, `Map.intersect/2`, `Map.intersect/3` for advanced filtering and set operations
- **Keyword**: New `Keyword.split_with/2` for conditional splitting
- **MapSet**: New `MapSet.split_with/2` and significant optimization of most functions

#### Comparison Functions
- **Date, DateTime, NaiveDateTime, Time**: New `before?/2` and `after?/2` functions for intuitive date/time comparisons
- Example: `Date.before?(date1, date2)` instead of manual comparison logic

#### Code and Module APIs
- `Code.loaded?/1`, `Code.ensure_all_loaded(!)/1` for runtime module checking
- `Code.prepend_paths/1`, `Code.append_paths/1`, `Code.delete_paths/1` for explicit path management

- `Macro.Env.lookup_alias_as/2` for alias resolution

#### Process and Task Improvements
- `Process.alias/0,1` and `Process.unalias/1` for explicit process aliasing
- `Task` optimizations: removed head-of-line blocking in `Task.yield_many/2`, selective receive optimizations for OTP 26+
- Reduced task footprint through optimization

#### DateTime Precision
- `DateTime.utc_now/2` and `NaiveDateTime.utc_now/2` now support microsecond precision specification
- `NaiveDateTime.beginning_of_day/1` and `NaiveDateTime.end_of_day/1` for day boundary operations

#### String and Formatting
- Unicode updated to version 15.0.0
- `String.valid?/2` introduces `:fast_ascii` mode for performance
- `'charlists'` now format as `~c"charlists"` by default in Code formatter and Inspect

#### File and Stream
- Distributed `File.Stream` support for working with remote file systems
- `URI.append_path/2` for path concatenation
- `Range.split/2` for range partitioning

## Breaking Changes

While v1.15 is designed to be relatively backward compatible, there are important changes requiring attention:

### 1. Code Path Pruning
- **Impact**: Applications that don't properly declare their Erlang/Elixir dependencies may fail to compile
- **Mitigation**: Set `prune_code_paths: false` in `mix.exs` (temporary solution)
- **Long-term**: Ensure all dependencies properly specify their application dependencies

### 2. Undefined Variables as Errors
- **Impact**: Code that relied on undefined variables attempting function invocation will now fail
- **Mitigation**: Use `Code.compiler_options(on_undefined_variable: :warn)` at top of `mix.exs`
- **Benefit**: Catches real errors earlier with clearer messages

### 3. Pin Variable Requirement in Binary Size
- **Impact**: Accessing undefined variables in binary size during pattern matching now requires explicit pinning
- **Example**: ` <<x::size(n)>>` where `n` is undefined now requires `<<x::size(^n)>>`
- **Rationale**: Makes variable scope clearer and prevents subtle bugs

### 4. Multi-letter Sigil Changes
- Multi-letter sigils now support uppercase and are treated differently in imports
- Custom parsers implementing sigils may need adjustment

## Migration Path

For most applications, upgrading to v1.15.0 should be straightforward:

1. **Update Elixir**: Run `asdf install elixir 1.15.0` or your preferred installation method
2. **Update Dependencies**: Run `mix deps.get` (Hex and Rebar now auto-install)
3. **Address Code Path Issues**: If compilation fails, check for missing application dependencies or enable `prune_code_paths: false` temporarily
4. **Update Logger Configuration** (Optional): Migrate Logger backends to handlers for enterprise logging features
5. **Test Thoroughly**: Pay attention to compiler error messages which are now more verbose
6. **Update Error Handling**: Code relying on undefined variable function invocation will need revision

## Conclusion

Elixir v1.15.0 represents a disciplined release focused on quality over quantity. The emphasis on compile-time and boot-time performance, combined with deeper Erlang/OTP integration and strategic API additions, positions Elixir applications for better real-world performance. The improvements to compiler diagnostics and error reporting will particularly benefit new developers and large teams maintaining complex codebases.

The release maintains excellent backward compatibility while introducing necessary breaking changes that improve the language's consistency and correctness. Projects can upgrade with confidence, though careful attention to code path issues in dependencies is recommended.
