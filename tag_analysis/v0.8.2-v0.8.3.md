# Changes from v0.8.2 to v0.8.3

## Overview

- **Release Date**: May 22, 2013
- **Previous Release**: April 20, 2013
- **Date Range**: April 20 - May 22, 2013 (32 days)
- **Total Commits**: 282 commits
- **Version**: v0.8.3

## Summary of Key Themes

The v0.8.2 to v0.8.3 release represents a significant evolution of Elixir with a strong focus on three major areas: **umbrella projects support**, **improving the interactive development experience (IEx)**, and **expanding the standard library with new collection operations**. Additionally, this release demonstrates Elixir's commitment to code quality through performance optimizations and careful API deprecations to guide users toward better patterns.

The release spans a 32-day development cycle with 282 commits, indicating substantial activity across multiple modules and subsystems. The changes reflect a maturing language actively incorporating feedback from early adopters while maintaining stability through careful deprecation policies.

## Major Features and Enhancements

### 1. Umbrella Projects Support (Most Significant Feature)

This release introduces comprehensive support for umbrella projects, a major architectural pattern for managing multiple interdependent applications:

- **`mix new --umbrella`** - New command to scaffold umbrella project structure
- **Umbrella project support in mix** - Full integration for building, testing, and managing dependencies across multiple apps
- **Dependency propagation in tasks** - Dependencies are now properly propagated through umbrella app hierarchies
- **Ordered task execution** - Umbrella tasks now run in the correct dependency order
- **Manifest-based file tracking** - Uses manifest files instead of directory timestamps to track generated files and remove unused .beam files
- **Umbrella-as-dependency support** - Umbrella projects can now be used as dependencies in other projects
- **MIX_PATH support** - New environment variable allows specifying alternative load paths for dependencies

This feature addresses the need for managing large Elixir systems composed of multiple related applications, a critical pattern for production deployments.

### 2. Interactive Elixir (IEx) Improvements

Significant enhancements to the interactive development experience:

- **Break-trigger for incomplete expressions** - Users can now type `#iex:break` to exit incomplete expression input (closes issue #1089)
- **Colored `ls` helper** - File listing now supports ANSI color output, including multi-column formatting
- **Enhanced file type display** - The `ls` helper now correctly renders file types for all paths
- **Path expansion in `cd`** - The `cd` helper now expands `~` to home directory
- **Improved documentation** - Better docstrings for IEx modules and helpers
- **Better error handling** - IEx won't crash on bad error messages or invalid stack traces
- **IEx.Remsh made private** - Cleaner API by making internal utilities private
- **Token error distinction** - Distinguishes between token errors raised during parsing vs. evaluation

### 3. Enum Module Expansion

The Enum module receives several new functions, solidifying it as the primary collection manipulation interface:

- **`Enum.to_list/1`** - Convert any enumerable to a list
- **`Enum.member?/2`** - Check membership (preferred over List.member?)
- **`Enum.uniq/2`** - Remove duplicates with custom equality
- **`Enum.max/1`, `Enum.max/2`** - Find maximum element with optional comparator
- **`Enum.min/1`, `Enum.min/2`** - Find minimum element with optional comparator
- **`Enum.at/2`, `Enum.at/3`, `Enum.fetch/2`** - Enhanced element access with safe operations
- **`Enum.equal?/2`, `Enum.equal?/3`** - Sequence equality comparison with optional callback
- **Extended Iterator protocol** - `Enum.empty?` and `Enum.member?` now work with the Iterator protocol

These additions provide more comprehensive collection operations while the iteration protocol support enables broader applicability across custom data structures.

### 4. Dictionary Operations Enhancement

New functions make dictionary manipulation more complete and consistent with standard functional programming patterns:

- **`Dict.take/2`** - Extract subset of dictionary by keys
- **`Dict.drop/2`** - Remove keys from dictionary
- **`Dict.split/2`** - Partition dictionary into taken and dropped portions
- **`Dict.pop/3`** - Pop a value and return with updated dictionary
- **`Dict.fetch/2`** - Safe key lookup returning {:ok, value} or :error

Performance optimizations accompany these new functions:
- Faster `HashDict.drop/2`, `HashDict.take/2`, and `HashDict.pop` implementations
- Optimized `HashDict.split` operation

### 5. String Module Enhancements

New string utility functions address common conversion and validation needs:

- **`String.to_integer/1` and `String.to_float/1`** - Convert strings to numeric types
- **`String.valid?/1`** - Validate if a string contains valid UTF-8
- **`String.valid_character?/1`** - Validate individual characters
- **`String.slice/3` behavior change** - Now returns empty string when out of range by 1 (Ruby-consistent semantics)

### 6. Kernel and Language Enhancements

- **`__DIR__`** - New special form to get current file's directory (closes #1019)
- **`Node.get_cookie/0` and `Node.set_cookie/2`** - Distributed Erlang support
- **`List.insert_at/3`** - Insert element at specific position
- **Pipe operator precedence change** - Lowered to support `1..5 |> Enum.to_list` (addresses #862)
- **`in` operator outside guards** - Can now use `in` with right-side expressions outside guards (liberates pattern #817)
- **Macro/attribute expansion in import/alias/require** - Support options from macros and attributes in these directives
- **Better error messages** - Improved error messages for invalid patterns in guards and matches

### 7. ExUnit Improvements

Testing infrastructure enhancements:

- **`ExUnit.CaptureIO`** - New module for capturing IO during tests (replaces ad-hoc approaches)
- **Setup error handling** - Failures in `setup_all` now invalidates all tests (proper semantics)
- **Load time tracking** - ExUnit reports now consider load time in addition to execution time
- **Exit message handling** - Better handling of exit messages from tests

### 8. Mix Build Tool Enhancements

- **`mix local.rebar` task** - Download and manage a local copy of rebar instead of system dependency
- **`mix deps.get --quiet`** - Suppress dependency fetch output
- **Dependency resolution improvements** - Cleaner dependency retrieval and convergence logic
- **IEx processing in Kernel.CLI** - Better integration between IEx and CLI argument processing

## Performance Optimizations

This release includes several performance improvements:

- **Optimized HashDict operations** - `drop`, `take`, `split`, and `pop` operations significantly faster
- **Optimized Mix.Shell.output_app?**
- **Faster exception handling** - Cleaner and speedier exception processing
- **Abstract syntax optimization** - Optimized `elixir_tree_helpers:abstract_syntax`
- **Reduced eval usage** - Removed unnecessary use of eval in IO.ANSI and other modules

## Bug Fixes

Notable bug fixes include:

- **Record rewriter fixes** - Handles variables matched in multiple clauses correctly (closes #1037)
- **Record argument evaluation** - Ensures record arguments evaluated in parent context (closes #1065)
- **RecordRewriter edge cases** - Added missing trivial clauses to handle empty cases
- **Regex.captures fix** - Fixed badmatch exception with `Regex.captures(%r/(.)/g, "cat")` (closes #1041)
- **Path.expand improvements** - Now correctly expands `~` in second argument (closes #1034)
- **IEx helper robustness** - Won't crash on bad error messages or invalid stack traces (closes #974)
- **Keyword argument splicing** - No longer unnecessarily splices keyword args (closes #989)
- **h/0 IEx helper** - Fixed for special forms like `c/2` (closes #1101)
- **Mix compile performance** - Quick compile mode (`-q`) no longer recompiles unnecessarily
- **Rebar integration** - Fixed full path issues when using in-project rebar
- **Module context checking** - Faster path for module context determination
- **Default argument warnings** - Improved and fixed unused variable warnings
- **Group leader cleanup** - Ensures no group leader leakage in capture_io

## Deprecations

The release introduces systematic deprecations to guide API evolution while maintaining backward compatibility:

1. **Code module**
   - `Code.eval` deprecated in favor of `Code.eval_string`

2. **Exception module**
   - `Exception.format_entry` deprecated in favor of `Exception.format_stacktrace_entry`

3. **IO module**
   - `IO.getb` deprecated in favor of `IO.getn`

4. **Enum module**
   - `Enum.at!/2` deprecated in favor of `Enum.fetch/2`
   - Previously deprecated `empty?` removed from Enum protocol

5. **Dict module**
   - `Dict.get!` deprecated in favor of `Dict.fetch!`

6. **List module**
   - `List.member?/2` deprecated in favor of `Enum.member?/2` (encourages use of Enum protocol)

7. **ExUnit module**
   - `assert left inlist right` deprecated in favor of `assert left in right` (consistent with language changes)

8. **Kernel/Quote**
   - `var_context` in quote deprecated in favor of `context`

These deprecations reflect a push toward more consistent naming (e.g., `fetch` for safe operations), protocol-based design (using Enum over List), and alignment with language features (using `in` operator).

## Breaking Changes

Three categories of backwards-incompatible changes were introduced:

### 1. Data Structure Reorganization
- **`List.Dict` moved to `ListDict`** - Cleaner module organization and naming

### 2. IO Behavior Changes
- **`IO.gets`, `IO.getn`, and friends return binaries from stdio** - Consistent binary-based IO (aligns with Erlang conventions)
- **`mix escriptize` receives arguments as binaries** - Consistent with IO changes

### 3. Operator Precedence Adjustment
- **`|>` pipe operator precedence lowered** - Now supports constructs like `1..5 |> Enum.to_list` without parentheses
  - This change allows more natural pipelining of range operations
  - Demonstrates commitment to ergonomic syntax as language patterns become clearer

## Closing Remarks

The v0.8.2 to v0.8.3 release demonstrates Elixir's maturation as a language and framework. The introduction of umbrella projects shows the project's commitment to supporting real-world application architectures. The extensive standard library additions (Enum, Dict, String functions) and developer experience improvements (IEx enhancements) make the language more practical for daily use.

The structured approach to deprecations—providing clear migration paths while maintaining backward compatibility—establishes a responsible API evolution pattern. The performance optimizations show that growth doesn't come at the cost of efficiency.

With 282 commits addressing features, bugs, documentation, and infrastructure, this release represents concentrated effort to build a production-ready foundation for functional programming on the Erlang VM.
