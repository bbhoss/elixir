# Changes from v1.8.0 to v1.8.1

## Release Information

- **Release Date Range**: January 14, 2019 (v1.8.0) to January 30, 2019 (v1.8.1)
- **Duration**: 16 days
- **Total Commits**: 7 commits (excluding release commit)

## Summary

Elixir v1.8.1 is a patch release that primarily addresses critical bug fixes and stability issues discovered shortly after the v1.8.0 release. This was a focused release with no breaking changes, maintaining full backward compatibility. The release focused on:

1. **Critical Bug Fixes**: Addressing runtime crashes and correctness issues
2. **Regression Fixes**: Reverting a problematic feature from v1.8.0
3. **User Experience Improvements**: Better IEx interaction and warnings
4. **Robustness**: Fixing floating-point arithmetic edge cases and test flakiness

The quick turnaround (16 days) suggests that issues in v1.8.0 were discovered in real-world usage and needed immediate attention.

## Major Bug Fixes

### Critical: Revert Optional Dependencies Feature

**Commit**: `ac947a5d1d` - "Revert Include optional dependencies in extra_applications (#8263)"

This was a significant regression fix. The v1.8.0 release included a feature to automatically include optional dependencies in `extra_applications`, but this introduced a problem in umbrella applications where different child applications depend on different optional dependencies.

**The Problem**:
- In umbrella apps where multiple children share a dependency (like Ecto)
- When each child uses different optional dependencies of that shared dependency (e.g., Ecto with both Jason and Poison as optionals)
- The parent application would include all optional dependencies from all children
- This caused child applications to fail when run in isolation

**Impact**: This was a critical regression that affected umbrella applications (a common pattern in larger Elixir projects) and needed to be reverted to restore functionality.

### IEx.pry Crash Fix

**Commit**: `82a511aafe` - "Fix IEx.pry crash when IEx (IEx.Broker) isn't running (#8730)"

Fixed a crash that occurred when attempting to use `IEx.pry/0` in contexts where the IEx broker wasn't running. This is an edge case that could occur in certain debugging scenarios or when using IEx programmatically.

### DateTime Timezone Database Reliability

**Commit**: `7c2e65f418` - "Do not rely on timezone database for DateTime.now"

Improved test robustness by removing dependency on a potentially incomplete timezone database (`FakeTimeZoneDatabase`) for DateTime operations. This prevents intermittent test failures that would occur when the fake database lacked entries for certain timezones.

**Impact**: Improves reliability of tests and prevents flaky test failures in CI/CD environments.

### Floating-Point Rounding Fix

**Commit**: `3d04cb0aa0` - "Fix rounding for subnormal floats (#8687)"

Fixed incorrect rounding behavior for subnormal (very small) floating-point numbers. This is a precision issue that affects numeric calculations at the edge cases of floating-point arithmetic.

**Impact**: Ensures mathematical correctness for edge-case float operations, important for scientific computing and financial calculations.

### Changelog Correction

**Commit**: `8fa9d728f1` - "Correct release date of v1.8 in CHANGELOG (#8646)"

Minor documentation fix correcting the release date in the changelog documentation. This was marked `[ci skip]` as it only affects documentation.

## Improvements and Enhancements

### IEx Help Command Enhancement

**Commit**: `7e4f9c5647` - "IEx h: sort results by arity (#8727)"

Enhanced the IEx `h` command (help) to sort results by arity when displaying multiple versions of a function. Previously, results were displayed in an arbitrary order.

**Example**:
```
iex> h :erlang.float_to_binary
```

Previously showed `float_to_binary/2` before `float_to_binary/1` randomly. Now consistently shows them sorted by arity, making it easier to find the specific function overload you're looking for.

**Impact**: Improved developer experience and discoverability in the interactive shell.

### IEx Terminal Warning

**Commit**: `b37ecb0f8e` - "Add IEx warning when using --remsh with 'dumb' terminal (#8563)"

Added a helpful warning message when users attempt to use the `--remsh` (remote shell) option with a 'dumb' terminal. The 'dumb' terminal doesn't support the advanced terminal features required for proper remote shell operation.

**Impact**: Reduces user confusion by providing clear feedback about terminal compatibility issues before they experience problems.

## Breaking Changes

**None**. This is a pure patch release with no breaking changes. All changes are backward compatible.

## Notable Technical Details

### Why This Quick Patch Release?

The 16-day gap between v1.8.0 and v1.8.1 is relatively short for a patch release, indicating:
1. **Critical Issues Found**: The optional dependencies revert suggests the feature was problematic enough to disable
2. **Real-World Testing**: Issues were likely discovered through community usage and reported quickly
3. **Rapid Response**: The Elixir team prioritized fixes for widespread problems

### Reliability Focus

This patch shows a focus on reliability:
- Fixing crashes (IEx.pry, float rounding)
- Improving test stability (timezone database)
- Reverting problematic features
- Adding user-facing warnings (terminal compatibility)

### No Major Features

Unlike v1.8.0 which introduced custom struct inspections, timezone database support, and significant performance improvements, v1.8.1 contains no new features—only fixes and enhancements.

## Conclusion

v1.8.1 represents the Elixir team's commitment to stability and reliability. While v1.8.0 delivered significant improvements and features, v1.8.1 quickly addressed critical issues that emerged in real-world usage. The revert of the optional dependencies feature was the most significant change, protecting umbrella applications from a breaking regression. The other fixes addressed edge cases, test robustness, and user experience.

This release demonstrates the importance of patch releases in maintaining a stable platform and the Elixir team's responsiveness to community feedback.
