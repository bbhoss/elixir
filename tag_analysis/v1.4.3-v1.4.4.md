# Changes from v1.4.3 to v1.4.4

## Overview

v1.4.4 was released on **May 15, 2017 at 16:53:22 UTC+2** as an emergency patch release, just **2 hours and 15 minutes after v1.4.3** (released at 14:38:10 UTC+2). This rapid release was necessitated by a critical regression discovered in the struct update syntax immediately after v1.4.3 went live.

**Commit Count:** 1 release commit
**Date Range:** May 15, 2017 (14:38:10 to 16:53:22 UTC+2)
**Release Type:** Patch/Bug Fix Release

## Summary

v1.4.4 is a minimal patch release addressing a single but significant regression introduced in v1.4.3's handling of the struct update syntax. The issue affected the pipe operator (`|`) usage when updating struct fields with the `__struct__` key present in the map arguments.

While v1.4.3 itself was focused on achieving full compatibility with Erlang OTP 20-rc.1, v1.4.4 corrects a code generation bug that broke struct pattern updates under certain conditions. The fix involved refactoring how the struct key is cleaned from map arguments to properly handle both simple maps and piped updates.

## Bug Fixes

### Elixir

#### Map - Struct Update Syntax Regression

**Issue:** A regression was introduced in v1.4.3 where the struct update syntax broke when handling the `__struct__` key in map arguments. The problem manifested when using the pipe operator with struct updates.

**Root Cause:** The code in `elixir_map.erl` was expanding arguments in the wrong order and not properly handling the pipe syntax pattern for struct updates. The `expand_struct/4` function was flattening the `CleanArgs` into the same list as the left-hand side, when the right-hand side map should be kept as a separate entity.

**Solution:** The fix extracted the struct key cleaning logic into two new helper functions:
- `clean_struct_key_from_map_args/3`: Handles both regular maps and piped map patterns
- `clean_struct_key_from_map_assocs/3`: Performs the actual key removal

The corrected approach ensures that:
1. The left-hand side struct reference remains separate
2. The right-hand side map is properly preserved as a map literal
3. Pipe syntax (`|`) in struct updates works correctly
4. The warning for `__struct__` key override is consistently applied

**Code Changes:** Modified `/lib/elixir/src/elixir_map.erl` with refactored struct expansion logic and added comprehensive test coverage in `/lib/elixir/test/elixir/kernel/warning_test.exs` to verify both direct struct updates and piped updates handle the `__struct__` key appropriately.

**Example of Fixed Behavior:**
```elixir
defmodule User do
  defstruct [:name]
end

# This now works correctly with proper warning
user = %User{name: "meg"}
%User{user | __struct__: Ignored, name: "joe"}
# Produces warning: "key :__struct__ is ignored when using structs"
```

## Breaking Changes

**None.** This is purely a bug fix release that restores functionality broken by v1.4.3. Code that was working before v1.4.3 should work correctly again after applying v1.4.4.

## Upgrade Recommendation

**Strongly Recommended.** All users on v1.4.3 should upgrade to v1.4.4 immediately if they use struct pattern matching or updates with the pipe operator. While the warning about the `__struct__` key is intentional, the actual functionality was broken for piped updates.

## Context: Why v1.4.4 Was Needed

v1.4.3 introduced significant changes for Erlang OTP 20-rc.1 compatibility, including a new warning system for the `__struct__` key in struct updates. However, the implementation had a subtle bug in how it handled the refactored arguments when the pipe operator was used. The quick turnaround for v1.4.4's release demonstrates the Elixir team's commitment to maintaining code quality and rapidly addressing critical issues.
