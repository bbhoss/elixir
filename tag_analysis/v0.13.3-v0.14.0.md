# Changes from v0.13.3 to v0.14.0

## Release Overview

**Date Range:** May 23, 2014 - June 8, 2014
**Total Commits:** 154 commits
**Release Date:** June 8, 2014

This release represents a significant evolution of Elixir, introducing fundamental improvements to data structure manipulation, testing infrastructure, and build system flexibility. The release spans approximately two weeks of concentrated development and focuses on developer experience, Windows compatibility, and standardization of APIs.

---

## Summary & Key Themes

v0.14.0 introduces several transformative features that significantly enhance the language's expressiveness and practical usability:

1. **Documentation as First-Class Citizen**: A major architectural shift moves documentation storage from the module's runtime info to the compiled beam files themselves, enabling lazy loading and better integration with documentation tools.

2. **Unified Nested Data Structure Access**: New functions (`get_in`, `put_in`, `update_in`, `get_and_update_in`) provide a consistent and elegant API for working with nested data, a critical capability for Elixir's functional programming paradigm.

3. **Testing Infrastructure Modernization**: The introduction of `on_exit/1` callbacks in ExUnit represents a paradigm shift away from teardown callbacks, enabling more reliable resource cleanup and better integration with process-based testing patterns.

4. **Build System & Configuration Improvements**: Mix receives multiple enhancements including the new `Mix.Config` module for configuration management, protocol consolidation support, and better tooling for Windows users.

5. **Struct Derivation**: The `@derive` attribute combined with protocol consolidation enables more powerful and flexible struct definitions with automatic protocol implementations.

6. **Task Semantics Change**: Tasks now automatically link to their callers, changing error propagation behavior and making failures explicit rather than implicit.

## Major Features & Enhancements

### 1. Documentation Storage & Code.get_docs/2

**Commits:**
- `211d9428b4` - Add version tag to Elixir's beam chunk
- `8a3f2cfc2f` - Remove :docs and :moduledoc clauses from the __info__ function
- `b1f0d3ed99` - Preserve docs chunk during protocol consolidation
- `8448513c8b` - Update tests that need to read module docs to write BEAM code to disk

**What Changed:**
Prior to v0.14.0, module documentation was stored in the runtime metadata accessible via `module.__info__(:docs)`. This approach had significant downsides—documentation was always loaded into memory even if never accessed, and it complicated protocol consolidation.

v0.14.0 shifts to storing documentation as a chunk in the compiled BEAM files, introducing `Code.get_docs/2` as the new API for retrieving documentation at runtime. This is a **backwards incompatible change**—code previously using `module.__info__(:docs)` will fail.

**Benefits:**
- Documentation is only loaded when explicitly requested
- Better separation of concerns (docs are now file-based, not runtime data)
- Enables better tooling support (ExDoc, IEx, etc.)
- Reduces memory footprint of running systems

### 2. Nested Data Structure Operations (get_in, put_in, update_in)

**Commits:**
- `a09a0c2a1a` - Add Access.update/3
- `4d53d8c710` - Add get_in/2, put_in/3 and update_in/3
- `4a183b462c` - Fix nested updates bootstrapping
- `2d38f20b43` - Add get_in/1, put_in/2 and update_in/2
- `e040688bd9` - Require get_and_update/3 instead of update/3 in Access
- `f3f0ec09b7` - Add get_and_update_in/* ops and update CHANGELOG

**What Changed:**
These functions provide a powerful and flexible way to access, modify, and retrieve values from nested data structures. They work with any data structure implementing the `Access` protocol.

**Function Signatures:**
```elixir
get_in(data, keys)           # Navigate nested structure
put_in(data, keys, value)    # Set nested value
update_in(data, keys, fun)   # Update nested value
get_and_update_in(data, keys, fun)  # Atomic get and update

# Path-based versions (with single arity)
get_in(keys_path)
put_in(keys_path, value)
update_in(keys_path, fun)
get_and_update_in(keys_path, fun)
```

**Impact:**
This is a fundamental improvement for working with nested data structures common in Elixir applications (nested maps, keyword lists, etc.). The consistent API reduces the need for custom helper functions and makes code more readable and maintainable.

### 3. ExUnit on_exit/1 Callbacks

**Commits:**
- `40dff7ebe8` - Support on_exit for registering callbacks in ExUnit
- `513ed0bbae` - Move on handler functionality to its own module
- `db70fd5a5f` - Also support on_exit on setup_all
- `cb5806bbf3` - Deprecate teardown and teardown_all

**What Changed:**
Introduces `on_exit/1` callback mechanism that guarantees execution once a test process exits, and always runs in a separate process. This is fundamentally more reliable than the previous `teardown/2` and `teardown_all/2` callbacks.

**Key Differences:**
- `on_exit/1` callbacks run after the test completes (not during)
- They run in a separate process (avoiding state pollution)
- Multiple `on_exit/1` calls can be registered
- Execution order is guaranteed (LIFO - last registered, first executed)

**Example:**
```elixir
test "resource cleanup" do
  {:ok, pid} = start_resource()
  on_exit(fn -> stop_resource(pid) end)
  # Test code
end
```

### 4. Protocol Consolidation & @derive

**Commits:**
- `e24cef0126` - Add protocol consolidation with mix compile.protocols
- `b161070345` - Merge pull request #2344 from madlep/fix_agent_start_link_timeout_option_doc
- `23f0ff81c4` - Write consolidated files to _build
- `3ab1db6740` - Move Protocol consolidation up to the Protocol module
- `2b3e53670e` - Provide Protocol.derive/3
- `34c2da2c65` - Initial work on @derive for structs
- `f6b0f29f5d` - Add docs for @derive

**What Changed:**
Two complementary features enhance protocol usage:

1. **Protocol Consolidation** (`mix compile.protocols` task): Pre-compiles protocol implementations into a single consolidated module, enabling much faster protocol dispatch (especially important for built-in types).

2. **@derive Attribute**: Allows structs to automatically implement protocols without manual `defimpl` declarations:
```elixir
defmodule MyStruct do
  @derive [Inspect, Enumerable]
  defstruct [:field1, :field2]
end
```

**Impact:**
These changes significantly improve performance of protocol-heavy code and reduce boilerplate for struct definitions.

### 5. Mix.Config Module & Configuration Management

**Benefits:**
Better structure and organization of configuration across projects, especially in umbrella applications.

**What Changed:**

### 8. Task Linking & Failure Propagation

**Commits:**
- `3e54d33481` - Do not catch failures on tasks
- `0fe1e686b3` - Revert "Set up the monitor only on await for tasks"
- `85a04fe919` - Set up the monitor only on await for tasks

**What Changed:**
**Breaking Change**: Tasks are now automatically linked to their callers. If a task fails, it will crash the calling process directly, rather than being silently caught.

**Before v0.14.0:**
```elixir
task = Task.async(fn -> raise "error" end)
Task.await(task)  # Had to explicitly await to see the error
```

**After v0.14.0:**
Tasks are linked by default, so failures propagate immediately.

**Rationale:**
This change makes error handling more explicit and prevents accidentally ignoring task failures. It aligns with Elixir's "let it crash" philosophy.

## Deprecations (With Warnings)

1. **Access Module:**
   - `Kernel.access/2` deprecated in favor of `Access.get/2`
   - Access protocol changed to require `get/2` and `get_and_update/3`

2. **Kernel Module:**
   - `Application.Behaviour`, `GenEvent.Behaviour`, `GenServer.Behaviour`, `Supervisor.Behaviour`
     → Use `Application`, `GenEvent`, `GenServer`, `Supervisor` instead

3. **Mix:**
   - Exceptions with `:mix_error` field no longer supported
   - Use `:mix` field and `Mix.raise/1` and `Mix.raise/2` instead

## Breaking Changes

These changes will break existing code and require migration:

### 1. Documentation Retrieval API (Major)

| Before | After |
|--------|-------|
| `module.__info__(:docs)` | `Code.get_docs/2)` |

Any code using `module.__info__(:docs)` must migrate to `Code.get_docs/2`.

### 2. Access Protocol

The `Access` protocol implementation changed:
- Old: Required `access/2` and `update/3`
- New: Requires `get/2` and `get_and_update/3`

Custom implementations must be updated.

### 3. Compiler Options

`Code.compiler_options/1` no longer accepts custom options. Only Elixir-specified options are allowed (use mix config instead).

### 4. Task Linking

Tasks are now automatically linked to callers. Code relying on silent task failures must be updated to handle linked failures explicitly.

### 5. Mix New Generator

`mix new` no longer generates supervision tree by default. Use `mix new --sup` to get one.

## Summary of Impact

v0.14.0 is a **significant stepping stone** in Elixir's maturation:

- **For Library Authors**: Protocol derivation and consolidation enable better abstractions; the new documentation API requires updates but enables better tooling.

- **For Application Developers**: Nested data manipulation functions are immediately useful; `on_exit/1` callbacks improve test reliability; task linking makes error handling more explicit.

- **For Framework Builders**: Mix improvements (Config module, better configuration management) support more sophisticated build systems and deployment scenarios.

- **Cross-Platform**: Substantial Windows support improvements acknowledge the need for Elixir to work seamlessly across platforms.

The release shows intentional API design, willingness to make breaking changes for the greater good, and careful attention to both user experience and system reliability. Many features introduced here (nested data functions, on_exit callbacks, protocol derivation) remain central to Elixir development even in modern versions.
