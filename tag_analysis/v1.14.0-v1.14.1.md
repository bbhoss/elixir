# Changes from v1.14.0 to v1.14.1

## Release Timeline

- **Start Date**: September 1, 2022
- **Release Date**: October 10, 2022
- **Duration**: 39 days
- **Total Commits**: 33 commits

## Overview

v1.14.1 is a maintenance release focused on bug fixes, error message improvements, and compatibility enhancements. Rather than introducing major new features, this release consolidates improvements and fixes discovered after the v1.14.0 release. The commit pattern shows steady, continuous improvement with emphasis on stability and developer experience.

## Summary of Key Themes

This release is characterized by four major areas of focus:

1. **Unicode and String Handling Robustness**: Multiple commits addressing edge cases in Unicode processing, particularly around malformed sequences and character classification
2. **Compilation and Type System Improvements**: Bug fixes in the compiler, type checker, and macro expansion system
3. **OTP 26 Compatibility**: Ensuring Elixir works correctly with Erlang/OTP 26
4. **Error Message and API Enhancements**: Better error messages, improved API options, and documentation updates

The release maintains backward compatibility while providing meaningful improvements to core functionality.

## Major Features and Improvements

### New API Features

#### **Macro.expand_literals/2**
- **Commit**: `3d2c3101c3` (Oct 7, 2022)
- **Details**: Added new function `Macro.expand_literals/2` to enable partial literal expansion in `@` attribute assignments
- **Impact**: Provides more granular control over macro expansion, allowing developers to expand literals within attribute contexts
- **Related Changes**: The internal function naming was refined (`expand_literal` → `expand_literals`), and the default `compile_env` argument was expanded to work correctly in this context

#### **System.shell/2 Enhancement**
- **Commit**: `d60040636e` (Sep 15, 2022)
- **Details**: Added `:close_stdin` option to `System.shell/2`
- **Backward Compatibility**: Defaults to `false` to maintain behavior from past Elixir versions
- **Impact**: Provides developers with more control over shell subprocess I/O handling

#### **Mix Test Improvements**
- **Commit**: `f0943e74a7` (Sep 7, 2022)
- **Details**: Added `--all-warnings` option to `mix test` command
- **Impact**: Allows developers to see all compiler warnings while running tests, not just errors and warnings from modified files

### Error Message Enhancements

#### **DateTime.add/3 Error Messages**
- **Commit**: `78d6b88e33` (Sep 23, 2022)
- **Details**: Added complete list of supported time units to the DateTime.add/3 argument error message
- **Impact**: Developers now get immediate, clear feedback about valid time units without consulting documentation

#### **Type Signature Order in Checker Messages**
- **Commit**: `7f494e6293` (Sep 23, 2022)
- **Details**: Fixed the order of type signatures in type checking error messages
- **Impact**: Error messages now display signatures in a consistent, logical order, improving clarity

#### **Struct Module Conflict Errors**
- **Commit**: `b78b480587` (Sep 4, 2022)
- **Details**: Now raises proper error messages when there's a module conflict with struct field definitions
- **Impact**: Better diagnostics for module definition issues

### Formatter and Build Improvements

#### **Formatter Configuration Caching**
- **Commit**: `bd63670765` (Sep 5, 2022)
- **Details**: Prevents caching of inputs from `.formatter.exs` files
- **Impact**: Ensures formatter behaves correctly when configuration files change without requiring cache invalidation

#### **Bootstrap Fixes**
- **Commit**: `d84f88954c` (Sep 9, 2022)
- **Details**: Fixed issues in the bootstrap compilation process
- **Impact**: Improves reliability of the compiler bootstrap phase
